## Clone tracing and narrow optimization

Workshop-only source `dd65fcec1` is a partial reduction, not a full-project performance pass. Static tracing shows: UI import parses the input, `normalize` clones it with JSON serialization, `commit` clones the previous project for undo and then `finalize`/`normalize` clones the new project; the old UI path additionally returned a deep project copy that the file handler discarded. The public API still returns an independent copy; the file handler now requests no return copy. Playtest formerly structured-cloned the whole project, selected one stage from that copy, then game `launchMap` normalized/cloned the one-stage project again. It now selects the stage before the first clone. The complete library is still copied, including unused and user-edited assets. Dynamic references, direct asset IDs, and runtime code prevent assuming a naive list of element asset IDs is sufficient.

For scale, direct inspection of the prior baseline 40-stage export found compact UTF-8 library 88,948,033 bytes, all stages 3,102,396 bytes and selected stage 2 54,773 bytes; these are serialized sizes, not measured memory savings. The dominant library remains. A small two-stage differential browser fixture SHA-256 `e123c9e091a410000a06ded1c2ba4eb8a84b81d3530b73cd38fca6f69aa11e3a` instrumented `structuredClone` calls on project-shaped objects only; it did not count JSON-based normalizations or browser heap. File import project clones fell from 2 to 1; the Playtest snapshot's structured clone changed from 2 stages / 507,607 JSON code units to 1 stage / 204,385 code units while retaining both assets. Real launched battle terrain and unit summaries, modified vector fill, unused user asset payload, original editor state and campaign owner were equal before and after. API import still returns an independent project copy. Normal UI quota/export/reload regression passed after the change. Run `browser-workshop-clone-compare.py BASE TAG` on each build; compact raw results are `evidence/workshop-clone-20261031.tar.xz`.

No new full-size run was attempted: the small test establishes removal of particular redundant copies, not sufficient reduction to fit the shared memory limit, and does not establish full-project import, Playtest, or original high-memory root cause. The earlier baseline also failed the bounded test.
