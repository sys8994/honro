# Profile regression comparison

The identical checked-in `tests/profile-store-p01.mjs` and `tests/profile-store-p01-preservation.mjs` were run in clean baseline `d342a7226e46e9c2b2e28cfb6836d3cdd3c47d48` and RC `2577ef15e1c9b81fbb824ffd68f3f265ca9086b2`, with the same checked-in fixture generators, Node and dependencies. Both fail in the same assertions before and after RC's map-only change:

- `profile-store-p01.mjs:13`: historical `7cab23ef` loader yields schema 4 without two presentation fields; current store yields schema 5 with those fields. This comparison targets an older contract. No expectation was changed.
- `profile-store-p01-preservation.mjs:4`: current `web/manifest.json` lacks a historical published generation required by the old test; both commits fail with the same absent object. No manifest was altered to satisfy it.

The current map contract is tested separately: `tests/act4-map-revision-rc.mjs`, `tests/act4-rc-archive.mjs`, and `tests/campaign-map-revision.mjs`. They check unchanged prior stages/Workshop, XP and reward/proof retention, byte-exact Act 4 archive and quota failure. `browser-migration.py` additionally checks heroes, equipment, clears, recruited party and Act 4 proof against the unchanged saved input in the actual App, then uses the restart UI. These results do not make the two historical tests pass and do not replace an end-to-end play/save/resume run.

A separate same-byte profile without an active battle (synthetically set to stage 30) was loaded through the same App store in both commits. Heroes, equipment, clears, recruited party, Act 4 proof and growth were unchanged; the identical projected output SHA-256 was `fdc53e7bebd37159801508acf85db1808e0daab2c7abb422e08512a64eaff42c`. Reproduce using `node tools/act4-rc/profile-projection.mjs`, with `HONRO_PROFILE_FIXTURE` pointing to the same fixture when running against another checkout. This is a profile preservation test, not normal gameplay or every possible prior save.

## Post-common-save browser comparison

`browser-legacy13-rest.py` used the same declared stage-12-cleared fixture and the same defense→next actor→walk→reload→Continue→pause→rest-cancel→explicit rest sequence on isolated Chromium contexts. The older P0 QA preview at port 8773 and the new combined QA preview at 8774 both restored the moved stage 13 actor with matching saved x/y/moveLeft within their own run, preserved stage 12 clear, kept the battle on cancel and reached an explicit rest after confirmation with the battle cleared. Wall-clock holds produced different displacement (older x=527.31, new x=514.48); this is not a deterministic coordinate or whole 1–30 campaign comparison. Current `browser-migration.py` separately verified the old Act4 source bytes archived unchanged and hero/equipment/clears/recruits/proof retained through the real restart UI. Existing custom/workshop regression remains 16/18 groups with two failure baselines not yet compared; no expectation was changed.
