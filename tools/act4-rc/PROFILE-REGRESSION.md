### Minimal-project isolation of embedded Workshop

`browser-workshop-minimal.py` starts one browser at a time with a validated 3,666-byte, one-stage/one-asset map (one player, one hound), placed as the isolated Workshop autosave before opening the real editor. The prior P0 preview and the new common-source preview each loaded the real embedded iframe and actual engine, accepted a real F defense (player acted and control passed to the enemy), and kept the seeded campaign profile byte-identical before action, after action and after the visible Stop button. The earlier large-project crash/60-second stall therefore does not occur for this minimal input; it does **not** prove whether project size, memory pressure, compiler cost or another large-project issue caused it.

The existing implementation uses direct iframe `onload` → `HONRO_READY` → `launchMap`, not a postMessage handshake. Probes showed iframe document complete with `HONRO_EMBEDDED=true` while App initialization was pending, then a resolved engine after approximately 4.4s on the new preview and 5.4s on the earlier preview. Captured `evidence/workshop-min-current.json` and `evidence/workshop-min-baseline.json` contain status, frame, console and request-failure traces; no page JavaScript errors occurred. In the newer trace two console 404s were both the local QA server's missing `/favicon.ico`. The abort of a font request occurred during navigation; the earlier run also recorded aborted font and audio requests. No iframe error or missing launch input was observed for the minimal project. Actual device performance, other projects and the earlier large-project failure remain open.
