# Stage 33 movement-save investigation

The stage 33/34 worker reported a real round-9 mid-turn rollback in `277cbbf1a2877042c479bfeaa9b6d3041ae1064d`, `game/reports/act4-rc-stage33-34/README.md`. The live export and reload differed; that evidence is not negated by this narrower check. The underlying cause remains unproven. In `shared/runtime/main.js`, the periodic battle snapshot is gated by `dirty`, and `pagehide` only cancels input; `Engine.move` itself emits no save event. Other game events can mark a battle dirty, so that observation alone does not prove why the recorded round-9 save was stale.

An isolated QA Chromium check used the RC preview source based on `43b268873` plus uncommitted subtitle sequencing changes. It declared stages 1–32 complete in the 45 SP fixture and entered stage 33 directly; it was not a normal playthrough. Two separate rightward keyboard movements and same-context reload/Continue were observed. After the second movement, both the live and stored archer were x=294.1936407618098, y=2242.5372386080403, moveLeft=2451.0701070040323; reload restored those values. Thus this initial-state probe did not reproduce the reported later-round defect. `browser-move-save-probe.py` repeats this limited observation on the QA URL in `HONRO_QA_URL` and prints values; it is not a passing regression test for the reported bug.
