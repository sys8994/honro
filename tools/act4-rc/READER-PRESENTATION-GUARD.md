# Act 4 reader presentation guard — scoped candidate

Base `ef21e956`: `act4-events.js` records a reader receipt only in its animation-frame observer when the actual line text matches a visible DOM node and the speaker remains allowed. `story.js` can synchronously advance and save/finish independently of that observer. If the observer has not caught up before the next input, the old terminal path retires the unreceipted line. This is a demonstrated race, not proof that it caused either original missing row: the original 37 and 40 runs did not retain the missing row's DOM/frame timeline. The original 37 Enter inputs were approximately 0.8–1.0 seconds apart; do not describe them as an established too-fast action.

This is a deliberate performance stress diagnostic; DOM presence alone does not prove a painted frame or diagnose the original run.

The candidate keeps the actual observer as the only source of receipt: an Act 4 reader's Next is disabled and its normal next operation is held until that current eligible row is observed. The observer then enables Next. The existing explicit Skip remains available and does not fabricate receipts; on a severely delayed frame the user sees Next disabled and may have to press it again once enabled. No other chapter dialogue is gated. It does not fabricate or repair old missing evidence.
