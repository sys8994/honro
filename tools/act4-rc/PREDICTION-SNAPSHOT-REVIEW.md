# Stage 38 prediction snapshot independent review

Candidate `03fd076323e9bc0334bdb762b0486eec63e4fa7a`, evidence branch `codex/act4-render-performance-followup@4f6d6c10`. **Not integrated:** its omission guard does not preserve full-clone behavior for all property access. Common RC remains unchanged by the candidate.

The developer's isolation test passed when run against the exact candidate source: ordinary property read and nested write to omitted art cause a full-clone retry; modified input art, outside-scope custom/workshop battles, and several unsupported values were tested there. Their reported 745 prediction comparisons and frame hash remain evidence for the tested cases, not proof of every possible access.

Independent counterexample: an official stage 38 battle with `honroLandmarks[0].asset.vector.root.d = 'M0 0'`. `withPredictionBattle` callback reading `Object.getOwnPropertyDescriptor(copy.honroLandmarks[0].asset,'vector').value?.root?.d` returns `null`, while the same callback on `structuredClone(battle)` returns `'M0 0'`; callback runs once and no retry occurs. The replacement accessor traps a direct get/set but descriptor inspection bypasses its getter. No live HP or RNG is changed in this counterexample. It is a synthetic unknown-access test, not evidence that current normal prediction actually uses descriptor inspection. The candidate therefore does not meet the requested safe fallback contract. Reproduce with `git show 03fd076:shared/engine/src/predictionSnapshot.ts > /tmp/honro-prediction-snapshot-review.ts` and `node tools/act4-rc/check-prediction-guard.mjs /tmp/honro-prediction-snapshot-review.ts`; it deliberately exits nonzero on the candidate.

A separate synthetic callback demonstrated the candidate reruns the callback after guarded access, so effects outside the cloned battle can occur twice. The live battle HP and RNG stayed unchanged in that example; it does not prove an actual global game effect occurs. The real prediction calls shared runtime hooks, so a future fix needs to show that aborted attempts cannot leak externally observable events/cache/state, rather than assuming battle cloning alone proves it. Check aliases and mutation attempts as well as direct read, reflection, delete, unknown object structures, custom/workshop and all stage gates; rerun fixed-source real-browser parity and relevant collision tests before integration.

`node tests/aim-launch-collision.mjs` on common source `ff2445743` without the candidate also fails its first stage 1 assertion `fixture no longer reproduces embedded muzzle` at line 25. This establishes the same failure on the current baseline; it does not establish its historical cause, and it is not a passing collision test.

## Withdrawal

The performance branch restored a single full `structuredClone` and one replay in `927fdd61834ca966655b2e4d2136b28c6fb7f4b6`, with the review documented at `4d452f1bea68cb1fbc4fdfc4551d83afbc434cb2`. The `03fd076` snapshot prototype's reported frame improvements are withdrawn and must not be counted as an achieved RC improvement. It was never integrated into common, so no common runtime rollback is needed. Previously integrated compact autosave and guide preparation are independent changes and remain in place. A new prediction optimization still requires its own sound state/input contract and validation.
