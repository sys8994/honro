# 31장 승선 목표의 별도 회귀 검사

원본 fe8d420b의 tools/act4-rc/evidence/stage31-b463-run/storage-snapshots.tar.xz 안 0049.json을 바이트 변경 없이 XZ 압축했다. 원본 SHA-256: 7a58b7fbe5dff81dbb630974e4b4112e10623f4aef74cdbd866ca07273af69ee.

실제로 34명을 처치한 13라운드 직후의 localStorage 읽기 스냅샷이다. 원래 프로필의 앞선 캠페인 완료는 합성 입장 조건이므로 1~30장 자연 진행으로 주장하지 않는다. 네 동행은 아직 배에 올라 있지 않다. inputs.json은 같은 실제 실행의 interactive-key/hold/wait 기록을 E 승선 입력까지 추출했다. 이후 전투/목표 상태를 강제로 바꾸지 않고 실제 UI 가져오기·계속·키 입력으로만 검사한다.

이 검사는 현재 런타임의 승선 목표 동작을 검증한다. 새 전투의 클리어 턴 수나 성공률, 진행 중인 별도 새 전투 검사를 대신하지 않는다. 원래 13라운드 완료와 최신 전체 플레이 실패를 함께 보존하며 어느 한쪽을 지우지 않는다.

첫 재생(41261047439)은 승선 안내 대사 중 이동 입력이 무시돼 실패했다. 실패 스크린샷과 상태를 보존했다. 후속 검사는 시간열을 맹목적으로 재생하지 않고 실제 대사/입력 가능/착지 상태를 확인하고 같은 원래 지지면의 이동 목표를 향해 일반 키 입력을 한다. 텔레포트, 대사 영수증 주입, HP 복원은 사용하지 않는다. inputs.json은 원래 성공 실행의 참고 기록이다.

물리 진단에서 두 번째 긴 점프가 원인임을 분리했다. x4895/y2932에서 오른쪽으로 오래 점프하면 최고점이 다음 상승 발판보다 낮아져 발판 밑을 지나 바다로 추락했다. 짧게 첫 급경사만 넘고 x4900에서 착지한 뒤 경사로를 걸으면 설오·담허 모두 x5800까지 피해 0으로 이동했다. 해당 경로를 실제 키 입력 검증에 반영한다. 두 번째 점프를 무조건 넣거나 실패 후 다른 동행에게 계속 입력하지 않는다. 지형이나 물 피해를 완화한 수정은 없다.

다음 실제 입력 실패(41262254682)는 x5800에서 하강한 검증기 경로 오류였다. 아래 선착장 지지면은 x5940부터 시작한다. 그림만 보고 하강 위치를 택하지 않고 충돌 면의 실제 겹침 범위를 사용한다. x5955까지 보행 후 하강→x6480 보행을 두 동행의 원래 저장 위치에서 엔진 모델로 확인했으며, 둘 다 피해 0·활성 동행 유지·아래 지지면 접촉을 통과했다. 최종 배 승선은 별도 실제 브라우저 결과를 기다린다.
