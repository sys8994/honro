Current complete-target correction publishes only lower rows bounded by world1716..1988.8 plus device rounding/padding. Conservative1714..1992 covers that band for native scale>1.05 and renderer pixel ratio>=1. Actual correction views had zero terrain-exterior pixels within the modified lower rows. This is expected, not a reason to invent unrelated test views.

Even at native's widest limit1.05, CSSwidth3840 gives visible x[-2148.571,5527.771]. Smaller current test/phone/desktop widths are nested inside. DPR changes backing resolution, not that world viewport; the Act4 renderer clamps effective native pixel ratio to at least1.

This is a bounded source/normal-camera argument, not universal protection of arbitrary forced cameras or ultra-wide canvases. Earlier actual four-view final Scene/terrain alpha checks and explicit Scene RGB outside original terrain checks remain evidence; their lower-exterior counts were zero and are recorded honestly. Common high-DPR budget, all-view actual visual validation and ordinary lifecycle still need testing. No new runtime geometry, external silhouette change, or permission waiver is introduced.
