# 중력 좌표 변환 공통화 제안 (국소 재현, 런타임 미연결)

세 갈래에서 재사용할 것은 **격자 좌표계 간 직각 회전과 인물 중심점의 위치**입니다. 월드 원점/크기가 다른 각 장의 순수 함수 입력에는 폭·높이와 출발/도착 방향만 둡니다. 발 좌표를 직접 돌리지 않고 몸 중심 (x, y−h/2)을 변환한 뒤 도착 방향의 발 좌표를 복원합니다. 속도는 이동값 없이 선형 회전만 합니다. 착지는 엔진의 책임입니다. 출발/도착 바운드도 같은 point 변환을 사용하지만, 폴리곤 경계의 시작점·순서·접촉은 로컬 소유자가 보존해야 합니다.

| 실제 국소 증거 | 재검증 | 합치면 안 되는 부분 |
|---|---|---|
| 6-4 실제 03 인계, h92, 무회복 먼 길 | 두 주파수 C→L 직전 pose와 실제 착지의 차이는 기록된 3.10/6.45 WU 낙차와 일치 | 문턱 위치, 열려 있는 지급 스킬·목표, 착지 전 조작 해제와 경고, 연습 상태를 유지한 체력 초기화 금지 |
| 6-6 D | 좌표 기록의 성공 138개 일치, 좌표 전환 미발생/거절 18건 제외 | 독립 D 도판의 좌/우 수용턱과 실제 물리 경계, 실패 처리, 접촉 지면. D는 기존 코드에서 스폰 위치도 중심 기준으로 돌림 |
| 6-8 우향 우회 | 두 주파수 기록된 월드 중심과 직전 exit foot/center 일치. 속도는 기록된 월드 벡터를 역산한 일관성 검사임 | 6-8의 gate는 공중에서 들어가는 특수 예외가 있으며 보스·조준·저장 잠금 자체는 별도. 스폰 위치는 원시 발 기준 변환을 사용해 D와 다름 |

스폰, 카메라, 발사 예측, 입력·AI, 다인 유닛·스테이지 이벤트, 저장 복구는 공통 코드에 넣지 않았습니다. 04/06/08 소유 파일은 쓰지 않았습니다. 저장 가드는 선택 도입 시 읽기 전용 조건입니다: 버전=1, 신뢰할 수 있는 외부 소유권 핀/장 ID, 행사 가능한 chart, 독립적으로 확인된 전환 epoch가 모두 필요합니다. 값이나 소유 권한이 틀리면 현재 방향을 유지/실패하며, A로 교정하거나 새로 생성하지 않습니다. epoch는 라운드가 아닙니다. 실제 저장 키·기존 저장 migration은 통합 승인 이후 별도로 검증해야 합니다.

재현: node vector-production/frame-affine-local/verify.mjs. 원본 파일 6개 SHA-256 pin, 64개 합성식, 8개 저장 기록 대조군과 실제 증거 재계산 출력이 evidence.json에 있습니다. 실제 플레이 재실행, 3장 동작 동등성, 캠페인 연결, 제작 적용 또는 테스트 가지 합병은 아닙니다.
