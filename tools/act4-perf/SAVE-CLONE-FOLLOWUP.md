QA only; input base `a7c270f7c7ec39df66489f8c0a2874eb267f807c`, original RC world SHA-256 `99c59777254cb4942d5bfc7b7398068fc294dc29ff7208ac5f468953ecf5e581`. The ten REVIEW_INDEX candidates were restored with the standard compressed/raw length and SHA checks; this does not use the new 33/34 art. No release or Pages deployment. Source change is limited to `flushBattleSave`: when the installed official Act 4 campaign wrapper is active, omit the first JSON clone, because its immediately following `persist` always takes `P.snapshot` from the same live battle, including its reader cursor. Other battles retain the old path. The snapshot and store's official-provider equality/signature checks are unchanged. This is independent of the separate dirty-state issue for moving boats/residents.

`save-profile-browser.py` uses synthetic 45 SP stage-40 entry, real App and nine seconds of held ArrowRight, then 1.5 seconds observation; headless Chromium 1440x900 DPR 1. It instruments JSON, render, persist and flush on the main thread. The first direct-entry and a failed equivalence probe (a test script `G` typo) are not treated as comparison runs. Camera and game time were not pinned, so this is a repeated normal-input diagnostic, not a fixed-camera causal benchmark or phone FPS. The only active browser was the target instance (10 live Chromium processes at end of later runs; zombie child processes accumulated and were included in the older `pgrep` counts). Five CPUs available, RAM available 15.2–16.1 GB in later samples; host load recorded per run. Each run opens a fresh browser/context. In an earlier baseline sample, each of eight flushes took 264–346ms and its enclosing rAF interval 317–400ms. Its first full JSON stringify/parse took 74–88/29–42ms; another stringify/parse inside persist took 73–110/30–49ms. Stack traces in the saved repeat identify the second copy as `P.snapshot` from the Act 4 persist wrapper. This is a direct correlation within a sampled main-thread call, not proof of every long frame's cause. A third baseline isolates the production signature algorithm over 13 relevant provider assets outside the frame sample: 0.9–12.2ms per asset (JIT and timing overhead included); this is a separate microprobe, not nested production timing.

On the same paused live state, legacy clone-then-persist and flush wrote byte-identical storage in each measured candidate run; dialogue reader was absent in these samples. The actual App export method produced raw battle JSON equal to the live battle (30,756,154 characters; no static asset refs), with download intercepted for inspection. This is a method test, not normal UI import/export or cross-device proof. The full-art snapshot remains in memory, so the exported contract is not changed. A separate non-mutating probe compacted the real battle in 49–73ms, cloned that compact object in 0.9–1.2ms and restored it in 71–88ms with byte-identical raw JSON. It does not justify changing the snapshot contract: repeated identity checks, custom/modified assets, event reader and raw export require further work.

`node tests/act4-map-revision-rc.mjs` passed. `tests/profile-store-p01.mjs` fails its schema migration equality on both this checkout and the unchanged base (schema 5/current presentation fields versus old schema 4 expectations); the failure predates this change. `tests/custom-map-return-profile.mjs` has the same 2/18 failing groups on both candidate and unchanged base: new-journey expected profile fields and training portrait stub. `tests/profile-store-p01-preservation.mjs` also failed on its historical manifest expectation; it was not established as a regression of this change. Release, actual 40 normal event progression, reload after dynamic ferry movement, reader-active snapshots, real-device FPS, and same-asset fixed-camera cold/warm idle/pan/zoom/water pixel/frame tests remain open. This patch changes no renderer, clip, art, zoom, or cache behavior and does not resolve the tile/foreground cold hitch or prove visual acceptance.
