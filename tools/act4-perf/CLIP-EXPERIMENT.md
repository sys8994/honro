# Group clip diagnostic — no renderer change

Chromium 154, 128×128 isolated Canvas/SVG fixture on the RC QA build. `group-clip-browser.py` draws the same synthetic paths using the actual `HonroVectorArt.draw`, a browser-rendered SVG, and an experimental offscreen-group/mask path. The `beige-underpaint` case has a full light base followed by overlapping opaque darker fills, reproducing the structure under investigation. Direct Canvas and Chromium SVG were byte-identical for this case, while removing the beige layer changed 351 edge pixels (total channel delta 5,747). The isolated group/mask alternative differed from the original SVG on 366 pixels (delta 20,098). The overlap, partial-opacity, hole and adjacent-shape cases also differed for the isolated-mask alternative; the transformed case differed in both paths (direct 15 pixels, isolated 376). Results: `evidence/group-clip-synthetic.json`.

This shows that repeated compositing of the light base can affect the antialiased edge even when the production Canvas matches Chromium's SVG interpretation. It does not prove the exact cause of all stage 33/34 seams or authorize changing general SVG/Canvas compositing. Group isolation is not equivalent for these fixtures, including transparency. Existing production renderer remains unchanged.
