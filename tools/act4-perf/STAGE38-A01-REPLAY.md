# Stage 38 A01 replay contract and measurements

Candidate `04dc78159177950dd5d71acc267b7ba161f59c37` replaces no general clone API. The previously rejected `03fd076` remains withdrawn and `withPredictionBattle` remains a native full clone. The new private `arrowReplaySnapshot` is used only by the fixed production `arrowPrediction` path for official campaign stage 38, preview 38, the unmodified A01 archer/arrow mode and non-workshop battle. It creates an isolated native structured clone once and runs the replay once. It retains units, terrain, collision metadata, skill/RNG/physics/state and placement metadata; only the placement `asset.vector` drawing bodies are omitted from that private replay. The live battle and portable saves are untouched. No result cache or invalidate-on-mutation shortcut is used.

Custom/workshop battles, other stages, skills or modes, unknown placement/vector formats, accessors, unsupported data and cross-field aliases between combat state and transformed placements/assets/vector nodes select the original complete clone before replay. Asset/body identity inside the recognized placement arrays is retained; if a transformed array/item/asset/vector is shared with other battle fields, full clone is selected. Checks inspect current data each time and do not trust object identity as evidence of immutable content. This contract concerns the production authored-JSON battle and fixed A01 call path; it is not a general-purpose replacement for `structuredClone`, a promise for arbitrary injected JavaScript objects or monkey-patched runtime hooks, or a portable export. Any future production hook that reads placement vector data must remove this optimization or change its contract and tests.

## Call-path audit

`Engine.predict` dispatches a non-martial redesigned archer shot to `redesignPrediction` and `arrowPrediction`. That routine constructs a detached `Engine`, calls `fire` and replays `stepProjectile`; the engine uses unit, skill, terrain, physics, projectile and report data. The constructor's `HonroQuestTargets.migrate` and quest damage routines inspect objective metadata and `honroElements` collision IDs, which are preserved. `HonroProgression` and `HonroClearReport` work on combat/growth/report fields. Stage 18 bell and Act 2–3 projectile-force hooks reject stage 38. `wreckDamage` accesses landmark vector presence only for preview 39, which this gate excludes. The equipment combat field also named `vector` is unrelated to placement art and is preserved. This audit applies to the exact source revision, not unknown future hook implementations.

As a separate dynamic check, the old full-clone replay's copied placement assets were wrapped with observation-only proxies for direct vector get/set, descriptor lookup, presence, enumeration and deletion. In 26 synthetic changed-state predictions there were no such accesses, and traced outputs matched the uninstrumented baseline. This is sample evidence supporting the static review, not proof for arbitrary future code. The candidate never uses these proxies or retries a replay after an external effect.

## Equality and contract checks

The earlier 745-case test had a test-only flaw: a custom flag could persist into later scenarios and the terrain collision index was not reset after replacing the battle fixture. Both were corrected before rerunning full-clone baseline and final candidate. The 149 non-passive skills × five independent synthetic conditions produced 745 identical output records, with no errors and unchanged live battle JSON/RNG; both SHA-256 `a4e5444fe613672f671080ba42b2d8c9d080a003c617a0f2f272bc12831c8db8`. The conditions include modified vector data, custom/workshop, broken terrain and status effects; they do not establish coverage of every possible effect or real user-authored map.

Another 26 predictions cover target movement, actual `approved38-upper` destruction, damage, statuses, actor/rank/skill changes, angle/power/wind changes, a custom flag and modified art, with and without unit collision. Baseline and candidate are byte-identical, SHA-256 `be4b6f9899a81bf3c1569d618e7ae79d2d5a3054ea5c8440f644917124940ab5`. The target-move, broken-terrain (ignore-units), skill, angle, power and wind cases each changed the appropriate baseline prediction. No replay caching is involved. A separate 24-prediction fixed camera/time comparison matches the full-clone image SHA-256 `1011369ef6886e03ba8b9a015605f0254a254500f58f6d99fb0ddf3fcff50d12` and output hash `bf8e4b6b2e11d76a62202c1d920e8c60bb1ade131784a8d1ad856e3fd9ad5a97`.

`stage38-contract-check.py` records exactly one narrow clone and one `HonroClearReport.cast` in the official case. Custom/workshop, other skill/stage/preview/mode, altered A01 mode, non-official flag, shared placement/vector/vector child, battle cycle and getter each selected full clone before one replay; invalid art retained the full clone's `DataCloneError` and ran no replay. This uses synthetic fixtures, not actual downloaded custom maps. TypeScript, full-clone reflection regression, stage 39 wreck, autonomous friendly fire and projectile friendly fire tests passed. `aim-launch-collision.mjs` fails the same initial embedded-muzzle fixture assertion on unmodified common baseline.
