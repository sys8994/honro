# 39장 실제 사격 경로와 경고 대응 기회

기존 v6 전진/위협 우선 입력 로그·경고 PNG와 별도 실제 저장 분기의 정상 UI 관측을 대조했다. 38장 완료 진입은 시험 fixture이며 이전 장 전체 실제 플레이가 아니다. 지도를 미리 분석한 QA 관측이고 사람의 초견 난도나 승률이 아니다. 배치 변경은 하지 않았다.

## 실제 사격과 동선

두 v6 실행 모두 서쪽 계단에서 상층 `approved39-upper`로 올라간 뒤 실제 하강해 `approved39-wreck-deck`에서 그물 해제·길 안정화를 수행했다. 전진 우선에서는 설오가 1R 상층 약 (1945, 821)에서 실제 발사했고 2R 약 (3361, 2113)으로 하강했다. 위협 우선은 서쪽 중층에서 먼저 교전한 뒤 휘겸이 2R 같은 갑판에 내려와 두 기믹을 수행했다. 전진 우선에서는 동쪽 `a4-39-n-3` 발사와 같은 shot의 피해 기록에 영웅 실드 72 및 주민 HP 59가 함께 있다. 기존 로그에는 피해 projectile ID가 없어 완전한 인과라고 단정하지 않는다.

추가 실행은 원본 게임이 생성한 10R 저장 `../screen-route-eleven-round/round-10-storage.json.xz`(원문 SHA-256 `f71125142de98506d13c823038a74419abfa155579d90544681e2c645384bd32`)을 별도 Chromium context에서 실제 Continue로 열고, 이후 정상 F 방어만 8회 입력한 35.19초 분기다. 원 저장의 그물·길 안정화는 실제 UI 수행 결과이며 좌표·HP·phase·receipt를 주입하지 않았다. QA wrapper는 원래 `fire`/`impact`를 그대로 호출하며 실제 발사와 충돌 시점 좌표 및 projectile ID를 기록했다. 완료 시 11R 적 턴이었고 구조 완료 전이다. 관측 중 pageerror와 기존 observer 실패는 0이다. 동 시간대 로그와 양 끝 화면은 이 디렉터리에 보존했다.

위 좌표는 각 발사·충돌의 두 끝점이지 탄의 전체 곡선이나 시야 가림을 재구성한 선이 아니다. 이 실행과 위협 우선 실행에서 여러 공격이 실제 닿았으므로 상층·하층 경로 전체가 기존 적과 겹치지 않는다는 가설은 성립하지 않는다. 동시에 모두의 위협 범위나 일부 적이 무의미한지를 이 사례만으로 결정할 수 없다.

## 경고와 실제 입력 기회

전진 우선 `../observer-paired/v6-progress/pilot-warning-1.png`에서 실제 표시된 중간보스 `a4-39-n-2` 경고 표적은 휘겸이었다. 경고 표본 후 12.8초에 설오 턴, 21.3초에 담희 턴, 31.6초에 표적 휘겸 턴이 관측됐고 휘겸은 32.7초에 방어했다. 이후 게임 history에 3R fired 및 relocate가 기록됐다. 시간은 로그의 벽시계 표본 차이이며 전체 화면 표시 지속시간이 아니다. 방어 입력은 기회의 직접 증거이지만 경고를 의식하고 회피했다거나 결과를 막았다는 증거는 아니다.

위협 우선에서는 경고 표적이 역시 휘겸이었으나 다음 설오·담희 턴 뒤 정상 출구 상호작용으로 승리해 표적의 후속 턴은 발생하지 않았다. 게임은 경고 미해결 상태로 종료할 수 있었던 이 실제 사례를 허용하므로, 목표를 늦추는 조건 추가 없이 **경고가 목표 진행 중 실제 선택을 제공하는지** 따로 검토해야 한다. 이는 해당 표적이 공격받았다는 뜻이 아니다. 가림에 따른 플레이어 선택 변화도 기존 자료에 직접 연결돼 있지 않다.

## 한 명만 옮기는 탐색안 — 미적용

추가 비교가 필요하다면 후보는 동쪽 경비 `a4-39-n-1` 한 명이다. 현재 원본은 (4860, 2143.5), `approved39-east-deck`, 왼쪽을 향한 정예 guard다. 예비 대안은 폐선 갑판 끝 `approved39-wreck-deck`의 x=4680, 보행면 보간 y≈2364.75로 옮기고 해당 support 참조만 맞추는 것이다. 구조 대상과 탈출 통로를 감시하는 경비라는 서사 가설을 이용하고 기존 적 수·HP·승리 조건·지형·선택 폐선 보스는 유지한다. 주민 safe 목표 x=4140~4477.5와 하부 동쪽 `approved39-east-bank`를 바꾸지 않아 우회 가능성을 유지하려는 계획이다.

이는 **좌표상 예비안**일 뿐이다. 실제 배치 점유·접지·주민과의 충돌, 하부에서 지나갈 여유, 경고 및 주민 보호 선택을 아직 검증하지 않았다. 기존 경로와 위협의 비중첩이 입증되지 않았으므로 후보 JSON을 변경하거나 두 정책의 개선 효과를 주장하지 않았다. 실행 전 해당 guard의 동작과 실제 지형·플레이어/NPC 간격을 검증하고, 안전 하층 경로를 실제 입력으로 확인해야 한다. 경비가 주민 목표를 직접 막거나 즉사 위험을 만들면 이 좌표는 폐기한다. 두 정책 비교도 똑같은 초기 조건·입력을 사전 고정하고 각 경고 대상의 정상 입력 기회, 주민이 실제로 보호받을 선택, 전투와 목표 동선을 측정해야 한다. 40장 자유 호송은 이 검토 범위 밖이다.

재현 도구 `tools/qa-stage39-wait-probe/lineproof.py`는 QA-only build, 해당 실제 저장과 실제 39 candidate `0bb8dd43bf33af941c88800c4e7e13bbf2c7d3dd924444c035c997daad8f5dcb` 및 32 far asset의 로컬 경로를 사용한다. 원본 월드와 기존 저장은 수정하지 않는다. 출력 디렉터리가 이미 있으면 덮어쓰지 않는다.
