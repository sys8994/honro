# Stage 32 native shelter door — separate QA candidate

This is a **candidate requiring visual and integration review**, not an approved final asset or campaign completion. It preserves the original Stage 32 BODY, collision, actors, events and map data. The only project-value additions are one extracted art asset and the opt-in `design.vectorShelterDoor`; `candidate-delta.json` identifies the exact base/output SHA and reconstruction operation. The larger derived project remains local. The optional source patch is on this branch and must be reconciled with the other ongoing Stage 32 event work, not blindly overwrite it.

The original candidate's real timber double door occupies approximately world x=2998..3118, y=674..867; its left jamb is close to the unchanged event exit target x=2992. The speaker starts at x=3069, y=869 and the existing visual marker is at x=3058, y=709. The old gray `a4:door` at x=2992, y=869, scale .9 was visibly offset and covered the facade/actor. The new art uses that original BODY's 24 compound fill layers and source-alpha clip in their original order and fill rules. `extract.py` keeps only contours whose bounds intersect the small ROI, preserves a separate compound per original color layer, and converts the selected path coordinates to absolute coordinates rounded to five decimal places. It does not duplicate the whole BODY. The extracted asset is 423,282 bytes, SHA-256 `e5f6c170b1b4c3778d7c9681e017cd002d539f8677e9567ced595c92119a4058`; the base candidate is `e22e8d2773728ef3443a93b95192dab0b64c711c5f484a8cad24c671f3b902b9`. Reproduce with `python extract.py /path/to/exact-stage32.json /tmp/wood-door.asset.json` (requires svgpathtools).

Direct Chromium canvas comparison of the extracted ROI with the original BODY reports equal alpha at 1× and 3×, with 771 changed channels, max 14 and MAE 0.010 at 1×, and 5,336 changed channels, max 18 and MAE 0.0074 at 3× (`extraction-pixel-comparison.json`). These are real nonzero AA/coordinate-conversion differences; they are not byte-identical and are not hidden by loosening an existing threshold. In the actual game the **closed** state draws the original BODY directly, so it does not redraw the crop. During opening, the old gray panel is suppressed only when the configured vector, BODY instance and terrain link resolve; otherwise the original panel remains. An intentionally simple dark interior and the cropped wood panel are painted before actor rendering, with the panel compressed around its left jamb. The flat dark interior still needs visual judgment and may need authored detail; no claim of final art approval is made.

`closed-*`, `half-open-*` and `open-*` are actual Chromium production renderer frames, using explicit diagnostic door time 0/.5/1, disabled intro and a manually set camera; no event receipt is injected. `resident-exit-fixture.png` and JSON use a **different** Chromium fixture: all enemies removed, archer positioned near the shelter, intro dismissed, and the production observer and renderer manually stepped. With no injected seen/completion flags, the real rendered `door-open` was observed, the shelter released its speaker and the NPC moved from x=3069 to x=2989.67 across the unchanged x=2992 threshold; complete remained false. Neither fixture proves normal combat, actual reunion dialogue, player input or full completion. The separate worker's reunion investigation remains open. Page JS errors were absent; the local favicon returned 404.

The apparently floating enemy `a4-32-d-3` was not moved. It is the `lantern` unit: `shared/runtime/world.js` declares `flying:true` and constructs flying units as fixed; `shared/engine/src/enemyAI.ts` treats fixed enemy lanterns as flying. Its non-grounded state is consistent with the existing class, even though this candidate's water trait says `ground`.

The current frame captures use the QA-only exact far WebP SHA `1ba81aae5bebeebd46cc094be2519797d67ef49a887d7aade45cb61b39878fff`. `runtime-sha256.txt` and fixture JSON preserve the tested source/build hashes and conditions.
