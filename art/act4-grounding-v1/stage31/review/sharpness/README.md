# 31장 확대 선명도 진단: 실제 Chromium PNG

2026-10-31. 동일한 후보 `project-v40-candidate.json` SHA-256 `540e65d68ab2049ea0271fa168c78b1024b598703ec9e63bcf7fc19c9e67ccc1`, 같은 월드 중심 및 동일 CSS 화면 390×844, 에뮬레이션 DPR 3에서 실제 Chromium canvas backing을 PNG로 추출했다. 파일은 리사이즈·JPEG 변환하지 않았다. `arch`는 중앙 큰 아치 아래, `right`는 오른쪽 높은 암벽이며 `z0.65`는 일반, `z1.65`는 최대 줌이다. `before`는 기존 DPR 1.7 상한 및 0.68 타일 상한, `after`는 4막 nativeArt 한정 600만 화면픽셀 이내 최대 DPR 3과 화면·LRU 한도에 맞는 타일 버킷이다. 전후 backing 크기는 각각 663×1101과 1170×1943으로 다르므로 원본 픽셀에서 비교한다.

- 일반 줌 이전 타일 0.68 대비 표시 밀도 1.105; 이후 타일 1.414 대비 표시 밀도 1.95. 화면 픽셀밀도는 이전 1.7, 이후 3이다. 타일 수 한도를 지키기 위해 표시밀도와 동일한 밀도까지 늘지 않을 수 있다.
- 최대 줌 1.65는 기존에도 타일 캐시 대신 직접 벡터를 그린다. 이 경우 바뀐 것은 화면 backing 상한이다. 직접 벡터 이미지에도 남는 둥근 풀 형태·색 띠는 캐시 해상도만의 문제가 아니며 원본 추적 형태의 검토가 필요하다.
- 같은 확대 위치의 일반 줌 cache/direct 평균 RGB 차이는 1000×700 환경의 DPR 2에서 중앙 0.925→0.380, 우측 0.837→0.350이었다. 비동기 화면, 색·배경 등이 포함된 보조 수치이며 미술 합격 지표가 아니다.
- Headless Chromium에서 45회 수평 카메라 이동, 390×844 DPR3의 예열 후 p95는 약 0.7→0.9ms, 타일 최대 보유는 기존 12개 한도였다. 1000×700 DPR3에서는 약 1.0→1.6ms, 최대 24개였다. 최초 화면 생성·실기기·전체 전투 프레임 성능의 보장은 아니다. 시험 중 한도 없이 고밀도 타일을 요청한 안은 캐시 재생성으로 p95 67.7ms여서 채택하지 않았다.
- 두 기존 테스트 `static-screen-cache*.mjs`는 현재 빌드 manifest 패턴 불일치로, `terrain-domain.mjs`는 과거 stage5 데이터 해시 불일치로 실패하며 수정 전 renderer에서도 동일하게 재현됐다. 별도의 44개 terrain-domain 렌더/타일 경계 테스트와 신규 정책 검사, 31/40 수면 및 배 표시 회귀는 통과했다.

정상 게임 진행·4막 전체 미술 수정·고DPR 실물 장치와 배포본 검증은 이 진단의 범위가 아니다. 원본 SVG의 거친/둥근 형태나 색 띠는 이 수정으로 다시 디자인되지 않았다.
