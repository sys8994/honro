## 기존 원본과 이번 범위

- 전체 11장, 매듭을 거둔 아침. 실제 productionStory 저작 결과에서 구조를 추출했다. `structure-contract.json`의 world가 스켈레톤의 원본이다.
- 플레이 크기 16000×12000, 면적 192,000,000, 종횡비 4:3. 전체 terrain bounds는 [-6000,-24000,22000,36000]. 배우 높이 92. 이 값은 기존 구현값이며 새 기준의 확정값/실측 합격값이 아니다.
- 현재 장은 4인 동행의 주민 구조가 중심이다. 소단의 혼 분리와 보호 위치 선택을 보존한다. 주민 구조 뒤 흔적은 자동 기록한다. 과거 매듭 제거·4턴 방어·전원 처치를 필수 목표로 되살리지 않는다.
- 현재 데이터의 적은 전투 적 42와 붙은 혼 1, 전투 정예 12다. 원본 저작기·pacing·quest simplification 적용 단계가 달라 과거 52/72 예산과 혼동하지 않는다. 이번 미술 준비는 편성/행동/승패를 바꾸지 않는다.
- 기존 소단/설오/담허/휘겸 디자인·기예·장비·성장과 `resident-4`, `resident-spirit-4`, `resident`, `trace`, `act2-11-resident`를 보존한다. 과거 목표 ID와 기존 저장 사건 이력도 삭제하지 않는다.
- 기존 11장 벡터 후보, raw/final, 실패 기록을 덮어쓰지 않는다. 새 후보는 이 디렉터리에 분리한다. 공통 런타임과 발행은 한 담당자만 관리한다.

## 전체 공간과 플레이 질문

시작 서쪽 능선 → 중간 지지 능선 또는 아래 우회/회귀길 → 낮은 주민 은신처로 연결한다. 상부 고목은 유리한 사격 위치와 선택 우회, 하부는 구조 접근과 합류에 의미가 있어야 한다. 큰 지형이므로 단순히 크기를 유지했다는 이유로 새 기준을 통과시키지 않는다. 정상 이동에 걸리는 시간·유효 고저차·불필요한 왕복을 실제 측정한 뒤 필요 범위를 판단한다.

핵심 질문은 '주민에게 붙은 혼을 다루는 동안 누구를 어느 높이에 둘 것인가'와 '직행 하강 또는 안전한 우회 중 어느 경로로 합류할 것인가'다. 새 수집 과제나 별도의 장소 탐색을 추가하지 않는다.

## 미술 설계

차갑고 쓸쓸한 한국 산지의 새벽 협곡. 넓은 원경 산세·안개는 독립 이미지로 유지한다. 지지 암벽(REAR), 실제 보행 접점(SURFACE), 연결 암반(BODY), 고목과 뿌리, 소규모 앞 식생(FORE)을 의미별 자산으로 제작한다. 동적 효과와 목표/주민은 미술에 굽지 않는다.

전체 개요뿐 아니라 시작·중앙·주민 은신처의 실제 배우 배율 시안을 따로 확인한다. 외곽은 풍부하게, 내부는 절제하게, 경계는 분명하게 한다. 현재 커다란 단순 암괴와 길쭉한 목재, 과대한 접지 암면을 그대로 미술 기준으로 삼지 않는다. 지질의 연속과 고목의 밑동이 보여야 하지만 실제 빈 통로를 배경 암벽으로 막힌 길처럼 보이게 해서는 안 된다.

## 정량 및 검수 계획

원격에서 v3와 새 통합 inventory 원본을 찾지 못했다. 없는 목표를 확정 수치로 복원하지 않는다. 아래는 이번 장의 검증 제안이며 플레이 전 수치다.

- 필수 주민 목표 접근·분리·구조·자동 흔적 기록·다음 장 연결: 정상 입력 경로 각각 1회 이상. 성공률 추정으로 일반화하지 않는다.
- 정상 경로 2종: 상부 지원+하부 구조, 하부 동행 합류. 턴·행동 시간·실제 피해 사건/회복·적 행동·위치 선택·이동거리·고저차를 기록한다. 턴 상한을 임의 강제하거나 적 수/HP를 조절해 맞추지 않는다.
- 기존 저장/새 입장: 성장·SP·장비·완료·이벤트 중복 여부 확인. 미술만 바뀌면 전장 revision을 일괄 올리지 않는다.
- 미술 3회: 전체 구조/지지/접합, 실제 보행 배율/조준/주민 식별, 최소/최대 줌·좌우 pan·390×844 모바일·구조 전후. 최종 통합 소스에서 별도 종합 확인.
- 원본→raw와 raw→최적화는 분리 측정. 의미별 Inkscape 저작, 불변 raw, 보호 접점과 틈, 명령/노드/바이트/겹침을 보존한다. 기존 오차 상한을 느슨하게 만들지 않는다.
- 기존 `stage11-response-flight-clearance` 실패 기록은 현재 재현 전 미확인으로 둔다. 무관한 테스트 전체 수리를 범위에 넣지 않는다.
