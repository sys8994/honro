## Stage 33 mid-turn movement is not restored

In the preserved scoped run after flood recovery and the stair probes, the mage was still active in round 9 and made the two west-route movement/jump attempts. A normal UI JSON download captured mage (753.374,2488.350), HP 1814, unacted, movement remaining 1701.126. A second normal UI download confirmed the mismatch. Stage/round, party growth and equipment, the other three allies and all 30 enemies' positions/HP/acted/movement, tide, water recovery records, terrain, decor, map and far backdrop matched. This is an observed **mid-turn movement rollback** in executed source `2577ef15`, not a successful save assertion. The underlying cause and whether it is the same as the separate shared RC save regression have not been established. The two downloads are retained locally; no live state was injected. The earlier initial, rising and high idle-party reload checks still stand for their narrower saved states.

Source inspection offers a possible explanation, not a proven root cause: `Engine.move()` walks without emitting a save event, the periodic battle snapshot depends on `dirty`, and `pagehide` only cancels input. The export action clones the live battle into the downloaded profile but does not itself persist that clone to the profile store. This is consistent with the observed difference between downloaded live state and the resumed checkpoint; the separate save-fix owner should verify against its current RC before changing behavior.
