# 짧은 인게임 씬

9장의 첫 받이진 설치를 대표로 삼는다. 새 9장에서는 소단이 사당 안쪽에 있어 처음부터 전장·미니맵·충돌·대사에 나타나지 않는다. 어느 받이진이든 0→1 설치를 성공하면 기존 행동 경계 큐에 첫 만남을 한 번 예약한다. 방울 → 사당으로 카메라 → 매듭을 잡은 채 문턱으로 76px 보행 → 방울을 붙든 손과 시선 → 대사 순서다.

실제 actor는 새 `HonroMaps.createBattle`에서만 `b.honroStaging.hidden`에 보관한다. 기존 저장에는 이 과정을 소급 적용하지 않는다. 등장할 때 동일 개체를 엔진 roster로 돌려놓는다. Game·Stage View·Playtest가 같은 compiler를 쓰며 사용자 작성 비캠페인 맵은 건드리지 않는다.

## 공통 계약

`HonroStoryStaging.register({id,stage,title,steps})`로 사전에 등록하고 `request(app,id,context)`로 기존 Story 큐에 예약한다. 아직 합의되지 않은 장면이나 새로운 사건 조건을 자동으로 만들지 않는다.

- `look`: `at:{actor|anchor|marker|x,y}`로 현재 실제 위치를 해석한다. actor는 unit ID 또는 네 주인공의 class다. `actor`를 함께 지정하면 그 인물이 목표 쪽을 본다.
- `move`: `actor`, `to`, `duration`, 선택 `reveal`을 쓴다. 기존 `Engine.walk(...,requireSupport=true)`와 실제 바닥/벽 판정을 재사용한다. 길이 막히면 마지막 유효 위치를 유지하고 다음 단계로 간다. 순간이동·새 물리 루프는 없다.
- `fx`: 등록된 sound와 선택적인 기존 Engine.fx를 한 번 재생한다. 넘기기 때 사운드를 뒤늦게 몰아서 재생하지 않는다.
- `dialogue`: 마지막 단계에 기존 대사 튜플을 넣는다. 인물별 카메라·초상·대화 기록은 원래 Story 경로가 처리한다.
- 위치의 `dx/dy`는 원래 anchor/marker에 더하는 작은 오프셋이다. `marker:'$trigger'`는 request context의 marker ID를 가리킨다. 존재하지 않는 actor/anchor, 죽은 인물, 막힌 경로 때문에 입력이 잠기지 않는다.

정적 registry는 데이터이고 진행 cursor는 `b.honroStory.staging` 한 곳에만 둔다. cursor, elapsed, 적용한 단계, 이동 결과, 현재 카메라/추적 대상과 복원할 카메라를 기존 대사 저장과 함께 보존한다. `b.honroStaging.once`는 queued/running/done을 구별해 중복 상호작용·대사 기록 열람이 다시 등장시키지 못하게 한다.

Scene의 새 프레임 루프는 없다. 기존 `Story.tick`에서 짧은 연출 시간만 진행하며 App은 `dialogue`가 존재하는 동안 원래대로 전투 물리·임무·조작을 멈춘다. 숨긴 탭·열린 모달·기록 열람은 연출도 정지하고 돌아왔을 때 누적 시간을 따라잡지 않는다. 캐릭터 리그는 지정된 인물의 짧은 이동/방울 손동작만 표시하며 공격·피해·기력·투사체를 생성하지 않는다.

장면 넘기기는 남은 위치/시선 상태를 안전한 공통 이동 경로로 한 번만 적용하고 전체 대사를 기록에 남긴다. Space/Enter는 먼저 움직임만 끝내 첫 대사로 넘어간다. 새로고침/내보내기/불러오기는 같은 cursor·현재 좌표에서 이어진다. 재시도는 새 전투이므로 처음부터 숨겨진 상태로 시작한다.

## 승인된 분리/합류 연결

24장 descriptor는 `on:'outcome',position:'after',requireSplit:true`다. 원래 outro를 먼저 읽고 짧은 look/move/fx를 마친 뒤 기존 outcome 처리로 한 번 돌아간다. 마지막 `{type:'dialogue'}`의 lines를 생략해 기존 대사를 그대로 쓴다. 대사를 넘기면 남은 분리 동작의 최종 상태만 적용한다. 후행 동작 중 저장은 대사의 끝 cursor를 보존해 다시 읽히지 않는다.

24장의 실제 `split-route-a/b` marker 쪽을 비추고 각 조 인물이 그 방향으로 28–36px의 첫걸음만 옮긴다. 멀리 남은 사람을 출구로 옮기거나 맵 이동을 대신하지 않는다. `move.towards`와 `distance`는 그 짧은 방향 이동이며 기존 walk 지지면·벽 검사를 그대로 쓴다. 새 전투의 scene stamp와 split version이 모두 있을 때만 자동 연결한다. 구형 전투·저장된 구형 outro에는 붙이지 않는다.

27장은 실제 party-reunion 목표가 완료된 안전한 경계에서 목표 모듈이 등록한 descriptor를 request한다. 출전 명단, splitSpawns, carry와 합류 목표 상태는 기존 분할/목표 모듈이 소유한다. 씬 모듈은 이 상태를 초기화하거나 중복 등록하지 않는다.

위 내용은 기존 9장 첫 만남과 24/27장 대표 구현이다. 다음의 2026-10-08 확장에서 다른 장면의 연출을 추가했다.

## 대사와 함께 움직이는 캠페인 씬 — 2026-10-08

사용자가 캠페인 전반의 인게임 씬 고도화를 요청했다. `story-direction.js`는 30장 도입과 주요 사건의 행동·시선·구도를 따로 저작한다. 대본 문장을 바꾸거나 괄호/말줄임표에서 동작을 자동 추측하지 않는다. 나무꾼의 증언, 홍만의 장례, 주민 구조, 소단의 첫 등장/대치/협력, 첫 혼령 조우, 돌림진·인양구·승려 증언·천도, 문장/장부 조사, 두 팀의 기록 대조 등이 대상이다. 모든 이벤트를 긴 영화로 개편하거나 정상 플레이 전30장을 검수한 것은 아니다.

새 전투는 `honroStaging.cinematic:2`를 받는다. 1장 나무꾼은 증언 사건까지, 3장 휘겸은 나루의 첫 만남까지, 4장 춘례는 피란문에서 발화할 때까지 엔진 roster 밖의 hidden cast에 둔다. 현재 사건의 행동 경계에서 같은 인물이 나타나 지지면 위로 걷는다. 새 숨김 배치의 발 높이만 공통 `HonroTerrain.place`로 16px 이내에서 맞춘다. 옛 전투·진행 중 대사·사용자 맵은 새 연출을 소급 적용하지 않는다. 9장 소단의 기존 첫 받이진 조건은 그대로다.

기존 descriptor의 선행/후행 단계와 `complete` 의미는 유지한다. 대사 쪽별 `staging.cues`는 그 쪽을 읽는 동안 보행·시선·몸짓·카메라를 병행한다. 같은 인물의 동작은 delay로 잇고 다른 인물은 함께 움직인다. 이 진행도 기존 `b.honroStory` 안의 cue index/elapsed/applied/results/done만 저장하며 새 전투 시계·AI·피해·투사체·의식 진행을 만들지 않는다. 쪽을 다시 그리거나 기록을 열어도 동작이 재시작되지 않는다.

이동의 출발점은 장면을 열 때 캡처한 origin이며 Engine.walk의 실제 경사·벽·몸·지지 판정을 쓴다. 경사 보행의 수평 속도가 느려져도 목표에 닿을 때까지 이어가고 막히면 그 자리에서 끝낸다. 넘기기는 같은 보행의 작은 substep으로 남은 최종 상태를 적용한다. 말하는 중간에 Space/Enter를 누르면 그 쪽의 동작을 마치고 다음 대사로 간다. 장면 전체 넘기기는 미등장 인물과 후속 동작도 한 번만 정리하고 원문 전체를 기록한다. 숨긴 탭·모달·기록 창은 그대로 연출을 정지한다.

리그의 inspect/point/guard/listen/lower-bow/bow/kneel/recoil/hold-bell은 실제 인게임 벡터를 사용한다. 전투 공격과 자원 소비를 발생시키지 않는다. 발이 붙은 짧은 보행, 듣는 자세, 손을 뻗는 동작, 몸을 낮추는 동작을 장면 의도에 맞춰 고른다. 대사 띠와 초상을 작게 해 전장을 더 보여주고, 가까운 화자 샷과 두 인물의 거리에 맞춘 구도를 사용한다. 안내의 목표 focus가 있으면 실제 목표를 우선한다.

첫 혼령은 사건을 포착한 실제 적 ID를 대사에 저장한다. 소단은 그쪽을 보고 가리키며, 설오는 경계 자세에서 소단 쪽으로 몸을 돌린다. 현형부를 자동 사용하지 않으며 대상이 이미 죽거나 사라졌으면 그 표적 샷을 건너뛴다. 결말 앞에 미처 읽지 못한 사건을 회수한 뒤 쪽별 cue를 만들므로 사건과 결말의 인덱스가 뒤섞이지 않는다.

`test:story-staging`에 `tests/story-direction.mjs`를 포함한다. 30장 도입의 전투 자원/목표 보존, 새 등장 3명, 병행 동작, 중간 저장, 기록 정지, 단계별 넘기기의 최종 위치 일치, 막힌 길/죽은 화자, 옛 저장/사용자 대본, 혼령의 실제 표적을 검사한다. DOM/Canvas 대역 검사는 브라우저 화면과 정상 플레이의 증거와 구분한다.

## 서사와 범위

도입/쉼터에서 소단의 손과 직접 응답을 미리 보여주지 않는다. 주민들이 소단에게 도움받았다는 정보와 방울 소리는 보존한다. 첫 만남에서 덕수의 생존, 혼을 떼어낸 담허, 영매의 역할, 소단이 손을 놓지 못하는 두려움과 남은 진의 필요성을 전달한다. 등장 전 까마귀 경고는 휘겸이 하고 등장 뒤에는 기존 소단 경고가 이어진다.

9장 아래의 두 진과 10장 위쪽 두 진은 별도 상태다. 10장 첫 설명에서 아래 진을 윗마당 양옆과 연결한다는 뜻을 밝힌다. 폭포와 빈 상여에 대한 불신, 비살상 대치, 외부 유입의 발견과 협력은 유지한다. 완료·증원·협력 조건은 이 씬 모듈의 권한이 아니며 바꾸지 않는다.

## 검증

`npm run test:story-staging`는 실제 App/큐/상호작용/보행을 DOM·Canvas·오디오 double과 함께 실행한다. 양쪽 진 설치 순서, 행동 경계, 전투 정지, 단계별 넘기기, 쪽수/이동 중 저장·재개, 반복 입력, 누락 anchor/막힌 경로/죽은 actor, 옛 저장, 재시도, 공방 공통 계약을 검사한다. 합성 위치/벽/사망은 음성/픽셀/정상 플레이 증거와 구분한다. 실제 브라우저 연출과 소리는 별도 검수한다.
