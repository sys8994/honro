# 짧은 인게임 씬

9장의 첫 받이진 설치를 대표로 삼는다. 새 9장에서는 소단이 사당 안쪽에 있어 처음부터 전장·미니맵·충돌·대사에 나타나지 않는다. 어느 받이진이든 0→1 설치를 성공하면 기존 행동 경계 큐에 첫 만남을 한 번 예약한다. 방울 → 사당으로 카메라 → 매듭을 잡은 채 문턱으로 76px 보행 → 방울을 붙든 손과 시선 → 대사 순서다.

실제 actor는 새 `HonroMaps.createBattle`에서만 `b.honroStaging.hidden`에 보관한다. 기존 저장에는 이 과정을 소급 적용하지 않는다. 등장할 때 동일 개체를 엔진 roster로 돌려놓는다. Game·Stage View·Playtest가 같은 compiler를 쓰며 사용자 작성 비캠페인 맵은 건드리지 않는다.

## 공통 계약

`HonroStoryStaging.register({id,stage,title,steps})`로 사전에 등록하고 `request(app,id,context)`로 기존 Story 큐에 예약한다. 아직 합의되지 않은 장면이나 새로운 사건 조건을 자동으로 만들지 않는다.

- `look`: `at:{actor|anchor|marker|x,y}`로 현재 실제 위치를 해석한다. actor는 unit ID 또는 네 주인공의 class다. `actor`를 함께 지정하면 그 인물이 목표 쪽을 본다.
- `move`: `actor`, `to`, `duration`, 선택 `reveal`을 쓴다. 기존 `Engine.walk(...,requireSupport=true)`와 실제 바닥/벽 판정을 재사용한다. 길이 막히면 마지막 유효 위치를 유지하고 다음 단계로 간다. 순간이동·새 물리 루프는 없다.
- `fx`: 등록된 sound와 선택적인 기존 Engine.fx를 한 번 재생한다. 넘기기 때 사운드를 뒤늦게 몰아서 재생하지 않는다.
- `dialogue`: 마지막 단계에 기존 대사 튜플을 넣는다. 인물별 카메라·초상·대화 기록은 원래 Story 경로가 처리한다.
- 위치의 `dx/dy`는 원래 anchor/marker에 더하는 작은 오프셋이다. `marker:'$trigger'`는 request context의 marker ID를 가리킨다. 존재하지 않는 actor/anchor, 죽은 인물, 막힌 경로 때문에 입력이 잠기지 않는다.

정적 registry는 데이터이고 진행 cursor는 `b.honroStory.staging` 한 곳에만 둔다. cursor, elapsed, 적용한 단계, 이동 결과와 복원할 카메라를 기존 대사 저장과 함께 보존한다. `b.honroStaging.once`는 queued/running/done을 구별해 중복 상호작용·대사 기록 열람이 다시 등장시키지 못하게 한다.

Scene의 새 프레임 루프는 없다. 기존 `Story.tick`에서 짧은 연출 시간만 진행하며 App은 `dialogue`가 존재하는 동안 원래대로 전투 물리·임무·조작을 멈춘다. 숨긴 탭·열린 모달·기록 열람은 연출도 정지하고 돌아왔을 때 누적 시간을 따라잡지 않는다. 캐릭터 리그는 지정된 인물의 짧은 이동/방울 손동작만 표시하며 공격·피해·기력·투사체를 생성하지 않는다.

장면 넘기기는 남은 위치/시선 상태를 안전한 공통 이동 경로로 한 번만 적용하고 전체 대사를 기록에 남긴다. Space/Enter는 먼저 움직임만 끝내 첫 대사로 넘어간다. 새로고침/내보내기/불러오기는 같은 cursor·현재 좌표에서 이어진다. 재시도는 새 전투이므로 처음부터 숨겨진 상태로 시작한다.

## 서사와 범위

도입/쉼터에서 소단의 손과 직접 응답을 미리 보여주지 않는다. 주민들이 소단에게 도움받았다는 정보와 방울 소리는 보존한다. 첫 만남에서 덕수의 생존, 혼을 떼어낸 담허, 영매의 역할, 소단이 손을 놓지 못하는 두려움과 남은 진의 필요성을 전달한다. 등장 전 까마귀 경고는 휘겸이 하고 등장 뒤에는 기존 소단 경고가 이어진다.

9장 아래의 두 진과 10장 위쪽 두 진은 별도 상태다. 10장 첫 설명에서 아래 진을 윗마당 양옆과 연결한다는 뜻을 밝힌다. 폭포와 빈 상여에 대한 불신, 비살상 대치, 외부 유입의 발견과 협력은 유지한다. 완료·증원·협력 조건은 이 씬 모듈의 권한이 아니며 바꾸지 않는다.

## 검증

`npm run test:story-staging`는 실제 App/큐/상호작용/보행을 DOM·Canvas·오디오 double과 함께 실행한다. 양쪽 진 설치 순서, 행동 경계, 전투 정지, 단계별 넘기기, 쪽수/이동 중 저장·재개, 반복 입력, 누락 anchor/막힌 경로/죽은 actor, 옛 저장, 재시도, 공방 공통 계약을 검사한다. 합성 위치/벽/사망은 음성/픽셀/정상 플레이 증거와 구분한다. 실제 브라우저 연출과 소리는 별도 검수한다.
