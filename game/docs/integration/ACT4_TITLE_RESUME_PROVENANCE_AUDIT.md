# Stage 39 title resume provenance audit

The RC `3d68d3f2` title Continue path opened the stage 31 rest hub after the actual-32-provenance 39 victory, although the saved `pendingDirect` and computed next stage were 40. This was a product navigation error, not established as a stale fixture field. `act4-content.js` declares transitions after 31–39 direct; `recordOutcome` stores the direct handoff, and `resultContinue` launches it without an intermediate rest. The title path instead calls `requestRest` → `hubId`, which chooses the latest eligible rest (31) and sets `restStageId` before `showRest` can consume `pendingDirect`.

Read-only comparison of the original stage32 export, stage39 entry fixture and actual stage39 victory profile: original has `mapNode=1`, `lastStage=33`, `honroJourney.stageId=31`, no `pendingDirect` or `restStageId`; fixture has `mapNode=39`, `lastStage=38`, `stageId=31`, `pendingDirect=39`, no `restStageId`; victory has `mapNode=39`, `lastStage=39`, `stageId=31`, `pendingDirect=40`, no `restStageId`. None has top-level `pendingRest` or `pendingNextStage`. `stageId` is retained from the previous rest and is not `restStageId`. The real 32 event and ledger were never modified.

With DOM/storage doubles, the RC source produced rest 31 for all six combinations of `mapNode` 1/39/40 and `honroJourney.stageId` 31/40 with a valid pending 40. The independently authored fix `e0ae4d132362cebc6f5b2aa31087958880f6ca75` consumes the valid matching direct handoff before hub selection, and all six combinations entered stage 40; mismatched pending targets remain rejected. The existing focused regression now includes this matrix. The earlier actual victory save was not changed: its UI-selected journey to 40 and `proofValid=true` are preserved separately in `codex/act4-stage39-provenance-rc` commit `d49e33a2`. Earlier independent real-browser tests of the fix used other game-generated 39 victory storage, not this exact RC save. This audit does not claim that stages 33–38 were actually played or that all other navigation flows were browser tested.
