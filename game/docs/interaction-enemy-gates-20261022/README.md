기준 master424c0e6b. 사용자는12장으로 표현했지만 부모가 실제 첨부 상단을 확인한 대상은 **13장 숨은 석문/R4/석문 빗장 열기**다. 자식 실행기는 첨부 원본을 열지 않았고 부모의 정확한 UI 설명과 현재 생산 화면으로 재현했다. 아래 사진은 첨부 원본이 아니라 준비한 R4 저장 fixture의 실제 Chromium이다.

## 우선 수정

`act2.eligibility`의360거리/`act3.eligibility`의220거리 일반 적 존재 gate와 공통 안내의 같은 차단 문구를 제거했다. 2막 개정/기존 저장과 3막은 같은 production 함수를 사용하므로 재시작이나 snapshot/적/완료 사실 교정 없이 적용된다. 거리·층·담당 인물·선행 기계 단계·생존 대상·중복 방지는 유지한다. 18장 전용 소스/목표/배치/수치는 수정하지 않았다.

`tests/interaction-nearby-enemies.mjs`는 닫힌 문 오른쪽의 살아 있는 수레가 있는R4에서 실제 E를 호출해 열림/출구 목표/중복1회/적과 성장 바이트 보존을 확인한다. 수정 전에는 동일 조건이 ‘주변 들림을 먼저 제압하세요’로 실패했다. `tests/interaction-enemy-gates-browser.py`는390×844 실제 터치와1180×757 KeyE, 열린 상태 저장→reload→Continue 및 진행 중 대화의 실제 다음/넘기기/입력 재개를 확인했다. 두 크기의 상호작용/대화 버튼이 화면 안에 있고 오류/HTTP실패0이다.

fixture 준비에서 선택 영웅을 보고된 위치에 배치하고 앞선 구조가 끝난R4를 만든다. 수레의 접근은 실제 Engine walk/충돌로 계산했다. 수정 코드는 좌표/적 처치/완료 플래그를 덮지 않는다. 실제 사용자 저장이나4턴 전투 완주를 검증했다고 하지 않는다. 초기 브라우저 harness의 reload마다 입력 fixture를 덮던 설정은 최초1회만 설치하도록 수정했고, 재개 대화는 실제 조작으로 마친 최종 통과 결과만 사용한다.

현재 이 커밋은 공통 gate 긴급 수정 단위다. 1~30장·옛 저장 단계 predicate 전수 조사, 전용 안내와 예외 검토는 후속 작업으로 계속한다. 특정 주민에게 붙은 혼 약화/분리는 일반 주변 적과 별도로 검토하며 아직 ‘필수 예외로 승인됨’으로 취급하지 않았다.
