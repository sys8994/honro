### hall 이후 record의 실제 표시 순서

R19의 실제 종료 저장은 이미 `phase=won`, 다섯 done 사실 true이고 HUD는 **목표 완료**다. 동시에 storyQueue에는 `hall`/`record` 두 장면이 순서대로 남아 있다. `record`가 새 이동 목표로 떠서9360까지 이동한 기록은 없다. 중간 한 틱마다 HUD 라벨을 촬영한 것은 아니며, 실제 입력 로그의 마지막 목표 hall과 종료 HUD/사실을 구분한다.

그 실제 저장을 다시 열고 production `outcome()`을 호출한 별도 검사에서, queue의 두 장면이 완료 대사의 앞부분으로 합쳐진 것을 확인했다. 생존 화자 필터를 거친 실제 표시 순서는 다음3줄이다.

1. 휘겸: “기록함 앞을 살펴보겠소.” (`hall`)
2. 기록: “칠십 년 전, 대종 외부 이송 / 타종 금지 · 인양로와 바깥길 봉쇄 / 출처: [잘려 나감]” (`record`, 원래 줄바꿈은 `/`로 표시)
3. 휘겸: “뒤편 작업굴로 갑시다. 승려가 말한 축을 찾아보겠소.” (outro)

즉 **승리 판정→hall/record를 앞에 붙인 완료 장면→장면 종료 시 단일 정산** 순서다. `대화 넘기기`와 같은 production finish 경로만으로 done/방문1회가 확정됐으며, 검사에서 직접 `outcome(true)`로 건너뛰는 fallback 없이 통과했다. 기존 marker/설계 메타와 조건의 차이는 기록할 뿐 맵·원고를 바꾸지 않았다. 이 추가 검사는 실제 R19 저장의 장면/정산 검사이며 전투를 재실행하지 않았다. 검사 SHA는 `972c1a5eaebef706b5a0198db3bd99259afb1327`다.

입력 기록은 사격41회+M10회복2회, 방어6회, 이동 구간10개, 점프4회, 구조/문 E 각1회다. 이동 구간 수는 실제 걷기 틱이나 거리 총합이 아니다. 옛 hold-hall 방어10증원은 현행 필수 체인에서 실행되지 않았으며, hall 이후의 원거리 response3체도 이번 종료 전에는 관측되지 않았다. 저작 metadata의 모든65체를 실제 등장한 것으로 세지 않았다.

R2–R8에 원거리 동행이 x2100 부근 바닥에서 공격을 이어 갔고, R14까지 구조 전 접근/교전에 시간이 들었다. 주력 석계단/쉼터 발판/상층 계단/법당 기단을 사용했다. 높은 서회랑·기도굴 우회·동쪽 balcony를 모두 전투로 활용한 사례는 아니다. 공격 우선 정책의 위치 선택과 생존 실패를 퀘스트의 필수 왕복 비용으로 바꾸지 않는다.
