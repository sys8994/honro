# 16장 페이싱 검사 근거

게임은 9f7091e782c82f8d4e9a5df23697132db5409fa0 그대로이며 게임 수치/코드/생성물 변경이 없다. 검사·문서 브랜치의 최종 커밋은 e975a63646af0e55f1a5c2edc01a5cca22cbe8c9다.

호위 우선 실제 입력은 구조/증언2턴 → 두 승려 도착/문/기록5턴 승리, 사망/소비품0이다. 같은13레벨27SP/normal 시작 핵심 필드를 기존22턴 시작과 대조했다. 정상 Engine/App의 이동·도약·공격·동행선택·방어·관찰 시간만 사용하고 시작 후 위치/HP/자원/목표는 설정하지 않는다. Native 검사이며 DOM/render/storage/clock double이므로 공개/실기기/사람의 체감시간 근거는 아니다.

첫 실행은 게임의5턴 승리 뒤에도 arrived가 영속해야 한다는 잘못된 검사 assertion에서 중단됐다(first-attempt-stop.log). 실제 피신 완료 frame의 접지·비점유 valid=true를 검증하도록 검사 시점을 바꾸고, 보존된5턴 checkpoint를 생산 Continue로 읽어 배우/자원/턴/지형/목표 동일성을 assert한 뒤 마무리했다. 이어하기 전후의 이동/위험/선택/행동 정책 원문은 같고 계측 복원만 추가됐다. 결과/trace의 continues와 arrivalProof를 참조한다. 사후 담허가 문에 접근해 정지한 제자와 겹친 기존 플레이어 이동 규칙과 NPC의 도착 전 관통을 구분하며, 일반 이동 규칙은 변경하지 않았다.

두 NPC는 예산4개 창(2·3·4·5턴)을 썼다. 예산 소진 정지 약52초씩은 존재하나 불필요한5–7개 추가 턴을 강제한 결과가 아니므로 이동 예산/속도/적 HP/편성을 낮추는 개선을 제안하지 않는다. moving/도착/예산/접촉/기타의 우선 분류라 조건 중첩이 있을 수 있고 미분류 시간도 공개한다. 시간은 엔진 simulation초다.

기존 frontline22 파일은 공격 우선 입력기의 원본 결과/trace를 그대로 복사해 보존했다. 이것을 정상 호위의 필수 소요로 해석하지 않는다. escort-trace는 전체 전투 trace이고 escort-pacing은 NPC별 라운드 예산/접촉/소비 계측이다. normal-entry는 동일 시작을 재현하기 위한 준비 fixture이며 이전15장을 실제 플레이했다는 의미는 아니다. 원본 byte 무결성은 files.json에 기록했다. 새 전략이나 장시간 검사를 추가하지 않았으며 제품 후보/Pages 반영은 부모 담당이다.
