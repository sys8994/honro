## 1. 진행 검수(완주)

  - 2막 봇: 13장 13라운드, 17장 19라운드.
  - 3막 봇: 21장 19라운드.
  - 장 전용 fullplay: 11장 통과, 28장 승리 9라운드.
- **도구가 출시 게임과 어긋남. 결과를 게임 결함으로 볼 수 없다.**
  - `act2-playthrough`(헤드리스)는 출시 압축 지도(`HONRO_ACT2_COMPACT_PACKAGES`, 웹 빌드에서만 정의)를 쓰지 않고 이전 대형 지도를 쓴다. 예: 14장 7600×10400(출시 4800×5400). 이동도 "legacy x-only" 방식이라 수직 경로에서 시간 초과된다(11·12·15·16장).
  - `act1-playthrough`: 5장에서 경로 헬퍼가 없는 지형 ID를 참조해 중단된다. 7장에서는 테스트용 앱 대역에 `updateHUD`가 없어 중단된다. 1·3장은 행동 예산 소진(기존 봇 한계).
  - `act3-playthrough`: 22장에서 경로 데이터(route)가 없어 중단된다.
  - 장 전용 fullplay 14개 중 12개가 실패한다. 원인은 오래된 기준값이다: XP 원장 예산, 적 총수 기대값, "적 행동 대기열 ≤3". 마지막 값은 `balance.ts`의 행동 예산 개정(+1)으로 이미 바뀐 설계다.
  - 2·10·21·22·23·30장 fullplay는 P1-1 변경을 되돌려도 같은 단언에서 실패한다. 최근 배치 변경과 무관하다.
- **결론:** 출시 지도 기준 자동 완주 검증이 사실상 비어 있다. 브라우저 실빌드를 직접 조작하는 완주 봇이 필요하다(6 밸런스와 공용).

## 2. 성능

측정: PC 1440×900(DPR 1)과 모바일 390×844(DPR 3).
- **진입:** 출전 시점부터 첫 프레임까지의 시간.
- **정지:** 영웅에 카메라 고정 3초.
- **이동:** 놀이 배율로 카메라가 맵을 두 번 가로지른 뒤 최대 축소로 한 번(9초).
- **절대값 주의:** 소프트웨어 렌더라 실제 GPU 기기의 절대 fps가 아니다. 타이틀 화면은 이 환경에서도 60fps다. JS 실행 시간, 긴 작업(long task), 저장 비용, 장 간 상대 비교로 읽는다.

**주요 발견**

1. **5막 41장 카메라 이동 끊김(최악):**
   - 이동 중 긴 작업이 최대 636ms이고, 지형 타일 78장을 다시 그린다.
   - 프로파일 6초 중 약 2.1초가 `act5-edge-art.js`의 `campPost → campPaintSource/campOwnershipGroup`이다. 타일 하나를 만들 때마다 군영 벡터 전체를 마스크·임시 캔버스로 여러 번 합성한다.
   - 개선 후보: 군영 합성 결과를 래스터 배율별로 한 번만 만들어 두고 타일에 잘라 붙이기.
   - 46·48·49장(`stage45Body`)도 같은 유형이다. 긴 작업 300~430ms.
2. **전투 저장 비용:**
   - 움직임이 있으면 `dirty`가 켜지고 1.2초마다 `flushBattleSave`가 돈다. 전투 객체 전체 `clone` 후 저장한다.
   - 5막은 메모리상 전투 객체가 2.9~8.7M자(그림 포함)이고, 저장본은 70KB로 압축된다.

   - 개선 후보: 압축 대상(그림 자산)을 복제 전에 빼고 복제하기. 또는 저장 간격을 적응형으로 조정하기.

## 3. 시각 일관성

- 50장 전경(행동 범위에 맞춘 PC 화면)을 검토했다.
- **바닥 아래 평판:** 21·26·28·41장(24·29 일부)은 지형 그림 아래가 수평선 하나로 끊긴 단색 갈색 판이다. 최대 축소나 모바일에서 화면 아래쪽 넓은 면적을 차지한다(더미 지형 2차 후보).
- **14장:** 압축 지도의 큰 직선 사면이 그대로 드러나 그림 밀도가 다른 장보다 낮다.
- 적 지원면 이탈·추락은 0이다(8 항목 측정). 소품 위치 자동 검사는 대부분의 그림이 장 단위 대형 자산이라 판별력이 낮았다. 3장에서 나온 2건(물 위 배, 공중 혼불)은 의도된 것이다.
- 화면에서 적 크기가 영웅과 비슷하게 작게 보이는 점은 크기 개편 2차 인계 문서로 넘겼다.
