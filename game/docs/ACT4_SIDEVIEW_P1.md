# 4막 측면 지형 선행 수정 — 33장 저지대 / 40장 동쪽 주경사

2026-11-16. 전수 제안서 P1-A의 **첫 두 구간**을 구현했다. 4막 전체 시점 교정이나 33·40장 전체 재제작의 완료 기록이 아니다. 기준 master는 `4b4e771e85e67a6b9aabd25b6f73e511946bc0f0`; 전수 점검 기준 `85c19fb78f3ac4c4bbf3f50d52199b6100ae15f8` 이후 변경도 확인했다.

## 설계 카드와 변경 계약

| 장 | 문제와 변경 | 보존 / 남은 범위 |
|---|---|---|
| 33 물 빠진 갯길 | 넓은 모래 윗면 안을 지나던 실제 발 위치에 낮은 접촉 띠와 청회색 전면 암벽을 연결. `approved33-left-bank`, `approved33-low`의 보행 경계를 기준으로 네이티브 색면과 알파를 함께 등록했다. 좌우 카메라에서 끊기지 않도록 시안은 월드 x −4600~12296까지 연장했다. | 기존 아치·상부 경로·계단·뒤쪽 해변·원경·조수 효과 보존. 장 전체 장식/상부 경로의 측면 재제작은 남아 있다. |

`shared/act4-sideview-art.mjs`가 기존 BODY 직후 각 장에 paint-only 자산 하나를 추가한다. 기존 BODY는 단일 coverage owner로 유지하고 추가 그림은 기존 native surface pass에 연결한다. 별도 렌더러나 물리 루프, 외곽 dummy collision은 만들지 않았다. 원본 124개 provider, 기존 elements, 지형·충돌·one-way·유닛·목표·이벤트·맵 크기·bounds·revision을 보존했다. Game/Workshop/Playtest가 같은 `shared/build.mjs` 연결을 사용한다.

기존 전투 스냅샷은 기존 그림과 상태를 이어간다. 신규 진입부터 새 그림을 사용한다. 기존 저장에 새 그림을 강제 주입하거나 전투를 초기화하지 않는다.

## 시안과 실제 벡터 제작

[장 제작 SOP](STAGE_PRODUCTION_SOP.md), [벡터 SOP의 표준 프롬프트](VECTOR_AUTHORING_SOP.md), [새 버전 SOP](HONRO_NEW_VERSION_SOP.md), 취향서·기록부와 terrain/environment 스킬을 참고했다. 실제 게임 스켈레톤과 현재 4막 재질을 분리한 참조를 사용하고 **전면 암반만** 투명 이미지로 제작했다. 원경·나무·배·목제 계단을 한 장에 새로 추적하지 않았다.

정확한 승인 원본 `stage21-concept.png`(SOP SHA `cc212aaadf77c80941ab46ee64b05020e6247bbef1734b4758823c077b6ab491`)는 저장소/확인한 로컬·연결 자료에서 확보하지 못했다. 현존 stage21 벡터는 보조 참조일 뿐 해당 승인 PNG와 동일하다고 하지 않는다. 이번 결과에 사용자 미술 승인을 부여하지 않는다.

원본·실제 프롬프트·해시·최종 SVG는 [source/manifest.json](../../shared/assets/environment/act4-sideview/source/manifest.json)에 있다. 인접 `production/33`, `production/40`에 immutable native raw, 등록 전후, 최적화 보고서, 최종 직렬화를 보존한다. 시안의 앞 가장자리는 그대로 물리로 쓰지 않고 기존 보행선에 색면과 알파를 함께 등록했다. 40장 몇 개 무채색 matte 면은 기존 암벽색으로 조정했다.

실제 Inkscape 1.4.4 (`dcaf3e7`, 2026-05-05) `object-trace`를 실행했다. 색상 스캔 `16,true,true,false,4,1,0.2`, 알파 스캔 `2,false,false,true,0,0,0.1`. 이번 자산의 16색 선택이며 전 장 공통 팔레트 강제가 아니다. 알파 128 미만의 숨은 RGB를 추적 입력에서 흰색으로 정리했고 실제 알파를 별도로 추적했다.

| 새 전면 모듈 | 등록 후 raw segment | 최적화 후 segment | 최종 SVG bytes | 배포 입력 JSON bytes |
|---|---:|---:|---:|---:|
| 33 | 155,012 | 95,317 | 1,229,362 | 1,235,075 |
| 40 | 54,555 | 34,029 | 442,135 | 449,315 |

원본 곡선을 기존 보행선에 등록하는 편집으로 native raw보다 segment가 늘었다. 원래 원본보다 가벼워졌다는 주장과 구분한다. 저장소 optimizer를 epsilon 0.05 source px, 1536/3072 렌더로 실행했고, 그 다음 모든 segment·hole을 보존한 소수 3자리 직렬화를 적용했다(좌표 오차 <0.00071 source px). 33장 최장 subpath는 58,554자다. 기존 60,000자 제한이나 검증기를 완화하지 않았다. 색별 compound path 16개를 편집점 16개라고 세지 않는다.

추가 런타임 입력은 합계 약 1.61 MiB다. 원본 PNG는 제작 자료이며 런타임에 중복 전송하지 않는다. 기존 BODY를 보존하는 선행 방식이라 추가 draw/메모리 비용이 있다. 실제 기기 FPS/저사양 장기 성능은 미검수다. 보관된 render-call 시간은 카메라 조건이 달라 전후 성능 개선/악화의 근거로 쓰지 않는다.

## 확인 수준과 한계

- **정적 계약**: `node tools/act4-sideview/check.mjs`에서 기존 입력/124 provider와 새 미술을 제외한 장별 데이터의 deep equality, 신규 자산 충돌 없음, 기존 vector schema를 확인했다. `npm run build` 성공. 무관한 전체 verify는 실행하지 않았다.
- **정적 벡터**: source/trace, registered raw/final을 같은 Chromium SVG rasterizer에서 1536/3072로 비교했다. painted-mask 평균 채널 오차는 0~1 기준 최대 0.000109. raw는 기존 엔진 subpath 한도 초과로 직접 가져올 수 있어야 한다는 조건을 충족하지 못하므로, 이 비교를 raw의 실제 게임 렌더 검증이라고 부르지 않는다. 최종 자산만 실제 production 렌더러에서 확인했다.
- **게임 합성 화면**: Chromium 157, 새 격리 context, 1440×900/DPR1. 33장 진입·서/중/동 저지대·양 끝, 40장 진입·분기·동쪽 주경사·상부·부두·오른쪽 끝을 확인했다. 주요 전후는 동일 중심/0.53배. overview 0.17은 진단용이며 실제 허용 최소 줌과 구분한다. 1.65배 접촉부, `HonroBounds`의 실제 최소 줌/카메라 경계, 390×844 모바일 일반/최소 줌을 추가 확인했다.
- **조수 상태 화면**: 33장 rising/high/low-return은 격리 상태 fixture로 실제 조수 렌더러를 호출했다. 만조에 잠기는 전면 암벽과 UI를 확인했다. 플레이를 통해 조수 주기를 완주했다는 의미는 아니다.
- **접촉선**: 최종 알파와 원본 walk edge를 33장 567점/40장 252점 대조했다. 최대 오차 각각 0.2141/0.1264 월드 단위(1.65배에서 0.354/0.209 px 미만). 표본 검사이며 연속 전체 곡선 오차 증명이나 실제 이동 검증의 대체가 아니다.
- **실제 입력**: 신규 진입 2곳과 위치만 옮긴 fixture 3곳(33 저지대, 40 동쪽 주경사/상부)에서 실제 ArrowRight/ControlLeft 입력, 이동·공중 상태·착지를 확인했다. HP/AP/스탯은 바꾸지 않았다. 신규 장 해금 및 위치 fixture와 실제 입력을 구분한다. 전 장 완주·전투 밸런스·전체 계단/상호작용 진행은 미검수다.
- **저장**: baseline master에서 만든 33/40 격리 저장과 최종 새 진입 저장을 각각 UI의 ‘이어서 걷기’로 재개했다. 지형·성장·HP 동일, 재개 표본 좌표 차이 0, 구판 그림/신판 그림 각기 유지. 사용자 브라우저의 기존 저장은 열거나 수정하지 않았다.

원시 결과와 화면은 `_local/reports/act4-sideview-p1-20261116/`, 전후 보고서는 `_local/archive/act4-sideview-p1-20261116/report.html`에 둔다. `final/`은 실제 빌드 화면, `vector-proof/`는 정적 SVG, `play-save/`는 입력/저장 증거다. 폐기 후보는 최종 증거에서 제외한다.
