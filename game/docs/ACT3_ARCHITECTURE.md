# 3막 건축 미술과 배치 계약

원본은 `shared/assets/environment/act3-architecture/`의 순수 SVG와 `production-manifest.json`이다. 기존 성문·담장·관창·2층 회랑·기록고·홍예교의 큰 형태와 앵커를 보존하고 기와 겹침, 처마 아래 그림자, 목재 옆면과 이음, 큰 화강암 면, 묶은 서책의 덮개·종이 단면을 보강했다. 거친 노이즈·외부 이미지·SVG filter·새 렌더러는 사용하지 않는다.

## 좌표와 충돌

- 모든 발 기준은 `(0, 0)`이며 위로 올라갈수록 y가 음수다. `reference.bounds`는 SVG viewBox와 동일하다.
- `groundContacts`는 실제로 칠해진 지지점이다. 맵 작성자는 인스턴스 scale/rotation을 적용한 같은 지점을 실제 지형·교대·강바닥에 붙인다.
- `floorSurfaces`의 y가 보행면이다. floor/solid/contact는 그림과 같은 transform을 써야 한다.
- `clearRegions`는 Native 픽셀까지 완전히 투명한 영역이다. 후경이 보이도록 남긴 문간·계단 우물·수로이며 자동으로 충돌을 만들지 않는다.
- `collision`은 비어 있다. 맵 작성자가 `suggestedSolids`를 선택해 실제 고체를 생성한다. 서가·종이창·내부 기둥·권양 장치·화덕은 별도 명시가 없으면 뒤쪽 그림이다.
- 원래 성문·담장·관창 시안에는 고체 계약이 없었다. 이 세 모듈의 `suggestedSolids`와 `floorSurfaces`는 비어 있으며 전면 사각형으로 자동 채우지 않는다.
- 새 지붕의 제안 고체는 넓은 실제 지붕면 안에 있다. 얇은 처마 끝은 시각 장식이며 보행 경로의 끝 받침으로 사용하지 않는다.

## 새 장소 변주

- `mansion-open-gallery.svg`: 높이 952, 두 층 바닥 -20/-400. 층간 380. 양측 회백색 종이창과 가운데 열린 통로, 바깥 기둥만 제안 고체.
- `ruined-foundry.svg`: 높이 847. 아래 바닥 -20, 두 상층 발판 -400. 중앙 460폭 절개. 지붕 손실부에는 가짜 지붕 고체가 없다. 그을린 회벽, 끊어진 목구조, 돌 화덕·모루·풀무는 장소를 구분하는 후경이다. 별도 불/위험물 기믹을 뜻하지 않는다.
- `sluice-pavilion.svg`: 높이 893. 조작 누각 바닥 -400, 돌 교각 세 곳이 y=0까지 내려오며 두 물길은 투명하다. 수문 판은 올라간 상태의 후경이다. 물·작동·위험 조건은 지도/임무에서 정의한다.
- `ferry-loading-pavilion.svg`: 높이 714. 하역 바닥 -140, 네 지지점, 비대칭 판벽과 빈 하역 칸. 매달린 도르래와 낮은 등불은 미술이고 임무 단서가 아니다.

공통 풍경 시스템이 뒤쪽 건축의 채도·대비를 낮춘다. 새 모듈은 건물 규모를 바꾸는 비균일 scale 대신 수평 간격·형태·바닥 높이가 다른 배치를 사용한다. 전투 캐릭터, 목표와 실제 보행면이 종이창이나 서가보다 먼저 읽혀야 한다. 왕궁이나 특정 역사적 건물의 확정 설정을 추가하지 않는다.

## 검사

`node tests/act3-architecture.mjs`는 실제 `compileSVG`와 `HonroVectorArt`를 사용해 10종의 제한된 SVG 어휘, 16 KB/90 path 미만 예산, 전체/지붕 bounds, 접지, 투명 통로, 보행면과 제안 고체의 실제 픽셀 일치, 390/760/1440 크기 렌더를 확인한다. SVG 자체 충돌을 등록하거나 캠페인을 수정하지 않는다.

기존 비활성 시안 검사 `tests/act3-town-assets.mjs`, `tests/act3-dense-assets.mjs`도 원래 접점 보존을 확인한다. Native 보고서는 `_local/reports/act3-architecture/`에 생성한다. 지도 배치, 실제 도달성/보행·탄도, Game/Workshop 브라우저 및 Pages 성능 검수는 통합 후보에서 별도로 수행해야 한다.

## 큰 건축 비례와 장소별 후면 구조

2026-10-07 최종 미술 보강은 큰 hall의 상단 창·긴 빈벽 문제를 다룬다. 아래 창과 양짝문은 실제 바닥에 붙고, 높은 벽의 추가 층감은 낮은 대비의 매입 목재띠로만 나타낸다. 그 띠는 밝은 상판·난간·돌출 발판을 갖지 않으며 보행면을 추가하지 않는다. 모든 기존 roof/floor collision, viewBox와 anchor를 보존한다.

30장에는 주막 천막, 작은 매표집, 밧줄을 건 빈 하역칸, 서로 반대쪽이 닫힌 창고, 높은 창고 판벽과 상자, 옛길 쉼칸을 배정한다. 창호·문·기둥·큰 가구 덩어리로 용도를 구분하며 미세 선 패턴을 늘리지 않는다. 27장 화재 가까운 서가는 그을린 재질을 쓰고, 기존 두 불의 실제 위치에는 재·탄목·따뜻한 국소 반사와 얇은 연기를 표시한다. 기존 제어가 끝나면 빛·불·연기는 꺼지고 재·탄목은 남는다. 전투 상태를 읽기만 하며 불의 규칙·시간·피해를 바꾸지 않는다.

`tests/act3-hall-art.mjs`는 16가지 건물의 원래 충돌/앵커/bounds와 48 Native 렌더를 검사한다. `tests/act3-visual-cues.mjs`는 두 불의 위치·독립 소등·제어 후 잔해·무연기와 상태 무변이를 검사한다. `tests/act3-art-regeneration.mjs`는 실제 생성기를 쓰되 파일을 바꾸지 않고, 1–20장 원본 객체 및 전30장의 compile collision/material, authored units/markers/design을 비교한다. 새 맵을 합법적으로 바꾸면 소스와 campaign을 함께 재생성한 뒤 검사한다.

전후 캡처는 같은 runtime/camera에서 `capture-act3-production.mjs --stages 27,30 --facade-focus`로 재현한다. `--art-source <file>`은 fire renderer의 명시적 이전 버전을 비교할 때만 사용하며 보고서에 파일과 SHA를 남긴다. 기본 실행은 현재 실제 renderer다. 실제 브라우저·Pages와 정상 전투 완주는 이 미술 증거의 범위가 아니다.
