# Stage23 호송 전장: 실제 기예와 유한 입구 검증

이 문서는 새 9800×6200 하역장의 **지원되는 전술과 남은 설계 공백**을 구분한다. 미술 revision의 승인, 정상 입장에서 전장까지의 도착, 전투 완주, 사람의 재미 평가, 브라우저·Pages 배포 합격을 뜻하지 않는다. 큰 화물의 장면·충돌 전환은 별도 runtime/geometry 검사 소유다.

## 재현과 진입 조건

- `node tests/stage23-escort-skill-roles.mjs`
- `node tests/stage23-escort-ingress.mjs`
- 결과: `_local/reports/stage23-escort/skill-roles.json`, `ingress.json`
- `stage23-escort-entry-helper.mjs`의 1–22장 실제 보상·합류 장부 호출로 만든 진입 fixture: XP 75748, Lv16, 일반 능력 수련6, 배운 기예 모두 rank1. 1–22장 정상 연속 플레이 저장은 아니다.
- 정확히 네 슬롯: 설오 A01/A14/A11/A02, 담허 M01/M04/M11/M03, 휘겸 S00/S03/S01/S04, 소단 O01/O04/O08/O11. SP03/M09 및 추가 패시브는 없다.
- 초기 22명·정예5·동시 행동3을 유지한다. 타깃을 추가하거나 자리를 옮기지 않는다. 후보28명은 ingress의 독립 비교에서만 사용한다.
- 기예 검사는 시작 동행의 지지된 좌표와 최초 아군 행동을 명시적으로 배치한다. 이후 `Engine.fire/tick/move/jump/wait/select/manualDive`가 좌표·HP·기력·이동력을 결정한다. native 호출 밖에서 원래 배우의 좌표·HP·기력·이동력을 쓰면 검사 자체가 실패한다. 소비품, 자원 충전, `recover` 호출로 결과를 만들지 않는다.
- 각도 탐색은 일회성 테스트 조사였고, 회귀 검사는 아래 고정 좌표·각도·충전량만 사용한다. 그림/SVG가 병렬 변경되어도 지형·배우·목표·사건·상태의 geometry fingerprint가 같은지를 검사한다. 그림 해시가 같다는 이유로 물리 합격을 대신하지 않는다.

## 소단: 투과하는 것은 탄이며, 소환은 호송 동행을 대신하지 않는다

중앙 측면 끝 `(4750,4430)`에서23.42405087°·0.73021378. 탄이 실제 암석 `sy-stone-corner`를 가로질러 E-3에322 피해, 비용59. 소단 본체의 좌표는 그대로다.

별도 기본 점프+오른쪽 이동90tick에서 몸 중심은 경계석 앞 `x4821.108`에서 멎는다. `locomotion.ts`의 `validTerrainContactPose` 주석과 `walkTerrain`, `Engine.integrateBody`는 넓은 시각/피격 반지름과 이동 탐침을 명시적으로 구분한다. 몸통·머리는 `min(6,max(2,r−2))`, 발은2다. 이번6px 코어는 벽 `x4830`보다최소2.892 밖에 있으며90tick 모두 고체교차0이다. 전체 r22 직사각형만 최대13.108 겹친다(72tick). 이것은 검사지표/시각 여유의 차이로 `observations`에 남기고 새23 지형관통 결함이나 설계gap으로 세지 않는다. 기예를 근거로 본체 벽 통과를 주장하지 않는다.

### O11 배회령

짐꾼 뒤의 `(2150,4700)`에서24°·0.35로 발사한다. 실제 `sy-ground` 착탄으로 rank1 배회령을 `(2435.899,4700)`에 부른다. 비용55. 적/주민의 몸을 소환 착탄면으로 오인하지 않는다. 소단 본체는 움직이지 않는다.

배회령은 실제 선택 API에서 거부되며 `HonroAct3.heroes`와 `Engine.heroesAlive`에 포함되지 않는다. 실제 소환 몸이 짐꾼보다65 이상 앞에 있어도 모든 동행이 뒤에 있으면 NPC를 선도하지 못한다. E 검사도 별도의 복제된 ‘잘못 선택된 소환 배우’ fixture에서 거절된다. 이것은 소환을 정상 선택할 수 있다는 뜻이 아니다.

실제 행동·review가 끝난 뒤 배회령은 약88 전진하여 B-0에129 피해를 준다. 그동안 NPC는 제자리에 남는다. 동일 자리·각도의 O01은 B-0 대신 짐꾼에게64 피해를 주는 위험한 실패 대조다. 짐꾼을 지난 지지 위치 `(2460,4700)`에서 −14.05626701°·0.60575625의 O01을 쏘면 B-0에96 피해, 비용0이며 아군 피해가 없다. 이 위치는 별도 포즈 fixture이고 정상 도착 주장은 하지 않는다. 정상 동행의 보행과 E는 여전히 필요하다.

## 실제 새 지도 유한 입구

`stage23-escort-ingress.mjs`는 기존 synthetic 평지 테스트가 아니라 현재 전체 새 지도와 실제 App을 사용한다. 초기 동행은 서쪽 입구를 차지하고 있으므로 주입구를 비운 경우/주입구만 막은 경우/양쪽을 막은 경우의 사전 지지 포즈를 명시한다. 목표 선행조건과 방어 회복을 측정할 감소 HP/기력도 setup에서만 만든다.

세 편대3/2/3 각각 다음을 검사한다.

1. 주입구가 비면 정확한 저작 슬롯 전체에 생성한다.
2. 주입구가 막히면 같은 편의 저작 alternate에서 전체를 생성한다.
3. 양쪽이 막히면 모두 대기한다. 일부 예약 성공 뒤 실패해도 배우/nextId/XP/entry/완료flag가 새지 않고 pending 이벤트가 유지된다.
4. 예고 뒤 실제 새 App.defend와 review 완료가 있어야 기회를 인정한다. 가짜 수동 경계, 적 경계, 이미 review 중인 행동은 다음 동행 기회가 아니다.
5. 전신 지형 여유·배우 간 여유·정확한 지지면과 슬롯을 실제 factory 결과로 검사한다. opposite-side 이동이나 임의 근접 검색을 허용하지 않는다.
6. 원래22명은 전원 살아 있고 좌표·HP·기력·이동력·행동 상태가 그대로다. 22+유한8=cap30, 별도 후보28+8=cap36, 행동상한3을 구분한다.
7. 높은 동행이 먼저 동쪽에 서 있어도 실제 `dock-mid` 완료 전 third 입구는 예고하거나 큐에 넣지 않는다.
8. 원본 지도 full-group factory 결과와 새 입구 생성체의 HP/maxHP, attack/baseAttack/baseHP, loadout/ranks, focus/maxFocus, armor/elite, XP weight/budget/granted, 몸 크기/maxMove를 정확히 비교한다.

현재 고정 회귀는 총15검사이며 원본 예산과 후보 예산 비교를 포함한다. 정상 호송 전투에서 세 편대를 소진하고 승리했다는 증거는 별도 fullplay가 담당한다.
