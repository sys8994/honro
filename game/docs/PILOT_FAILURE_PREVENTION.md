# 제작 시행착오 재발 방지

새 작업·재시도 전에 해당 항목을 확인한다. 실패를 발견한 담당자가 **원인 → 재시도 금지 조건 → 대체 절차 → 재검증 증거**를 같은 수정 단위에 기록한다. 조정자는 다음 담당자에게 적용 항목을 전달한다. 해결되지 않은 항목은 합격 표시를 금지한다.

## 플레이 시험

### P01. 제작된 모듈이 시험 실행기에 없음
- 발견: 4막 시범 전투 모듈을 배포 빌드에는 추가했지만 시험의 수동 모듈 목록에는 누락했다. 구형 HP로 실행한 결과를 새 편성 평가로 오해했다.
- 금지: 수동 목록만 믿고 장기 시험을 실행하거나, 이 실행의 피해량에 맞춰 밸런스를 수정하지 않는다.
- 절차: 공식 모듈 목록을 공유하고 순서·누락·파일 해시를 검사한다. 실행 직후 실제 모듈 API, 신선한 적의 예산 태그, 활성화 훅을 확인한 뒤 장기 실행한다.
- 실패 처리: 해당 실행은 어댑터 오류로 중단·보존한다. 성공률의 성공 표본으로 쓰지 않고 오류 분모에 남긴다. 수정판은 버전과 해시를 바꿔 새로 실행한다.
- 재검증: `tests/quantitative-playtest-manifest.mjs`의 누락·중복·향후 모듈·순서 회귀 통과. 실제 NativeCanvas 초기화에서 전체 manifest 및 pilot API/신규 예산/활성화 sentinel 통과(run `1f2002fb-f0a0-4a38-a437-7a25f205bea3`). 1frame 초기화 증거이며 전체 플레이 합격은 아니다.

### P02. 투사체 중력을 점프 중력으로 오인
- 발견: world gravity 320으로 발판을 설계했으나 실제 점프 중력은 1000, 기본 도약 높이는 약218 world units였다.
- 절차: 현재 실제 캐릭터 신체와 엔진의 점프·아래점프를 측정한다. 개별 연결 검사 뒤 입구부터 연속 이동을 검사한다. 중간 좌표·HP·이동력 주입으로 연결을 통과시키지 않는다.
- 증거: `tools/act4-pilot/probe-skeleton.mjs`; 지형 SHA가 다른 이전 결과는 재사용 금지.

### P03. 시험 자체의 메모리 누적
- 발견: 전체 캠페인 중복 조립 및 NativeCanvas 미소비 프레임으로 480frame에 RSS 약4.79GB까지 증가했다.
- 절차: 원본 레지스트리 한 번, 해당 장의 재귀 자산 의존성만 로드한다. 실제 픽셀 readback으로 프레임을 소비한다. renderer를 no-op으로 바꿔 관측 증거를 만들지 않는다.
- 증거: `tests/quantitative-playtest-closure.mjs`, `tests/quantitative-playtest-native-readback.mjs`. 600frame 후반 RSS 평탄은 확인했으나 장시간 안정성을 대신하지 않는다.

### P04. 입력·집계가 실제 행동과 다름
- 발견: 적 planner 재시도를 행동 수로 중복 계산, 근접기가 사거리 밖에서 공격, 정상 drop의 준비 상태를 미수락으로 판단, gzip/강제종료 로그 누락.
- 절차: 실제 accepted fire/movement/support 변화와 입력 반환·상태 전이를 기록한다. 선택한 합법 기예의 실제 사거리로 접근한다. gzip·잘린 로그·외부종료를 모두 집계한다.
- 증거: `tests/quantitative-playtest-activity.mjs`, `tests/quantitative-playtest-policy.mjs`, `tests/quantitative-playtest-log-reader.mjs`. drop 준비 상태·실제 반환값 회귀도 통과했다. 전체 경로의 유효 아래점프 실측은 별도다.

### P05. 지형 이동 후 옛 목표 좌표가 남음
- 발견: 갑판/카메라/정책이 서로 다른 옛 y1860을 사용했다.
- 절차: 실제 authored boarding 설정을 단일 좌표 원본으로 사용한다. 생성된 갑판과 전원 접지·전멸·상호작용 승리 계약을 함께 확인한다. 정책은 현재 관측 가능한 목표를 읽고 고정 승리 테이프를 사용하지 않는다.
- 증거: `tools/act4-pilot/test-boarding-config.mjs`; 일반 맵 fallback과 새 맵 모두 검사.

### P06. 옛 성장 기준으로 새 기예의 피해 예산 계산
- 발견: legacy LA01·과거 계수·rank4 기준 shot과 현재 A01 기본 rank1의 피해가 크게 달랐다.
- 금지: 유효한 실행기 확인 전에 HP를 조정하거나, 결과를 보고 시험 파티를 강화하지 않는다.
- 절차: 장별 고정 정상 진입 프로필과 현재 기예·방향 방어·영체 저항으로 실제 피해 행렬을 측정한다. 일반 적 1–2 유효 공격, 중간보스 2–3 파티 라운드를 확인한다. 새 기준은 후보 버전으로 기록하고 같은 고정 코호트에서 재검증한다.
- 재검증: [고정 실제 피해 기준 v2](ACT4_PILOT_COMBAT_REFERENCE.md), 실제 App 38개 actor 대조 및 native 접촉65행, `tests/act4-pilot-damage-reference.mjs` 통과. 연습용 기본 몸체·부활·옛장비 fixture 시도는 철회 이력으로 구분한다. 전체 정상 플레이 처치 라운드는 아직 별도 검증 대상이다.

### P07. 길찾기 없는 정책으로 복합 지형 난도를 평가
- 발견: v4 정책은 목표 x로 이동하다 정체 시 점프하고 가까운 하향 목표에서만 drop했다. 공개 지지면 연결·우회·도달 가능성 탐색이 없었다.
- 금지: 알려진 경로 탐색 결함을 둔 채 장시간 완주 시험을 반복하거나, 그 실패율을 게임 난도로 해석하지 않는다. 정책을 통과시키려고 맵을 직선화하지 않는다.
- 절차: 현재 캐릭터의 실제 이동·점프·낙하 물리와 공개 지형으로 일반 연결 그래프를 구성한다. 고정 장별 좌표 테이프·숨은 적·미래 전투 oracle은 금지한다. 별도 소규모 지형에서 오름/하강/횡단/막힌 길 우회/불가능 목표를 검증한 뒤 정책 버전을 고정한다.
- 재검증: `tests/quantitative-playtest-navigation.mjs`의 합성 연결/우회/불가능 목표 및 follower 회귀 통과. v5 실제 App 600frame에서 shore→west-step 정상 점프 착지 확인(run `6941d498-b92c-4e07-9d94-391c8b1f4589`). 전체 경로/승률 합격은 아니다. 고정 조준 오차·시험 파티는 그대로 유지한다.

### P08. 공개 목표를 무시하고 출구부터 향하는 정책
- 발견: 31 HUD는 ‘남은 위협 제압’을 먼저 안내하지만 v5는 처음부터 선착장을 목적지로 삼았다. 낮은 최단로만 가면 상부 미탐색 적을 놓칠 수 있다.
- 금지: 알려진 목표 해석 결함을 둔 채 장기시험을 반복하거나, 숨은 적 좌표/미리 정한 장별 방문 순서를 주입하지 않는다.
- 절차: 실제 공개 HUD 목표·남은 위협 수와 실제 카메라 관측 이력으로 탐색한다. 공개 지지면의 미탐색 전망점을 일반적으로 선택하고 실제 화면으로 적을 발견한다. 위협 해소 뒤에만 다음 공개 목표로 전환한다.
- 재검증: v6 공개목표/미탐색지지면 탐색과 `tests/quantitative-playtest-exploration.mjs`의 상부 시야 발견·숨은 적좌표 접근 거부·출구 우선 오류 회귀 통과. 실제 새 후보의 v6 App 검증은 미완료다. v5 짧은 점프 결과를 v6 전체 목표 증거로 확대하지 않는다.

### P09. 목적·예산이 다른 시험을 같은 성공률로 집계
- 발견: 같은 source/stage/policy라도 600frame sanity와60,000frame holdout은 다른 프로토콜이다. 실행 종료 정보만 묶으면 잘못된 성공률 분모를 만든다.
- 금지: 좋은 sanity 결과를 사후 holdout으로 승격, 시작 기록 없는 시도 추정 분류, 반복 seed를 독립 표본 취급, 외부 종료·잘린 gzip 누락.
- 절차: 실행 전에 목적·frame/wall 예산·controller/source/cohort ID를 시작기록에 고정한다. 프로토콜별 분모와 전체시도/기술오류/정상실패/미분류/반복seed를 함께 공개한다. Holdout 기술오류는 승인 blocked다.
- 재검증: stats/log-reader/freeze 회귀 통과. 공격행동 분석은 owner+원본shot으로 연타를 묶고 실제 HP 감소만 사용한다. provenance/maxHP/소속이 없으면 null로 남긴다. 원시거리와 의도된 유효이동·낙하도 분리하며 이전 로그를 소급 보정하지 않는다.

### P10. 경고 표적만 보인 것으로 가정하고 문구를 놓침
- 발견: 31장 경고 대상의 중심점이 viewport 가장자리에 걸릴 때 텍스트는 화면 밖이나 UI 뒤에 있거나 최소 줌에서 작게 표시되는데도 인지 receipt가 저장될 수 있었다.
- 금지: 내부 `seen` 값이나 DOM 존재만으로 실제 경고 목격을 증명하지 않는다. 화면을 확대한 후의 결과를 기본 카메라 가독성으로 확대하지 않는다.
- 절차: 표적 표시와 최소 크기의 문구 전체가 viewport 안에서 HUD를 피하도록 실제 표시 위치를 계산한다. 두 영역이 완전히 보여야 receipt를 기록한다. 월드 중간 단계에서 그린 경고는 배우 렌더가 다시 덮을 수 있으므로 최종 월드 렌더 뒤에 표시하며 턴 배너도 가림으로 판정한다. 렌더·카메라·줌·모바일·저장 복원을 실제 브라우저에서 관찰한다.
- 증거: `tests/act4-pilot-warning-layout.mjs`는 레이아웃 경계의 단위 확인이다. 실제 브라우저 UI 표시와 저장 검수는 별도로 기록한다.

### P11. 하층 막힘을 지형 결함으로 단정
- 발견: 32장 담허가 하층 x≈849에서 오른쪽으로 막혔고 바위 충돌 하나를 제거한 진단에서는 전진했으나, 실제 정상 플레이의 왼쪽 점프 두 번으로 상층 진입로에 복귀할 수 있었다.
- 절차: 충돌 요소를 제거해 얻은 비교는 원인 진단에만 사용한다. 정상 이동·점프·아래점프와 지형층별 우회를 먼저 확인하고, 실제 귀환 불가가 확인될 때만 최소 교정과 새 플레이를 검증한다. 진단 복사본과 정상 완주를 분리한다.
- 증거: `tools/qa-stage32-fullplay/RESULT.md`의 실제 16턴 완주와 저장 복원.

## 지형·미술

### A01. 전체 시안 추적 후 사각형으로 잘라 재사용
- 발견: 연결된 암괴·해안·다리를 잘랐더니 잘린 기둥과 다른 오브젝트 조각이 남았다.
- 금지: 연결된 전체 장 추적을 생산 자산으로 취급하거나 잘린 경계를 장식으로 숨기지 않는다.
- 절차: 전체 이미지는 구도 참고용. 배경·독립 지형 모듈·공통 장식·근경을 생성 단계부터 분리한다. 각 모듈에 충분한 투명 간격을 둔다.

### A02. 잔디·노이즈가 많은 시안을 최적화로 구제
- 발견: 4개 모듈에 3천여 subpath가 생겼고 줄여도 자산당 약190–227KB와 형태 손상이 남았다.
- 금지: path 수나 엔진 한도 통과만으로 경량화·미술 합격을 선언하지 않는다. 손실 상한을 올려 실패 시안을 억지 통과시키지 않는다.
- 절차: 큰 윤곽과 2–3개 넓은 음영면으로 시안을 다시 만든다. 불필요한 잔디·균열·반투명 테두리를 원본 단계에서 줄인다. 원본을 보존하고 실제 vector-only 픽셀로 확인한다.

### A03. 색상 추적의 겹침이 작은 중요 색을 덮음
- 발견: Colors의 Stack 추적에서 목재의 갈색이 뒤의 녹색 면에 덮였다. 8→12색 증가만으로 해결되지 않았다.
- 절차: 중요 색/형태 ROI를 원본과 비교한다. 비적층 추적 또는 목재 별도 모듈을 사용한다. 비적층의 경계 틈은 별도로 확인한다. 연결 원본 비트맵이 뒤에서 틈을 감추지 않도록 검사 렌더에서 이미지를 제거한다.
- 현재: 배경·새 독립 모듈은 비적층 추적으로 전환, 최종 틈·접지 검수 전.

### A04. 물리 연결 통과를 지형 설계 합격으로 오해
- 발견: 반복된 좁은 허리 암주, 빈 공간 위 한 줄 지그재그 발판은 연결 검사에 통과해도 전략·자연스러운 공간감을 충족하지 못했다.
- 절차: 충돌 스켈레톤 단계부터 겹치는 교전 공간, 후퇴·측면·대체 오름길, 넓은 고저 변화와 실제 차폐를 이미지로 검수한다. 긴 직선 목표<20%, 상한<30%; 미세 지터로 회피하지 않는다.
- 실측 재발 확인: 정상줌 0.7의 진단 화면에서 31장 77.36–100%, 34장 83.46–100%, 39장 88.42–100%로 모두 긴 직선 상한을 넘었다. `tools/act4-pilot/measure-support-straights.py` 및 `test-support-straights.py`는 단순 분할·미세 지터의 위장 통과를 거부한다. 기존 후보는 보존하고 실제 보행선 굴곡을 별도 개정·물리 재검증한다.
- 미술 매핑: 검증된 보행 상면·머리 공간·실제 이동 통로는 보호한다. 그림 밖 투명벽이나 그림에만 있는 가짜 발판을 금지한다. 접촉선 매핑의 수학적 통과도 최종 화면 검수를 대체하지 않는다.

### A05. 화면마다 직선 비율을 강제해 자연성을 손상
- 발견: 같은 전술 평면 두 개가 전체윤곽27.65%, 모바일crop43.36%로 바뀌었다. 확대 배율에도 물리 구간이 달라져 같은 곡률이 다르게 판정됐다.

### A06. 공통 얕은 발판을 긴 지형 몸체로 늘림

### A07. 한방향 발판에 두꺼운 바위를 씌움

- 금지: 캐릭터를 앞에 그려 관통을 숨기거나, 기존 바위를 조금 더 잘라 억지 재사용하지 않는다.

- 정량: 재질 변경으로 직선 비율을 꾸미지 않는다. 자연/목재/모든 고유 보행선 값을 함께 공개한다. 현재 R2 natural37.368%는 실패 상태로 보존한다.

### A15. 주술사 조준 예측이 아군을 무시하는 불일치 (2026-10-31)
- 실패: 예측은 SOUL_SKILLS의 모든 아군을 제외했지만 실제 직접 조준 원탄은 아군과 충돌했다. 테스트 정책은 적 명중을 기대하며 같은 아군에게 반복 피해를 줬다.
- 절차: 예측의 무조건 아군 제외를 제거하고 실제 원탄 충돌 정책을 따른다. 자동 자탄·소환물의 기존 아군 보호는 그대로 둔다. 승률을 높이기 위해 실탄 아군 피해 규칙을 바꾸지 않는다.

### A14. 긴 추적 복합 경로의 색면·구멍 손상 (2026-10-31)
- 실패: 안전 길이에 맞추려고 색별 복합 경로를 Boolean 절단하면서 벽면에 사선 구멍이나 잘못된 채움이 생겼다. 성공 반환이나 path 수 감소만으로 원본 보존을 판단할 수 없다.
- 절차: 원본 색면 순서·fillRule·상위 clip을 보존한다. 긴 복합 경로는 제한된 `dParts`로 저장하되 렌더 때 하나의 Path2D와 한 번의 fill로 결합한다. 상대 moveto 및 내부 구멍을 독립 경로로 채우지 않는다. `tools/vector-production/preserve-compound.mjs`를 사용한다.
- 한도: 파트32개/파트60,000자/복합240,000자/숫자120,000개/자산 복합 합계4MB. 단일 하위 경로가 한도를 넘으면 시각 오차를 측정해 원본을 단순화하며 한도를 무제한 해제하지 않는다.
- 검증: `tests/vector-compound-parts.mjs`, `tests/vector-symbols.mjs`, `tests/vector-clip-seams.mjs`. 전체 원본/변환본 RGBA 비교와 실제 게임 배율 화면을 별도로 확인한다. 중첩 alpha/부분 clip은 렌더 백엔드별 실제 결과를 확인하며, 색면 자체의 무차별 Boolean 재시도는 금지한다.

### A16. 도달 직후 불필요한 자동 점프 (2026-10-31)

### A17. 승인된 지형 컷아웃을 전체 게임 환경으로 착각 (2026-10-31)
- 실패: 플레이 지형 벡터만 배치하고 아래 지반·해저·좌우 연장을 생략해 지형 덩어리가 공중에 뜬 것처럼 보였다. 유한한 배경 조각을 뒤에 붙이는 것만으로는 조각의 직각 끝선이 사라지지 않았다.
- 절차: 기존 플레이 BODY/충돌을 보존하면서 비플레이 환경의 연결 지질을 별도 저작한다. 생성 전에 실제 `HonroBounds.focus/zoomLimits`로 최소 줌·수동 pan·세로/가로 viewport의 외곽을 계산해 레이아웃 가이드에 넣는다. 줌 축소·카메라 제한으로 부족한 미술을 감추지 않는다.
- 연결: 새로운 해안이 지반/해저로 실제 이어지도록 그린다. 넓은 연속 지질이 필요한 경우 조각의 사각 경계를 반복 봉합하지 말고 새 환경층을 하나의 연결된 그림으로 수선한 뒤 Inkscape로 추적한다. 기존 플레이 스켈레톤을 다시 생성하지 않는다.
- 깊이: 물 시각은 viewport 끝까지 연속되게 하되 색과 깊이 안개는 world-depth에 고정한다. 실제 연결 해저가 깊은 물로 흐려지는 것과, 지반 없이 단색 사각형/안개로만 가리는 것을 구분한다. 물리 수위·회복 정책·플레이 bounds는 시각 연장 때문에 바꾸지 않는다.
- 충돌: 비플레이 배경 암반이 배우와 겹치면 alpha 수치만으로 관통 판정하지 않고 동일 실제 이동 좌표/카메라의 전후 프레임을 비교한다. 같은 평면의 가짜 선반으로 보이면 자연스러운 해안 수로를 원본 그림에 설계한다. 직사각/물결 alpha 구멍, 반투명 바위, 숨은 collider로 봉합하지 않는다.
- 검증: 원본 시안/추적/전체·일반·최소 줌 양끝·모바일·낙하 프레임을 확인하고, 기존 지형/배우/이벤트 좌표의 불변과 새 자산의 collision 없음도 검사한다. 조수 스테이지에서는 최저·최고 수위 모두 노출 지형과 물리의 관계를 확인한다. 대표 viewport 검사를 모든 무제한 화면 크기 지원으로 확대 주장하지 않는다.
- 중복 레이어: BODY를 원본 전체로 바꾼 뒤 옛 하단 FORE를 그대로 두면 물 다음에 바위·모래가 다시 불투명하게 칠해져 수중 지반이 마른 스티커처럼 뜬다. 실제 배우 가림용 근경인지, FULL BODY와 중복인지를 같은 카메라의 물 전/후 순서로 비교한다. 중복만 제거하고 원본 지질·충돌·배를 보존하며 미사용 벡터 자산도 함께 제거한다.
