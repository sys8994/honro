## 2. 클리어 모달 X
확인: shared/runtime/main.js open() 337행은 모든 모달에 data-action=close를 붙인다. outcome() 553~578행은 done=true, 보상/진행 저장 후 result 모달을 띄운다. close() 338행 및 close 액션 956행은 창만 지운다. 이미 done인 전투에는 결과 창을 재생성할 경로가 없어 사용자가 보고한 막힘과 일치한다.

수정:
- 결과 모달의 닫기 동작은 result-continue와 동일한 단일 함수로 연결한다. 승리/패배/커스텀맵/분할 캠페인의 기존 다음 행선지를 그대로 사용한다.
- X, Escape, 배경 닫기가 허용된 경로를 같은 정책으로 통일한다. 단순히 X만 숨겨 Escape 구멍을 남기지 않는다.
- 보상 지급은 outcome에 두고 닫기에서는 다시 지급하지 않는다. 연속 클릭으로 이동/보상이 중복되지 않도록 한다.
최소 확인: 승리 X/Escape, 패배 X, 두 번 누르기. 전체 캠페인 완주 불필요.

## 4. 스킬 미리보기 전수 코드 조사

### 공통 확인
실제 경로는 shared/runtime/main.js talent → HonroUI.talent → shared/engine/src/campUI.ts → shared/runtime/skill-preview.js다. shared/engine/src/main.ts에도 별도 과거 preview 구현이 있지만 지금 HonroApp의 주 경로로 오인하지 않는다.
- setup은 기본기+선택 스킬만 남긴 격리 연습 전투를 만든다. 다른 패시브·기예와의 합성은 보여주지 않는다. 이것을 현재 실전 빌드의 정량 데미지 시연으로 설명하면 안 된다.
- 표적은 기본적으로 모두 지상 hound, HP2400, fixed=true이며 일반 지형은 파괴 불가 바닥뿐이다. 반사 두 기술만 벽이 추가된다.
- tick은 phase가 transition/enemy이면 Engine.tick 대신 stepUnits+tickRedesign만 호출한다. 실제 switchTeam/enemyAction은 진행되지 않는다. 유인·덫·적대전이·다음 턴 지속 효과에 필요한 사건이 빠진다.
- summon phase는 정상 Engine.tick을 거치므로 모든 소환수가 전혀 행동하지 않는다고 단정하면 안 된다. 다만 먹귀의 수명 만료/포획 후 공격 등은 별도 장면이 없다.
- 7초/11초 고정 리셋은 실제 완료 조건을 모른다. 기예별 핵심 동작이 끝난 후 짧은 여백을 두고 반복하되 무한 대기 상한만 남긴다.
- 카메라는 units/일부 projectile/skillGeometry만 본다. 자탄·필드·진목·벽 및 지속 효과는 시야 후보에서 빠질 수 있다.

### 구현 원칙
실제 Engine의 피해·충돌·소환·회복 함수를 재사용한다. preview를 위해 게임 엔진 수치를 바꾸지 않는다. 작은 시나리오 정의로 지형/아군/적/발사/후속 행동/완료 조건을 지정한다. 일반 단발은 공용 시나리오를 재사용한다. 적 턴을 영구 정지하는 대신 필요한 적 한 명의 짧은 행동만 진행한다. 프리뷰 전투는 저장/보상/경험치/실제 프로필에 영향을 주지 않는다.

## 5. 모달 휠·스크롤·버튼
확인:

- campUI.ts talentView 52행의 장착/강화 actions가 효과표 밑에 있다.

수정:
- 상세 모달의 상단에 제목+액션을 묶는다. 닫기와 겹치지 않게 하고 모바일에서는 필요한 만큼 줄바꿈한다.

- 사용자의 '빼기'가 SP 회수인지 장착 해제인지 확인 질문 중이다. 답변을 우선한다. 현재 구현자가 장착 해제로 단정하지 않는다.
- 장착 해제까지 한다면 sanitizeLoadout의 자동 채우기를 반드시 고려한다. shared/engine/src/progression.ts sanitizeLoadout은 빈자리에 아는 스킬을 다시 채운다. 단순 splice만으로는 새로고침/다른 조작 후 다시 장착될 수 있다. 명시적 빈 슬롯/사용자 선택 의도를 저장하는 최소 호환 설계를 해야 한다. 기본기는 제거하지 않는다.
- 장착/SP 버튼 조작에서는 가능한 부분 DOM만 갱신한다. 전체 갱신이 필요해도 같은 dialog scrollTop, armory scrollTop, 선택 스킬, 포커스를 저장·복원하고 preview를 불필요하게 재시작하지 않는다.
- 표 위·설명 위·빈 여백 어디서든 같은 모달이 스크롤되게 한다. 중첩 scroll trap/불필요한 preventDefault를 만들지 않는다. 단순 onwheel 수동 scrollTop 우회부터 추가하지 않는다.
최소 확인: 표 위 wheel, 스크롤 아래에서 +/−·장착 후 같은 위치, 모바일 세로 버튼 접근. 다른 HUD/전투 전체검사 금지.

## 7. 응수세·검막·호혼령 기획
확인:
- warriorData.ts: S08 응수세는 검술 계열 counterStance, S14 검막은 검기 계열 bladeScreen.
- warriorMechanics.ts: 응수세는 현재 HP2~5.5% 회복, 20~30% 감소, 적 턴에 전방 가까운 적에 1회 반격. 검막은 전면을 지나는 투사체만 50~70% 감소시키고 다음 검기에 축적.
- engine.ts stepSummonTurn의 warden 분기는 방호와 혼 속성 보너스만 준다. HP/기력 회복은 없다.
- spBalanceModel.ts는 현대 액티브 전체의 완성된 정량 모델이 아님을 명시한다. legacy score 하나만으로 '균형 완료'라고 결론내리지 않는다.

제안 기본안:
- 응수세를 유일한 방어/반격 스킬로 남긴다. 낮은 단순 회복 추가보다 '버티며 맞아도 실제 반격 기회가 생김'을 개선한다. 지속 창/반격 조건/사거리의 현재 한계를 먼저 수치로 비교하고, 무조건 모든 방향 무적이나 자동 다회 반격은 피한다.
- 검막 S14는 검기 계열 공격으로 대체한다. 가칭 '파열참': 검기가 첫 적 또는 지형에 닿을 때 짧은 횡방향 검압을 펼쳐 근접 군집을 공격한다. 단일 월영참·직선 관통참·공전 회륜검기와 역할을 나눈다. 벽을 무시한 광역 피해가 되지 않도록 차폐를 따른다. 저장된 S14 SP/슬롯은 같은 ID로 보존하며 옛 투사체/상태의 처리만 호환한다.
- 호혼령은 기존 방호에 범위 내 동행의 HP·기력 회복을 더한다. 같은 동행/소환귀 행동당 1회, 최대치 초과 회복 없음, 실제 회복량만 기여 경험치로 기록한다. 무한 중첩 회복/소환 반복 경험치 농사를 막는다.
- 수치는 구현 직전에 기존 비용·턴·범위·실제 유효 대상 수를 넣은 간단한 계산으로 결정한다. 방호+회복+혼 보너스를 각각 전부 최대 효용으로 합산하지 않는다. 3/8/12턴의 기존 SP 시나리오와 피해 방지/실제 회복/행동 기회 축으로 비교한다.
최소 확인: 방어1회/반격1회, 대체 공격의 충돌/범위, 호혼령의 실제 HP·기력 회복과 상한만.

## 8. 회귀망령 O05
확인: data.ts의 O05는 phase=all,fuse1.45. engine.ts phaseSweepDamage는 outbound .42 / return .78이며 fuse 만료 시 속도를 뒤집고 hit를 비운다. 지형 정지나 실제 지나온 궤적 역재생이 아니다.

수정:
- outbound는 적 관통·약한 1차 피해, 지형에는 swept collision으로 멈춘다. 해당 발사에 맞은 적 ID를 별도 기록한다.
- 멈춘 지점에서 망령 출현 연출을 보이고, 기록한 실제 궤적을 역순으로 따라간다. 단순 vx 부호 반전이나 현재 소단 좌표 직선 유도와 혼동하지 않는다.
- 귀환 중 첫 유효 적과 만나면 폭발한다. 1차 피해 기록이 있는 적에는 폭발 피해 보너스를 준다. 직접 피해+폭발 중복 적용이 의도 없이 생기지 않도록 한 번만 집계한다.
- 기록은 발사별로 독립. 반향령 복제 시 path/hit 배열을 공유하지 않는다. 귀환 도중 시전자가 이동했어도 기록된 발사 시작점까지 돌아가 소멸하는 안을 기본으로 한다.
- 지형 미접촉이면 최대 비행시간/월드 경계에서 안전하게 종료한다. 무한 비행/배열 증가 금지. 궤적은 거리 기준 표본+보간으로 충분하고 모든 physics frame을 무제한 저장하지 않는다.
- 1차 피해 몬스터가 사망/포획/전향했을 때 표식을 피해로 잘못 재사용하지 않는다. 저장/이어하기는 비행 단계·경로·cursor·표적 기록을 보존한다.
- 예산은 1차 소피해+귀환 적중 확률+폭발 유효 대상+표식 보너스를 합쳐 비교한다. 왕복이 반드시 모두 적중한다고 가정해 과하게 너프하지 않는다.
최소 확인: 적 관통 후 벽 정지→역경로 첫 적 폭발, 미표식/표식 피해 차이, 벽 미접촉 종료, 반향 복제의 독립 상태.

## 보고와 완료
각 변경의 실제 수정 파일·커밋·최소 확인 결과만 짧게 보고한다. 사전 기획 문서를 코드 구현 완료로 표시하지 않는다. 관련 수정이 끝난 뒤 기존 분리 빌드로 생성하고 원격 master와 Pages를 확인한다. 공개 브라우저 검수가 차단되면 이를 미완료로 명시한다.
