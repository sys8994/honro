## 29장 변경 카드

`r29-high-road`의 x=4550–5550은 평면이며 rear 난간은 그림이므로 탄을 막는 실체 엄폐가 없다. 기존 동일 polygon의 윗면을 높이 95의 석제 정비 받침으로 sculpt하여 사선과 위치 선점에 영향을 주도록 한다. 별도 겹친 solid를 추가하지 않는다.

변경 구간의 top 좌표:

```text
[4550,1840], [5130,1840], [5205,1745], [5290,1745],
[5385,1840], [5550,1840], [6100,2190], [6500,2190]
```

underside·지하 점검교·출구·맵 규모는 유지한다. 위에 있던 사수 하나는 발 Y만 새 표면에 맞춘다. 적 총 27/정예 7, 전력·XP, 유한 증원, 목표·이벤트·대사와 ID는 보존한다. 기존 상하 탈출 선택이나 참가 동행을 새로 설계하지 않는다.

29장 campaign map revision만 `1→2`로 올리고 기존 저장 계약을 사용한다. 이전 revision의 진행 중 전투는 해당 장 입구에서 재시작하며 성장·SP·장착·캠페인 진도는 보존한다. 다른 장 revision이나 공통 저장 정책은 변경하지 않는다.

## 확인 근거와 남은 범위

사전 실제 물리 확인: 29장 낮은 점검교 지붕 y=2560에는 바닥 y=2760에서 모든 기본 몸이 기본 점프로 착지했다(상승 213.6). 이 길은 추가 발판 없이 보존한다. 이는 새 상층 받침의 이동 검수 결과와 구분한다.

실제 Engine 실탄 확인: 담허 M01을 `(5000,1840)`, angle=0, power=1로 발사하면 변경 전 `a3-29-dark-lock-approach-4`에 130 피해, 변경 후 받침에 막혀 0 피해였다. 받침 위 `(5230,1745)`에서 angle=-15.53, power=0.592로 발사하여 같은 적에게 148 피해를 주었다. 시작 위치·단독 적·앞 목표 완료는 명시 fixture이며 정상 전투 완주 증거가 아니다.

`node tests/stage29-service-cover.mjs` 통과: 변경 구간 왕복 기본 보행(점프0·피해0), 이어지는 기존 상층 출구까지 실제 이동 후 A 선택, 목표·이벤트·대사·퇴로·다른 장 원본 보존, 기존 revision1 전투 폐기 후 29장 revision2 재생성 및 성장·장착·완료 기록 보존을 확인했다. 저장 확인은 기존 revision 계약을 직접 호출한 것이며 앱 UI/저장 재개 전체 검사가 아니다. 공통 `app-regression-helpers.mjs`는 최신 시작 코드에서 기존 App hook을 찾지 못해 실행되지 않았으며 무관한 로더/앱 수리는 하지 않았다. 필요한 빌드 성공 후 production Chromium으로 이를 보완했다. 29장 진입·수정 사수의 저작 좌표/몸 접점·받침 횡단과 실제 localStorage revision1 기록의 새로고침→전투 폐기→Continue→29장 입구 revision2 재시작을 통과했으며 성장·장착·완료 기록이 유지되고 pageerror는 없었다.

동일한 현재 공통 Native Scene·카메라 `(5200,2200,0.6)`로 전후를 캡처하고 이미지와 렌더의 전투 상태 불변을 확인했다. 새 받침과 지지 사수의 높이 변화가 보이며 하층은 동일하다.
