## G1. 진행 구조와 실제 엔진 뼈대
- 이미지 전에 시작점·필수 경로·선택 경로·재합류·상호작용·실패/복귀를 스켈레톤에 표시한다. 정상 이동·점프·낙하·이동 예산으로 필수 목적이 가능한지, 특수기는 필수로 가르친 경우를 제외하면 지름길/전술 대안으로 작동하는지 먼저 실제 공통 엔진에 올려 확인한다. 줄곧 평평한 횡단로, 장식뿐인 상하 층, 공중에 뜬 비의도 발판을 탈락시킨다.

- 무명사 외부는 정상 장소에 내부 붕괴가 조금씩 새어 나오다가 피날레에서 압도한다. 내부는 거리·연결·내외부·규모·중력 중 장별 지배 원리를 달리하고 단순 상하 반전을 반복하지 않는다. 장소별 실루엣·팔레트·여백을 구분한다. 플레이어는 이상 현상과 실제 안전 발판을 혼동하지 않아야 한다. 피날레의 전장 규모·연결 진과 역할, 방어 압박은 원본의 인과와 장 순서를 보존한다. 무한 적 섬멸을 승리 조건으로 쓰지 않는다.

### G1-A. 맵 규모·구성 탈락 기준 (시안 생성 전에 통과)
- **너무 작거나 단순한 맵은 탈락**이다. 접지 검사·승리 가능 여부·완성된 미술로 이 관문을 대체할 수 없다. 전투·이동 장은 최소 3개의 실제 지리 구역을 기본으로 설계하며, 각 구역에 다른 랜드마크와 행동/사선/위험을 준다. 짧은 종결 씬처럼 원기획이 비전투인 장은 맵을 억지로 늘리지 않고, 화면 여러 구획에서 서사·공간 변화가 읽히는지를 별도로 검증한다. 한 방이 최종 보스전인 경우도 위협과 대응이 달라지는 교전 구획을 확보한다.
- 같은 축으로 쭉 가면 끝, 그냥 평지/유사 플랫폼 반복, 상하가 보이기만 하고 서로 갈 수 없음, 같은 경로를 높이만 바꿔 복제, 끝난 길을 오래 걷게 해서만 커 보이는 설계는 반려한다. 전투/횡단 장에는 적어도 한 번의 실질적 분기·재합류 또는 역할이 바뀌는 대체 진입을 보여준다. 내려갔다가 복귀할 수 있는지와 우회가 주 경로와 다른 전술을 만드는지를 확인한다.
- 장별 목적에 맞춰 **동일 유형의 실제 후반 기존 장**과 견준다(6-1 외부 산악은 5막 후반, 외부 방어전은 4막 후반과 5막 외부도 비교). Play Bounds 폭×높이, 대표 합법 루트 길이·고도차·이동 횟수, 전체 지리/구역 수, 분기·재합류, 사선 변화 수, 카메라 1배에서 실제 화면 몇 개를 사용하는지 기록한다. 비플레이 외곽·원경·빈 공동의 픽셀로 크기를 보충하지 않는다. 근거 없는 월드 단위나 공통 배수는 합격선으로 쓰지 않되, 비교군보다 작으면 기획적 이유와 정상 플레이 증거를 남긴다.
- 최대 줌아웃에 전체 구조 하나, 정상 배율로 각 구역과 분기/합류 캡처, 실제 상·하/내외 이동·지형 사용 로그로 PASS를 남긴다. 국소 경로 테스트는 그 구간의 물리만 입증하며 장의 규모·구성 통과로 기록하지 않는다.

### 시안 화풍 기준: A / 각진 암반 면 및 중간 밀도 (2026-11-24 사용자 선택)
- 6막 전경 암반의 화풍은 A안을 기준으로 한다. **정리하는 것은 질감이지 지형 구조가 아니다.** 먼저 검증한 여러 구역, 실질적 분기·재합류, 외곽 범위와 지형의 거시 곡선을 유지한다. A의 한 구간 암반 그림은 조형 참고이며 원본 지리나 맵 전체를 대신하지 않는다.
- 표준 프롬프트에 덧붙일 고정 문구: “실루엣 안에 서로 맞물리는 비대칭 큰·중간 각진 암반 면을 배치한다. 암반 벌크는 불투명한 닫힌 색면으로 만들되 큰 주 암판 안쪽과 사이에 방향성 있는 층리, 중간 크기 쐐기 암면과 끊어진 균열을 배치한다. 벌크 중·하부에도 실제 지질 구조가 보여야 한다. 접지 윤곽·재질 접합부의 작은 결은 국소적으로 남기고 중간 암판군을 거쳐 큰 면으로 자연스럽게 이어준다. 전체 면을 같은 세밀도로 채우지 않고 조용한 큰 암면과 구조가 모이는 부분을 함께 둔다. 지질의 큰 흐름은 유기적이되 내부 면은 각진다. 등간격 삼각 메시, 반복 세밀 모자이크, 사진 질감, 그라디언트·광륜·그림자 번짐, 페인트 가장자리의 잔색, 조감·상면 노출은 사용하지 않는다. 원경 및 안개는 지형과 분리한다.”
- **밀도 기본값: 1안.** 대·중간 면을 암체의 일차·이차 절면으로 읽히게 한다. 2안처럼 조밀한 층리와 광맥은 크게 드러나는 협곡·단층부에서만 부분 적용하고, 암판과 이음 방향을 따른다. 둘레·깊은 벌크 일부는 조용하게 남긴다. 화풍 적용 진행 승인과 장 전체 미술 합격은 구분한다.
- **벌크 디테일 과소도 반려**한다. 낮은 대비의 넓은 면이 본체 대부분에 반복되거나, 작은 결이 접지 윤곽에만 있고 비윤곽 중·하부 두 곳 이상에서 층리/암판의 방향이 정상 배율에 읽히지 않으면 반려한다. 1막 1·2장과 같은 카메라/배율에서, 본체의 대표 3구간(중앙과 사면 둘)을 내·외곽으로 나눠 읽는다. 작은 요철·기하를 임의로 채우지 말고 대·중·소 세 크기 역할을 각각 확인한다. 최적화 시 시안의 층리·중간 분절 실루엣을 보호하고, 비용 문제는 먼저 중복·오프스크린 렌더·타일·잔노이즈를 분리 측정한다. 디테일 보강으로 이어지는 밝은 광맥이 보행선처럼 읽히거나 배경 시선을 빼앗으면 명암을 낮춘다.

## G3. Inkscape 본체, 외곽, 충돌
1. 검토한 시안을 의미 단위로 Inkscape에서 벡터화·편집한다. 시안 전체 자동 추적과 자유형 난수 폴리곤 금지. 색별 compound path 수만으로 가벼움을 주장하지 않는다. 원본·작업 SVG·배포 생성물 분리.
2. **상하좌우와 네 모서리 접합부터 닫는다.** 새 Map v6는 하나의 확장 지리 도메인 안에 Play Bounds를 둔다. “더미”는 이 도메인 안의 비플레이 연장 영역이지 별도 직사각형 스커트가 아니다. 기존 body 밖 지층과 암벽 무늬·톤·기울기·수목 수관이 이어지는지 실제 최대 줌아웃/카메라 극단에서 본다. 원경과 전경을 잘못 이어 붙이거나, 줌/카메라를 가려 오류를 숨기지 않는다. 바람길·부유체·열린 계곡은 의도와 증거가 있으면 비워둔다.
3. 공통 엔진이 동일 지리에서 충돌을 투영한다. 시각 보행면을 살피고 발끝·경사·계단·교량·낙하/착지·일방통과·사다리·상하층·동적 상태를 대조한다. 정상 HUD에서 디버그 윤곽과 블러 다중 띠는 없어야 한다. 실제 몸, 발사와 예측, 높은/낮은 사선을 양방향 확인한다. 정합 오버레이는 별도 QA 컷에서만 켠다. 위치 강제나 준비된 성공 결과는 정상 클리어 증거가 아니다.

### G3-A. 계단의 정측면과 한 벌의 경계 (2026-11-24 추가)
- 정면에 보이는 계단을 보행 가능으로 추정하지 않는다. 실제 진행 방향과 함께 높이가 바뀌는 단면을 저작해 입구·끝·받침·이어지는 마루를 드러낸다. 정면 장식이나 멀리 있는 창살·난간은 비충돌 층으로 빼고 발판과 같은 대비를 피한다.
- 이동면 시각 좌표와 충돌 좌표는 같은 원본에서 생성한다. 계단 그래픽을 촘촘히 넣어도 엔진에 완만한 경사선을 사용한다면 발 위치 오차를 실제 이동으로 재고 증거를 남긴다. 상승·하강·양 끝·머리 여유·가로 중력 상태를 정상 HUD 및 QA 오버레이로 각각 대조한다. 좌표만 그린 오버레이는 실제 움직임의 증거가 아니다.
- 6장 V5의 A–E 구성과 하단·우측 이탈구는 보존한다. 회랑/계단의 정면 표현만 고쳐 불필요한 시안 재생성이나 맵 축척 확대를 하지 않는다. 열린 이탈구의 밀폐를 외곽 연속성 개선으로 간주하지 않는다.

## G4. 외곽 확정 뒤 벡터 비용 절감
- 활성 자산의 좌표·transform·clip 적용 후 실제 채운 벌크 합집합 면적을 월드 단위 제곱으로 계측한다. 공동·하늘·원경·UI·캐릭터를 분모에서 제외하고 겹치는 채움 면적은 한 번, 렌더에 제출한 노드/경로는 각각 센다. 본체/외곽/윤곽·장식과 경로·닫힌 폴리곤·앵커·제어점 정의를 따로 기록. alpha 1/128 기준 및 1×/½× 민감도 또는 의미상 같은 재현 프로토콜을 기재한다.
- 같은 방식의 기존 1-1은 5,721 / 4,726,434 WU² ≈ 1,210 노드/M WU², 1-2는 4,239 / 2,225,080 ≈ 1,905. 미술·비용 비교용 경고 범위이지 기계적으로 맞출 노드 제한이 아니다. 컴파운드 수와 노드·폴리곤 수를 혼동하지 않는다. 원본/배포/전송 bytes, 동일 장면 cold/warm p95 프레임/렌더, 정규 확대에서 외곽 오차 및 주요 샘플을 전후 같이 기록한다.
- 벌크의 노이즈·겹침·불필요한 거의 공선 점부터 크게 줄인다. 윤곽의 세밀한 그레인, 얇은 지지부, 접지선과 모든 모서리·의도된 틈, tone transition은 보존한다. 반투명 블러 외곽의 색별 중첩을 제거하거나 하드 에지 재저작한다. 구조별 허용 오차를 먼저 정하고 여러 강도의 후보 비교 후, 검수를 통과하는 가장 가벼운 것을 고른다. %만 낮추거나 시각 비교 없이 노드를 목표 수치로 맞추지 않는다.

## G5. 교전·목표·대사
- 수량/종/라운드는 레퍼런스이지 할당량이 아니다. 장소 의미가 있는 복수의 비대칭 군집 또는 이유 있는 단독 배치. 한쪽 몰빵, 등간격, 정예 이름만 다른 동일 역할 금지. 앵커, 역할, 사선·엄폐·빈 구간, 적 종류와 행태 대비, 실제 첫 조우 시점, 활성/동시 행동 상한, 유한 증원을 기록한다. 끝없는 인상은 파동 연출과 압박으로; 공략 목표는 원문 인과와 일치해야 한다.
- 큰 적의 공간·카메라·몸 크기·약점을 함께 확인한다. 크기/색조 변주는 이유를 데이터에 남기고, 작은 적도 작은 이유가 있어야 한다. 약점이 있다면 실제 히트와 연동하고 사전 지식이 있는 인물만 미리 말한다. 모르면 막힌 몇 번의 실제 몸통 피격 뒤 대상의 행동과 눈에 보이는 단서로 자연스럽게 추론하고 성공한 첫 약점 명중때만 짧게 확인한다. 출구·호송·목표·사선이 큰 몸에 막히면 먼저 자리와 동선을 조정한다. 기존 리그를 쓰며 새 캐릭터/몬스터 그림 금지.
- 필수 대사 건너뜀/다시보기 여부, 인과 전달, 전투 안내 타이밍, 주·선택 이벤트 성립 순서, 실패 회복과 보상 중복, 저장 후 재시작을 시험한다. 파티 분할/재합류 및 귀중한 서사 장치는 일반 땜질로 변형하지 않는다. 5막 50장→산문/저장과 연결은 실제 6막 진입·후속 보존이 검증된 릴리스 범위에서만 변경한다.

## G6. 각 장마다 전체 검수표, 지형 5회 이상
기준선은 0회다. 다섯 회 모두 G1~G4의 지형 체크리스트(구조, 외곽, 접촉, 가독성, 비용, 등록 스코프)를 돈다. 아래는 매 회 특화 초점이지 체크를 나눠 한 번씩 한다는 뜻이 아니다. 실제 결함/가설/변경 또는 새 검증 조건과 증거를 남기며 재내보내기·동일 사진 복제는 회차가 아니다.
1. 구조·등록: 실행 원본/packet/레이어·맞춤 조건 A/A, PC 전체 실루엣과 플레이 경로.
2. 디테일·접합: PC 정상·최대 줌아웃·클로즈업, 4변/4모서리, 같은 재질과 윤곽, 레퍼런스 대비.
3. 화면·상태: 1440×900 PC, 390×844 모바일 및 필요한 모바일 가로폭, 극단 카메라, 실제 동적/이상 상태, 얇은 타일·전송·복귀.
4. 접촉·비용 회귀: 이동/중력 착지·발사 실측, 필요한 실제 충돌 오버레이, 이전 빌드의 정상 HUD와 비교, 대비·오차·비용 대조, 이전 저장과 다른 장 보호.
5. 통합 소스 종합: 같은 브라우저 렌더러의 정확한 최종 빌드에서 독립 재검. 빌드 이전 증거로 최종 통과 판정 금지.
- 별도 전투 검수: 정상 성장/장비의 실제 기본·보조·특수 조작으로 입장부터 승리, 정산, 다음 장/저장까지. 대표 합법 경로와 실패·복귀를 확인. 경로별 시드·난이도·파티·스킬·장비·정말 사용한 이동/턴/아군·적 라운드·실시간·피해·추가 적·클리어 조건을 기록. 준비 상태, 봇 스모크, 사람 동등 법적 입력 실플레이를 분리. 같은 지점 두 번 막히면 처음부터 반복하지 말고 로그/좌표에서 원인 분리 후 수정. 목표 미달·재현 실패는 남긴다.
- 최소 필수 기반: 공통 빌드, stage own tests와 `test:terrain-domain`, `test:terrain-readability`, `test:ground-contact`, `test:camera`, `test:objective-clarity`, `test:campaign-contracts`, `test:current-story-display` 또는 동등한 동일 경로 증거; 적용된 일방통과·저장·대사·증원·성능 검사 추가. 무관한 전체 검증을 기계적으로 반복하지 않는다는 뜻이지 이 장의 항목을 생략하라는 뜻이 아니다.
- 증거 행 스키마: 장/내부 ID, 자산 소유자, source SHA와 build/packet SHA, 회차·gate·이전/변경 값, 상태/시드/뷰포트/DPR/줌/좌표, 실제 결과와 캡처 링크, PASS/FAIL/BLOCKED/N-A(근거 필수), 발견 결함/재검 범위. 장별 최종 판정은 모든 필수 gate PASS와 실제 스크린샷. 미감은 실제 화면과 대비를 보이고 승인 여부를 취향 기록에 남긴다.

## G7. 통합·배포·보고
- 장/파일 소유권 분리. 설계·시안·검증 독립 병렬, 같은 파일에 한 작성자. 수정 단위 원격 커밋. master 최신/차이 검토, 강제 push 금지, 기존 클라이언트 늦은 로딩 자산을 보존. `HONRO.html`, `HONRO_WORKSHOP.html`, `web/`은 빌드 생성물로만 갱신.
- 해당 장 검수가 끝나기 전에는 준비·브랜치·엔진 렌더·검수와 공개 배포를 구분한다. 실제 나갈 통합 SHA에서 확인 후 기존 Pages, 링크/실제 동작/저장·이전 전환을 직접 읽는다. 앞서 끝난 장이 있어도 미완성 장으로 법적 동선을 열어두지 않는다. 배포 후 기존 이력과 동일한 장 빠른 회귀. 문제는 되돌릴 단위와 손실을 기록한다.
- 30분마다 감독자가 각 레인의 실제 파일·상태 확인, 숫자와 스크린샷/재현 제공, 장애 분리 및 직접 재개. 검증 전 수치 꾸미기 금지. 전체 완료 및 보고 또는 사용자의 중지 때 종료.
