# 일반 쉼터에서 시작한 6막 연속 플레이

일반 쉼터에서 6-1을 연 다음 같은 Chromium 탭에서 실제 키와 버튼으로 진행한다. 새 컨텍스트는 방금 작성된 경계를 다시 열어 비교하는 용도로만 사용한다. 진행 중인 탭의 기록은 갈아끼우지 않는다.

첫 PC 판은 51→52→53→54→55를 이어갔다. 각 실제 경계를 검증하고 원래 일반 저장도 바이트 단위로 비교했다. 53과 54의 실제 혼 O06, B와 C를 통과했다. 55에서는 온전한 결속 전략을 시도했으나 실제 피격으로 결속이 약화됐다. 해당 전략의 검수를 실패로 남겼다. 이어가는 새 판은 복구 전략을 쓴다. [첫 판 로그](intact-first.json) · [실제 실패 화면](intact-bell.webp)

```bash
npm run build
python game/docs/act6/mumyeongsa-p00-p10/baseline/continuous.py --build "$PWD" --out /tmp/honro-act6-intact --engage-bell
python game/docs/act6/mumyeongsa-p00-p10/baseline/continuous.py --build "$PWD" --out /tmp/honro-act6-repair --engage-bell --bell-case repair
```

같은 쉼터에서 새로 시작한 복구 판은 실제 55 결속을 수리해 56까지 라이브로 열었다. C를 걸어 원래 (928,1136) 난간에 착지했다. 이후 검수기가 구판의 원본 적 3명만 예상해 중단됐다. 원본 3명의 ID와 발점을 계속 엄격히 확인하고, 승인된 신규 시작 적 2명의 ID와 발점도 명시했다. 이후 장을 이 판의 결과에 포함하지 않았다. [중단 기록](repair-first.json)

별도 한 탭은 52에서 종터 교전을 마친 뒤 넉백 때문에 담허 발점이 출발 조건의 높이에서 벗어났다. 검수기에 실제 담허 작업 지점 x4480 재접근을 추가했다. 다음 판은 54에서 M09 충전이 예정값을 지나 사격이 성사되지 않아 멈췄다. 실제 발사 버튼을 놓기 전 현재 충전값에서 기존 반경·지지면을 다시 예측하고, 실패 때 소유자가 승인한 실제 사격만 재시도하도록 검수기를 보강했다. 새 한 탭에서 51→52→53→54→55의 연속 저장 해시를 확보했고 55 복구를 진행했다. [55 도달 시점 기록](through-55.json)

같은 탭에서 실제 55 HLN01과 고정 소단의 복구를 거쳐 56을 열었다. C 수신 뒤 원래 난간·역류 대피를 통과하고 새 실내 D를 걸어 57에 도달했다. 51→57 여섯 번의 실제 경계 해시와 일반 원본 저장 보존, 56·57의 별도 재로드를 기록했다. 이 시점은 57 진행 중이다. [연속 57 인계와 출발 자료](through-57.json) · [57 라이브 화면](warm-57.webp)

57까지 간 판은 재합류 때 휘겸이 돌단의 설오에게 막혔다. 휘겸은 (5424.662, 2988.497)에서 이미 담허와 140 world px 안에 있었는데 검수기가 x5385 도착만 요구했다. 검수기는 이제 원본 57 경계 정의를 읽어 각 배우의 거리와 접힐 지형에 대한 발점 유효성을 함께 확인한다. 독립 실제 입력 판이 이 조건으로 네 배우를 58에 보냈다. [발점·라이브·새 저장](../hall-d/reunion-native-57.json)

후속 한 탭의 첫 중단은 52였다. 소단이 x3660.301에 서 있었으나 위의 `landing-1`과 같은 x의 아래 `landing-3`에 내려왔다. 단일 연속 판은 실측 발점이 더 낮은 기존 발판이면 그 아래부터 계속하며 지난 발판을 통과한 것으로 기록하지 않는다. 별도의 52 전수 발판 판은 여전히 네 배우 각각에 대해 다섯 단과 출구를 요구한다. [연속 52 중단](lower-shelf-first.json) · [발점 화면](lower-shelf-first.webp)

다음 같은 탭은 낮은 단에서 계속해 57까지 6개 서명을 남겼다. 담허 옛 돌단에 뛰기 전 설오의 실제 발점이 `(5275.641,3041.766)`에서 더 왼쪽으로 움직이지 않았다. 기존 검사기의 x 목표 5260에서 15.64 world px 떨어져 도약을 시도하기 전에 멈췄다. 다음 검수는 이 발점도 도약 출발점으로 쓰고 실제 돌단 착지와 접힐 지형의 발점 검사는 동일하게 수행한다. [여섯 경계 해시와 첫 중단](ward-approach-first.json) · [중단 화면](ward-approach-first.webp)

다음 한 탭도 57까지 실제 경계를 남겼다. 돌단에 가기 전, 난간의 안전 범위 오른쪽 경계가 x3350인데 휘겸이 `(3342.897,3328.915)`에 서 있었다. 난간 경고 입력은 정상이며 두 번째 입력에서 게임이 붕괴를 거부했다. 다음 검수는 휘겸을 오른쪽 x3424 부근의 안전한 발점으로 직접 옮긴다. [원본 해시와 금지 구간](rail-clearance-first.json) · [난간 화면](rail-clearance-first.webp)

같은 보호 범위의 실제 발점 (3329.547,3324.699)에서 난간 개방을 다시 눌렀다. 휘겸을 안전한 발판으로 옮기라는 문구와 실제 바닥의 표시 (3424,3348.148)가 표시됐다. 이 입력에서는 난간의 체력이 그대로였다. 휘겸을 오른쪽 실제 발점 (3438.397,3341.216)까지 걸어서 다시 누르자 원래 난간 붕괴가 처리됐다. 이후 이 판은 돌단 합류를 통과하고 접힌 석교로 올라가는 휘겸의 별도 이동에서 멈췄다. [실제 발점·안내·거부·성공](rail-clearance-grounded.json) · [차단 화면](rail-clearance-blocked.webp) · [개방 화면](rail-clearance-safe.webp)

다음 연속 판은 실제 복구 뒤 56까지 같은 원본 바이트와 다섯 경계 해시를 기록했다. 56의 역류를 재현했고, 보통축 E에서 방어 후 다음 조작을 기다린 22초 한계에 걸렸다. 중단 화면에는 라운드 5의 담허가 E에 접지하고 입력 단계로 돌아와 있었다. 후속 실행은 방어 직전 상태와 좌표를 기록하며 실제 적 포격이 끝날 때까지 60초를 허용한다. [첫 중단과 다섯 경계](reflow-flight-first.json)

57 독립 정상 판은 휘겸이 돌단과 접힌 하단 앞을 실제로 다시 도약했다. 안전 난간과 곽진 관련 절차, 네 원본의 D 발접촉, 58 라이브와 새 일반 기록까지 확인했다. 57의 로스터는 7/17, 최대 활성/공격 9/6, 7라운드로 누적·라운드 하한은 남았다. [57 독립 원자료](../encounters/57-native-capped.json)

[연속 경계](relay-to-eave-first.json) · [실제 M09와 C 종점](relay-to-eave-witness.json)

후속 한 탭은 같은 쉼터에서 51을 시작해 58까지 연속 일곱 경계를 서명했다. 57에서 담허가 살아 있는 상태로 휘겸을 실제 (5301.771,3046.523)에 내려놓자 거리가 108.329로 줄었다. 설오 13.162, 소단 111.264와 함께 세 사람 모두 기존 140 범위와 접힐 지형의 발점 조건을 통과했다. 네 원본과 곽진 증거를 지킨 상태로 D에 닿고 실제 58을 열었다. 독립 새 컨텍스트에서 58을 다시 열어 동일 저장 바이트도 확인했다. 58 이후는 같은 진행 탭에서 계속한다.
