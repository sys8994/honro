# 54장 M09와 55·56장 저장 이음

[고정 원본 실패](../second-pass.md) · [브라우저 실측](observed.json) · [54장 타격](legacy54-m09.webp) · [55장 직접 진입](legacy54-live55.webp) · [빈 종터 완료](relay-stage55-outcome.webp) · [56장 직접 진입](relay-live56.webp)

고정 원본의 L 차트에서 M09를 실제 입력으로 발사하면 방사체의 중심과 새 진목이 y=2924에 남았다. 진목의 y를 y=2930으로 단정한 저장 검증이 `invalid-new-checkpoint`를 냈다. 수정 빌드에서 x=2311.28610963249의 타격과 진목 y=2924를 그대로 두고, 실측 반경 6과 법선 (0,−1)으로 같은 `mid-contact`의 49번 윗면 y=2930을 찾았다. live 55 수신은 같은 장의 진목 ID, 소유자, 발사 번호, 기예, 실제 위치와 지지면을 모두 확인했다. 기존 55장 기록의 면 위 y=2930 형식도 서명된 면에서만 받았다.

| 검수 | 결과 |
|---|---|
| 수정 빌드의 기존 54장 출발 기록 → N→L→C→L → 실제 M09 → 55장 live | PASS. 새 55장 기록은 세대 4였다. |
| 같은 브라우저의 빈 종터 전투 → 56장 live | PASS. 휘겸이 걸어가 빈 종터에 닿았고, 실제 HLN01에 결속이 풀렸다. 소단이 접지해서 다시 묶고, 설오와 소단의 포격으로 빈종각귀를 해소한 뒤 휘겸이 받침을 정렬했다. 새 56장 기록은 세대 5였다. |
| 새 55·56장 기록을 독립 브라우저 컨텍스트의 휴식 → 이어가기로 재로드 | PASS. 로드한 직후 각 저장 바이트가 이전과 같았다. |
| 55장 새 기록에서 지지 지형을 다른 면으로 바꾸거나 증인 기예를 M01로 바꾸고 외부 해시를 다시 계산 | PASS. 두 복제 기록 모두 거부했고 전투를 열거나 저장을 고치지 않았다. |
| 54·55·56장 기존 형식의 고정 캡처와 잘못된 기존 M09 | PASS. 정상 세 저장을 열었고 잘못된 기예를 거부했다. |
| 53·54 새 본편 공간, B 실제 수평 중력 교전, 새 53 출발 기록, 56장 본체 이후 종결 | 이 수정의 검수 범위 밖이다. |
