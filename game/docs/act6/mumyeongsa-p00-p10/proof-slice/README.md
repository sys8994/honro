## 이번 구현

`HONRO_ACT6_B_SLICE=1`로 빌드한 내부 검수판의 사용자 진입점은 `HONRO.html` → 설정 → 기록 관리 → 디버그 모드 → 여정첩 6막 → 53 → **53 → 54 문턱·중력 검수**다. UI는 신뢰된 클릭으로만 열 수 있다. 실제 게임 App·Engine·Canvas와 임시 검수 프로필을 사용한다. B의 두 구역은 동일 엔진과 한 캐릭터 인스턴스를 공유한다. 정식 장 53→54의 저장·보상 전환 대신, 경계를 밟은 프레임에서 내부 검수 구역 번호가 53에서 54로 바뀐다.

`→`는 처음 정상 바닥에서 오른쪽을 향한다. B 진입 뒤 몸의 중심을 유지한 채 발 기준점을 오른쪽으로 바꾸고, 실제 +X 힘으로 떨어져 석벽에 접지한다. 접지한 뒤 `→`는 벽을 따라 위쪽으로 이동한다. 접촉이 확인된 발이 y=710을 넘을 때 첫 교전 구역이 열린다. 적도 공중에서 +X로 떨어져 같은 면에 착지하고, 적 턴에 벽을 따라 이동한 뒤 실제 `LA01`을 쏜다. 담허는 `Ctrl`로 반대 방향에 도약하고 다시 붙을 수 있다. 키보드 조준과 실제 `Space` 충전 후 `M01`은 엔진 투사체 및 자연 충돌을 사용한다.

B 구조 벡터 [편집 원본](../../../../../shared/act6-b-slice/threshold.svg)은 보정 이미지에서 확인한 목재 문틀·부서진 난간·세로 석대만 저작했다. 그림의 접촉면은 x=760의 돌 면과 y=970의 마루 위에 맞췄다. 원경에는 기존 게임 렌더를 사용한다. 전체 장 미술, 외곽·모서리 및 56 본체 연결은 실장하지 않았다.

기존 54 M09/55/56의 내정 패킷, 차트 전환, 경계 저장 소유자와 기존 저장 키는 스톡 경로를 사용한다. 새 빌드 모듈은 검수 모드의 선택된 장에서만 실행된다. 저장 호환성 검수에는 **현재 저장소의 캡처 경계 기록**을 새 브라우저 컨텍스트에 넣고 일반 쉼터 버튼으로 읽는 테스트를 포함한다. 이미 저장된 기록을 다시 읽는 검수와 해당 기록을 실제 게임 진행으로 새로 쓰는 검수를 별도로 기록한다.

## 실행

```sh
git worktree add --detach /workspace/honro-act6-proof HEAD
npm --prefix /workspace/honro-act6-proof ci --cache /tmp/honro-act6-npm-cache --ignore-scripts
npm --prefix /workspace/honro-act6-proof/game ci --cache /tmp/honro-act6-npm-cache --ignore-scripts
cd /workspace/honro-act6-proof
HONRO_ACT6_B_SLICE=1 npm run build
folder=game/docs/act6/mumyeongsa-p00-p10
python "$folder/proof-slice/route_drawing.py"
python "$folder/proof-slice/browser.py" --build "$PWD" --out /tmp/act6-b-proof --hz 60 120 --viewport 1024 720
python "$folder/baseline/cold_resume.py" --build "$PWD" --out /tmp/act6-cold-proof
```

테스트는 실제 키보드 이벤트로 걷기·점프·조준·충전·발사를 진행하고, 동작을 관측한다. 60·120은 브라우저 요청 프레임 속도며 그 간격을 로그에 기록한다. 엔진 내부 적분은 두 경우 모두 기존 1/120초다. 디스플레이 하드웨어의 입력 지연 계측과는 별개다.
