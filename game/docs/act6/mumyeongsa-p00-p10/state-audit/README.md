# 6막 본편 편성과 피날레 상태 검수

사용자가 직접 실플레이한다는 최신 검수 지시에 따라 편성은 전체 소스에서 대조했다. 전투·이벤트·저장 조건은 앱의 실제 엔진, 장 전용 소유자, 일반 경계 코덱으로 검사했다. 테스트는 접지 위치·차례·피해 상태를 공급한다. 브라우저 입력, 실플레이 라운드와 시간, 난이도별 수행, 실기기 성능은 이번 버전에서 미실측이다. 이전 버전의 화면과 입력 증거를 보존했다.

런타임 후보는 `aeee6e8e78c7e4fc0182b736eca6200774796517`이다. 상태 검사와 아래 빌드 증거가 이를 참조한다. [상태 검사 원자료](native-state.json) · [일반 앱 빌드 파일과 로컬 HTTP](local-build.json)

58의 첫 공격은 낮은 사선이다. 몸을 지역 밖으로 옮겨 첫 노출을 얻는다. 두 번째 중력대는 벽과 천장으로 이어진 마루를 이용하거나 담허의 진목으로 바닥 구역을 붙들 수 있다. 세 번째 확대 유지점은 별도 공격 대상이다. 큰 공격에서 엄폐한 설오의 체력·실드는 `1286 / 0`으로 유지됐고 노출된 휘겸은 `3688.1 → 3310.1` 피해를 입었다. 돌기둥 진입, 동쪽 마루·상행 회랑, 아래 본당과 후면의 원혼이 그 선택을 압박한다. 대도사를 쓰러뜨려도 유지점이 작동하면 수정 진목을 놓을 수 없다. 원본 한 명이 죽은 상태는 새 59를 거절하고 기존 58 저장을 보존한다.

59의 수비병·원혼은 서쪽 높은 단, 교각 발치, 동쪽 혼길·암반에 서로 다른 역할로 들어온다. 개막 10명은 첫 정상 소유자 갱신 뒤의 수이며 그 전에는 교각 꼭두 한 명만 있다. 개막 10과 양쪽 분대 28, 현장 위협 3으로 41이다. 서·동 상한을 지키고, 나머지 편성은 진척과 각 전선의 실제 수용 자리에 따라 들어온다. 낮은 돌길을 양쪽으로 번갈아 훑는 대형 앞발은 상단 회피, 휘겸의 방어 또는 직접 반격으로 대응한다. 방어 표본에서 서·동 방향의 예고와 실제 공격이 각각 렌더러에 전달됐다. 서쪽 타격 시 휘겸 체력은 `3688.1 → 3614.1`이었다. 가름진에는 서쪽 지지석, 교각 방어, 소단의 종터 혼길, 동쪽 파열과 양쪽 전선·앞발 정리가 필요하다. 봉합 뒤 잔존 적이 있는 상태에서도 마지막 교각 위협을 해소하고 네 명이 접지하면 승리한다. 소단의 사망은 패배이며 기존 59 저장 바이트는 그대로다.

## 이벤트·저장

- **51·52** 실제 임무 소유자로 51 경계암귀 사망과 네 발점, 52 설오 투사체의 지지석 직격·석교 경비 해소·소단 종터·네 명 집합 순서를 확인했다. 두 장의 패배 상태는 전환 기록을 만들 수 없다.
- **53~56** 53 진목, 54 M09·차트, 55 바깥 세 앵커·종터, 56 정상 탈출·역류의 필수 서명 조건을 실제 코덱에 넣어 확인했다. 임무 전체의 실제 전투는 앞선 입력 증거를 참고한다. [B](../native-b/README.md) · [C](../torn-eave/README.md) · [소단](../sodan-thread/README.md) · [실내 D](../d-interior/README.md)
- **57** 돌단의 담허가 엔진 피해로 390→0이면 명시적 패배 원인 표시, D 봉쇄, 쓰기 0, 동일한 서명 57 재시도. 살아 있는 담허는 곽진 경로와 네 원본의 D 접지를 거쳐 서명 58을 만든다. 기존 실제 A14 사망 무응답, 생존 배우 거리 153.1 중단은 다른 기록이다. [이전 사망](../encounters/57-body-loss-before-outcome.json) · [연속 검수의 거리](../continuous/README.md)
- **58·59** 대도사·원혼, 양쪽 전선과 앞발, 패배 후 직전 저장 보존, 정상 R·59와 60 서명은 위 표와 원자료에 기록했다.
- **60** 무전투 두 혼을 엔진이 걷게 한 뒤 네 발점, 휘겸의 수비대 추모, 마지막 프레임 권한, 완료 영수증, 실제 타이틀 콜백을 확인했다. 상태 검수의 화면은 대역을 사용했다. 이전 버전 별도 공개 입력 기록에는 정규 시작에서 기존 여정 표시가 한 번 다시 직렬화된 것이 남아 있다. 60에 들어간 이후 엔딩까지 원본 및 경계 저장은 보존됐다. [이전 60 기록](historical-60-public.json) · [이전 타이틀 화면](historical-60-title.webp)
- **새·이전 저장** 추적 중인 52~60의 기존 서명 상태 9개를 정상 경계 코덱으로 읽었다. 필수 플래그를 하나씩 제거하고 테스트용 해시를 다시 계산한 상태도 모두 거절했다. 인계 검사는 원래 기록과 바이트를 보존한다. 이전 긴 브라우저 재실행은 최신 지시에 따라 57 도착 뒤 중단했다. [중단 당시 해시](historical-stopped-at-57.json) · [끝까지 도착했던 이전 관측](../continuous/README.md)
