# 혼로 1~5막 지형 경로 전수 점검

기준은 배포 소스 25094081a다. 출시 구성의 50장을 Chromium에서 열고 전체, 시작, 상·중·하 카메라 표본에서 실제로 그린 벡터 552개를 배포 에셋과 매칭했다. 상시 보이는 지형과 근경이 대상이다. 원경 이미지, 배우, 실시간 물과 효과, 다른 진행 상태에서만 등장하는 에셋은 이 수치에 포함하지 않았다.

현행에서 더 줄어드는 구조가 확인된 **28장 64개 에셋**을 적용했다. 실제 경로 세그먼트 **229,138개**, 벡터 JSON **7,796,340 바이트**가 줄었다. 출발점은 설정별 활성 공급자와 기존 승인 경로다. 곡선 후보는 불변 원본에서 만들고, 클립 밖 제거는 현재 승인 경로의 화면에 기여하지 않는 하위 경로만 제외한다. 접촉선, 핵심 실루엣, 위치·회전·클립·채움 규칙, 충돌 및 승리 조건은 보존한다. 원본은 저작 소스와 이전 릴리스에 남긴다.

- **2막**에서는 같은 원본 그림을 클립으로 나눴을 때 각 조각에 전체 곡선이 남은 경우가 있었다. 2·4·7·10장의 일부 조각에서 클립 밖 경로를 제거했다. 7장의 기존 서·동 암반 승인본은 유지하고 외곽만 줄였다.
- **3막**에서는 바닥 접점에 변환해서 그리는 좁은 스트립 밖 경로가 남았다. 2~10장의 실제 contactMapping과 여유 9 원본 단위를 확인해 완전히 가려지는 하위 경로를 제거했다. 저작 쪽 접점 배열이 달라지면 빌드에서 이 최적화를 재검수하도록 SHA-256 확인을 둔다.
- **4막**에서는 2장의 대형 근경과 5·6장의 대숲·마을 색면을 줄였다. 10장은 반복 형상이 전송 묶음에서 공유된다. 다른 조각까지 정리한 후보는 활성 묶음을 222,041 바이트 키워 제외했다. 도착 계단만 정리한 후보는 묶음을 12,289 바이트 줄였다.
- **5막**은 10장 모두 현재 근경 승인본을 로드하는 것을 확인했다. 수치상 통과한 추가 후보는 한 세그먼트 감소에 그쳤고 현행 아트 공급자와 서명을 유지했다.

변경 전후 모두 실제 장에서 그린 벡터의 d/dParts 세그먼트와 JSON 바이트를 집계했다. 클립 정의 자체와 후보 원본 보관 파일, 전송용 풀의 중복 공유는 표에 합산하지 않는다. 세그먼트 개수와 편집기 노드 수, 화면 프레임률은 별개의 지표다.

## 실행 확인

- Inkscape 1280·2560 비교, 데스크톱 크기 Chromium 28장 전후 같은 카메라 및 모바일 390×692 기준 10개 대표 장의 이미지·팬/줌·접촉부를 확인했다. 보호된 접점이나 발판이 끊기는 변화는 관측되지 않았다. 후보 게임 상태와 충돌은 기준판과 같았고, 기준·합본의 50장 벡터 로드에서 오류가 없었다.
- 물리·목표 데이터 대조는 합본 소스의 1~40장과 2막 컴팩트 장에서 동일했다. 1막 6장, 2막 1·2·7·10장, 4막 2·10장 대표 구간에서 실제 키보드 도약과 착지를 확인했다. 2막 2장 초기 표본은 오른쪽 보행 이동량 0, 3막 3장과 4막 5장 입력 표본은 대기 중 제한에 걸려 각 장의 전체 진행 확인에는 사용하지 않았다.
- 구버전 저장의 4막 그림 참조는 각 공식 장의 정확한 기존 서명과 현재 그림 서명을 대조할 때만 복원한다. 실제 과거 공급 그림 서명에 대한 전투 상태 보존과 조작 서명 거부를 확인했다. 별도 Chromium에서 공식 4막 1·2·3·5·6·7·9·10장 직전 판의 전투 스냅샷을 읽고 배우·HP·좌표·턴·진행·충돌이 동일함을 확인했다.
- 같은 Chromium에서 팬/줌 36회 표본의 Canvas 그리기 p95는 2막 2장 6.3→4.7ms, 3막 3장 5.5→4.1ms, 4막 2장 3.0→2.3ms였다. 프레임 간격은 비슷했고 다른 장에서 소폭 느린 표본도 있었다. 모바일 실기기 성능은 미측정이다.
- 전후 비교 그림과 원본·후보 검사값은 실측 작업 폴더 _local/reports/terrain-audit/에 남겼다. 빌드 지형 교체표는 [승인 경로 목록](../../shared/data/terrain-path-optimization.json)이다.
