## 2. 다음 작업: 엔딩곡

**확정 입력:** 사용자 선택 최종 음원. 크레딧에 넣을 곡명과 참여자 표기도 사용자가 확정할 때 반영한다. 약 3분은 이전 기획의 목표이고, 최종 파일을 임의로 자르거나 엔딩을 정확히 3분으로 맞추라는 요구는 아니다. 최종 음원이 전달되기 전에는 선곡·공개·대체 작업을 하지 않는다.

**현재 상태:** 엔딩 전용 준비 코드가 타이틀곡 `assets/bgm/main.mp3` 및 그 Git blob 해시를 임시곡으로 고정한다. `shared/act6-ending-replan/credits.json`의 개발자·곡 표기는 기준 커밋에서 비어 있다. 공용 BGM 빌드에는 허용된 MP3 목록이 있으므로, 새 곡을 전투 재생 목록에 끼우거나 `assets/bgm/`에 파일만 던져 넣지 않는다. 엔딩 전용 자산 경로와 빌드 출력 계약을 먼저 읽고 가장 좁게 연결한다. 새 음원을 사용해도 타이틀곡과 다른 막의 전투곡은 유지한다.

**보존할 연출:** 6막 10장에서 필요한 마지막 대사와 인게임 사건을 마친 뒤 별도 산문 이동 없이 스틸컷으로 이어진다. 느린 페이드, 읽을 시간, 탭으로 다음 문장 진행, PC/모바일 전용 구도, 음침하고 아름다운 무명사 컷과 별도 마지막 컷, 크레딧과 타이틀 복귀가 이미 구현돼 있다. 음악 교체를 계기로 서사·문구·구도나 완료 저장을 재작성하지 않는다. 시간 조정은 실제 음원과 장면을 보며 필요할 만큼만 한다. 음악의 방향은 혼로의 단조·한국 악기 어법, 과도하게 감상적이지 않은 잔잔한 여운, 너무 느리지 않은 흐름이다. 중국풍으로 들리는 선율·화성이나 촌스러운 훅은 피한다. 이는 사용자가 곡을 판단하는 기준이며, 새 곡을 에이전트가 대신 고르라는 뜻은 아니다.

**완료 조건:** 새 음원이 기존 임시곡을 실제로 대체했는지 보통 10장 완료 경로와 엔딩 미리보기에서 확인한다. PC·모바일 시작과 사용자가 넘겼을 때의 음악 지속, 크레딧 도달과 타이틀 복귀 시 재생 정리, 기존 BGM 설정과 완료 저장 보존을 점검한다. 빌드와 공개판 재생을 별개로 보고한다.

## 3. 다시 결정하지 말아야 할 것

### 지형과 벡터

- 제작의 기본은 **정측면 시안 → Inkscape 벡터화 → 주변 지형 접합 → 최적화 → 실제 렌더 검수**다. 맵에디터를 제작의 중심으로 삼았던 실험은 폐기했다. 편집 도구를 보조로 쓰는 것과 이전 제작 방식 전체를 되살리는 것은 다르다. 정측면에서 계단·발판·배경의 역할이 분명해야 한다. 원경은 이미지, 플레이 지형은 벡터로 분리한다.
- 1막 1·2장은 미감과 성능 비교 기준으로 보존한다. 작은 평탄 맵이나 장식만 겹친 가로 한 줄은 피한다. 위·아래 경로, 경사, 자연스러운 큰 윤곽 변화가 실제 이동 선택을 만들어야 한다. 무명사는 경로가 장 사이에서 이어지고 중력과 시점의 변화가 이동 방식에도 드러나야 한다. 6막 6장의 열린 낭떠러지처럼 서사·기믹상 의도된 공간은 덮지 않는다.
- 4방향 접합은 카메라에서 확인한다. 기존 맵의 연장부와 최신 맵의 단일 확장 지형은 현재 맵 구조에 맞춰 처리한다. 사방에 별도 장식 더미를 무조건 새로 만드는 규칙은 아니다. 플레이 충돌과 미술의 윤곽, 층과 색·텍스처가 한 재료처럼 이어져야 한다.
- 윤곽 부근은 촘촘하지만 선명하게, 내부 벌크는 조금 더 굵은 면으로 구성해 자연스럽게 이어지게 한다. 접합부터 맞춘 뒤 노드를 줄인다. **지형 밀도의 분모는 빈 공동을 제외한 실제 벌크 면적**이다. 노드와 폴리곤 외에도 바이트, 렌더 비용, 흐림과 테두리 노출, 화면비별 충돌 일치를 본다. 일반 플레이의 자동 윤곽선과 검수용 충돌 표시는 구분한다. 시각 교정만 요청됐을 때 지지·점프·동선을 바꾸지 않는다.

### 전투와 몬스터

- 권장 수량은 비교 기준이다. 적을 한쪽이나 등간격으로 쌓지 말고, 길목·엄폐·방어선·높이와 적의 역할이 맞는 군집을 만든다. 증원은 계획 수, 실제 출현 수, 동시 활동·공격 상한, 중단 조건을 구분한다. 승리 조건을 지키고 전원 처치가 필요 없는 장을 섬멸전으로 바꾸지 않는다.
- 거인은 필요한 상대만 과감하게 크게 한다. 작은 적은 작은 채 위협적일 수 있다. 같은 몬스터의 색·체급 변주는 장소와 사건이 설명할 수 있어야 한다. 약점은 인물이 미리 알 만한 경우 현장 대사로, 모르는 경우 유효한 타격을 관찰한 뒤 추론·확인으로 드러낸다. 화면 크기뿐 아니라 공간 수용, 피격부, 사선, 대사 발동과 처치 흐름까지 함께 확인한다.
- 몬스터 벡터는 전체 면적으로 나눈 밀도를 사용하지 않는다. 장승을 기준으로 정규화한 형상·경계와 역할별 범위를 사용한다. 노드를 채우기 위한 쪼개기나 잔무늬가 아니라 외형이 읽히는 부분을 개선한다. 새 그림은 파트와 관절을 분리해 벡터화하고 실제 게임에서 대기·공격·피격과 해당 종의 이동을 확인한다. 고정형에게 걷기·점프가 없다는 이유만으로 결함으로 세지 않는다. 숫자 통과는 미술 승인과 다르다.

### 이야기와 UI

- 설명문보다 인물의 상황, 관계, 행동으로 전달한다. 인물마다 말투를 유지하고, 이벤트를 알려야 할 때도 ‘게임 안내문을 읽어 주는’ 식으로 쓰지 않는다. 분량 수치는 가이드이며 대사 수를 채우기 위해 사건이나 반복 대사를 추가하지 않는다.
- 엔딩은 사용자 승인본의 서사 결론과 이미지 구도를 보존한다. 강제 산문 이동, 작은 가로 원본을 잘라 쓰는 모바일 버전, 굵고 빠르게 넘어가는 자막은 되돌리지 않는다. 엔딩곡의 반영과 이야기 재기획은 별개다.
- 검수 진입은 기존 디버그 여정첩의 접근 흐름에 맞추고 일반 UI에 별도 우회 버튼을 늘리지 않는다. 실험·검수는 격리 저장에서 한다. 기존 저장이 깨져도 된다는 과거 허용은 그 디버그 진입 복구에 한정해 해석하고, 일반 저장 초기화 규칙으로 확대하지 않는다.
- 6막 정비는 휴식터가 아니라 장비·기예를 바꾸는 선택형 기능이다. 회복 없이 소단의 좌정, 곽진의 후위, 9장 첫 진입 연출을 유지한다. 기존 정비와 기믹을 한 UI로 합치기 위해 서사와 저장을 바꾸지 않는다.

- 크게 바꾸기 전에 해당 코드와 레퍼런스를 확인한다. 서로 독립인 일은 병렬로 진행할 수 있지만 같은 장·파일·배포의 작성자는 한 명으로 둔다. 결과가 불명확하면 먼저 실제 원격을 확인하고 같은 쓰기를 반복하지 않는다.
- 정량 기준은 좋은 후보를 고르는 수단이다. 테스트 통과, 실제 애플리케이션 화면·동작, 사용자 미감 판단, 수동 완주를 같은 뜻으로 쓰지 않는다. 검수할 때 저장이 보존되는지, PC/모바일 중 무엇을 확인했는지, 정상 진입과 검수 진입 중 어느 쪽인지 적는다.
- 수정 단위로 커밋과 비강제 푸시, 최종 통합 후 Pages 상태 확인이 기본이다. 이관 자체가 계정 접근을 주지는 않는다. 생성 HTML·번들을 손편집하지 않는다. 실행 변경은 원본을 고치고 기존 빌드·배포 흐름을 사용한다. 과거 정상 배포 자산을 임의로 삭제하지 않는다.
- 기능별 핵심 테스트와 직접 바꾼 플레이 경로에 먼저 시간을 쓴다. 관련 없는 전체 테스트를 반복 실행하거나 미실행을 통과로 적지 않는다. 문서만 바뀌면 파일·링크·커밋을 확인하고 게임을 다시 빌드하지 않는다.
- 보고는 한국어 존댓말로, 변경점과 확인 근거부터 간결히 적는다. 화면 증거가 중요한 변경에는 같은 조건의 전후 스크린샷을 남긴다. 예전 작업의 30분 보고는 종료됐고, 새 세션에서 자동으로 재개할 업무는 없다.
