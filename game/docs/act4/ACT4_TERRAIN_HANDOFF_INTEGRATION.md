```sh
python tools/act4-vector-production/import-handoff.py /path/to/HONRO_ACT4_HANDOFF shared/data/act4/handoff-art
npm run build
```

## 적용 검증

- 공식 author 적용 후 소스와 발행용 장 JSON 모두에서 미술 필드를 빼고 기준과 동등함을 확인했다. 2장 지형 12개와 등불의 배치·비행 범위, 10장 42적과 조수·승리 설정을 포함한다.
- 새 벡터 23개는 기존 런타임 제한과 장별 BODY 참조 검사를 통과했다. 40장 기둥은 비균등 월드 등록과 원래 네 배치를 합성하고 하나의 내부 심벌을 네 번 사용한다.
- 2장 비행 범위·하층 이동·문짝의 이전 방식과 새 방식, 5장 차폐, 6장 문, 7장 신호 접근, 8장 동굴 사건, 9장 구조 경로, 이동 갑판, 정산 조건, 저장 자산 서명의 집중 엔진 검사를 실행했다.
- 브라우저 완주·정산과 공개 검수는 장별로 실제 실행한 기록에 따라 판단한다. 새 장 진입, 이전 저장 이어하기, 현재 저장 이어하기는 서로 다른 확인이다.
## 후보 빌드의 화면과 저장 확인

- Chromium 153, 분리 저장, 보통 난이도. 32~39장은 이전 장 완료를 기록한 준비 프로필로 일반 App 진입을 실행했다. 40장은 보존된 원정 저장에서 정상 재시작 메뉴를 사용했다. 32~40장에서 신규 자산 표시, 실제 방향키 이동, 데스크톱·모바일 뷰포트, 새로고침과 이어하기를 확인했다.
- 31장 R14·36장 R12·40장 보존 저장은 기존 미술을 표시한 채 이어졌다. 32장은 큰 JSON 내보내기 파일을 가져오기 메뉴로 복원했다. 처음 시도한 직접 localStorage 삽입은 브라우저 용량 한도에 걸렸다.
- 35장 초기 후보에서 상단 단차가 떠 보였다. 기존 암반의 네 색면을 새 흙비탈 뒤로 연결하고 보행선 위에는 그리지 않았다. 대나무 배치 열두 곳은 하나의 심벌을 공유한다. 수정 후 데스크톱·모바일 화면, 이동·이어하기, 차폐를 재확인했다. 32장의 흙마당 하단 직선 이음과 36장의 흙·기존 산기슭 색 경계는 보완이 남았다.
- 최종 생성물의 장별 지연 로딩 데이터 합계는 32장이 3.14 → 9.95 MB로 가장 크게 늘었다. 35장은 2.16 → 4.93 MB, 36장은 3.82 → 5.65 MB, 37장은 4.26 → 7.04 MB다. 이 수치는 압축 전 파일 크기다. 모바일 뷰포트 캡처를 실제 단말 프레임·메모리 검증으로 세지 않는다.
- 공개판 e57736aa2의 성공 발행 파일 770개를 후보 빌드에 보존했다. 전체 장 완주, 정산·다음 장 연결, 최종 미술 보완을 마친 뒤 master·Pages 반영을 판단한다.

## 2026-11-13 장별 공개와 진행 검수

- 32장 인계 원본은 하단에 수평 잘림이 있었다. 새 `body-joined`에서 골목과 동굴 개구부 아래만 바위 지형 방향으로 잘라 기존 암반과 맞물리도록 했다. 이전 본체 ID와 현재 12개 충돌 지형, 문턱을 유지한다.
- 32장 원정·계획 성장 투자 조건에서 엔진의 일반 입력으로 12적 전멸 8R, 기예 발사 31회, 전원 생존을 확인했다. 이전 같은 성장 조건의 8R와 일치한다. R9의 전투 종료 저장에서 미술 참조만 후보로 바꾼 격리 복사본을 Chromium으로 열었다. 실제 키보드로 문턱에 접근하고 재회·행방 대사를 읽어 안전 7명을 확인한 뒤 전원 집결과 9R 정산 1회를 확인했다. 예전 본체 참조의 저장 가져오기도 확인했다.
- 36장은 기존 비플레이 지반의 윤곽과 명암 구조를 보존하고 색을 폐촌 흙에 맞췄다. 문이 넘어지기 시작한 R12 저장의 격리 복사본에서 미술만 새 참조로 표시해 Chromium으로 문 넘어짐, 대사, 집결과 13R 정산을 확인했다. 신규 전투 전체 라운드가 13R라는 판정은 아니다.
- 공개 순서는 31·32·38, 이어 35·36이다. 32장은 Pages에서도 재회·안전 7명·9R 정산을 확인했다. 31·38의 이미 확인된 경로는 반복하지 않았다. 로컬 미공개 후보는 `HONRO_ACT4_HANDOFF_PREVIEW=1`로 빌드한다.
- 35장은 대숲·지반 보완 전 RC5 완주에서 20R·30처치·4명 생존이었다. 현행 후보는 적 30기와 기존 충돌·진행을 유지하며, 새 미술에 대한 이동·차폐·저장 복원과 두 화면 폭을 확인했다. 현행 후보의 전투 완주는 실행하지 않았다.
- 36장은 지반을 흙비탈 아래로 165 올려 겹치고 암반 색을 조정했다. 문·적 9기·보상·이벤트를 유지한다. 신규 전투는 위협과 진행 중 행동이 모두 끝나면 자유 집결을 허용한다. 같은 R12 보관 저장의 격리 비교에서 문 넘어짐·대사·전원 집결·정산을 실제 입력으로 진행했고, 기존 조건 13R에서 새 조건 12R로 줄었다. 기존 전투 저장은 이전 조건과 자산 참조를 사용한다.
