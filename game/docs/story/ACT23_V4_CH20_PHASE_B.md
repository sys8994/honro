# 20장 검토 원고 결합

`v4-reviewed/HONRO-CH20-reviewed-final.json` 확정 52행의 ID·화자/채널·조건·문구를 그대로 `shared/data/reviewed/act23-v4-ch20.json`에 옮기고 내부 판본 `revision:1`만 추가했다. 새 대사·장면 설명을 쓰지 않았다. 원고의 구현검증 메타데이터는 원본 그대로 보존했다.

## 실행 계약

- Phase A, Phase B의 20장 명시 허용 및 정확한 52행 자료가 함께 있어야 활성화된다. map revision은 520이다. 일반판과 Phase A 단독은 이 원고를 표시하지 않는다.
- 실제 돌림진 해제/호송 목록 합류/입구 위협/대열 출발 상태로 도입을 나눈다. 실제로 볼 수 있는 위험이 없으면 그 위험이 남았다는 대사를 만들어 표시하지 않는다.
- 기존 `act23-v4-act3.js`의 부상자 정지·근접 지원·동반 이동·지원자 이탈/재결합과 같은 짐 한 번 인계·넉백 중단/재접근·유한 매복/행동 기회 판정을 그대로 사용한다. 부상자 정지와 인계 시작을 실제 상태에서 관찰해 대사를 열고, 해당 대화 동안 물리 상태가 앞서 넘어가지 않도록 한다. 완료에는 실제 지원 이동과 기존 `careReady`가 필요하다.
- 유한 매복의 실제 원혼 이동을 관측한 후 MID.04를 연다. 실제 고지 접지와 지형에 막히지 않는 사격선 관측이 있어야 MID.05를 연다. 마지막 위협은 기존 지정 위협과 정확한 유한 입장 명단으로 판정한다. 지도 전체 잔적을 새 필수 조건으로 추가하지 않는다.
- `objective`, `convoy-gilchan`, `convoy-mason`의 전체 roster를 고정해 기억한다. 살아 있는 모든 호송 대상의 실제 바깥 접지·거리·누적 이동과 필수 두 인물의 생존이 있어야 도착/시간차 문답을 연다. 석공·길찬만 도착하고 부상자가 안에 남으면 TIME 전체를 보류한다. 모든 생존 대상과 실제 손실 수를 구분하며 사망자는 생존수에 포함하지 않는다.
- 기본 호송안은 전원이 보호 대상이므로 익명 주민 손실을 새로 허용하지 않는다. `permittedLosses:[]`에서 손실 분기는 **현재 정책상 보류**다. 허용된 익명 손실이 있는 자료에만 BRANCH.02/POPUP.02를 허용하도록 분리했고, 두 도착 분기는 서로 배타적이다. 팝업은 승인된 원문 템플릿의 두 자리만 실제 roster에서 계산한 0 이상 정수로 치환한다. 별도 요약 문구를 만들지 않는다.
- TIME.01–08은 독립 저장 사건으로 앞 문답 완료 뒤에만 열린다. TIME.07에는 같은 짐 보유 및 석공이 실제 Engine 보행으로 빈자리까지 이동한 증거가 필요하다. TIME.08을 마치기 전에 시간차 저널을 저장하지 않는다.
- 바깥의 실제 `20.town-refugee`와 동행의 근접 조우가 있어야 NEWS를 연다. 동굴 석공이나 pending slot으로 피란민 증언을 대신하지 않는다. NEWS 완료 뒤에만 두 번째 저널을 저장한다. 부상자와 빈자리·석공의 실제 도착을 확인한 뒤 COMPLETE를 연다.
- 같은 run의 실제 완료에만 `history.stages[20].reviewed20`을 남긴다. 승인된 막종료/쉼터 행 ID와 `endingAllowed`/`restEndingAllowed`를 공통 계층에 제공한다. 19장 퇴장/표식의 새 실제 목격 저장이 없으면 관련 선택/엔딩을 허용하지 않는다. 소단 선택대화와 막종료 첫 행은 19장의 같은 완료 run에서 세 주민의 실제 부르는 몸짓과 연결된 혼의 시각 응답 영수증이 모두 있을 때만 허용한다. 새 음성·고유 이름·문구는 추가하지 않는다. 옛 완료와 과거 cursor로 이를 채우지 않는다.

## 공통 결합 인터페이스

`spec.templateVars(app,row)`는 `A2.S20.POPUP.02`에만 `{survived_count,lost_count}`를 반환한다. 공통 계층은 exact template와 metadata의 정수 값을 함께 검증한다. 막종료는 `endingRows`/`endingAllowed(profile,row)`, 쉼터는 `restRequired`/`restOptional`/`restEndingAllowed(profile,row)`를 사용한다. 이 담당 파일은 공통 cursor·routing 코드를 직접 수정하지 않는다.

## 확인과 한계

`node tests/act23-v4-reviewed20.mjs`와 기존 `node tests/act23-v4-convoy-care.mjs` 통과. 정확한 52행, 돌림진 장면 저장, 실제 피해로 인한 정지/지원 이동, 실제 impulse로 끊긴 인계의 소유권 유지, 살아 있는 부상자 누락 방지, 배타적 인원 분기, TIME.04 저장 재개/문답 순서, 실제 피란민 부재 가드, 정확한 두 저널과 목격 이력 엔딩 가드를 확인했다. 기존 care 검사는 무저장/공중 저장/분리 후 저장에서 실제 재접근과 같은 짐 1회 인계를 확인했다.

새 binding 검사의 선행 클리어·적 사망·최종 도착·일부 완료 상태는 명시적 fixture이며 정상 호송 완주라고 하지 않는다. 짧은 지원 이동·넉백은 실제 Engine 실행이다. 이 검사에는 실제 Canvas·음향·적의 정상 연속 공격·미술 집중 검수·공개 배포 증거가 없다. 부족한 목격/분기 근거로 보류된 행은 완료 행으로 세지 않는다. 공통 번들·빌드·저장 cursor 이관·최종 브라우저 확인·배포는 부모 통합 담당이다.

## 실제 Chromium 결합 검수 (2026-10-27)

부모의 11–20 내부 후보 `http://127.0.0.1:8768/HONRO.html`에서 `python tools/testing/act23-v4-reviewed20-browser.py` 통과. 자동 프레임을 멈추고 실제 App/Engine을 25ms씩 진행했다. 본문은 실제 DOM과 확정 원문을 비교하고 Enter로 넘겼다. 19장 브라우저 검수의 실제 완료 프로필에서 같은 run의 퇴장·세 표식·주민 호명 몸짓/혼 응답 영수증을 가져와 소단 선택대화와 첫 막종료 행을 허용했다. 이를 새 음성·실제 이름 발화의 검수로 확대하지 않는다.

선행 클리어·경지, care 이전 단계, 무관한 적 제거, 최초 호송 위치와 동행의 접근 위치는 명시적 fixture다. 부상자는 `Engine.hurt`로 정지했고, 휘겸의 근접 지원과 실제 보행으로 이동했다. `Engine.impulse(350,-160)`로 길찬의 인계를 끊고 공중/분리 상태를 저장·reload한 뒤 실제 재접근으로 같은 `20.family-baggage`가 석공에서 길찬에게 정확히 한 번 인계됨을 확인했다. 유한 매복의 입장은 기존 offered/ended action으로 열었으며, 그 적의 처치는 fixture다. 부상자·길찬·석공의 바깥 도착과 누적 이동은 직접 완료 위치/플래그를 지정하지 않고 기존 호송 보행으로 확인했다. TIME.06 뒤 구 escape 보행이 아들을 끌어당겨 부자 간격이 220을 조금 넘으면 빈자리 접근이 멈추던 경계는 이 장의 마지막 접근 동안만 아들이 실제 `Engine.walk`로 아버지를 따라가도록 했다. 빈자리 보행이 인계 목격을 완료할 때까지 구 호송 보행을 보류하며 소유권/아이템/한 번 인계 계약은 유지한다. 실제 브라우저에서 아들 추종 201.50, 아버지 빈자리 접근 467.99 world 거리를 관측하고 TIME.07–08을 열었다. `tests/act23-v4-reviewed20.mjs`에는 221 간격에서 실제 추종·빈자리 접근을 실행하고 접근 중 저장/continue 후 거리와 같은 짐을 보존하는 집중 회귀를 추가했다. 이 검사의 도착·전투 종결은 fixture다. 이 검사와 `tests/act23-v4-reviewed19.mjs`, 기존 `tests/act23-v4-convoy-care.mjs`가 통과했다.
