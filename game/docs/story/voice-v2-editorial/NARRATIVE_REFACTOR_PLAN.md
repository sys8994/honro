# 서사 코드 정리안 · 첫 수정 단위

## 확인된 문제
현행 대사 선택에 원본, 장별 교체, 목표 수정, bespoke map payload, narrative snapshot, canon 수정, evidence 변환, pacing 수정이 관여한다. 서로의 이전 함수를 잡아 감싸는 방식이 반복된다. 일부 연출과 교정은 한국어 문장 일부와 행 번호로 연결되어 있다. 실제로 17장의 5라운드 옛 설명은 마지막 pacing 층에서 3라운드로 바뀐다. 파일 하나의 문장이 곧 화면의 문장이라고 볼 수 없다.

## 없애지 않을 것
- 기존 진행 전투를 복원하는 legacy 대사·파티 분할·waterworks payload.
- 목표 조건·실제 전투 판정·보상·저장 큐와 cursor.
- Workshop 사용자가 작성한 원고.
- 다른 기능과 섞인 파일 전체. prose 부분이 중복이라고 파일 전체가 미사용인 것은 아니다.

## 첫 정리 범위
1. 현재 신규 진입에 최종 적용되는 원고를 먼저 고정해 구조화된 비교 기준을 만든다. 이 단계는 문장 수정과 별도 커밋으로 남긴다.
2. 현재 원고의 편집 위치를 하나로 모은다. 장/장면/행의 안정된 ID, 화자, 본문, 조건, 카메라·동작 참조를 가진다. 빌드 시 직접 생성하고 런타임의 추가 덮어쓰기 층은 만들지 않는다.
3. 현행 원고와 저장된 옛 원고 중 무엇을 쓸지 명시적 선택 지점에서 한 번 결정한다. 현재 override 안에 섞인 호환 처리는 이 경계로 분리하되, 옛 저장의 실제 동작은 바꾸지 않는다.
4. 연출은 한국어 문장 검색 대신 행 ID로 연결한다. 장면 내 줄 수가 달라져도 이름 공개·협력 수락·목격 조건을 잃지 않게 한다.
5. 대조가 끝난 현재 원고만 새 원고로 교체한다. 중복된 현재 표현 변경 경로는 제거한다. legacy 파일은 별도의 사용 경로 조사 없이 삭제하지 않는다.

## 최소 확인
- 신규 30장 원고의 구조화된 전후 비교는 빠른 데이터 검사로 한다. 전체 맵을 반복 플레이하는 작업으로 확대하지 않는다.
- 실제 연출은 변경 위험이 있는 장면만 확인: 2장 이름 공개, 7장 구조 대사, 9→10장 협력/철수, 12·14장 bespoke, 17장 3턴, 27장 무명 조우와 28·29장 목격 조건.
- 저장 중간 대사 cursor·완료 플래그·파티·HP·목표 목록이 유지되는지 제한된 대표 저장으로 대조한다.
- Game/Workshop 공통 빌드 원천과 사용자 원고 보존을 확인한다.

전면 엔진 재작성·전체 파일 삭제는 이 작업의 승인을 받은 것으로 간주하지 않는다. 우선 서사에서 확인된 중복 권한과 문자열 의존을 제거한다. HUD/렌더링 등 다른 구조 정리는 기존 측정 근거와 소유권 조사로 별도 범위를 정한다.
