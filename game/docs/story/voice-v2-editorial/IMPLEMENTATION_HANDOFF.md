# 확정 원고 연결 작업

## 권한과 범위
사용자는 작성 원칙 v2.0을 최상위 기준으로 채택하고 모든 현행 스토리 텍스트 개편을 요청했다. 원고는 담당 조정자가 직접 읽고 작성했다. 이 디렉터리의 일곱 JSON은 구현용 원고다. `status=editorially-reviewed-awaiting-integration`은 문학·인과 검토 완료, 코드 연결과 실제 화면 검수 전이라는 의미다. 문장 창작을 위임하지 않는다.

## 입력
- act1-scenes / act2-scenes / act3-scenes: 주요 대사.
- supplement-scenes: 남은 1막 퇴장·상호작용·증원 반응, 상태별 대사, 첫 혼령 튜토리얼, 묵종 이상 현상, 대체 경로 도입.
- rest-dialogue: 1~30장 및 막 뒤의 선택 대화. null은 해당 분할 팀/미합류 화자의 신규 대사를 만들지 않는다는 뜻이다. 표시 조건은 기존 규칙을 존중한다.
- arrivals-endings: 도입·막 엔딩·막 이후 쉼터. 도입은 진입 전에 읽혔으면 전투 시작 때 중복 재생하지 않는다.
- summaries: 완료 후 기록 요약. 진입 전 노출하지 않는다. 목격 조건이 붙은 요약은 실제 목격 플래그 확인 후에만 덧붙인다.

배열의 세 번째 숫자는 원문의 의미상 메타데이터 출처 후보이며, 새 원고의 행 ID가 아니다. 현재 최종 적용 장면에서 확인하고 카메라/동작의 의미가 맞게 연결한다. 제거된 행의 동작을 엉뚱한 발언에 붙이지 않는다. 새 canonical 행 ID는 원고와 별도 필드로 고정하고, 과거 저장의 index/ID는 그대로 읽는다.

## 구조 정리
`NARRATIVE_REFACTOR_PLAN.md` 범위만 시행한다. 새로운 최종 덮어쓰기 모듈을 또 추가하지 않는다. 현재 대사 카탈로그와 한 번의 선택 경계를 만들되, 전투 메커니즘을 전면 재작성하지 않는다. 먼저 기존 최종 원고의 구조 동등성을 확보하는 커밋, 그다음 제공 원고 적용 커밋으로 나눈다. 현재 중복 표현 변경을 제거하고, 옛 저장용 선택과 동결 원고는 유지한다.

기본 파일보다 늦게 적용되는 최종 데이터가 기준이다. 특히 다음은 이미 확인했다.
- 12/14장의 map initialState에는 별도 원고가 있다.
- EvidenceQuests는 3/16/17/19/22~30장의 원고와 기록 표현을 바꾼다.
- Act2Pacing의 14장 4라운드, 17장 3라운드, 18장 4라운드+안착은 유지한다.
- stage5-waterfall의 실제 목표는 주박목과 물길진이다. 옛 고리쇠/받이진으로 되돌리지 않는다.
- story-canon-v1의 includes/append, story-direction의 한국어 부분문자열, story-framing의 행 번호, stage12-quarry의 담허 근접 여부 분기, bell-anomaly의 안착 여부 교체, stage10 안전 퇴장 과거문구 projection을 의미 ID로 옮긴다.
- 27장 검은 공간은 이름 없는 화자다. 원고에서 식별용으로 쓴 ‘이름 없는 화자’를 실제 화자명이나 초상으로 표시하지 않는다. 5컷, 즉시 수동 넘김, 건너뛰기/멈춤/복귀 유지.
- 29장 목격 대화 두 줄, 28장 목격 퇴장, 20장 종 이상현상 회상은 respective witness 조건 유지.
- 기록 kind/documentId, 2장 홍만 이름 공개 revealName, 협력 수락과 once 플래그는 보존한다.
- 대사를 바꾸기 위해 HP·목표·보상·스킬·파티·지형을 바꾸지 않는다.

## 유지 판단
원문의 기술 안내/경고/실패 원인이 실제 규칙과 일치하는 부분은 검토 후 유지한다. 모든 문장을 억지로 다른 표현으로 바꾸는 것이 요청의 목적이 아니다. 역사적 스냅샷이나 미사용 덮어쓰기 문장을 새 플레이에 다시 연결하지 않는다. `supplement-scenes.retainWithoutChange`와 `deletionsOrMigrations` 참고.

## 확인과 비용
관련 원고 원천과 빌드 연결만 확인한다. 전체 저장소 재탐색, 새 세계관 기획, 전체 대화 복사, 대량 스크린샷, 매 커밋 전수 테스트는 불필요하다. 데이터 수준의 현재 30장 원고/조건 비교는 필요하다. 실제 화면은 수정 위험이 있는 장면을 선별한다. 검증 실패 시 기존 실패인지 구분하고 무관한 수리는 하지 않는다.

각 일관된 단위는 커밋·원격 push. master 병합·Pages 발행은 부모 최종 검수 뒤. 코드 연결 중 정보 누락이나 원고/실제 상황 불일치가 발견되면 위치와 조건만 보고한다. 임의의 대체 문장을 만들지 않는다.
