# 25·27장 수로 연결

기존 City의 독립 도착 영수증을 쓴다. 25장 다섯 곳·27장 네 곳을 자유 순서로 방문하며 각 지점의 두 실제 영웅이 접지해야 한다. 단순 축지 인덱스·한 명 도착·선택 검은 공간 완료는 이를 대신하지 않는다. 일반 출구는 검은 공간이나 전체 이상현상 저널을 요구하지 않는다. 새 도착점·휴식·자동 회복·실패 복구를 추가하지 않았다.

25장 저널은 가구별 생활도구와 두 실제 환경 이상(물방울의 방향 변화, 실제 배경 창의 어긋남) 관찰이 모두 있을 때만 기록한다. 물방울은 기존 환경 렌더러의 실제 시간과 같은 식으로 읽고 현장 동행·viewport를 함께 확인한다. 진목 작업 경고는 실제 실패한 연결 시도 뒤 기존 두 진목을 살피는 짧은 표시와 실제 적 접근이 겹칠 때만 허용한다.

27장 검은 공간은 기존 선택 진입·낙하·정지·skip·복귀·중단 저장의 READY 복구를 그대로 쓴다. 승인된 개인 9문구 순서와 정렬을 보존하고, 복귀 발화에는 시간·종 질문을 공유하지 않는다. 개인 저널은 실제 원래 발판 복귀 뒤 `owner=설오`, `party_shared=false`로 보존한다. 중단 저장은 새 witness를 만들지 않는다.

`tests/act23-v4-reviewed25-27.mjs`에서 production App/Engine의 역순 도착, 한 사람만 도착한 경우 거부, 저장/Continue, 실제 진입 조작, 기존 checkpoint 복구, 환경 관찰 지연, 기존 검은 공간 낙하/skip/복귀와 담허 상태 보존을 검사했다. 적 상태·영웅 도착 위치·viewport 시간은 fixture다. 이 단위의 실제 Chromium/정상 전투 검증은 아직 미실행이다.

공통 `stake-crossing.js` 통합 요구: retry 직전 전용 모듈의 `captureRetry`, 실제 checkpoint 복원 직후 `restoreRetry`를 호출한다. 보존 대상은 이미 끝난 원고 재생·실제 관찰·저널뿐이다. 물리 도착·적·지형·소모 자원은 기존 checkpoint가 복원한다. 해당 두 줄은 부모 소유 공통 파일에 직접 적용하지 않고 통합 제안 스크립트에 담았다.
