# 21장 검수 원고 연결

기준 `15243cc1`에 부모 최종 채택 30문구를 독립 provider로 연결했다. 22–24장은 최종 채택 데이터를 보존했으며 이 단위의 실행 연결은 21장만이다. 25–30장은 미전달이다. 활성 공통 파일은 수정하지 않았다.

## 전용 파일과 통합 요청

`shared/runtime/act23-v4-ch21-scenes.js`는 기존 City plugin을 감싼다. 기존 수레 HP/파괴와 곽진·주민 실제 보행, 600/라운드 이동 예산, 유한 후발 2체, 보호/실패, 기존 지역 위협·먼 선택 경로를 유지한다. 기존 두 전투원의 수치/종류/XP/위치/스킬을 유지하고 공유 guard rig의 표시만 옛 빈 갑주와 현재 죽은 수비병으로 구별한다. 갑주의 실제 짧은 swept 보행/방향 전환과 빈 내부·별도 옛 문장, 주민의 부상 표시, 수레 바퀴 정지를 전용 미술에서 표현한다. 생존 수비병의 표시명은 부모가 명시한 역할명, 곽진은 명시 화자, 수레는 승인 목표에 있는 명칭을 쓴다. 추가 창작 대사는 없다.

`act23-v4-ch21-reviewed.js`는 정확한 ID/화자/본문/stage/revision/status를 확인한다. 실제 수레 정지, 주민 위협, 마지막 살아 있는 부상자의 실제 문턱 보행, 실제 안전 도달/국소 위협 해소, 옛 빈 갑주를 근처 생존 동행이 관측한 증거가 해당 행의 조건이다. 혼/위협이 이미 죽으면 보류 위험 대사를 취소한다. 인물 행은 매 행 현재 생존·출연을 확인한다. 원고 종료 acknowledgment와 실제 관측·호송·rowId/커서를 직렬화한다.

저널은 실제 구조·갑주 관측·대조/출발 설명을 마친 뒤에만 기록한다. 곽진/휘겸의 구면 발화 또는 현재 수비병들의 생존이 성립하지 않은 대체 실행에서 그 사실을 만들어 쓰지 않는다. 조건상 생략된 저널만으로 전투를 영구 정지시키지는 않는다. 실제 완료 provenance에 구조/문장 proof를 남겨 후속 장이 구판 cleared를 새 관측으로 오인하지 않도록 한다.

쉼터 선택 6행은 전투 진입 전 21장 장소/현장 관찰/합류/party 출연을 요구한다. `act23-v4-ch21-art.js`의 `mountRest`가 실제 현재 성문 전장을 별도 preview Engine/Scene으로 배경에 렌더링한 뒤 관측을 기록한다. 전투를 시작하거나 NPC/자원/보상/원본 battle을 변경하지 않는다. 실제 진입은 observation을 폐기하며, 진행 중 전투·구조 후·다른 장소·분할 무휴식에서 재생하지 않는다. 각 행의 실제 화자를 따로 검사한다. 원고 대체초안 REST_*는 등록하지 않는다. 장소 설명 alias 조회는 arrival seen을 소비하지 않는다.

부모가 적용할 구체적인 변경은 `tools/testing/act3-v4-parent-integration.mjs`의 `patch()`에 있다. **현재 고정 base용이며 최신 공통 인프라에 그대로 덮어쓰지 말고 해당 의미를 통합한다.** 이 스크립트는 별도 validation worktree에만 실행했다.

1. `shared/build.mjs`: 모델 씬/provider 2개와 별도 미술 1개 목록, PhaseA+CH21 opt-in, 전용 데이터 payload(기본 null).
2. 공통 reviewed registry: rowsReviewed/accepts/finished/failure와 stage21 lineAllowed/present/journal/talkId를 provider에 위임. 기존 11장 경로 유지.
3. `story.js`: 매 행 가드를 11장 한정에서 정수 reviewedStage로 확대. 원고 본문은 여전히 stage별 정확 whitelist로 확인.
4. `act23-v4.js`: stage21 opt-in map revision421. 기존221은 기존 성장/SP/장착/완료 보존 discard 경로, 같은421은 그대로 재개.
5. `rest-journey.js`: 실제 pre-entry 관찰 mount 후 선택대화/저장 cursor 복구, 선택대화 종료의 쉼터 redraw 후 preview 재연결. stage21의 빈 required-arrival을 pending으로 오인해 선택대화 cursor를 폐기하지 않도록 처리.

## 실제 수행한 검증

검증 위치는 `/tmp/honro-act3-reviewed-check` detached worktree다. 이 작업 브랜치에는 부모 공통 변경이나 생성 HTML/web를 넣지 않았다.

- `node tests/act23-v4-reviewed21.mjs`: 원본 App/Engine/Story의 정확한 원고 gate·수레 실제 damage·갑주 swept 이동/방향·위험 해소 가드·실제 유한 예산 주민/곽진 호송·문턱 발동·서로 다른 갑주 관측·저널 순서·실패 화자·휴식 각 행/alias·중간 저장과221 성장 보존 재시작을 확인했다. DOM/Canvas/storage double이며 전투 사망·영웅 위치·일부 round/actor 경계는 fixture다. NPC 좌표를 주입해 호송 성공을 만들지 않았다.
- 기존 `act23-v4-city.mjs` 15항목과 `act23-v4-common.mjs`를 실행했다. 25/27 두 사람 도착/자유 순서, 26 실제 구조, 28 재합류·12적턴/기구/호송, 기존 firstSpirit queue/Continue와 provenance가 통과했다.
- `HONRO_ACT23_V4_PHASE_A=1 HONRO_ACT23_V4_PHASE_B_CH21=1 npm run build` 성공.
- `tools/testing/act23-v4-reviewed21-browser.py`: 실제 Chromium DOM/Canvas/Enter/localStorage/reload/Continue, 수레 정지/방향 전환·부상자 보행·빈 갑주/문장·저널·실제 쉼터 관측과 선택대화 중간 cursor 재개, 390×844/1280×800. pageerror0. 전투 사망·영웅 위치·round/serial 증가는 fixture이며 NPC는 실제 물리로 보행했다.

전체 구조→일반 거리의 수레/갑주/곽진 식별→부상자 이동/모바일이라는 서로 다른 상태의 실제 PNG를 직접 확인했다. 선택대화 재개에서 공통 requiredPending의 11장 한정 오류를 발견하여 통합 패치에서 고쳤다. 별도 최종 build/Chromium을 다시 실행하고 성문 구조 완료/저널과 쉼터 field preview·대화 재개 화면을 재확인했다. 원시 PNG/capture.json은 검증 worktree의 `_local/reports/act23-v4/reviewed21-browser/`에만 있다.
