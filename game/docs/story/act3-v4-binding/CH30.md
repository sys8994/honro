# 30장 배 호송과 과거 행선지

기존 연실의 배와 곽진의 실제 승선·첫 하선 호송·도보 회수·귀항·둘째 무리 재합류·마지막 하선을 유지한다. 구조 인원은 실제 하선과 안전영역 도달에만 증가한다. 단순 턴/승선/타이머를 구조 완료로 보지 않는다. 모든 예정 유한 공격이 실제 입장하고 해소되어야 한다.

핵심 사공 증언은 살아서 구조된 현재 사공이 실제 안전한 곳에서 한다. 설오가 죽어도 실제 상호작용과 살아 있는 사공의 증언은 이어진다. 열셋·아이 둘은 과거 하구행의 대상이며 현재 생사는 미확정이다. 지도 대조는 기존 지도와 현재 강 방향을 한 화면에 놓고 새 종이를 수집하지 않는다. 선택 화자의 사망으로 지도 조작을 잠그지 않는다.

생존 동행의 기존 옛길 실제 집결 뒤 저널을 기록한다. 새 배 완주/증언/지도 proof와 마지막 실제 생존 명단이 있는 사용자에게만 완료 후 쉼터 원고를 제공한다. 막종료 서술은 각 줄의 실제28/29/30 증거를 별도로 확인한다. 과거 막종료/쉼터 커서는 한 번 재정렬하고 새 커서는 저장한다. 장소 설명 조회는 arrival once를 소비하지 않는다.

production App/Engine 검사가 두 실제 항차와1230px 항행, 네 명 하선, 곽진 귀항/재합류, 유한 공격의 실제 행동 admission, 항행·승선 안내·사공 대사 저장, 설오 사망 뒤 핵심 증언과 지도·생존자 집결을 통과했다. `act23-v4-reviewed30-browser.py`의 실제 Chromium 검사도 두 항차·네 명 실제 하선·곽진 귀항/재합류·실제 행동 admission·항행/안내/사공 커서 저장·390px 화면을 통과했고 pageerror는0이다. 전투 적 사망·영웅 안내 위치는 fixture이며 배/NPC 좌표를 주입하지 않는다.

`A3.S30.ENDING.01/02`와 같은 묶음의 `.03`은 두 항차·현재 사공의 과거 증언·지도 대조를 모두 끝낸 뒤, 생존한 실제 동행이 곽진 옆의 동쪽 해안/옛길 접근부에 접지 집결한 시점에 재생한다. 원본 상세기획 30장7번은 “현재 물길과 옛 이송도” 확인 뒤 곽진이 주민 보호에 남고 동행이 다음 여정으로 나서는 순서다. 승인 원고의 호송·과거 행선지 확인·생존 동행 집결 조건을 이 실제 출발 전 집결에 연결했고 본문·condition·audience·delivery·once·group·order는 그대로 보존했다. 곽진·배·주민을 대사 위치로 옮기지 않는다.

지도 확인 뒤 승인된 OBJ.04의 안내 대상만 곽진 옆 접근부로 제시한다. 모든 생존 동행의 접지와 실제 곽진으로부터360px 이내를 확인하고, 각 행은 원래 화자의 실제 생존/출연/거리 가드도 통과해야 한다. 고지대 기존 `old-road` marker `(9450,4300)`는 별도의 기존 물리 완료 목표로 유지했다. 이별 뒤 안내는 그 목표로 돌아간다. 저널/장 완료도 원래 높은 옛길 집결 전에는 성립하지 않는다. 접근부 집결을 건너뛰어 기존 높은 목표로 간 저장은 먼 곽진의 두 행을 생략하며 설오의 살아 있는 출발 의향만 재생할 수 있다. 이 선택 이별이 죽은 휘겸/먼 곽진 때문에 길을 잠그지 않는다.

`act23-v4-reviewed30-farewell-compat.mjs`와 `act23-v4-reviewed30-farewell-browser.py`는 실제 native 배 왕복/네 명 하선/곽진 귀항·재합류/유한 wave 행동 admission/사공·지도 이후 실제 near-Gwakjin 조건을 검사했다. `.01→.02→.03` 원고와 순서를 보존하고 `.02`의 localStorage reload·390px 화면, 대화 전후 배/NPC/자원 동일, 이별 후 별도 기존 높은 출구를 확인했다(pageerror0). 접근부 우회 시 먼 발화 생략과 완료 소프트락 없음은 모델로 확인했다. 전투 사망·영웅 안내/집결/출구 위치는 fixture이며 NPC/배 좌표·구조 수를 주입하지 않았다. 화면은 `_local/reports/act23-v4/reviewed30-farewell-browser/`에서 직접 확인했다.

## COMPAT30: 승인 본문 없는 구판 표시의 생략

최종 `HONRO-CH30-reviewed-final.json`와 부모 판단로그의 아래3항목은 모두 `LEGACY_ONLY`, `canonical_ids: []`이며 본문 `text`가 없다. 최종 rows에 대응하는 구판 대체 본문도 없다. 미검수 초안의 내용을 적용하지 않았다.

| 정확한 ID | 예정 표시 슬롯 | 적용 정책 |
|---|---|---|
| `COMPAT.30.REST` | `restEndings.30.required.0` 대체 | 배 완주·증언·지도 proof 없는 구판에서는 새 완료 쉼터 대사를 생략 |
| `COMPAT.30.ENDING.01` | `actEndings.30.lines.0` 대체 | 구판에 신판 배 출항/한태록 체험을 새로 부여하는 회고 생략 |
| `COMPAT.30.ENDING.03` | `actEndings.30.lines.2` 대체 | 구판에 현묵의 진목 잔영 체험을 새로 부여하는 회고 생략 |

이미 저장된 승인 회고/여정첩의 `profile.record`와 기존 서사 기록은 삭제·재작성하지 않는다. 완료·성장·파티·seen은 보존한다. 과거 막종료/쉼터의 진행 중 표시 커서만 새 증거별 원고 목록에 한 번 재정렬한다. 새로운 구조/사공/지도/잔영 proof는 구판 clear 값으로 만들지 않는다. 별도 실제28 기록함·29 잔영 proof가 있는 사용자는 각 증거에 해당하는 승인된 막종료 줄을 계속 받을 수 있다. 실제 신판30 proof가 있으면 원래 승인50행의 해당 분기와 각 화자 가드를 사용한다. 여정 UI 상태 자체가 없는 구판 완료 저장도 예외 없이 읽도록 전용 migration의 null 가드를 고쳤다.

이3개는 구판 회고의 표시 대체 슬롯이며 새로운 필수 진행 목표나 구조/행선지 증언이 아니다. 생략해도 기존 완료·해금·성장은 유지되고, 신판 본선의 필수 사공 증언·과거13명/아이2명의 행선지·현재 생사 미확정·지도 연결을 빼지 않는다. **구판 사용자에게 새 대체 회고를 보여 주려면 이3개 ID의 별도 최종 채택 본문이 필요하다.** 현재는 부모가 허용한 근거 없는 줄 생략 정책으로 닫았으며, 새 문구 작성 요청은 하지 않는다. 모델 검사와 실제 Chromium localStorage reload는 여정 UI 상태 없는 구판 저장의 역사 기록/성장/seen 동일성, 커서 재정렬, 표시3개 생략과 새 proof 미생성을 확인했다. 공통 bark 어댑터는 통합 담당 소유로 수정하지 않았다.
