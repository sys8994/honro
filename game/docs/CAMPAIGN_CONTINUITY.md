# 캠페인 연결·저장 회귀

`npm run test:campaign-continuity`는 하나의 프로필을 1–20장에 순서대로 이어서 실제 `App.launch/mount/stopBattle/continue/outcome/persist`와 저장 로더를 검사한다. 매 장마다 이미 얻은 성장과 해금 상태를 이어받으며, 별도 초기 프로필로 장을 독립 실행하지 않는다.

## 검사하는 동작

- 이전 장 완료 전 다음 장 진입 차단, 장별 동행 구성, 2장/5장 모집과 10→11장 소단 합류
- 각 장의 피해·기력·이동력·아이템·목표 상태·장부 위치·지형·배치를 저장한 후 새 App 인스턴스에서 이어가기
- 완료 처리의 중복 호출, 재방문 보상 중복 방지, 패배 후 획득 성장과 지급 예산 보존
- 이전 1막 완료 저장의 2막 합류 복구, 디버그 결과와 일반 진행 격리
- 프로필 schema 1–4 읽기, 오래된 전투 revision 폐기 시 성장과 완료 기록 보존

검사 결과와 각 장의 이어진 프로필 요약은 `_local/reports/campaign-continuity/summary.json`에 생성된다. 결과에는 검사 유형, 원본 해시와 한계를 함께 넣는다.

## 증거의 범위

이 검사는 전투 상태를 직접 구성하는 명시적인 fixture 회귀다. 승리·패배는 전투로 얻지 않고 최종 상태로 설정하며, 브라우저 DOM 이벤트·그림·대화 화면은 test double이다. 따라서 실제 입력으로 20장을 완주했다거나 브라우저의 localStorage, 터치 입력, 성능을 검증했다는 증거가 아니다. 기존 장별 정상 엔진 전투 기록과 실제 공개 빌드 브라우저 검수는 별도 증거로 유지한다.

제작 파이프라인은 이 결과를 기술 회귀로만 소비해야 한다. 실제 플레이 요구를 이 fixture로 충족시키거나 화면 검증으로 바꿔 표시해서는 안 된다.
