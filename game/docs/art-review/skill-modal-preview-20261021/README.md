기반 master `ee73add5`, 1차 완료 커밋 `e7406cc31eef34ba86dbbaec911dc10c51a1e4a7`. 최종 변경은 이 보고서와 함께 별도 브랜치 `codex/skill-modal-preview-audit`에 보존한다. master/Pages에는 아직 통합하지 않았다. 2장·12장 등 다른 작업과 통합 순서를 부모가 조정한 뒤 최신 원본을 병합하고 생성물을 다시 빌드해야 한다.

## 변경과 검수 순서

1. 모달은 하나의 외곽 테두리·배경·clipping 안에 비스크롤 헤더와 별도 overflow 본문을 둔다. 제목·X·SP 바·장착/회수/강화가 헤더에 있다. 본문이 헤더 뒤에 들어가지 않고 증감/장착 뒤 본문 위치와 시연을 보존한다. 시작/중간/끝, 360/390/1280 및 가로 844×390, 긴 제목, 44px 버튼, 비대칭 safe area 48/24/16/12px, 0/잠금/최대/SP소진/장착 상태를 실제 브라우저에서 확인했다.
2. 코드상 효과와 조건을 [84개 계약](../../SKILL_PREVIEW_SCENARIOS.md)에 매핑하고 경지 1/8의 실제 결과를 검사했다. 쇄암시는 실제 목재 파괴, 삼재파는 천장 반사 뒤 세로 폭 200 이상 삼각형, 회복은 실제 HP/기력/이동력, 분혼은 소환령 HP 또는 방호의 실제 분담 등으로 검사한다. 단순 피해 수로만 모든 스킬을 합격시키지 않는다. 공전검기는 projectile 1개 안의 실제 orbit.blades 5~9개를 센다.
3. 모든 시연을 데스크톱과 모바일에서 렌더하고 저장 불변·오류·접지를 확인했다. 지상 늑대는 실제 floor/platform 충돌면을 쓰고 공중 표적은 실제 bat 종류다. 전로시는 올려 쏜 뒤 turnArrow가 한 번만 성공하고, 이후 다시 입력할 수 없으며 실제 궤적과 명중을 확인했다. 상시 기예는 조건을 실제 입력으로 발동시키고 같은 조건의 미습득 엔진과 관찰값을 비교한다.
4. 최종 시각 검수에서 비행 뒤 계속 축소된 화면과 늦은 줌으로 순간 효과가 잘리는 문제를 정리했다. 카메라는 실제 현재 객체와 geometry로 즉시 확대 시야를 확보하고, 동작 뒤 부드럽게 돌아온다. 캡처도 결과 수치만 확인한 늦은 프레임 대신 실제 효과 충족 프레임에 남겼다. 최종 전체 렌더/모달/저장 검수를 마친 동일 원본의 생성 파일을 빌드했다.

## 보존 범위와 한계

원래 4계열 목록과 SP 바는 변경하지 않았다. 스킬 수치/효과/성장/저장/캠페인 지형/에셋·배경·캐릭터 이미지는 변경하지 않았다. 시연의 초기 표적 HP·위치·자원과 입력 정책만 장면에 맞게 정하며 모든 공격/명중/회복/소환/패시브 결과는 실엔진이 계산한다. 절명시 표적은 초기 손상 상태와 중립 피해 반응을 사용하는 훈련 표적이다. 미습득 기예의 격리 시연은 경지 1을 사용한다. 캐릭터 조합과 실제 캠페인의 피해량을 검증한 것은 아니다.

실제 휴대폰 하드웨어가 아닌 Chromium 터치 및 safe-area CSS 변수 에뮬레이션이다. 전체 84개의 전투 판정을 캠페인 모든 지형에서 검증했다는 뜻이 아니다. 기존 23장 성장 저장 fixture 실패는 이전 master에서도 재현된 별도 이슈이며 해당 테스트/판정을 변경하거나 완화하지 않았다. master/Pages 통합 및 공개 화면 검증은 이번 단계에서 수행하지 않았다.
