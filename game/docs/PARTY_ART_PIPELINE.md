# 네 동행 캐릭터 제작·검수 기준

현재 설오·담허·휘겸·소단은 **몸을 늘리고 얼굴 크기를 남성 셋 ≈ 동일, 소단은 조금 작게 맞춘 v009**다(2026-09-30). 최신 추가 요청이 최초의 ‘머리 크기는 그대로’보다 우선한다. 앵커 수는 512/541/480/511로 직전과 정확히 같다. v008의 얼굴 형태·이목구비 상대 배치·팔레트는 유지하며 머리 파트 전체를 균일하게 확대/축소한다. 몬스터의 3배 예산과 구분한다.

`proportions.mjs`가 발목을 기준으로 몸 경로·관절·전체 포즈 목표를 함께 변환한다. 먼저 머리·머리카락을 위치만 이동하고, 마지막 `head-scale.mjs`가 새 머리 pivot을 중심으로 크기를 맞춘다. 휘겸은 어깨 간격과 가슴을 30% 넓히고 주먹 10%, 신발 폭 12%, 검날 길이 12%를 보완한다. 손잡이와 발바닥 기준점은 유지한다. 담허 지팡이는 새 손 높이와 지면에 맞춰 늘린다.

### 얼굴 크기 기준

장식 전체의 외곽 대신 `face_plane`을 같은 게임 배율로 그려 얼굴 높이를 측정한다. 갓, 머리카락, 상투/쪽머리, 수염을 측정에서 제외한다. 휘겸의 넓은 턱과 설오의 긴 얼굴 등 고유 형상은 유지하므로 얼굴 폭을 강제로 같게 찌그러뜨리지 않는다. 가려진 두개골 부피의 의학적 측정이 아니라 같은 시점의 게임 얼굴 크기를 비교하는 제작 기준이다.

| 인물 | v008 대비 머리 균일 배율 | 같은 배율의 얼굴 높이 | 얼굴 폭 |
|---|---:|---:|---:|
| 설오 | 0.96 | 45.375 | 36.0 |
| 담허 | 1.03 | 44.750 | 39.75 |
| 휘겸 | 1.22 | 44.375 | 45.0 |
| 소단 | 0.88 | 39.250 | 31.5 |

표의 높이/폭은 415 벡터 단위 표시 기준에서 8배 래스터 측정 후 환산한 값이다. 남성 얼굴 높이 차이는 최대 약 2.3%, 소단은 남성 평균보다 약 12.5% 작다. 머리카락·갓·이목구비·선 두께를 함께 균일 변환하고 얼굴 기준점과 머리꼬리 pivot도 같은 변환을 적용한다. 이 비율이 동작에서 유지되는지 별도로 검사한다.

`canvas.visualHeight` 415/415/425/399는 **기존 몸 표시 배율의 기준**이다. 이를 새 키로 덮어쓰면 키 증가가 상쇄되므로 유지한다. 새 `presentationHeight`는 변경된 머리/갓까지 포함하는 여백을 확보하고 체력바·상태 표시·정보창/윤곽 마스크에만 쓴다. 실제 유닛 `h/r`, 충돌과 발사 위치는 바꾸지 않는다. 공방 전후 비교는 같은 배율, 256/128/96/64px 축소 검토는 새 전체 높이를 기준으로 한다.

원래 생략되었던 어깨·팔꿈치·손·발 목표를 v008 리그에서 먼저 풀고 새 비율에 옮긴다. 해석기가 고정 `[240,185]` 대신 에셋의 `rig.bindThorax`를 읽는다(이전 에셋은 기존 기본값 사용). 공격 이벤트·동작 길이·루프·접지 구간은 보존한다. `face.authoringMap`은 제작 입력에서 복제해야 한다. 공유 참조를 수정하면 같은 프로세스의 두 번째 빌드에서 얼굴이 다시 이동한다.

## 제작 입력과 좌표 기준

- 실제 입력은 사용자가 제공한 `260916_설오_캐릭터시트.png`, `260916_담허_캐릭터시트.png`, `260916_휘겸_캐릭터시트.png`, `260916_소단_캐릭터시트.png`다. `tools/party-forge/references/`에 원본 그대로 보관한다. 제작용 PNG는 게임 HTML에 넣지 않는다.
- `references.json`에 각 PNG의 SHA-256·크기·얼굴 crop·게임 얼굴 crop·형태 지침을 기록한다. 생성기가 파일 해시를 검사한다. 휘겸의 초상은 왼쪽을 향하므로 제작과 비교에서 함께 반전한다.
- `portrait-shapes.mjs`는 **원본 PNG의 픽셀 좌표**로 얼굴 윤곽, 귀, 머리, 눈썹, 두 눈, 코, 입, 수염을 작성한다. 이름 있는 경로와 `part`가 파트 마스크다. 제한된 수의 곡선으로 직접 작성하며 자동 추적의 작은 조각이나 중복선을 가져오지 않는다.
- 캐릭터마다 한 개의 균일 배율과 평행 이동으로 게임 좌표에 옮긴다. 눈·입을 따로 임의 조정하거나 얼굴 가로/세로를 다르게 늘리지 않는다. `portraitMaps`의 원본/게임 기준점·배율·반전·이목구비 기준점이 rig JSON의 `face.authoringMap`에 남는다.
- 몸은 고정 v006 원본 `shared/assets/party.v006.runtime.js`에서 v007의 복식·모션 개선과 v008 시트 얼굴을 재현한다. 직전 비교 원본은 `tests/fixtures/party-v008.runtime.js`이며 SHA는 `references.json`에 고정한다. 과거 compact 설오 시안은 사용하지 않는다.
- viewBox `[-100,-140,880,680]`, 발 기준 설오 `[240,479]`/나머지 `[240,480]`, 표시 배율 기준 높이를 유지한다. 가려진 관절은 v008의 해석된 위치와 새 몸 배율을 따른다. 얼굴의 균일 변환·실제 연결부·접지·이벤트 시점을 검사한다.

## 앵커와 용량 예산

| 인물 | v008 → v009 앵커 | 변화 | 곡선 제어점 | 경로 / 색상 |
|---|---:|---:|---:|---:|
| 설오 | 512 → 512 | 0% | 71 | 92 / 18 |
| 담허 | 541 → 541 | 0% | 69 | 90 / 17 |
| 휘겸 | 480 → 480 | 0% | 53 | 93 / 20 |
| 소단 | 511 → 511 | 0% | 93 | 94 / 21 |

M/L/Q/C의 명시된 끝점을 윤곽·내부 경로 모두에서 집계한다. Q/C 제어점과 닫기 Z는 합산하지 않는다. 생성 시 v008 대비 **정확히 1배**를 강제한다. 렌더러가 계산하는 활시위·화살은 고정 에셋 수에서 제외한다.

v009 에셋 런타임은 144,669 bytes로 v008 82,549 bytes보다 62,120 bytes 늘었다. 좌표 정밀도와 명시적인 관절 목표가 증가분이며 경로·제어점·색상 수 증가는 없다. 공통 리그 런타임은 17,562 bytes다. `metrics.json`에 캐릭터별 raw/optimized SVG·rig/animation bytes·LOD 경로 수·제작 소스 SHA를 남긴다. PNG 참조와 이전 원본은 공방 전용이다.

## 형태와 팔레트

- 설오: 길게 갈라지는 앞머리·높은 묶음머리, 가는 턱, 낮은 눈꺼풀과 얇은 입. 코가 외곽에서 튀어나오는 옛 측면 다각형을 없앤다. 겉옷은 어두운 회록색, 하의는 시트의 어두운 색으로 맞춘다.
- 담허: 회색 관자와 짧은 상투, 무거운 눈꺼풀, 짧은 콧수염·턱수염. 예전 긴 흰 수염을 재사용하지 않는다. 먹빛 겉옷과 회색 안감·밝은 옷깃을 구분한다.
- 휘겸: 갓 아래 두 눈, 넓은 턱, 짧은 수염, 뺨의 흉터. 갓과 머리의 틈을 닫고 갓끈은 눈·입을 피한다. 남색 무복을 유지한다.
- 소단: 둥근 머리 덩어리, 긴 앞머리와 낮은 쪽머리, 작은 눈·코·입, 부드러운 턱. 턱 아래를 검은 머리로 가리지 않고 목과 귀를 연결한다. 상아색 겉옷에 **옷깃 안쪽·치마·소매/신발의 연보라색 포인트**를 복원한다. 붉은 머리끈을 유지한다.

피부는 바탕/그늘/따뜻한 면, 머리는 바탕/큰 밝은 면, 눈과 입은 제한된 선과 면으로 구분한다. 작은 눈에 과도한 흰자·반사광을 추가하지 않는다. 텍스처 필터와 래스터 삽입은 없다.

## 작성·런타임·모션

`recipes.mjs`가 v006을 복제해 v007 몸·모션을 만들고, `sheet-faces.mjs`가 머리/목/머리꼬리를 시트 경로로 교체하고 색상을 적용한다. `proportions.mjs`가 몸·관절·포즈를 재배치한 다음 `head-scale.mjs`가 최종 얼굴 크기를 맞춘다. `build.mjs`는 SVG·rig JSON·animation JSON·런타임을 `shared/assets/party/`에 생성한다. 생성 SVG와 두 HTML만 직접 수정하지 않는다.

`shared/runtime/party-rig.js`의 머리 회전·이동만 허용하는 구조를 유지한다. v008 머리 pivot `[240,143]`을 얼굴과 같은 거리만큼 옮긴다. 몸통의 비균일 늘어남/전단을 얼굴에 적용하지 않는다. v007에서 줄인 이동 발 들기·설오/휘겸 몸통과 옷자락 흔들림을 새 몸 비율로 옮기며 접지·무기 연결·동작 시간을 보존한다.

`rebuild-game-adapter.mjs`는 엔진의 이동·충전·발사·피격·점프를 읽는다. 물리 좌표·충돌 크기·전투 수치·세이브는 미술 작업에서 바꾸지 않는다. 엔진 점프를 시각 root 이동으로 중복 적용하지 않는다. Game·Stage View·Playtest는 `shared/build.mjs`의 동일한 에셋·공통 렌더러를 쓰며 캠페인 적 소단에도 적용된다.

화면 높이 80px/160px 기준의 3단계 LOD를 유지한다. 주요 윤곽·눈·입은 남기고 작은 귀선·주름·봉제선을 생략한다. SVG는 상세 경로를 보존한다.

## 시각 검토와 반복

v008의 얼굴 반복 수정 이후 v009는 전신 비율 → 휘겸의 손/신발/검 보완 → Game/Workshop 일치 → 추가 머리 크기 요청에 따른 두 후보 비교와 최종 얼굴 정렬 → 작은 크기·모션 순서로 검토했다. `_local/reports/party-forge/`에 전후·얼굴·크기·5동작 도감과 시각 관찰을 남긴다. 자동 검사 통과를 미술 품질 승인으로 판정하지 않는다.

1. **시트/벡터 직접 비교**에서 머리 덩어리, 귀·턱 길이, 눈 간격과 높이, 코·입, 수염/머리카락을 본다. v008/현재 전신·얼굴도 비교한다.
2. 256/128/96/64px, 밝은/어두운 배경, 좌우, 단색 실루엣을 확인한다. 64px에서는 표정보다 머리·갓·리본·도구의 식별을 본다.
3. idle/attack/move/jump_fall/hit 스크럽과 6시점 도감에서 얼굴 비율·목 틈·모자 연결·손/무기·발 접지·루프 경계를 본다.
4. 4인 × 5동작 × 101시점의 유한 행렬·머리 비율·관절 연결·팔 도달·대기 발 고정·루프와 양방향 조준 시위를 검사한다. PNG 해시/crop, 두 눈과 입의 얼굴 내부 위치, v008 머리의 균일 변환과 남성 셋/소단의 얼굴 크기 관계, 게임 내 체력바 간격도 검사한다.
5. 두 HTML의 실제 발사 버튼 누름/뗌, 엔진 피해·점프를 확인한다. 세 화면 픽셀 일치·렌더링 상태 불변·편집 프로젝트 보존을 검사하고 실제 화면을 연다.
6. 다른 브라우저 부하 없이 전체 `npm run verify`를 실행한다. 구조적 통과와 직접 본 미술 평가를 구분한다.

```powershell
npm.cmd run build
npm.cmd run test:party
# _local/reports/party-forge/index.html 열기
npm.cmd run verify
```

공방에서 인물·동작·시점·방향·배경·실루엣·관절을 바꾸고 제작 소스 해시가 붙은 메모를 저장할 수 있다. `references.png`는 시트/현재, `faces.png`와 `comparison.png`는 v008/현재, `headLineup.png`는 같은 배율의 네 머리와 장식 없는 얼굴 면, `*-sizes.png`는 축소 검토다. `browser.json`은 63개 구조/연결 검사, `VISUAL_REVIEW_v009.md`는 관찰과 수정 이력이다. 보고서는 `_local/reports/party-forge/`, 직전 이미지는 `_local/archive/party-v008/`에 둔다.

별도 정면 얼굴·립싱크·다양한 표정 세트·천 물리 시뮬레이션은 제공하지 않는다. 64px에서 세밀한 표정까지 읽는 것을 목표로 하지 않는다. 모든 실기기와 캠페인 모든 프레임을 수동 검수했다는 의미도 아니다.
