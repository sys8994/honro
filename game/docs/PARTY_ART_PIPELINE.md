# 네 동행 캐릭터 제작·검수 기준

현재 에셋은 설오·담허·휘겸·소단 v007이다. 2026-09-29 요청에 따라 **직전 게임의 v006 원본 대비 약 2배의 앵커**로 얼굴·복식·손·도구를 개선했다. 몬스터의 3배 예산과 구분한다. 과거 거절된 compact 설오 시안은 사용하지 않는다.

## 원본과 제작 입력

- 고정 입력: `shared/assets/party.v006.runtime.js`. 원본 SHA-256, 캐릭터별 앵커 수·발 기준점·크기는 `tests/fixtures/party-baseline.json`에 있다. 원본이 달라지면 생성기가 실패한다.
- 입력 이미지는 이 원본을 실제 리그로 렌더한 전신·얼굴·이동·공격 화면이다. 외부 그림을 새로 추적하지 않았다. 전후 공방은 원본 API와 에셋을 격리해 같은 동작·높이로 비교한다.
- 원본의 `paths[].part`가 파트 마스크 역할을 한다. 머리/목/머리꼬리 경로는 다시 작성하고, 나머지는 기존 의미 있는 파트 위에 면·주름·봉제선·매듭을 작성한다. 가려진 팔꿈치·무릎·손목은 원본 리그의 pivot/parent와 IK 길이를 근거로 유지한다.
- 원본 viewBox는 `[-100,-140,880,680]`, 발 기준점은 설오 `[240,479]`, 나머지 `[240,480]`이다. 기준 높이 415/415/425/399를 유지한다. 얼굴 비교는 각 프레임의 머리 중심을 따라 확대하며 전신 비교에서 머리 장식까지 확인한다.
- 색상 역할: 원본 직업별 옷/무기/머리 색을 유지하고 `skinLight/skinShade/skinWarm`으로 얼굴 면, `feature/eye/eyeLight`로 이목구비, `clothLight/clothShade`로 옷 주름, `leatherLight/metalLight`로 도구 재질을 나눈다. 사진 필터·래스터 삽입은 없다.

## 예산과 얼굴 구조

| 인물 | v006 앵커 → v007 | 배율 | 곡선 제어점 | 경로 / 색상 |
|---|---:|---:|---:|---:|
| 설오 | 268 → 514 | 1.92× | 54 | 102 / 17 |
| 담허 | 267 → 517 | 1.94× | 78 | 96 / 16 |
| 휘겸 | 228 → 458 | 2.01× | 44 | 97 / 18 |
| 소단 | 261 → 497 | 1.90× | 72 | 97 / 19 |

M/L/Q/C의 명시된 끝점을 윤곽과 내부 경로 모두에서 집계한다. Q/C 제어점과 닫기 Z는 앵커 수에 합산하지 않는다. 생성 시 원본의 **1.9~2.1배**를 강제한다. 기존 직선을 의미 없이 분할해 수를 채우지 않는다. 렌더러가 계산하는 활시위·화살은 고정 에셋 예산에서 제외한다.

얼굴은 머리 전체·관자·광대·턱·귀를 먼저 잡고, 눈썹/눈꺼풀/동공·코·입 순서로 작성한다. 공통 작성 좌표는 눈 `[252,114]`, 코끝 기준 `[264,124]`, 입 `[255,132]`, 턱 `[251,143]`, 귀 `[230,118]`, 목 `[240,151]`이다. 곡선 윤곽과 실제 코끝은 캐릭터별로 달라진다. 눈과 입이 얼굴 경로 안에 있는지 검사한다.

- 설오: 짧게 정리한 턱과 머리 매듭, 초록 겉옷·견갑·화살통·활의 재질을 구분한다.
- 담허: 회백색 눈썹·콧수염·긴 수염, 눈가와 광대의 나이, 겹친 삼베와 호리병을 표현한다.
- 휘겸: 단단한 턱·짧은 수염, 갓의 테두리·관·끈, 남색 무복·검날·칼집을 구분한다. 갓끈은 눈과 입을 가리지 않도록 턱 아래로 지난다.
- 소단: 부드러운 턱, 낮은 머리끈·머리꼬리, 자주/상아색 옷의 층, 부적과 방울의 면·테두리를 표현한다.

## 제작 경로와 모션

`tools/party-forge/recipes.mjs`가 원본을 복제해 디자인을 작성한다. `build.mjs`가 SVG·rig JSON·animation JSON·런타임 데이터를 함께 내보낸다. 결과는 `shared/assets/party/`다. 생성 SVG나 HTML만 고치지 않는다.

`shared/runtime/party-rig.js`는 v006의 공통 행렬·목표 좌표 IK·활시위 제약을 분리한 렌더러다. 머리 회전축을 목 위 `[240,143]`으로 옮겼다. 몸통 변환으로 머리의 위치를 계산하되 머리 자체에는 회전·이동만 적용한다. 몸통의 늘어남/전단이 눈·코·턱의 비율까지 바꾸던 문제를 막는다.

이동 시 공중에 있는 발의 들어 올림을 기존의 60%로 줄인다. 설오·휘겸의 골반/흉곽 수직 흔들림은 65%, 옷자락 흔들림은 75%로 조정한다. 발 접지 시점·보행 주기와 기존 idle/attack/jump_fall/hit 동작은 유지한다. 손목과 도구의 부모 연결을 유지하며 손의 엄지·주먹 윤곽을 보완한다.

`rebuild-game-adapter.mjs`는 엔진의 이동·충전·발사·피격·점프를 읽는다. 어댑터의 상태 연결은 이번에 변경하지 않았다. 실제 점프 높이와 이동 좌표는 엔진이 담당하며 시각 root 이동을 중복 적용하지 않는다. 전투 수치·물리 충돌 크기·세이브는 바꾸지 않는다.

작은 크기에서는 중요 윤곽과 이목구비를 유지하고 잔주름·봉제선만 생략한다. 실제 화면 높이 80px/160px를 기준으로 3단계 LOD를 선택한다. SVG는 전체 상세 경로를 보존한다. 게임·Stage View·Playtest는 모두 `shared/build.mjs`의 같은 에셋과 렌더러를 사용한다. 캠페인의 적 소단도 새 소단 에셋으로 표시된다.

## 검수 순서

1. 원본/현재 전신과 얼굴을 같은 높이로 비교한다. 코·턱 돌출, 눈·입 위치, 목 연결, 인물 구분을 본다.
2. 256/128/96/64px, 밝은/어두운 배경, 좌우 방향, 단색 실루엣을 확인한다. 64px에서는 수염·갓·리본·도구가 식별 기준이다.
3. 5개 동작을 스크러빙하고 6시점 도감으로 팔·다리 연결, 손/도구, 발 접지, 루프 경계, 옷자락을 본다.
4. 캐릭터마다 5개 동작 × 101시점에서 머리의 비율 유지·관절 연결·유한한 행렬·팔 도달 범위·대기 발 고정·루프 연결을 검사한다. 활은 좌우 × 4각도 × 3충전량에서 손과 시위 접촉을 검사한다.
5. 두 HTML에서 실제 발사 버튼을 누르고 떼어 충전/공격 상태를 확인하고 실제 엔진 피해·점프를 연결한다. Game/Stage View/Playtest 그림 일치, 렌더링 전투 데이터 불변, 편집 프로젝트 보존을 검사한다.
6. 다른 브라우저 부하 없이 전체 `npm run verify`를 실행한다. 구조적 검사 통과와 미술 평가를 구분해 기록한다.

```powershell
npm.cmd run build
npm.cmd run test:party
# _local/reports/party-forge/index.html 열기
npm.cmd run verify
```

공방에서 인물·동작·시점·방향·배경·실루엣·관절을 바꾸고 제작 소스 해시가 붙은 검수 메모를 저장할 수 있다. `metrics.json`은 path/color·원본/최적화 SVG bytes·rig/animation bytes와 소스 해시, `browser.json`은 수치 검사, `VISUAL_REVIEW.md`는 직접 본 평가를 담는다. 보고서·이미지는 `_local/reports/party-forge/`, 과거 원본 복사본은 `_local/archive/party-v006/`에 둔다.

현재는 기존 측면 벡터 스타일의 개정판이다. 모든 표정·별도 정면 얼굴·립싱크는 포함하지 않는다. 64px에서 세부 표정까지 읽히는 것을 목표로 하지 않는다. 의상은 의미 있는 파트의 변환 애니메이션이며 천 시뮬레이션이 아니다. 모바일 실기기와 전체 캠페인의 모든 프레임을 수동으로 확인했다는 의미도 아니다.
