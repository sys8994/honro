## 확인된 원인과 구현 위치

`main.js`는 전투 모달을 음악 일시정지 사유로 전달했다. 이를 제거했다. ESC만으로 다음 곡이 선택된다는 제보의 정확한 조건은 기존 기록에서 재현되지 않았으며, 이번 검사는 동일 스트림·곡·계속 증가하는 재생 시각을 확인한다.

허공터는 기존 `resetPractice()`가 적의 체력을 복구하고 적 턴을 건너뛰었다. `world.js`가 만드는 새 허공터에 `practiceCombat`을 표시하고 `engine.ts`의 정상 전투 턴을 통과하게 했다. 독립된 훈련 전용 물리/AI 루프를 추가하지 않았다. 별도 단위 검사에서 쓰는 구형 practice fixture는 기존 자동 리셋 경로를 유지한다. 넓은 다각형 지형을 줌아웃했을 때 바깥 지면 높이와 하단 채움이 어긋나는 부분도 공통 `renderer.js`에서 실제 표면 기준으로 고쳤다.

화살 조준선은 `skillVisuals.ts`의 화면 배율 보정과 대표 경로 선택을 사용한다. `skillMechanics.ts`의 전로시 예측은 복제한 전투에서 실제 `turnArrow`와 투사체 스텝을 실행하며 원본 HP·지형·RNG를 변경하지 않는다. 화면 예측은 30Hz 단위로 캐시한다. 발사 버튼/E 입력은 같은 목표 좌표를 사용한다.

담허 기본 기파에는 `rebuild-game-adapter.mjs`의 정적인 qi 그림이 공통 투사체 렌더러보다 먼저 적용됐다. 이 우선 그림을 제거하고 `skillVisuals.ts`에 담백한 기류를 그린다. 폭발의 공통 burst/ring·접촉 inkImpact·대상별 inkImpact 중복을 단일 `qiBurst`로 정리했다. `fireBloom`은 화호/연폭호에 쓰며 새 폭발 효과는 각각 화면 시간 0.55/0.85초 동안 재생한다. 기존 파문/번개와 같이 배속에서 너무 짧아지지 않고 일시정지에서는 멈춘다.

축지진목은 첫 발사로 하나만 설치되어 연결 상대가 없었다. 추가로 정확한 도착 좌표가 막히면 아무 안내 없이 실패했다. 첫 연결 쌍과 주변 안전 지면 탐색을 적용했다. 자리 자체가 없으면 안내하고 텔레포트를 거부한다. 저장된 진목과 턴 사용 기록은 기존 필드를 그대로 사용한다.

## 저장과 한계

저장 스키마·skillRevision·성장 배분 초기화는 없다. 캠페인과 Workshop 작성 맵은 유지하며 허공터의 선택/새로고침이 캠페인 프로필을 바꾸지 않는지 검사했다. 빙호 지연은 발사 시 투사체에 저장하므로 비행 중 복원해도 유지된다. 기존에 지연이 명시된 비행 중 빙호는 저장된 지연을 존중한다.

검사는 격리한 프로필·통제 전투·실제 브라우저 입력을 사용했다. 사망과 적 턴 조건 일부는 상태를 구성해 재현했다. 전 캠페인을 정상 육성으로 수동 완주한 결과는 아니다. 예상 궤적은 현재 전장 상태에 기반하며 이후 적 이동과 지형 변화까지 예언하지 않는다. 실기기 모바일 GPU·터치 체감과 장기 밸런스는 이번 자동 검사 범위 밖이다.
