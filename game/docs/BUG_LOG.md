## HBUG-026 — Game / Workshop 공통화

- 증상: V2는 게임과 다른 지형·배경·유닛 renderer, 지면 탐색, 경량 이동 물리를 사용했다. Draft export는 좌표 반올림·node 축소를 수행했다.
- 원인: 별도 authoring/runtime 개념과 중복 구현. 플레이테스트에 실제 게임의 턴·투사체·AI·HUD가 없었다.
- 변경: shared 엔진/Scene/camera/compiler/unit factory를 사용한다. Stage 1~10은 RC21의 103개 exact polygon과 원본 상태를 canonical v3로 이관했다. 실제 게임 HTML을 iframe에 넣어 Playtest하고 Stop은 원본 편집 상태로 복귀한다. Element Studio visual/collision/socket을 실제 게임 경로에 연결했다.
- 검증: `tests/migration.mjs`(10 Stage × 3 난이도), `tests/integration.py`(Stage 1~10 픽셀 차이 0, 동일 420 tick 물리/투사체, 실제 유닛, 왕복, 모바일 HUD), `tests/editor-features.py`(20개 도구 검사), 성능 before/game/editor JSON. 상세 정확한 결과는 루트 VALIDATION.md.
- 한계: 모바일은 Chrome 에뮬레이션이다. 10 Stage 전체 수동 클리어·실기기 Safari는 미수행. 오래된 RC별 Node 검사 12개는 원본에서도 실패해 별도 비교 결과를 기록했다.

## HBUG-027 — 편집 왕복·진행 격리·Playtest 오디오

- 재현: 새 solid를 그린 후 export/import하면 detail 기본값이 추가됐다. 가져온 맵을 종료하면 테스트 프로필이 앱에 남았다. Playtest에서 실제 클릭해도 BGM starts=0이었다.
- 원인: 인간 생성과 import의 정규화 시점 불일치, imported profile 복원 누락, 엔진 기본 테스트 settings의 무음 값이 실제 앱 설정을 덮음.
- 변경: 인간/Agent transaction에 같은 canonical finalize를 적용했다. launchMap은 원래 프로필과 Stage를 보관하고 stopBattle에서 복원한다. 테스트 프로필에 원래 오디오 설정을 유지한다. 기존 캠페인 persist는 테스트 중 차단한다.
- 검증: edited geometry/material/ID 문자열 왕복, 가져오기 파일 입력·retry·localStorage 불변·원래 프로필 복원, iframe 실제 MP3 currentTime 증가와 Stop의 AudioContext/stream 폐기. `tests/authored.py`, `tests/audio-browser.py`, `tests/editor-features.py`에 재현 회귀를 남겼다.

## ART-260916 — 260916 설오의 실제 게임 연결 (철회)

- **최종 상태**: 사용자가 디자인 실패로 평가하고 이전 표시로 복구를 요청했다. 게임 빌드와 렌더러를 v006으로 되돌렸다. 아래 기술 검사 기록은 디자인 승인을 의미하지 않는다. compact 산출물은 실험 기록으로만 보존한다.

- **관찰/요청**: 새 시트의 compact 설오는 독립 시연에만 있고 게임은 이전 v006을 사용했다. 사용자가 실제 캐릭터 교체를 요청했다.
- **원인**: 새 리그는 `motion` 목표 보간 구조이며 기존 v006의 `animation` 구조와 호환되지 않는다.
- **수정**: `compact-game-adapter.mjs`가 설오의 실제 이동·점프·피격·충전·발사 이벤트를 읽는다. 0.32초 활 들기, 충전량별 당김, 양방향 조준, 즉시 화살 숨김, 동작 간 보간을 연결했다. 보간 중 최소 관절 길이를 침범하는 목표를 IK로 보정한다. 점프 lift를 제거해 물리 높이와 중복하지 않는다. `game/build.mjs`가 compact 에셋과 의존성 없는 런타임을 포함하고 `renderer.js`가 게임·HUD·초상에 사용한다. 다른 캐릭터와 물리·탄도·저장은 그대로다.
- **검증**: `compact-game-adapter.test.mjs` 3개(양방향 -85~90도 조준·관절 도달·시위 접점·고정 활팔·상태 전환·배속별 걸음·엔진 불변), `rebuild-game.mjs` 실제 게임 31개, `game.mjs` 일반 전투 21개 통과. 실제 키/버튼으로 이동·점프·충전·발사·표적 피해·다음 턴을 확인했다. 모바일 크기, 초상, 다른 세 캐릭터, 오프라인 요청 0건, 브라우저 오류 0건도 확인했다. [리그 연결 결과](../../tools/honro-vector-forge/reports/seoro-260916/game/integration.json), [일반 게임 결과](../reports/browser-qa.json).
- **한계**: 브라우저 자동 검사와 대표 화면 검수다. 실제 기기의 터치·성능과 전체 캠페인 플레이를 대신하지 않는다. 캐릭터 외형의 사용자 실플레이 검수는 남아 있다.

## HBUG-025 — 행동 제한 이유와 기절 지속 표시

- **날짜/상태**: 2026-09-19 / 구현·상태 전환·브라우저 검증.
- **원인**: 기절은 턴 시작에 `stun`을 소비하고 `acted=true`로 바꾼다. 따라서 이후에는 일반 행동 완료와 구분할 정보가 없고 순간 텍스트가 사라진다. 플레이어 HUD는 체력 비율만 보여주고, 비활성 발사의 이유도 안내하지 않았다.
- **수정**: `stunnedRound`에 기절로 행동을 잃은 턴을 기록한다. 현재 기절과 다음 행동 기절을 구분하고 다음 턴에는 만료된다. 동행 칩은 기절·결박·저주·행동 완료를 표시한다. 기절한 동료를 누르면 이유를 알리며 행동 권한을 부여하지 않는다. 하단 상태 줄과 발사 설명에 기절, 결박 효과/횟수, 저주, 기력 부족, 재사용 대기, 착지 대기, 이동력 소진, 턴/공격 처리 상태를 표시한다. 결박은 공격 불가로 오표시하지 않는다. 적·동맹 정보 카드도 같은 상태 설명을 사용한다.
- **검증**: 실제 `stun → newRound` 소비 후 표시 유지와 다음 턴 회복, 결박 상태의 실제 발사, 자원/쿨다운 구별. 1440/844/390/320 폭에서 상태 텍스트·비활성 버튼·동료 클릭·넘침 없음 확인. 좁은 동행 칩에서는 상태 이름을 우선해 ‘기…’로 잘리지 않도록 했다.
- **저장/영향**: 선택 필드 `stunnedRound`만 추가하며 기절/결박의 게임 규칙은 바꾸지 않는다. 과거 저장에서 이미 소비된 기절은 원인을 추정해 복원하지 않는다. 접촉 복구로 상태이상을 치료하지 않는다.
- **파일**: `combat-status.js`, `ui-bridge.js`, `main.js`, `controls.css`, `unit-info.js`, `engine.ts`, `types.ts`. 상세 검증/화면은 [보고서](../reports/STAGE8_CONTACT_STATUS_2026_09_19.md).
