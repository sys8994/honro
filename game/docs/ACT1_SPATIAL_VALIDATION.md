# 1막 공간 개편 검증과 범위

2026-10-05. 실제 지도 작성 자료와 공통 production Engine/Canvas를 사용했다. 브라우저 Game·Stage View·Playtest의 DOM, HUD, 입력과 성능 검증은 이 환경에서 실행하지 못했다. Native Canvas 결과를 그 검사의 통과로 취급하지 않는다.

## 통과한 검사

- `npm run verify:offline`: 빌드·타입 검사·기존 게임 회귀·이관·카메라·환경·물·기예·이야기·2막 회귀와 새 1막 검사를 포함한 비브라우저 집계
- 16개 동결 계약: 임무/이벤트/파티 합류/인물 클래스/기예/적 수치/AI 목표, 기존 저장의 지형·HP·턴·진행 보존
- 25개 실제 목표 상태 검사: 구조·호송·방어·장부·받이진·결박·보스·기존 저장 재개
- 10장 × 4개 직업 몸체의 실제 이동/기본 점프 검사. 미합류 직업도 충돌 여유를 확인하기 위한 격리 검사에만 넣었으며 캠페인 파티를 바꾸지 않음
- 5장은 출구 도달 외에 받이진 → 비탈 바위 → 기본 점프 → 실제 사격턱의 접근 경로를 추가 확인
- 38개 실제 투사체 검사: 모든 장의 노출된 고저차에서 활 양방향, 3–10장의 기 양방향, 2장의 높은 엄호 사격, 실제 법사 의식 이후 5장의 고리쇠 명중
- 편집 API와 직접 Workshop 변경/삭제가 같은 정규화를 거치며 장식 metadata 때문에 막히지 않음. 지지 지형 삭제, 잘못된 null 자료, 상호작용/충돌 자산으로의 변경도 회귀 검사
- 새 풍경의 지지점, 개별 나무 뿌리 접지, 순수 SVG/JSON 왕복, Path2D 캐시 재사용, 렌더 중 전투 상태 불변성
- 2막의 stage 데이터·미션·조명·미술은 그대로 유지. 2막 recipe를 다시 실행해도 기존 Library 자산 순서를 보존하며 전체 프로젝트가 동일
- 기존 산수 원경의 모든 path·변환·달 기하 해시가 승인된 원본과 동일

## 3장 충돌 이음새 수정

서쪽 나루 바위의 왼쪽 collider 끝은 경사지보다 약 1.3단위만 높았다. 이 지점에서 발 지지면 노출 검사가 바닥을 먼저 제외하고, 몸체 벽 검사가 아직 바위를 잡지 못해 휘겸 몸체가 지면 아래로 내려갔다.

- 수정: `place3-stone-west`의 그림과 기존 collider를 함께 12단위 위로 이동
- 다른 지형·인물·미션·글로벌 물리는 변경하지 않음
- 수정 전 실제 move/tick으로 휘겸이 x≈1066에서 y≈2506까지 지면을 통과하는 현상을 재현
- 수정 후 네 몸체 모두 x≈1063, y≈1978에서 피해 없이 정상 정지. 1/30·1/60·1/120초 입력 간격에서도 확인
- 네 몸체 모두 같은 기본 점프로 바위를 넘어 장부와 출구까지 도달
- 새 진입/재시도에만 적용. 진행 중인 기존 Battle을 덮어쓰지 않음

검사: `node tests/act1-collision-repair.mjs`. `capture-act1-collision.mjs`는 이 실제 엔진 상태의 수정 전후를 공통 Canvas로 그린다. 이 화면은 전투가 제거된 충돌 격리 fixture이며 정상 캠페인 완주 화면은 아니다.

## 이미지 검토

각 장에서 전체 지도, 진입 카메라, 대표 장소, 세로 화면, 좌/중/우 이동과 장소의 세로 화면을 확인했다. 최종 목록은 80장이다. 미술/코드 검토에서 나온 다중 나무 뿌리의 부유, 끊긴 뒷기둥, 제당 접지, 편집 metadata 문제를 수정한 뒤 재검토했다.

비교용 이전 지도는 개편 전 1막 데이터 그대로다. 이전 그림도 동등한 SVG primitive 정규화를 적용해 Native SVG backend의 검은 원/안개 오류를 제거했다. 그 오류를 원래 브라우저 게임의 미술 결함인 것처럼 비교하지 않는다.

## 정상 엔진 전투

`node tests/act1-playthrough.mjs`는 실제 합류 파티와 입장 성장값, 이동/기본 점프, 기예, 상호작용, 아이템, 대기만 사용하는 정상 엔진 자동 플레이 검사다. HP·목표·피해·인물 위치를 강제 변경하지 않는다. 저장된 전투 checkpoint는 같은 현재 지도 fingerprint일 때만 재개한다.

`node tests/act1-combat-evidence.mjs`는 각 장의 현재 지형/인물/상호작용 배치 fingerprint와 완주 기록을 대조한다. 누락·오래된 기록·패배·봇 한도 초과를 성공으로 바꾸지 않는다. 검증 집계와 별도로 정상 전투 결과를 확인해야 한다.

현재 지도 fingerprint, 비어 있지 않은 합법 행동 기록, 저장된 종료 상태의 실제 목표 판정을 대조해 **1–10장 모두 완료**를 확인했다. 성공한 실행에서는 합류한 모든 동행이 생존했다.

| 1 | 18 | 1 |
| 2 | 13 | 1 |
| 3 | 22 | 2 |
| 4 | 9 | 2 |

10장의 첫 전투 우선 제어기는 38턴에 패배했다. 이 기록을 별도로 보존했고, 같은 입장 구성에서 두 받이진을 먼저 확보하고 아래쪽 길에서 싸우는 합법 제어기 재시도로 20턴에 완료했다. 5·6장은 같은 지도 fingerprint의 전투 checkpoint를 이어 검사했다. 정상 전투 결과를 단순 목표 fixture나 과거 지형의 기록으로 대체하지 않았다.

자동 플레이의 승패는 한 입장 성장/기예 구성과 해당 제어기의 결과다. 전체 빌드의 난이도, 모든 인간 전술, 실제 브라우저 조작감 또는 사용자의 최종 미술 승인을 보증하지 않는다.

## 재현

- `npm run build`
- `npm run verify:offline`
- `npm run test:act1:offline`
- `npm run test:act1:normal`
- `node tests/act1-combat-evidence.mjs`
- `npm run capture:act1 -- final --review`
- `node tools/environment/capture-act1-collision.mjs` (충돌 회귀 실행 후)

실제 브라우저 경로가 허용되는 환경에서는 `npm run verify`와 별도 성능 검사를 추가로 실행해야 한다.
