## 아키텍처와 검수 결론

### 분량과 선택 구조
실제 장비는52개다. 전용은 캐릭터당8개로32개, 공용은 티어당5개로20개다. 기본 지급 소품4개는 전용8개에 포함한다. 티어당 총13개이며 T1/T2 고유능력 없음, T3/T4 고유능력은 항목당 하나다.

전용은 각 캐릭터의 T1 두 개와 T3 두 개가 고정 획득, T2 두 개와 T4 두 개가 각각2택1이다. 캐릭터별 한 회차 최대6개다. 공용은 티어마다 고정2개+3택1 한 사건이므로 한 회차 최대12개다. 전체 고정24개+선택12건=최대36/52개다.

12개 선택 그룹의 미선택16개는 같은 회차의 다른 보상·회수·상점·재처치로 지급하지 않는다. 이전56개안의 미선택 회수 장부는 이번안에서 폐기한다. 새 회차의 새 runId에서는 다시 고를 수 있다.

### 공개 범위와 예약
현재 공개 콘텐츠는1–3막30장이다. 현재 장비 시스템/보상이 이미 구현됐다는 뜻은 아니다. 그 콘텐츠에 매핑한 정의31개를 우선 연결하면 회차 최대23개다. 4막 정의8개를 더하면1–4막39종·회차 최대29개다. 5–6막13종은 예약으로 둔다.

31/35/36 초기미리보기는4막 정식 공개가 아니다. 모든4막 보상은 officialAct4=false인 동안 일반 진행에서 잠근다. 테스트용 강제 진입이나 미리보기 승리가 정상 보상 원장에 쓰이면 안 된다. 아직 없는 NPC/정예/도달영역은 현재 완료가 아니라 제작 대상이라고 명시했다.

5–6막은 정확한 사건·적·NPC가 없으므로 단계별 eventId와 선택 그룹만 예약한다. 해당 막 콘텐츠의 기존 조건에 연결하기 전 normalEnabled를 켜지 않는다. 장비를 위해 현재30장 공개 범위를 확장하지 않는다.

### 기본 수치와 상한
장비 기본 옵션은 장비를 뺀 heroStats 결과에 합산해 한 번 적용한다. HP/기력/공격/이동력은 비율, 방어와 치명 확률은 %p, 치명 배율은 배 가산, 턴 기력 회복은 고정값이다. 예를 들어 기본 HP1000에 HP+20% 두 개면1400이다.

두 장비의 카탈로그상 기본 옵션 최대 합은 HP+40%, 기력+40%, 공격+16%, 이동력+12%, 방어+5%p, 치명 확률+5%p, 치명 배율+0.20, 턴 기력 회복+8이다. 방어 최종 상한은 현재 HERO_ARMOR_CAP=70%, 기본 치명 확률은 heroStats의75%, 스킬 치명 최종 확률은 기존 critProfile의80%, 치명 배율3.5를 유지한다.

기력 비용은 기존 manaCost(랭크·패시브·주천·소환 할인) 뒤 장비 할인율을 합산해 최대30%로 제한하고, 비용 할증을 그 뒤 더한다. 원래 무료가 된 비용0은0으로 유지한다. 기존 소수 비용 정책은 그대로 두고 임의 정수 올림을 전역 도입하지 않는다. 가격 표시와 발사 가능 검사도 같은 함수를 쓴다.

고유 위력·반경·수명·방어·회수 계수는 항목에 적힌 곳에만 한 번 적용한다. 원본 SKILLS/전역 속성표를 변조하지 않는다. 기존 랭크·패시브 효과를 장비로 두 번 계산하지 않는다. 후속탄·소환 공격은 이미 강화된 주인/원본의 값을 복사하는 기존 경로를 따라야 한다.

### 낮은 티어가 남을 이유
T1/T2는 입문·성장 역할이며 모든 낮은 티어를 종결품으로 유지하려고 새 승급 시스템을 만들지 않는다. 그러나 T2의 공격/기력형과 HP/방어/이동형은 같은 티어에서 다른 역할이다. 선택 전 현재 기본 스탯에 장착한 차이를 보여 준다.

T3 급락시·격퇴시·파진목·회생진목·점프 비용·사생참·반향령·쇠약 강도은 T4의 관통 감쇠·회기시 회수·좁은 천뢰호·넓은 원호파·저HP 방어·검기 비용·넓은 혼령탄·강한 귀결과 역할이 다르다. T4의 숫자가 높아도 해당 T3의 기능까지 포함하지 않는다.

공용 고른돌추와 요동추는 같은 티어의 안정/위험 선택이다. 고비용 할인과 저기력 할인도 발동 조건이 달라 후자가 항상 상위가 아니다. 각 선택지는 피해만이 아니라 자원·생존·이동·특정 기술 투자를 비교하게 한다. 어떤 아이템도 필수 진행이나 보스 공략의 열쇠로 쓰지 않는다.

선택 비교로 공용T1은 HP/기력·공격/이동·비용/회복으로, 공용T2는 공격/HP/치명·공격/기력/비용·HP/기력/이동으로 역할을 나눴다. 초기 청동뇌문의 작은 치명배율 옵션은 비교 가치가 약해 공격/비용형으로 교체했다.

### 기존 코드에서 확인한 점과 추가 변경
읽기 기준은 master bdb6fe6f1c1531c6ebfdaf60569c455ba307c437다. 점프는 engine.ts jumpCost()/jump(), 편차는 damageVariance.ts rollDamage(), 진목은 skillMechanics.ts 생성/만료, 반향령은 engine.ts spawnSummon/expireSummon의 기존 라운드 필드가 실제로 있다. 새 공중 조작·난수 원장·독자 객체 시계를 만들 필요가 없다.

점프 높이20%는 수직 속도에 sqrt(1.20)를 곱하는 안이다. 수평 속도값은 바꾸지 않지만 체공 시간 증가로 자연 수평 이동이 달라질 수 있다. 실제 지지면의 새 길과 정상 물골 횡단은 허용한다. 기존 충돌·천장·이동 예산·입수·낙사 판정은 그대로다.

고른돌추는 기존 난수 표본의 진폭만 절반으로 한다. 요동추는 기존 표본 x를 이용해1.03+0.25x로 만든다. 비치명 방어 전 기본100에서 기대 평균103, 표준편차 약14.43, 하한78·상한128이다. 기존 피해 편차는 균등 표본 계열이며 정규분포라고 부르지 않는다. 치명타의 별도 추첨·상한은 유지한다.

기존 세이브는 damageRoll을 .85~1.15만 허용한다. 요동추를 넣으려면 store.ts validOrigin의 허용범위 .78~1.28과 관련 미리보기 설명을 함께 조정해야 한다. 기존 seed/index와 이미 저장된 roll은 유지하며 불러오기 때 재추첨하지 않는다. 단일플레이 저장 재추첨 방지용 별도 영구 원장을 이번에 추가하지 않는다.

진목과 소환령 수명은 모두 현재 라운드 기준이다. 파진목은 최대9→10라운드, 반향령은 최대8→9라운드로 한 번만 늘린다. 반향령 활성 상한은 ECHO_LIMIT의1~3 그대로다. 일반 소환령 전체의 상한을 확인하지 않은 채 일괄 연장하지 않는다. M07은 명시적인 개수 상한 대신 기존 유한 수명/설치 정책을 따르며, 장비가 새 설치 행동을 주지 않는다.

천뢰호 전달 출발점 변경, 소단 공격의 아군 치유 전환, 일반 장비 흡수 이벤트 신설은 이번52개에서 제외했다. 대신 기존 천뢰호 반경/위력, 기존 M10 치유량, 기존 A06 회수율만 보정한다. 실제 읽기 확인된 연결점이 있어도 장비 기능 자체가 구현 완료됐다는 뜻은 아니다.

마지막 검수로 두 coupling을 피했다. O06 duration을 늘리면 공용 curseTurns 때문에 DOT도 늘 수 있어 지속 대신 공격약화12→15%로 바꿨다. M03은 새 반경 인자 대신 기존 geometryBoost의 두께만20% 늘린다. 일반 적 방어무시는 ward .32 하한보다 먼저 적용하며 보스류에는 넣지 않는다.

### 데이터와 effect dispatch 인계
제안 파일은 equipmentData(아이템/이벤트/선택 정의), equipmentState(검증/획득/선택/장착), equipmentEffects(순수 수치/조건 조회), equipmentUI(기존 쉼터 연결)로 책임을 나눈다. 이 이름은 새 설계상의 책임이며 현재 파일이 존재한다는 주장이 아니다.

itemId는 회차 안의 한 실물을 식별한다. 랜덤 인스턴스ID/affix/내구도/강화/세트는 없다. 모든 효과는 whitelist effectId와 검증된 params로 선언하고 임의 eval 함수나 임의 스크립트 문자열을 데이터에 넣지 않는다.

단순 스탯은 heroStats 뒤 재계산, 비용/기본 위력/반경은 manaCost/effective, 낙차·관통·회수·진목·반향·사생참은 각 기존 helper, 조건부 피해/방어/속성은 applyHit의 지정 계층에 얇게 연결한다. 스킬 미리보기와 실전이 다른 공식을 쓰지 않게 modifier 조회를 공통화한다.

효과 적격 주체는 실제 파티 영웅이다. 소환·섭혼·일반 동맹·시민·적에게 장비 목록을 복사하지 않는다. 소환/진목에 필요한 효과는 주인의 생성 시점에 지정된 값만 기록한다. Battle/Unit에는 장착된 두 itemId의 읽기전용 스냅샷만 두고, 소유/선택 원장은 프로필에만 둔다. 일반 공격 스탯은 주인 공격에 이미 들어가므로 소환·자탄에서 다시 장비 공격%를 곱하지 않는다.

조건부 주공격은 정상 영웅 시전의 기존 공격 문맥으로 판별한다. 자율 후속/소환/지속/환경·살흔·먹귀 전달을 새 발동원으로 보지 않는다. 무구백의는 원래30% 아군 HP 피해를 본체에서15%로 줄이는 범위이며 이미 경감된 shove/자율후속에 재경감을 곱하지 않는다. 이 적격 경계는 좁은 테스트가 필요하다.

### 장착과 stat recompute
공용 물건 하나는 전 파티에서 한 사람만 장착한다. 이미 담허가 착용한 공용품을 설오가 고르면 “담허에서 해제하고 설오에게 장착”을 한 번 확인한 뒤 원자적으로 이동한다. 개인 소품은 해당 classId의 개인 슬롯에서만 사용한다. 해제하면 물건은 인벤토리에 남는다.

착용/해제는 실제 휴식터에서만 가능하다. 전투 중·일시정지·전투 결과 장면·증원 사이에는 불가하다. 분할 원정 중에는 기존 팀/체크포인트 잠금에 맞춰 합류한 휴식터까지 변경을 잠근다. 전투 스냅샷마다 소품 복사본을 만드는 방식은 피한다.

현재 applyHero는 최대치 증가분으로 현재 HP/기력을 올리는 동작이 있으므로 장비 교체에 그대로 사용하면 안 된다. 성장/레벨업 경로는 보존하고 장비 재계산 경로는 현재 HP·기력의 절대값 유지, 감소 시 새 최대치로 clamp, 최대치 증가로 회복 없음으로 분리한다. 이동 예산도 전투 중 재생성하지 않는다.

장착 전후 비교는 HP/기력/공격/방어/이동/치명/턴회복과 적용 기예 비용, 고유효과의 대상 스킬을 보여 준다. 고유효과가 대상 미습득 때문에 아직 작동하지 않는 경우 “기예 미습득”이라고 표시하되 그 기술을 강제 해금하거나 해금 시점을 늦추지 않는다.

heroStats는 장비 없는 기저값과 장비 보정을 구분해 계산하고, applyHero의 성장/레벨업 호출도 같은 장비ID를 전달해 효과를 지우지 않게 한다. 장비 교체만 current 절대값 유지 모드로 실행한다. split-campaign의 snapshot/restore/outcome 재적용도 같은 recompute 경로와 현재값 정책을 써야 하며 별도 최대치 차이만큼 회복시키면 안 된다.

독립 읽기검수는 최신039f342의 split-campaign.js snapshot12–21/restore23–38/initialize60–78/outcome82–87도 확인했다. restore27–28의 최대치 증가분 회복과 outcome85의 C.applyHero를 그대로 두지 말고, 같은 장비 포함 기저와 reason별 현재치 정책으로 통합한다. 분할 원정 전체를 재설계하는 것이 아니다.

장비 reason에서는 hp/focus/moveLeft 셋 모두 절대값을 유지하고 새 maxHp/maxFocus/maxMove가 작아질 때만 clamp한다. 성장 증가분 보정이나 split restore의 최대치 차이 보정을 장비 착탈로 호출하지 않는다. 새 전투 시작의 정상 이동 예산 지급은 별도 기존 규칙이다.

### 저장 구조와 중복 방지
프로필에 equipment.schema=1, runId, definitionRevision, ownedItemIds, equippedByClass, rewardLedger를 둔다. rewardLedger[eventId]는 eligible/pending/committed 및 선택한 itemId/choiceGroup을 기록한다. 미결정 선택 목록은 ledger에서 파생해 별도 원장과 불일치하지 않게 한다.

선택 확정은 이벤트 적격·공개 gate·그룹 미결정·선택 itemId membership을 먼저 검사한다. 복제 프로필에서 선택/owned/equipped 변경을 완성하고 기존 단일 profileStore writer에 저장 성공한 뒤만 화면에 획득을 확정한다. 저장 실패면 성공 메시지/능력 적용을 하지 않고 선택을 유지한다. 이중 클릭은 in-flight UI 잠금과 committed 검사로 모두 차단한다.

엔진 전투 스냅샷/장 시작 체크포인트를 불러올 때도 장비 원장은 현재 회차 프로필이 권위다. 이전 battle.rewardFacts를 다시 읽어 이미 committed된 eventId는 무시한다. 반복 처치·승리 화면 재진입·장 재도전은 같은 선택을 다시 띄우거나 미선택 보상을 주지 않는다.

유효성 검사는 itemId/소유권/slot/classId/중복 공용/choice membership/그룹당1개/공개 gate/유한 params를 확인한다. 인벤토리는 committed 원장에서 정합성을 확인하되 알 수 없는 새 버전 항목을 조용히 삭제하지 않는다. 형식 충돌은 기존 저장 실패 소유자에 넘겨 원본 바이트를 보존한다.

외부에서 의도적으로 편집한 JSON이나 선택 전의 별도 옛 파일을 강제로 덮어쓰는 치팅까지 완전 차단하는 서버 원장은 도입하지 않는다. 일반 이어하기·재접속·장 체크포인트·동일회차 구버전 스냅샷 재처리에서의 중복/재선택을 보장 범위로 삼고 이 한계를 숨기지 않는다.

실제 App.persist()는 성공 시에도 undefined를 반환한다. 선택 commit은 이 반환값을 성공 판정으로 쓰지 않는다. 기존 profileStore.save(candidate)의 boolean을 받는 얇은 commit 어댑터를 두고, 저장 성공 뒤에만 app.profile/normalProfile을 candidate로 교체한다. 단일 저장 writer와 기존 실패 복구 소유자를 그대로 사용한다.

### 세이브 버전과 과거 보상 소급
현재 캠페인 schema4, 코어 Profile.version2/revision13이다. 기본 인계안은 equipment.schema1과 캠페인 schema5를 추가하되 코어 revision13은 유지한다. 코어 revision을14로 올리면 store.validate의 상한뿐 아니라 [4..13].includes에 묶인 성장/튜토리얼 분기도 전부 다뤄야 하므로 장비만을 위해 불필요하게 올리지 않는다. 기존 XP/스킬 마이그레이션 재실행 금지.

기존 세이브에는 장비 원장이 없으므로 최초 전환 때 runId를 한 번 부여한다. 이미 합류한 동료의 기본품과 이미 깬 장의 필수 클리어/필수 사건 고정 보상은 정책상 소급 지급할 수 있다. 이는 과거의 실제 이벤트 수행을 복원했다는 뜻이 아니라 오래 플레이한 진행을 존중하는 명시적 소급 정책이다.

이미 깬 장의 선택 보상은 자동 선택하지 않고 pending으로 등록해 다음 안전한 휴식터에서 비교 후 한 번 고르게 한다. 선택 보상이 도입되기 전 세이브라고 양쪽/세 개 전부 주지 않는다. 실제 수행을 증명할 수 없는 선택 정예/선택 수문/숨은 도달 보상은 클리어 사실만으로 소급하지 않으며 미획득 상태로 재방문할 수 있다.

기존 진행 중 전투에는 새 장비를 자동 장착해 저장된 투사체 위력/HP를 바꾸지 않는다. 새 물건은 소급 인벤토리에 두고 다음 휴식터에서 장착하게 한다. 새 회차의 기본품 자동 장착은 빈 개인 슬롯에서 전투 생성 전만 처리한다. 신규 회차는 원장과 선택을 초기화하며 기존 회차의 인벤토리를 계승하지 않는다.

### 획득 알림과 선택 UX
아이템은 전장에 떨어지는 물리 오브젝트가 아니다. 기존 성공 이벤트를 관찰해 “아이콘+이름+얻었다/발견했다” 메시지를 넣는다. 선택 수문은 실제 접근/상호작용, 정예는 실제 처치 사실, 스토리/NPC는 실제 step 완료를 사용한다. 공격으로 멀리서 오브젝트를 맞히기만 해서 위치 도달을 대신하지 않는다.

고정 보상은 저장 확정 후 기존 메시지/알림 흐름에 표시한다. 비행·강제 조작·대사 읽기·보스 전환 중에는 획득 사실을 큐에 보존하고 다음 안전 경계에서 보여 준다. 선택 UI는 획득 알림과 다른 “소품 선택” 화면이며 비교 전에는 어느 물건도 획득되지 않는다.

선택 화면은 각 대안의 이름·물건 아이콘·기본 옵션·고유효과/대상 스킬을 모두 보여 준다. “이번 회차에서는 하나만. 고르지 않은 소품은 얻을 수 없고 결정 후 바꿀 수 없다”를 확인 버튼 바로 위에 표시한다. 미결정 상태로 닫거나 재접속해도 같은 대안이 남으며 진행을 막지 않는다.

모바일은 기존 성장/기예 쉼터 UI 안에 소품 항목을 넣고 동행 전환→개인/공용 두 줄→소지 목록→비교→장착/해제를 같은 문법으로 처리한다. 터치 대상은 최소44px, 이름/효과는 줄바꿈하고 hover에 의존하지 않는다. 새 SaaS 대시보드나 전투 위 별도 관리창은 만들지 않는다.

### 아이콘과 제작 순서
아이콘은 itemId와 물건 이름으로 고정한다. 제안 자산 경로는 shared/assets/item-icons/v1/<itemId>.webp이며 실제 제작 경로는 담당 세션과 맞춘다. iconBrief는 행동/폭발이 아니라 물건의 실루엣·재질·주색·매듭/부착물을 설명한다. 같은 형태의 색놀이로52개를 만들지 않는다.

탁한 회갈색 한지 바탕, 거친 붓결/담채의 한국풍 실제 소품 한 개 중심. 실루엣·재질·매듭/부착물로 구분. 글자·숫자·티어문자·인물·발사 궤적·불꽃·강한 발광·스킬 장면 없음.

순서는 데이터/원장/장착 기저→기본 스탯과 소수 대표 효과→나머지 기존 helper 보정→1–3막 보상 연결→잠긴4막 정의→짧은 UI/저장/이벤트 검수다. 아이콘은 안정된 itemId와 병행 제작하되 부모가 자산 품질과 파일 연결을 확인한다. 이 문서 세션은 이미지 생성/실제 게임 코드 수정/배포를 수행하지 않았다.

## 좁은 검수

- **데이터** 52개ID·이름·tier13씩·전용8씩/공용20·기본옵션수·T3/T4고유1·이벤트36·선택12·최대36을 자동 검증한다. 선택 itemId는 유일 획득 이벤트 하나만 가진다.
- **선택/저장** 2택1 하나와3택1 하나에서 비교→취소/닫기→재접속→확정→이중탭→재도전 순서만 집중 확인한다. 미결정 보존·commit 후 대안 잠금·저장 실패 시 미지급을 확인한다.
- **고정/정예/위치** 대표 클리어1건,12장 정예 태그1건,15장 선택 수문1건만 검수한다. 처치/도달 사실 없이 지급되지 않고 같은 eventId 재처리는 무시해야 한다.
- **공개 gate/디버그** 정상30장 완료로31/35/36/40 보상이 나오지 않는지 확인한다. 디버그 소지52개/미리보기 획득이 정상 프로필에 저장되지 않아야 한다.
- **장착/자원** 휴식터 착용/해제, 다른 동행의 공용품 이동, 전투중 거부, 분할원정잠금만 확인한다. HP/기력 최대치 착탈 반복으로 현재값이 증가하지 않아야 한다.
- **기본스탯/미리보기** 대표 두 장비의 합산과 실제 unit값/비교창/스킬 비용을 맞춘다. 공격 스탯을 원본/소환/파생에서 두 번 적용하지 않는지 한 기술만 확인한다.
- **점프** 고갯돌매듭의 높이, 가벼운칼끈의 비용을 평지·낮은천장·물골 정상착지·실제낙수에서만 확인한다. 새 공중조작이나 면제 경로는 없다.
- **편차** 동일 시전의 원본/다중탄이 같은 damageRoll을 쓰는지,고른돌 평균불변,요동추 .78~1.28,치명타 분리,저장/재개가 유효한지만 확인한다. 새 재추첨 방지 시스템을 만들지 않는다.
- **수명** 파진목 +1라운드와 반향령 +1라운드를 각각 한 번 확인한다.재접속재연장없음,대상별usedRounds 유지,반향령 ECHO_LIMIT/소멸 보전은 기존대로여야 한다.
- **기술별 얇은 보정** 급락·격퇴·관통·회기·M10·천뢰호/원호파·사생참·검기·쇠약·혼령탄/귀결은 각 수정 helper당 대표 기술1개만 비교한다. 새 전체30장 순회를 요구하지 않는다.
- **경계 효과** 무구백의의 주공격/자율후속/밀침충돌 구분,온혼거울 비중합1,틈새호패의 보스/ward보호 예외,저HP방어70%상한,무딘동전 치명최저1을 해당 대상만 확인한다.
