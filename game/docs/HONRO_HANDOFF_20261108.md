# 혼로 1장부터 40장까지 개선 인수인계
2026년 11월 8일 확인 자료 기준

이 문서는 작업공간과 대화가 초기화된 뒤 새 담당자가 혼로 작업을 이어받기 위한 프로젝트 자료다. 2026년 11월 8일 사용자는 이 인수인계 문서를 GitHub에 게시하고 새 담당자에게 줄 짧은 프롬프트를 요청했다. 이번 게시 범위는 이 문서 한 파일이다. 기존 게임 개발과 30분 자동 점검은 보류 상태이며, 초기화·삭제·개발 재개나 기존 미발행 코드의 push를 실행하라는 지시가 아니다. 새 담당자는 사용자의 재개 지시를 확인한 뒤 아래 절차를 수행한다.

## 1. 가장 먼저 지킬 사용자 방향

- 혼로 GitHub 저장소는 sys8994/honro다. 기존 공개 주소는 https://sys8994.github.io/honro/ 이다.
- 1~40장을 새 정량 기준, 전체 구상과 시안, 지형·게임플레이 제작, 실제 플레이·정량·시각 검수, master와 기존 Pages 배포까지 연결하는 것이 목표다.
- 1장은 기존 완성도가 높은 결과를 존중한다. 튜토리얼이므로 쉬워도 된다. 난도·턴 수·고도폭을 맞추려고 적이나 동선, 위험을 억지로 늘리거나 좋은 지형을 뜯어고치지 않는다.
- 장 전체 구상과 플레이 스켈레톤, 전체 장면 및 대표 보행 시안을 먼저 정리한다. 그 구상 안에서 의미별 부품·레이어를 제작한다. 부품부터 만든 뒤 이어 붙이는 것으로 전체 장 설계를 대신하지 않는다.
- 전체 구상 선행은 전체 이미지를 통째 자동 추적하라는 뜻이 아니다. 정식 벡터 저작 단위는 의미별 레이어·자산이다.
- 코덱스 사용·재개는 금지한다. 조정 담당자가 실제 원문·소스·원인과 결과를 직접 확인한다.
- 기존 버전, 원본 기준, 승인된 미술, 저장 진행, 다른 담당자의 변경, 유효한 후보·실패 기록을 보존한다.
- 실제 개발이 재개되면 사용자가 중단하기 전까지 계속하되, 장별 내부 검수와 배포 후 다음 장을 이어간다. 독립 준비는 파일·자산 단위로 병렬화할 수 있으나 공통 런타임과 발행은 한 담당자가 관리한다.
- 변경은 로컬에서 보존해 모으고 마지막에 허용된 범위로 발행한다. 매 수정마다 원격 push를 강행하지 않는다. 기존 AGENTS.md·SOP의 변경 단위별 push 문구보다 최신 사용자 지시를 우선하며, 명시적으로 거부된 원격 작업을 재시도하거나 우회하지 않는다. 이번 인수인계 문서 게시 요청은 기존 미발행 코드의 push나 개발 재개 승인으로 확대하지 않는다.
- 명시적으로 거부된 브라우저·원격 쓰기는 다른 도구·호스트·계정·프로토콜로 우회하지 않는다.

## 3. 초기화 전후 현재 상태를 다루는 방법

이 문서는 2026년 11월 8일 관측의 인계다. 아래 SHA나 파일 존재를 새 환경의 현재 상태라고 추정하지 않는다.

마지막 확인된 공통 checkout HEAD는 16935498ed1066d18bb6c516ab8341edd17588ca다. 로컬 origin/master 추적값은 3949e90이며 35커밋 앞서 있었다. 이것은 최신 원격을 실시간 확인했다는 뜻이 아니다. 인계 작성 중 추가 확인된 실제 GitHub master는 9b985c844ca4eb89ab04935a7c5022a6bdbff9ea이며 Pages 실행 #442는 성공했다. 이 커밋에는 대화·진동·33장 수정 빌드와 31장 UI 증거 갱신이 포함된다. 다만 공개 페이지의 실제 동작은 직접 검증하지 않았다. 구 로컬 HEAD 16935498은 원격에서 발견되지 않았으므로, 그 변경이 최신 master에 전부 보존됐다고 가정하지 않는다. 최신 원격 커밋 링크: https://github.com/sys8994/honro/commit/9b985c844ca4eb89ab04935a7c5022a6bdbff9ea

공통 checkout에는 기존 미커밋 수정 24개와 미추적 항목이 있었다. 주요 수정 영역은 shared/runtime의 이야기·목표·상호작용·저장·메뉴·동행·act23/act4, shared/engine/src/enemyAI.ts, shared/build.mjs, package.json, BUG_LOG.md와 일부 테스트다. 모두 이번 미술 후보의 변경이라고 간주하거나 전체 reset·통째 커밋하지 않는다.

1장 격리 미술 후보의 마지막 검수 커밋은 de7b44b104c73c3a13efd42661c10e794413b86c다. 이후 문 장식 연결 작업은 중단됐다. 중단 작업 트리의 hook이 아직 해당 후보 저장소에 복사되지 않은 최종 자산을 참조하며 source lock과 통합 검사는 실행되지 않았다. 현재 작업 트리를 검수된 de7b44b와 같다고 취급하지 않는다. 미완성 문 작업을 그대로 빌드·활성화·발행하지 않는다.

2장 발판 후보 커밋은 24fdd36039dea52880a9d08412ff33c8b4aa525a, 3장 잔교 후보 커밋은 8811248이다. 로컬 후보 식별자이며 원격에서 가져올 수 있다는 보장은 없다. 관련 bundle·patch·자산·원본·테스트가 실제 전달됐는지 별도로 확인해야 한다.

이 문서만으로 소스·자산 백업이 완성되지는 않는다. 초기화 전에 필요한 로컬 후보·미커밋 변경·git bundle·원본 시안·raw/final SVG·검수 자료·v3를 영구 보존하고 새 환경에서 다운로드해 열 수 있는지 확인해야 한다. 문서 작성은 실제 초기화 승인이 아니다.

## 4. 최근 1장부터 3장까지 작업 범위와 정정

1장: 서·동 가지, 입구 바위, 뿌리·작은 돌을 실제 Inkscape 경로로 연결한 기본 비활성 후보다. 기존 BODY와 공통 나무·풀, 원경, 5400×2200 지형·충돌·카메라·진행 계약을 유지했다. 전체 재설계가 아닌 기존 충돌 단위의 미술 연결이다. 마지막 문 장식은 미완성이다.

1장 플레이 정정: R26 Engine 실행은 XP 0에서 자동 훈련된 AP04/A11/A14 및 A01/A11/A14 구성을 사용했다. 실제 새 게임의 A01만 보유하고 SP3을 쓰지 않은 상태와 다르다. 피해 사건은 5회, 합계 112였고 종료 HP 365는 회복을 포함한다. 무피해·정상 초회 튜토리얼 완주로 보고하면 안 된다. helper는 productionStory:false이며 실제 브라우저·보상·다음 장까지 보증하지 않는다.

1장 최신 보존 방향: 기존 튜토리얼 난도와 크기, 런타임 적 12체(초기 8 + 유한 증원 4), 행동 상한 3, 이야기를 단지 턴 목표를 맞추기 위해 바꾸지 않는다. 실제 새 시작 상태와 현재 소스를 재확인한다.

2장: 8개 BODY 통합 시안과 호송로 시안을 만들었으나 보행 배율의 재질 크기·y3300 절단선·좌우 접합 문제로 반려했다. 최종 보존 후보는 left-descent-stone-mid 한 발판이다. 기존 4300×3300·14개 지형·상여 호송·원경/REAR·revision8을 유지한다. 전체 지형 완료가 아니다. 기존/새 캠페인 저장 왕복·충돌 불변·준비 접지 검사는 있었지만 실제 브라우저·정상 장 완주·전체 HTML 빌드·master/Pages는 미완료다.

3장: 기존 6500×3100 BODY v7을 유지하고 dock-west 한 곳의 목재 상면·전면 보만 제작한 기본 비활성 후보다. 서측 잔교 폭 760·상면 y2028~2060·두께 62를 유지했다. 다른 잔교·지주·창고와 전체 장 개편은 남았다. Engine 이동 fixture는 적과 다른 아군을 제거하고 승패를 껐다. 정상 전투 완료가 아니다. 정식 빌드는 후보 활성 여부와 무관하게 Stage31 보호 검사 'Runtime changed after actual Engine probes.'에서 중단됐고 가드를 바꾸지 않았다.

세 장의 진행 자료는 모두 T2 시안 단계를 0으로 두면서 T3/T4 부분 제작·연결을 진행했다고 기록했다. 즉 전체 구상·시안보다 부분 구현이 앞선 문제다. 부품별 제작 자체는 SOP가 허용·권장하므로, 문제를 '부품으로 만들면 안 된다'로 잘못 교정하지 않는다.

과거 전체 장면 참고는 존재한다. game/docs/art-references/quiet-layered-20261019/의 honro-layered-concept.webp, honro-stage2-high-cliffs.webp, stage3-ferry.webp 등이 있다. 1장 옛 합성 시안 SHA256은 3ad5f1987fdaabbf13b33d909931b01a773ed0567f8ad5d7115b003b1ba344d5다. ## 5. 40장 공통 정량 기획

기존 원본값·현재 구현값·새 제안값·사용자 확정값·실측값을 분리한다. 장별 턴/활동시간, 정상 전략별 성공률·피해·적 실효 행동, 초기/필수/선택/증원 수, 정예/중간/주요보스, 예고·대응, 맵 가로·세로·면적·종횡비·활용 구역, 경로·점프·하강·유효 고저차, 기믹·승패·필수 보호·화면 품질과 측정 방법을 정한다.

40장을 나란히 비교해 난도는 완만히 상승하되 장별 강약·휴식·서사 예외를 둔다. HP·적 수·턴만 늘리지 않고 패턴·협공·목표 압박·지형 선택을 본다. 맵 크기는 초반 완만한 증가 후 비교적 일찍 수렴하고 국소 편차를 허용한다. 필요한 장만 큰 예외로 둔다.

v3의 20턴 상한은 과거 설계·검증 예산이지 강제 패배 타이머가 아니다. 최신 사용자 예외는 사유·실측을 남긴다. 전원 생존도 전 장 공통으로 추가하지 않는다. 비전투·호송·탈출에는 해당 지표를 적용한다. 기존 수치를 유지할 때도 원칙과 해당 장의 이유를 기록한다.

순서는 설계 카드 → 플레이 지형·동선 → 전체 구상·미술 시안·스타일 기준 → 공통/장별 미술 → 아군/NPC → 적 → 이벤트 → 대사/씬 → 세 집중 검수·실제 플레이 → 최종 종합·배포다. 실제 설계는 서로 영향을 확인하되, 장 전체 기획 없이 부분 재질부터 제작하지 않는다.

## 7. 전체 구상과 시안

실제 지형 데이터에서 스켈레톤을 출력하고 캐릭터 크기·기본 점프·이동으로 회색 모형을 확인한다. 전체 overview와 대표 플레이 카메라를 함께 준비한다. 원경·REAR·SURFACE·BODY·FORE·FX/INTERACT 역할, 연결 지질, 보행선, 고저차, 랜드마크, 광원, 재질 크기, 가림과 여백을 전체 시안에 연결한다.

대표 한 구간에서 지면·바위·갈대·목재·작은 건물·캐릭터 크기를 같은 조건으로 비교한 스타일 기준판을 만든다. 기존 채택 레퍼런스를 실제로 열어 비교한다. 구조 스켈레톤·스타일 참고·개체 참고의 역할을 구분한다. 필수 앵커·접촉선·빈 공간을 겹쳐 확인한다. 프롬프트만으로 구조 고정·화풍 일관성을 보증하지 않는다.

전체 구상 이후 의미별 부품/레이어로 제작한다. 생성 직후 배우 크기와 실제 보행 배율의 저비용 합성으로 재질 크기를 먼저 본다. 전체 그림만 보고 정밀 추적·최적화를 반복하지 않는다. 전체 월드의 넓은 확장 때문에 실제 보행 암면이 커지지 않도록 국소 재질과 외곽을 분리하고 접합을 확인한다.

## 8. 지형과 원경

solid·one-way·물·위험·공중 공간과 사격각·엄폐·높이차를 함께 구성한다. 일반 전략 경로는 실제 접근 가능하게 하고 기예 퍼즐은 의도·보상·대체 필요를 명시한다. 밟는 지붕은 one-way다. 화면 Y 높이와 원근상 앞뒤 길을 혼동하지 않는다. 낭떠러지·경사 접점·머리 여유·오버행·천장·필수 사격선을 바뀐 구간에서 확인한다.

stage.terrains 전체 polygon과 shared/map/terrain-domain.js가 단일 지리 원본이다. 충돌은 기존 시뮬레이션 범위로 투영한다. 새 dummybody/skirt·단색 외곽 벽·가림막으로 결함을 숨기지 않는다. Play/Camera Focus/Visual/Terrain Bounds를 구분하고 shared/map/bounds.js의 공통 정책을 따른다.

현재 문서의 terrain 여유 좌우 6000·상하 24000, 전술 가로 6800, 기준 적 높이 66·식별 3.75px·최대 줌 1.65는 현행 정책 설명이다. 소스와 대조하고 새 장 목표로 무조건 복사하지 않는다.

원경은 독립 이미지, 플레이 근경은 공통 벡터다. 승인 매핑·로딩·캐시·시차·크롭을 이유 없이 바꾸지 않는다. 원경에서 충돌을 추출하지 않는다. 실제 지형에 붙은 나무·바위·건물은 우선 L1-back, 중경은 장소 설명에 필요할 때만 사용한다. 근경 뒤쪽 지표·보행면·앞 경사면은 한 장소로 연결하고 전체 근경을 충돌 polygon으로 잘라내지 않는다. 앞 가림은 렌더 순서로 처리한다. 물·안개·기믹을 정적 그림에 굽지 않는다.

맵 끝도 같은 지질·큰 명암면·색 계열의 연속이다. 최소 줌·좌우 최대 pan·모바일에서 사각 절단·단색 벽·틈·떠 있는 덩어리·가짜 통로가 없어야 한다. 카메라 제한·배우 축소로 숨기지 않는다.

## 9. 미술 기준

한국형 다크 판타지, 성숙하고 차갑고 쓸쓸한 공간을 유지한다. 한국화 진경산수·수묵담채의 큰 산세·명암·여백·안개를 참고한다. 중국/일본풍 건축, 흔한 서양 판타지, 동화풍으로 흐르지 않는다.

외곽은 풍부하게, 내부는 절제하게, 플레이 경계는 분명하게. 큰 실루엣→중간 형태→2~4개 주요 명암면 순서다. 반복 삼각형·격자 돌·타원 돌무늬·미세 균열·노이즈·거대한 단색 면으로 채우지 않는다. 내부만 화려하고 외곽이 단순한 것도 피한다.

플레이 지형·오브젝트·캐릭터·개별 벡터 에셋은 그라데이션 대신 면으로 명암을 나눈다. 원경 분위기와 기술 이펙트의 허용을 일반 벡터로 확대하지 않는다. 광원·재질 명도·세계 단위 크기를 일치시키고 배우·조준선·보행 경계 가독성을 우선한다. 막별 색감은 달라도 그림체는 통일한다. 4막은 낮의 밝기가 남은 우중충한 푸른 안개·쓸쓸함·공허함이다.

캐릭터 그림 수정은 반복 실패로 중단된 범위다. 새 사용자 지시 없이 이번 스테이지 작업에 끼워 넣지 않는다.

## 10. 실제 Inkscape와 최적화

게임 지형 원본, 채택 시안·편집 SVG, 배포 산출물을 분리한다. 코드는 스켈레톤·좌표 변환·자산 연결·검사·재생성에 사용한다. 레퍼런스 없는 즉흥 polygon 그림을 기본 미술로 쓰지 않는다. 손으로 좌표를 만든 뒤 Inkscape에서 열기만 하는 것은 해당 SOP 수행이 아니다.

의미별 자산마다 크기·viewBox·원점·foot/pivot·support/socket·접지·보존 형상·빈 공간을 정의한다. 실제 Inkscape 색 추적·곡선/노드·합치기/빼기·clip·레이어로 제작하고 색수·Stack·Smooth·speckle·optimize를 기록한다. 추적은 시작점이며 번짐·잡티·중복·구멍·붙은 부품을 정리한다. 최종 벡터에 image 요소/외부 bitmap을 남기지 않는다. fit/crop 후 눈대중 배치를 하지 않는다.

raw SVG를 불변 보존하고 모든 후보는 같은 raw에서 만든다. 누적 Simplify로 오차를 감추지 않는다. 시안→raw와 raw→최적화 오차를 분리한다. 접촉선·발판 끝·출입구·가는선·접합·구멍을 보호한다. 실제 크기와 최대 확대에서 전체 색·alpha·윤곽·국소 중요 부위·좁은 틈을 비교한다.

node/path/subpath/명령/바이트/overdraw/메모리/실제 전송량을 따로 센다. compound path 수가 작다는 것만으로 가볍다고 하지 않는다. 기존 오차·엔진 한도를 결과에 맞춰 올리지 않는다. 과거 30% 절감·1.5px 등은 해당 자산 계약과 구분하며 임의 전 장 기준으로 만들지 않는다.

수치 통과는 후보 선정일 뿐이다. 원본/최종 전체·일반·확대·상태/모션·실제 엔진 연결 결과를 직접 본다. 문제 부위는 원본 복원이나 보수 처리 후 재검수한다. 자동 visualApproved나 사용자 승인을 만들지 않는다.

## 11. 아군 NPC 적과 증원

아군/NPC는 동선·사건·공간 점유에 맞춰 배치하고 시야·첫 이동·상호작용·출구를 막지 않는다. 현행 리그·도착·보호 계약을 유지한다.

적은 무엇을 지키고 어떤 선택을 요구하는지부터 정한다. 전위·후위·고지사수·정예·공중 지원을 실제 지지면·차폐·사선·교전거리와 연결한다. 군집 사이 여백은 접근·재정비·예고·퇴로를 위한 것이며 무기능 고립을 정당화하지 않는다. 등간격·작은 난수오차·항상 두 마리·좌우 복사를 금지한다.

초기수·정예·유한 증원·동시 생존 상한·행동 상한을 분리한다. 정예/난이도 배수를 중복 적용하지 않는다. 과거 2막18~28·정예 HP 1.55 / 공격 1.15·행동 3~4 등의 구현을 모든 장의 사용자 확정값으로 복사하지 않는다.

증원은 실제 진입로를 쓰며 파티·구조 대상 위에 생성하지 않는다. 변경한 로직에 대해서 예고·입장·첫 행동·점유 대기·대체 입구·중복·취소·Continue를 확인한다. 실효 행동은 피해뿐 아니라 제압·회피·위치/경로·기예 선택·목표 압력이다. 제자리·표적 없는 발사·도달 못 하는 추격은 실효 행동이 아니다.

## 12. 이벤트 대사 장면

trigger(위치/턴/처치/상호작용)→조건→결과→완료/실패→다음 상태를 잇는다. 증원 유한성·중복 발화·대화/메뉴 중 정지·턴 off-by-one·보상/출구/다음장·저장 복원을 변경 범위에서 확인한다. 대사가 약속하는 행동·보상은 게임에 실제 존재해야 한다.

대사 수정 전에 실제 적용 원문과 조건을 읽는다. 인물은 메시지 해설자가 아니라 현재 상황에 놓인 사람이다. 설오는 거리·바람·사선·흔적, 담허는 혼·진·술법 위험·사람 상태, 휘겸은 사람 수·퇴로·방어선·책임, 소단은 혼의 목소리·들린 사람·실과 부상에 주목한다. 가이드의 말투·호칭을 지킨다.

명언형 성장 요약·추상어 핑퐁·대사 뒤 뜻풀이·전원 초연함·같은 정보 반복을 피한다. 기계적 금칙어 치환이나 무조건 단축은 하지 않는다. 선택 기록을 건너뛰어도 필수 인과와 다음 행동이 이해되어야 한다. 기록 읽기 중심의 루즈한 진행을 늘리지 않는다.

특별한 대상은 필요하면 1~3장 앞 복선, 실제 등장 시 2~4줄의 인물별 반응을 연결한다. 보이지 않는 요소를 대사가 묘사하지 않게 한다. 생사·정체·공개 시점·핵심 관계·승패·파티 분할은 임의 변경하지 말고 먼저 보고·필요한 승인을 받는다.

## 13. 실제 플레이와 조작 진단

정상 성장·정상 입력으로 시작→이동/교전/기믹→승패→보상/출구/다음장 흐름을 확인한다. HP·좌표·턴·적삭제·강제 명중/승리를 주입하지 않는다. 현재 UI에 없는 숨은 소모품·개발 명령을 정상 플레이로 쓰지 않는다.

Engine 진단, 적 제거/승패 해제 이동 fixture, 준비 진입 세이브, Native 공통 렌더, 실제 브라우저 UI, 정상 연속 캠페인, 실제 사람의 재미, 공개 Pages를 분리한다. 한 종류를 다른 것으로 보고하지 않는다.

실패 시 실제 각도/차지·이동력·경로·점프·입력 시점·기예 효과부터 본다. 이동 펄스 제한의 이동력 낭비, 위층 적의 x만 따라 아래층 왕복, 과도한 후퇴로 건강한 전열 정지 같은 조작 결함으로 게임을 약하게 만들지 않는다. 도착 여부와 미세 잔여 이동력도 확인한다.

입력, 실제 발사값, 라운드/행동, 이동거리/남은 이동력/대기 손실, HP/보호막/피해, 적 실효 행동, 접지·목표 상태, RNG/시점 차이를 기록한다. 실패를 보존하고 성공 한 번으로 지우지 않는다. 장에 맞는 여러 전략을 비교하고 조건·표본 수를 명시한다. 한 번 성공을 성공률·재미·전체 난도 합격으로 부르지 않는다. Stage31의 4인 생존/20라운드/승선은 전용 계약이며 다른 장으로 복사하지 않는다.

## 14. 저장과 비파괴

성장·XP 장부·SP·장착·모집·완료·설정·Workshop 사용자 프로젝트를 보존한다. 실제 지형 변경 장은 현행 revision 정책에 따라 필요한 현재 장 전투 스냅샷만 폐기하고 같은 장 입구에서 새 지형으로 시작한다. 같은 revision은 정상 Continue를 유지한다. 분할 원정은 현재 팀·장 시작 자원을 쓴다. 미술만 바꿨다고 전 장 revision을 올리지 않는다.

같은 assetId의 그림 교체도 서명/복원을 깨뜨릴 수 있으므로 새 ID·호환 공급자를 구분한다. Engine JSON 왕복을 App 내보내기→가져오기→Continue·브라우저 저장 용량 검수로 대체하지 않는다. 기존 진행 전투의 적·HP·좌표·목표를 임의로 덮어쓰지 않는다. 이전 원본·raw·승인 근거·실패 후보를 삭제해 정리하지 않는다.

## 15. 세 집중 검수와 최종 종합

실제 런타임 이미지를 직접 열어 세 차례 서로 다른 검수를 한다.
① 전체 구조: 형태·동선 연속성·지지 구조·랜드마크·외곽 연결.
② 보행 배율: 재질 크기·접지·전경/원경·배우/조준선/상호작용 가독성.
③ 카메라/상태: 일반·확대·최대 축소·모바일·좌우 pan·이동/파괴/기믹 전후의 잘림·공백·가림·충돌 불일치.

문제 수정 후 해당 화면을 재촬영한다. 같은 화면 반복이나 자동 검사 세 개로 횟수를 채우지 않는다. 마지막에 최종 소스의 이야기·공간·전투·미술 결합과 회귀를 별도 종합 검수한다. 소스가 바뀌면 영향 증거를 갱신한다.

소스 SHA/미커밋 범위, 화면·카메라·화면비·상태, 직접 본 문제, 수정·재확인·한계를 남긴다. AI는 취향서/승인·반려에 비춰 어긋남·비교·질문을 보고하며 재미·미감·사용자 승인을 꾸며내지 않는다. 내부 기술 검수와 사용자 취향 판정은 구분한다. 장별 승인 답변을 기다리는 새 대기는 임의 추가하지 않는다.

## 16. 필요한 검사와 파일 구조

매 수정마다 전체 verify·전 장 순회·모든 기예·전체 migration/integration·대량 스크린샷·별도 검수자를 의무화하지 않는다. 디자인은 결과 이미지/레퍼런스/영향 모션, 지형은 바뀐 이동/통로/퀘스트, 저장은 관련 구/신규 경계, 공통 연결은 영향받는 Game/Stage View/Playtest, 성능은 실제 문제나 변경, 문서는 문구/링크를 확인한다. 최소 검사를 장 개편의 3회 집중 검수·최종 종합·실제 플레이 생략의 구실로 쓰지 않는다.

기존 테스트는 보존한다. 실패는 새 변경/기존 실패를 구분하고 무관한 수리로 범위를 부풀리지 않는다. guard 해시·한도·근거를 결과에 맞춰 덮어쓰지 않는다.

런타임은 shared/runtime/, shared/engine/src/, shared/map/, shared/data/. CSS/밸런스는 game/src/, game/config/. HONRO.html과 HONRO_WORKSHOP.html은 생성물이므로 직접 편집하지 않는다. 공통 shared/build.mjs, Engine, Scene, HonroMaps를 사용하고 Workshop 전용 렌더러·물리를 만들지 않는다.

유지 명세는 game/docs/, 검사 입력은 tests/fixtures/·game/tests/fixtures/, 결과/캡처는 _local/reports/·_local/game-reports/, 일회 보고/압축본은 Git 제외 _local/archive/. BUG_LOG에는 원인·변경·확인·한계를 짧게 기록한다.

## 17. 커밋 원격 발행

현재 작업에서는 일관된 변경 단위를 로컬 커밋·파일로 보존해 모으고, 마지막에 최신 사용자 지시와 허용된 범위에 따라 발행한다. 저장소의 과거 변경 단위별 push 문구만 보고 매번 원격 쓰기를 강행하지 않는다. 원격 거절은 그대로 존중한다. 이번 별도 인수인계 문서 게시를 다른 코드·자산의 발행 허가로 사용하지 않는다.

허용된 최종 발행 시 최신 원격·타인 변경·단일 발행 담당을 확인한다. 원격이 앞서면 변경을 읽고 보존 통합하며 force push하지 않는다. 원격을 읽어 의도 SHA를 확인한다. 내부 검수 최종본을 master 통합 → 필요한 정식 빌드 → 기존 Pages 배포 → 해당 SHA의 실행 성공 → 공개 화면/동작 직접 확인까지 수행한다.

로컬 커밋·push·master·CI·Pages·공개 확인은 별도 상태다. 문서만 변경하면 게임 빌드/플레이를 추가하지 않는다. 실제 성공 발행 그래프는 최근 7일 전체와 최소 최신 2개를 보존한다. 미발행 후보를 성공 등록하거나 발행 날짜를 꾸미지 않는다. RELEASE_OPERATION_GUARD.md의 정식 보존 도구·원본 검증을 따른다.

## 18. 차단과 결과 불명

승인 대기·진행 중·결과 불명·명시 거부·실패·성공을 나눈다. 결과 불명은 원요청 상태와 원격을 먼저 읽고 중복 쓰기를 제출하지 않는다. 명시 거부를 다른 경로로 우회하지 않는다. 필요한 승인이 있는 경우 정확한 동작·대상·이유·이미 완료한 범위·상태·다음 조치를 보고한다. 허용된 독립 작업은 계속하지만 차단을 통과로 쓰지 않는다.

인계 시점에는 기존 브라우저 실행의 socket/process_singleton EPERM 관련 실패·제한 기록이 있고 실제 브라우저 검수가 미완료다. 기존 코드 작업의 원격 push에도 거부 보고가 있어 후보에서 재시도하지 않았다. 정확한 과거 거부의 도구 결과는 이 문서에 포함되지 않았으므로 모든 원격 작업이 거부됐거나 새 환경이면 허용된다고 추정하지 않는다. 새 담당자는 해당 동작의 원요청·권한·결과를 확인한다. 이번 신규 문서 게시 요청과 과거 코드 push를 구분하며, 거부된 동작은 다른 경로로 우회하지 않는다.

## 19. 진행률과 보고

한 장 = 지형 50 + 게임플레이 50, 각각 5단계 × 10점이다.
T1 기획/정량/스토리/원경·지형 연결. T2 스켈레톤/시안/레퍼런스 대조. T3 실제 Inkscape/형상 보존/최적화. T4 게임 지형/충돌/발판/이동/카메라/목표·저장 연결. T5 서로 다른 3회 검수·수정 재검수.
G1 적/보스/기믹/동선/퀘스트/전술 설계. G2 구현·상태 전이·핵심 확인. G3 정상 성장·정상 입력의 시작~종료·저장/진행. G4 여러 전략 실측/목표 비교/화면·흐름/수정. G5 최종 종합·정식 빌드·master·Pages·공개 확인.

단계가 확인됐을 때만 완료 점수를 준다. 진행 중을 임의 완료로 환산하지 않는다. 별도로 사용자가 요청한 부분 추정 방식은 SOP 완료율과 분리한다. 전체는 40장 동일 비중 평균이며 한 장 100%는 전체 2.5%다. 최신 소스 배포·공개 확인 전에는 장 100%를 선언하지 않는다. 공통 SOP·도구·반복 검수·부품 추가를 각 장에 중복 가산하지 않는다.

실제 작업 재개 후 매 30분 전체와 장별 상태, 확인된 단계, 이번 변화와 증거, 완료·진행·실패·미측정, 차단·해결 시도·재개, 다음 작업을 보고한다. 변동이 없으면 없다고 말한다. 중요 결과·화면·블로커·배포는 즉시 보고한다. 시안·Native·브라우저·공개 Pages를 구분한다. 보류 상태에서 자동으로 개발을 재개하지 않는다.
