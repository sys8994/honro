# 2막 공간·SVG 개편 구현

2026-10-05. 새로 시작하는 11–20장 전체를 대상으로 한다. 구현 결과의 실제 브라우저 검증과 사용자의 최종 미술 검수는 별도 단계다.

## 공간 구성

- 11: 두 어깨 높이가 다른 소나무 분지, 매듭과 주민의 터
- 12: 대각 채석 절개, 실제 낙석 복구 구간, 마지막 구역의 입구
- 13: 열린 함몰지에서 실제 낮은 천장과 석문으로 넘어가는 경계
- 14: 위·중·아래 생활 터와 뒤쪽 살림집, 연결 계단·툇마루, 피난 다리
- 15: 낮은 수문 목, 높은 사격 수갱, 배수되는 홈
- 16: 법당 앞마당, 다섯 칸 법당·석재 기단, 짧은 측면 회랑과 기록실
- 17: 엇갈린 작업 터, 사람 크기에 맞춘 인양틀과 공구 작업막
- 18: 실제 양쪽 암반 접촉 턱 사이에 박힌 묵종
- 19: 18과 동일한 구조·종 좌표. 풀린 결속과 절제된 청동 반사, 이름을 부르는 자리
- 20: 낮은 출구에서 넓어지는 새벽 고개. 행렬의 필수 길은 계속 오른쪽으로 이어진다

13·15·17·18·19에 같은 3층 왕복 선반을 복제하던 생성기는 제거했다. 각 장은 저작된 공간 계획과 노출 표면을 가진다. 18/19는 같은 `bellFloor`·`bellRoof`와 종 배치 원본을 공유한다.

14장 다리의 닫힌 장애물이 앞선 하층 구조를 막지 않도록, 기존 다리 문을 짧은 선택 피난 보행대에 배치했다. 필수 구조 경로는 열린 바닥으로 유지한다. 모든 문을 열고 통과하는 검사 외에, 목표 순서대로 실제 문을 열어 가는 보행 검사를 추가했다.

선택 발판은 기본 점프를 기준으로 다시 확인했다. 18/19의 공통 발판은 30 단위 낮췄고, 여섯 발판은 실제 접근 가능한 방향을 선택 경로에 기록했다. 필수 길에는 점프·사다리·승강기·강제 순간이동을 요구하지 않는다.

## 한 지형, 한 렌더러

- `workshop/recipes/act2-caves.js`: 장별 원본 평면/단면, 목표·적 배치와 공간 참조
- `shared/map/space-layout.js`: 저작·import·Workshop이 함께 쓰는 공간 참조/형식/폴리곤 검증
- `st.design.space`: rooms, surfaces, connections, routes, sites, encounterSites, scenery, landmarks, lights, views
- 실제 충돌은 `st.terrains`를 기존 `HonroMaps`가 컴파일한 결과 하나뿐이다
- 암면·밝은 보행 edge·석재 기단은 실제 solid 내부에 clip한다
- 뒤쪽 암반과 생활층은 비충돌 풍경이며, 명시적인 WORLD 지지면과 낮은 대비를 사용한다
- 지도 바깥의 연장은 visual-only다. 카메라를 위해 물리 지형을 추가하지 않는다

Game, Stage View, Playtest는 같은 `shared/build.mjs` 목록과 공통 `HonroScene`을 사용한다. 별도 Workshop 물리나 별도 시연 렌더러는 만들지 않았다.

## 편집 가능한 미술

`shared/assets/environment/act2-*.svg`에 소나무, 집, 법당, 등잔, 묵종, 인양틀, 석문, 작업막, 계단·회랑·담장과 원경을 둔다. SVG에 래스터 이미지를 감추지 않는다.

`tools/environment/build-act2-art.mjs`는 제한된 SVG 규격을 `asset.vector` v1 display list로 컴파일한다. `shared/map/vector-art.js`는 검증한 Path2D를 캐시한다. 외부 참조, script/image/foreignObject, 지원하지 않는 기능은 오류로 거절한다. 그룹의 중첩 opacity는 격리 합성이 구현될 때까지 명시적으로 거절한다.

`tools/environment/act2-scene-composition.mjs`는 실제 지형·유닛·목표를 바꾸지 않고 장소별 건축 묶음과 뒤쪽 지지면만 재현한다. 해당 단계는 반복 적용해도 동일하며 첫 막을 변경하지 않는다.

Workshop은 실제 SVG bounds로 선택·배치·회전·크기를 처리한다. 숨겨진 옛 polygon 점을 SVG의 편집점처럼 보여 주지 않는다. SVG 원본 내보내기를 제공하고, 충돌은 별도 polygon으로 남긴다. 복제/이름 변경과 JSON export/import 이후에도 벡터 모양을 보존한다.

19장 오래된 혼의 표식은 마지막 조사 단계 전에는 표시하지 않는다. 미션 상태가 바뀌면 같은 scene에서도 정적 캐시가 갱신된다. 종의 청동 gradient가 없는 사용자 편집 자산은 정상 벡터 표시로 돌아가며 오류를 내지 않는다.

새벽 원경은 기존 산 윤곽을 보존했다. native SVG backend에서 검게 나오던 ellipse/`use`는 동일한 기하의 명시적 path로 풀었으며, 원본의 모든 경로를 정규화해 비교한다. 이는 새로운 산 형태를 만든 변경이 아니다.

## 저장과 버전

새 전투의 `honroAct2GeometryRevision`은 3이다. 목표 revision 2와 별도다. 진행 중인 옛 전투의 terrain, marker, HP, 턴, 파괴·수위·목표 상태를 새 맵으로 덮어쓰지 않는다. 새 장 진입·재시도에 새 지도와 그림이 적용된다.

정규 Workshop 지도 형식은 version 5로 올렸다. 벡터 전용 자산을 모르는 옛 v4 클라이언트가 빈 그림으로 조용히 읽지 않고 거절하게 하기 위한 capability 경계다. 새 클라이언트는 v4 지도를 기존 WORLD 구성 그대로 읽으며, v1–v3에만 기존 이관을 적용한다. 캠페인 프로필/저장 schema는 계속 4다.

## 검증

자세한 격리 검사의 범위는 [공간 검증 계약](ACT2_SPATIAL_VALIDATION.md)에 있다.

- 목표·서사·필수 인물·방어 반경/턴·증원 수·클래스·기예·적 수치·경험치 및 첫 막 보존
- 부분 진행 중인 옛 저장의 재개 보존
- 열 장 × 네 인물 필수 보행, 닫힌 문 순서 보행, 기본 선택 점프 52건
- 파괴 목표 여섯 곳의 실제 투사체, 선택 고저차의 일반 활/기 사격
- 18/19의 동일 구조·종 배치, 20장 행렬의 실제 이동·쉼터 대기·재출발·도착·한 번의 증원
- 현재 지형 fingerprint와 일치하는 11–20장 정상 엔진 자동전투 완주. 캐릭터/적 HP·목표 상태를 강제로 바꾸는 fixture 방식이 아니다
- 실제 공통 renderer의 Native Canvas 화면: 전체 지도, 플레이 배율, 좌우 pan, 세로 화면, 종 전체 구도와 상태 변화
- 잘못된 공간/벡터 import, 구 버전 capability 거절, JSON 왕복, 렌더 중 전투 데이터 불변성

정상 자동전투는 장마다 한 가지 정상 입장 성장/기예 구성으로 수행했다. 여러 기예 구성의 난이도, 사람이 느끼는 조작과 전술 가독성, 브라우저 성능까지 보증하지 않는다.

### 재현 명령

- `npm run build`
- `npm run verify:offline` (브라우저와 긴 정상 전투 제외)
- `npm run test:act2:normal` (열 장 정상 엔진 자동전투, 오래 걸릴 수 있음)
- `npm run test:act2:combat-evidence` (기존 전투 결과의 현재 지형 일치 여부 확인)
- `npm run verify:offline -- --combat-evidence` (현재 전투 증거까지 포함한 집계)
- `npm run capture:act2 -- final --review`

`npm run verify`의 실제 브라우저/Game·Workshop·Playtest 입력 검사와 브라우저 성능 측정은 이 환경의 접근 제한 때문에 실행하지 않았다. Native Canvas를 그 검사의 대체 통과로 기록하지 않는다. 공개 업로드, push, main 병합과 배포는 수행하지 않았다.
