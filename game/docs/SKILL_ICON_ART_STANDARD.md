# 혼로 스킬 이미지 아이콘 표준 v1.0
작성: 2026-10-22 KST. 상태: 제작 기준 확정, 전체 에셋 제작·통합 검수 진행 전.
사용자 승인 방향: 먹붓 상징형의 큰 실루엣에 절제된 입체 명암을 더한다. 화려함은 줄이되 밋밋한 기호 복제로 만들지 않는다.

## 1. 적용 범위와 원칙
- 실제 최종 런타임에 노출되는 모든 능동·궁극·패시브 스킬을 고유 ID별로 관리한다. 초기 data.ts 선언이 아니라 설치/개편 함수가 모두 적용된 목록을 사용한다.
- 현재 인물은 설오·휘겸·담허·소단이다. 옛 클래스 인물명은 미술 기획 근거로 사용하지 않는다.
- 아이콘은 스킬 효과를 구별하는 수단이다. 분위기 좋은 삽화 자체가 목적이 아니다.
- 그림 생성·수정은 이미지 도구로 직접 한다. 코딩 작업은 목록 추출, UI 연결, 압축·패키징, 테스트에 한정한다. 과거 이미지 반복 편집으로 생기는 질감 누적을 피하도록 각 아이콘은 독립 텍스트 생성한다.
- 완성 전의 후보/폴백/미검수 항목을 완료로 계산하지 않는다. 스킬 효과·수치·저장·성장은 이 작업에서 바꾸지 않는다.

## 2. 시각 문법
- 성인 취향의 한국형 다크 판타지. 절제된 붓 형태, 넓고 부드러운 명암 면, 짙은 먹색 바탕.
- 주형태 1개, 보조형태 최대 1개가 원칙이다. 관통·연쇄처럼 복수 대상이 필수면 보조물을 단순한 작은 실루엣으로 제한한다.
- 주형태는 화면 약 65~78%를 차지하고, 사방 10% 안팎의 안전 여백을 확보한다. 배경은 조용한 짙은 면이며 장소 삽화는 넣지 않는다.
- 명도는 어두운 바탕/중간 몸체/밝은 핵심의 3단계로 설계한다. 재질감은 큰 면의 변화로만 표현한다.
- 거대한 발광, 렌즈광, 입자비, 불필요한 불꽃, 초미세 얼룩·반복 입자·종이결·잔긁힘·장식문양을 금지한다.
- 인물 얼굴·해부학·표정은 효과 식별에 꼭 필요하지 않으면 제거한다. 혼은 한 개의 단순한 머리·흐름 덩어리로 표현한다.
- 글자, 스킬명, 숫자, SP, 레벨, 테두리, 버튼, 등급 장식, 선택/잠금/비활성 표시는 그림에 굽지 않는다. 부적에는 읽을 수 없는 굵은 의례 표식 하나만 허용한다.

## 3. 계열별 차별화
- 설오: 가는 사선 운동과 화살촉, 절제된 뼛빛·황토·연한 금속색. 관통/산개/반사/회귀는 궤적 형태로 구별한다.
- 휘겸: 넓은 베기·돌진·방어의 무게감, 회백 금속과 낮은 채도의 청회색. 담허 원호와 혼동하지 않도록 검/몸의 방향 또는 방어 형상을 남긴다.
- 담허: 파동·굴절·진목·비술의 구조, 상아·옅은 청록. 불/얼음 등 실제 효과가 필요한 때에만 해당 보조색을 쓴다. 원호파는 원형 물결이나 검격이 아니며, 축지진목은 한 쌍의 표식이 핵심이다.
- 소단: 부적·혼·결속·소환의 형상, 낡은 상아와 탁한 자주/진홍. 저주·장악을 모두 화염이나 해골로 뭉개지 않는다.
- 색을 제거해도 같은 계열 내 스킬을 구분할 수 있어야 한다. 클래스별 색상만 달리한 동일 그림 재사용은 불합격이다.

## 4. 패시브와 궁극기
- 패시브도 전부 고유 그림을 만든다. 회복/재생/연속/반격/방어 등 실제 지속 효과를 정적인 중심 형태로 상징화한다.
- 패시브임을 알려 주는 표식은 DOM으로 분리한다. 액티브처럼 폭발 장면을 임의로 추가하지 않는다.
- 궁극기는 중심 형태의 힘과 대비로 구별하되 더 많은 입자·광채·금테로 해결하지 않는다. 궁극 표식도 UI에 남긴다.
- 자동 후속타 패시브는 같은 클래스 기본공격과 혼동하지 않도록 반복/후속의 보조 형태를 명확히 한다.

## 5. 파일·데이터 계약
- 고유 ID가 유일한 연결 키다. 이름이나 배열 인덱스로 매핑하지 않는다.
- 배포 경로: shared/assets/skill-icons/v1/{ID}.webp. 원본 생성물과 프롬프트는 별도 보존한다.
- 배포 후보는 정사각 256px WebP를 기본으로 하며, 32~48 CSS px 및 고밀도 화면에서 검수한다. 필요하면 개별 예외를 기록한다.
- 파일 목표는 보통 20KB 이하/개, 예외 35KB 이하. 품질을 망가뜨려 예산만 맞추지 않는다. 전체 및 현재 인물 묶음의 실제 전송량을 기록한다.
- manifest에는 ID, 이름, 계열, passive/ultimate, 효과 요약, 시각 모티프, 프롬프트 버전, 자산 경로, 해시, 검수 상태를 기록한다.
- 기존 스킬과 manifest ID 집합은 정확히 일치해야 한다. 누락·중복·잘못된 확장자·손상·이름/효과 불일치를 자동 검출한다.
- 원본 그림을 코드로 필터링하거나 과도하게 샤프닝하지 않는다. 내보내기의 크기/포맷 변환 및 비교용 배치는 창작 수정과 구분한다.

## 6. UI 연결
- 현재 compact HUD의 22px는 벡터 기준이다. 32~36px 내외의 이미지 영역을 우선 검토하되 버튼/터치 영역, 텍스트, 맵 시야와 충돌하면 조정한다.
- 스킬창은 기존 헤더/닫기/스크롤/SP 추가제거 동작을 보존한다. 이미지 변경을 명분으로 UI를 다시 전면 개편하지 않는다.
- 선택·비활성·잠금·랭크·SP·패시브/궁극 표식은 UI 레이어에서 표현하고 접근성 이름을 보존한다.
- 실패 시 기존 벡터 폴백을 제공하지만 최종 커버리지 검사에서는 이미지 누락으로 실패시킨다.
- 시작 화면에서 전체 아이콘 선로딩 금지. 현재 화면, 현재 인물, 장착 슬롯 중심으로 지연 로드한다. 해시 캐시와 방향/화면 재진입 시 재사용을 검증한다.

## 7. 제작 순서
1. 최종 스킬 목록 추출 및 전체 개수 확정.
2. ID마다 실제 효과 → 핵심 모티프 → 인접 스킬과의 차별점을 작성.
3. 공통 프롬프트 + 스킬별 모티프로 독립 생성. 반복 편집 대신 문제가 있는 항목만 새 생성.
4. 원본/배포본/32px 축소를 열어 보고 후보를 판정.
5. 클래스별 전량 비교판으로 중복·색/밝기·형태 일관성 확인.
6. 이미지 공급과 UI 연결 후 실제 화면 검수.
7. 수정 단위 커밋·원격 푸시. 최종 통합 검수 후 master와 기존 Pages에 반영하고 공개본 확인.

## 8. 최소 3회 집중 검수와 별도 최종 검수
- 1회: 의미/정체성. 목록 전량 대조, 실제 효과와 그림의 모순, 클래스 내 혼동, passive/ultimate 누락 확인.
- 2회: 미술/축소. 22px 기존 기준, 32px 목표, 48/64px 및 원본에서 핵심 실루엣·명도·잔무늬·과도한 화려함 검토. 큰 이미지 만족만으로 통과 금지.
- 3회: 실제 UI/성능. 모바일 세로·낮은 가로·PC에서 스킬창과 전투 HUD, 선택/잠금/기력 부족/패시브/궁극/스크롤/재진입, 네트워크 실패 및 요청량 확인.
- 별도 최종: 최종 빌드와 최종 자산 해시에 맞는 실제 화면을 다시 열어 전반적인 조화, 전량 커버리지, 저장/조작 회귀를 확인한다.
- 실패 항목은 수정 후 해당 검사를 반복한다. 회수만 채우거나 테스트 코드 통과를 미술 합격으로 바꾸지 않는다.
- 실제 스크린샷과 비교용 합성판을 명확히 구분한다. 실물 휴대폰/Safari 미검증은 별도로 밝힌다.

## 9. 확장·수정 관리
- 이 문서는 버전 관리한다. 공통 스타일 변경은 minor/major 버전, 개별 모티프·구도 보정은 항목 revision으로 기록한다.
- 신규 스킬은 inventory와 manifest에 추가하고 동일 검수 절차를 거친다. 삭제/숨김은 이유와 런타임 노출 상태를 기록한다.
- UI 크기·색·효과 정의가 바뀌면 해당 스킬과 인접 유사 아이콘을 함께 재검수한다.
- 승인된 원본/프롬프트/해시를 남겨 되돌릴 수 있어야 한다. 실패 후보를 배포 자산에 섞지 않는다.
