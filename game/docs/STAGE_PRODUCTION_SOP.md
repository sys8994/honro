# 스테이지 제작 SOP v1.2

장 개편은 아래 의존 순서로 진행하되, 모든 자산을 완성한 뒤 처음 통합하지 않는다. 검수는 변경 범위에 맞추고, 전체 개편은 세 미술 관점과 최종 종합 판정을 유지한다. 렌더 연결만의 확인을 전체 개편 완료로 표시하지 않는다. 전 장 재플레이·전체 verify·모든 스킬 검사·별도 검수자를 기본 절차로 추가하지 않는다. 사용자 최신 지시와 요청 범위가 우선한다.

## 벡터 저작 기본 경로

2026-10-28 확정된 [벡터 제작 SOP](VECTOR_AUTHORING_SOP.md)를 함께 따른다. 단계 1의 실제 플레이 스켈레톤을 먼저 고정하고 단계 2에서는 레이어/자산별 시안을 실제 Inkscape로 벡터화·정리한다. 전체 장 이미지 추적과 임의 코드 폴리곤 그림을 정식 제작 기본값으로 삼지 않는다. 공통 자산과 장 고유 지형, 미술 원본과 충돌 원본, 편집 원본과 배포 산출물을 구분한다.

## 0. 장별 설계 카드

스토리의 전후 연결, 승리조건/실패조건, 현재 참가 동행, 전투의 핵심 질문, 맵 크기/종횡비/수직성, 주요 장소/랜드마크, 반드시 보존할 ID·이벤트·기믹, 이번 변경 범위를 먼저 기록한다. 기존 기획을 보존하는 항목과 새로 설계하는 항목을 구분한다.

설계 카드와 동선 초안이 생기면 기존 공통 엔진에 내부 통합 preview를 먼저 연결한다. 임시 미술·원본 벡터·기존 적법 자산을 구분해 표시하고, 실제 보행면·동행 크기·카메라·필수 사건을 이른 시점부터 함께 본다. 시안·추적·최적화를 전부 끝낼 때까지 통합을 미루지 않는다. 내부 preview는 미술 승인이나 배포 완료가 아니다.

정상 플레이에서 보이는 끊긴 접합·가려진 배우/목표·잘못된 보행면과 진행 불능, 원문·저장 손상부터 고친다. P2 미세 장식이나 서로 다른 rasterizer의 1px 안티앨리어싱 차이만으로 출시를 차단하지 않는다. 실제 Game에서 보이는 틈·형상 손실·가독성 문제를 그 차이로 치부하지 않으며, 남은 작은 개선은 후속 항목으로 기록한다.

## 1. 플레이 지형과 동선

solid·one-way·물·위험·공중 공간과 사격각·엄폐·높이차를 함께 구성한다. 시작→필수 이벤트→목표→출구를 실제 이동능력으로 연결하며 일반 전략 경로는 접근 가능하게 한다. 기예 퍼즐 경로는 의도·보상·대체 경로 필요 여부를 명시한다. 밟는 지붕은 one-way다. 수직 포격의 높이는 화면 Y이며 원근상의 앞뒤 길과 혼동하지 않는다. 초기 아군 위치는 이 단계에서 임시 배치한다.

검수는 바뀐 길의 연결, 낭떠러지/경사 접점, 필수 사격선만 확인한다.

## 2. 공통 미술 구성

공유 assetId·재질·조합을 사용하고 원경·근접 장식·플레이 지형·전경을 분리한다. 접지, 인물 대비 크기, 한옥 구조, 광원, 여백, 미세 반복 없음으로 형태를 확인한다. 원경은 독립 이미지, 근경은 공통 벡터로 제작한다. 복사한 장별 패스를 만들지 않는다. 줌아웃 외곽도 같은 지형 세계로 연속되게 한다.

근경의 뒤쪽 지표 폭·보행면·앞 경사면은 하나의 연결된 장소로 설계하고 캐릭터 충돌면과 구분한다. 전체 근경을 충돌 폴리곤으로 잘라내지 않는다. 필요한 가림만 렌더 순서로 처리한다. 임의 삼각 분할·같은 돌의 격자 복제·거대한 단색 면으로 빈 곳을 채우지 않는다. 미술 완성도와 런타임 연결 완료를 구분한다.

실제 Inkscape 추적·편집 원본(raw)이 기존 에셋 예산 안이고 필수 형상·보행면과 실제 Game 표시를 보존하면 사용할 수 있다. 최적화는 그 원본을 기준으로 최대 두 후보만 시도한다. 두 후보가 실패하면 예산 안의 raw를 채택하고 손실 후보를 버린다. 이는 반복 작업의 운영 상한이며 시간/횟수가 찼다는 합격 규칙이 아니다. raw도 예산을 넘거나 형상을 잃었으면 원인을 수정한다. 기존 코어 validator의 형상·기하·성능 한도를 낮추지 않는다.

## 3. 아군/NPC 초기 배치

계획한 동선·스토리 상황·공간 점유에 맞춰 초기 위치를 확정한다. 시야와 이동 시작이 막히지 않는지 확인하고 NPC 역할/주인공 리그, 동행 도착 조건 등 현행 기획을 보존한다.

## 4. 적 배치

적마다 지형과 목표를 활용할 역할을 정하고 총수·밀도·정예·증원 예산을 기록한다. 등간격·항상 두 마리 쌍·좌우 복사를 피하고 장소 의미에 맞는 비대칭 군집과 여백을 둔다. 공중 적은 지형 밖의 여유 공간에 놓으며 공격이 불가능하면 접근/재위치가 가능해야 한다. 총원만으로 완료를 판정하지 않는다.

검수는 끼임·고립·즉시 부당 피격·행동 없는 배치와 필요한 교전 한 번만 확인한다.

## 5. 이벤트 상태 전이

trigger(위치/턴/처치/상호작용)→조건→결과→완료/실패→다음 상태를 연결한다. 증원의 유한성, 중복 발화, 대화 중 정지, 턴 조건 off-by-one, 완료 모달/출구 연결을 변경 범위에서 확인한다. 대사가 약속하는 행동과 보상은 실제 이벤트에 있어야 한다.

## 6. 대사·씬

화자·청자·주어·목적어·행동 주체를 명확히 하고 필수 정보를 선택 읽기에 숨기지 않는다. 사건은 이동·행동·환경 변화와 짧은 대사로 전달하며 긴 설명으로 대신하지 않는다. 다음 장의 시작 위치와 합류/퇴장 동기를 연결한다. 초상화는 해당 인물 또는 없음으로 한다. 새로 바꾼 대사·씬만 확인한다.

## 7. 집중 미술 검수와 최종 종합

장 개편은 실제 런타임 캡처를 직접 열어 다음 세 관점으로 집중 검수한다. 같은 snapshot 세트를 관점별로 재사용할 수 있으며, 세 번의 촬영·별도 검수자·별도 검수 프로세스를 강제하지 않는다.

1. 전체 형태·동선 연속성·지지 구조: overview에서 지형·가지·지붕·암반이 연결된 장소인지, 외곽까지 완결되는지 확인한다.
2. 디테일·가독성·전경/원경 구분: 일반 플레이 거리에서 재질의 중간 크기 형태, 접지, 캐릭터·조준선·상호작용 대상의 식별을 확인한다.
3. 일반/확대/최대축소/모바일 및 이동·기믹 전후: 다른 화면비와 카메라 위치, 변화한 상태에서 잘림·공백·가림·오인·충돌 불일치를 확인한다.

문제 수정 후에는 영향받은 화면/상태만 다시 확인한다. 최종 소스에서는 앞선 수정의 회귀와 이야기·공간·전투·미술의 결합을 종합 판정한다. 이 최종 판정은 별도로 남기되, 유효한 캡처·검수 근거를 재사용하고 촬영과 세 관점 검수를 처음부터 순환하지 않는다. 관점 수나 촬영 횟수가 자동 합격을 뜻하지 않는다.

검수 기록에는 소스 SHA(미커밋이면 변경 내용), 화면/상태, 직접 본 문제·수정·재확인·남은 한계를 남긴다. 실제 보지 않은 이미지나 미실행을 통과로 쓰지 않는다. hash/manifest는 출처와 변경 탐지 수단이다. 전체 hash만 달라진 무관한 장의 검사를 출시 차단으로 확대하지 않고, 실제 바뀐 코드·기하·보행면·미션·저장·에셋의 영향을 확인해 필요한 근거만 갱신한다. 코어 validator의 한도를 완화하거나 실측 없이 증거 hash만 교체하지 않는다. 별도 대형 gate 시스템은 만들지 않는다.

## 8. 관련 플레이·결과 보고·배포

수정 장의 시작→바뀐 이동/사격/핵심 기믹→승패·출구 연결을 실제 플레이로 확인한다. 위치 선점의 보상, 분산·합류·회귀·수직 동선, 캐릭터 고유 스킬의 물리 특성과 장소 이벤트는 해당 장의 설계 카드에 맞춰 평가하며 모든 장에 복잡한 구조를 강제하지 않는다. solid/one-way/위험/천장과 그림의 일치, 접근 불능·고립·불필요한 벽도 확인한다.

필요한 빌드와 변경 관련 검사를 실행한다. 새 지형은 새 진입/명시적 재시도에 적용하며 진행 중 저장의 지형·배우·전투·성장·SP·장착·캠페인 진척을 보존한다. revision만 바꾸어 기존 전투를 임의 초기화하지 않는다. 완료·부분 구현·미실행·후속 개선을 구분한다. 핵심 원문·승패·파티 분할을 숫자나 검사 통과를 위해 바꾸지 않는다.

내부 검수 후 최신 master와 타인 변경을 보존해 반영하고 필요한 HTML을 빌드해 기존 Pages에 배포한다. 공개판의 변경된 화면/동작을 확인하고 커밋·push·배포·공개 검증을 구분해 보고한다. 관련 결함을 고치면 그 항목만 재확인한다. 장별 사용자 승인 대기를 임의로 만들거나 로컬 검증을 공개 배포 검증으로 부르지 않는다. 문서만 바꾸면 문구·링크를 확인하며 게임 빌드·자동 플레이는 생략한다.

## 재료·렌더 연결만의 제한된 작업

단계 0에서 보존할 장별 데이터와 변경 범위를 기록하고 단계 1~6의 변경 여부와 최소 확인 결과를 남긴다. 기존 승패·스토리·참가 동행·ID·이벤트·기믹·충돌·발판·랜드마크를 보존하며 불필요한 새 기획을 만들지 않는다. 필요한 빌드와 활성·에셋 참조·오류 확인 및 변경된 화면/동작만 검사한다. 공통 렌더러 연결 완료와 전 장 개편·미술 합격은 별개다. 전 30장 연결 작업의 과거 대표 스모크 기록은 장별 재설계의 검수 증거를 대신하지 않는다.

### 실제 플레이 검사에서 지킬 입력·기록 원칙 — 2026-11-01

- 실패를 난이도 문제로 분류하기 전에 실제 각도/충전값,남은 이동력,접근 경로,기예의 이동 효과를 확인한다. 고정된 이동 호출 횟수 때문에 이동력을 버리거나,위층 적의 x만 따라 아래층에서 왕복한 결과로 적을 약하게 만들지 않는다. 실제 계단·합류 지점과 동행 역할을 사용한다.
- 변경 구간의 브라우저 실제 입력을 먼저 확인한다. 통과한 최종 빌드에서 전체 개편 또는 요청된 완주를 한 번 수행해 신규 진입·기예 사용·승리·정산·저장 복원까지 확인한다. 전체 도중 같은 위치·조건에서 다시 막히면 처음부터 재실행하지 않는다. 기존 저장이나 조건을 기록한 준비 상태로 해당 구간만 재현하고, 실제 입력으로 확인한다. 준비 상태 확인은 연속 완주와 구분하며, 관련 변경이 이미 검수한 근거에 영향을 줄 때만 그 근거를 갱신한다.
- 임무가 주민의 승선·호송이면 영웅의 불필요한 승선/낙수를 완료 조건으로 추가하지 않는다. 의도된 고지 호위 경로와 주민 배 이동을 실제로 확인한다. 시작→완료를 한 컨텍스트에서 확인하고 원래 승리 뒤 재로드를 별도 복원 세이브 검증과 구분한다.
- 저장 비교는 보상 알림 등 정상 UI 처리 시점을 맞춘다. 비교가 다르면 필드별 before/after를 먼저 남긴다. 알림의 정상 false→true 전이를 성장/장비 손실로 오인하지 않되,값을 직접 고치거나 임의 제외해서 통과시키지도 않는다.
- 제자리 방어 같은 부정 대조는 일반 플레이나 성공률이 아니다. 실제 Engine 초기 RNG·합법적인 Game UI 입력·성장/장착·입력 정책의 동등성을 확인하기 전에는 seed 라벨이나 모델 성공 횟수를 표본 성공률로 주장하지 않는다. 화면의4턴 클리어는 보통 적3턴이 지난 상태이며, 상대 턴·발사 횟수·입력시점도 구분한다. 한 번의 빠른 탈출이나 낮은 피해를 전체 난도 합격으로 쓰지 않는다.

### 주민 호송·런타임 변경 재검수 (2026-11-01)
- 주민끼리 경사 하강 후 가까워지는 경우를 검사한다. 기존 겹침에서 접지한 주민이 정상 보행으로 간격을 늘리는 경우와 새 겹침·뒤에서 밀기·공중 통과를 구분한다. 위치 강제 이동이나 충돌 무시로 정체를 통과시키지 않는다.
- 정체를 조사할 때에는 필요한 시점의 좌표·지지면·경로 index·대사 상태와 실제 저장 원문을 함께 남긴다. 마지막 phase 로그를 실패 종료 시점의 상태로 단정하지 않는다.
- 공유 런타임 변경도 실제 영향받는 동작을 기준으로 재검수한다. 비배포 preview에서 관련 Engine 입력/실제 UI 목표를 확인하고 근거를 갱신한다. 전체 hash 차이만으로 무관한 장의 전체 플레이를 다시 요구하지 않으며 원문·저장·기하·보행면을 보호하는 코어 검사는 유지한다.
- UI 시험이 읽는 비교 JSON·저장 fixture는 실행 전에 존재·형식·해시를 점검한다.404나 JSON 파싱 실패는 게임 난이도/클리어 실패와 구분한다.
- 초기 배치 보고 화면은 턴 안내 띠가 사라진 뒤 촬영하고,적 배치를 볼 수 있는 카메라를 사용한다. 도입 연출·시작 인물만 보이는 화면을 전체 몬스터 배치 증거라고 표시하지 않는다.
