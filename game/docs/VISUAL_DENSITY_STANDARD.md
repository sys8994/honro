# 화면 역할별 미술 밀도 기준 · 2026-10-29

## 수정 사유

사용자가 4막 검수 화면에서 배경 폐가·바위 무늬는 과밀하고 실제 발판·지형 윤곽은 지나치게 단순하다고 지적했다. 이전 제작은 개별 시안 재현과 안전 한도 통과에 치우쳐 같은 화면의 중요도·밀도·대비를 통제하지 못했다. 이전 31–40 미술 후보는 이 기준의 재검수 대상이며, 기존 완주/최적화 수치만으로 미술 승인을 유지하지 않는다.

## 원칙

동일 노드 수가 아니라 **같은 화면 크기에서 역할에 맞는 시각 밀도**를 맞춘다. 곡선 제어점·직선 정점·compound subpath·색 면 수는 서로 대체 지표가 아니다. 노드와 바이트는 실행 비용, 실제 화면의 경계 빈도·작은 색 조각·대비·형태 인지는 미술 기준으로 나누어 기록한다.

1. **플레이·상호작용**: 접촉면, 발판 끝/두께/이음, 엄폐 상단, 문의 판재/빈 철물 자리, 연결 균열을 우선한다. 단색 막대에 무작위 점을 뿌리는 대신 입체 구조와 재질을 읽히게 한다.
2. **배경 건물·장식**: 실루엣과 재질별 큰 명암, 장소의 특징만 남긴다. 모든 기와·잔돌·목재 흠집을 보존하지 않는다. 문이 상호작용 대상이어도 집 전체를 같은 밀도로 만들지 않는다.
3. **지하/심부 BODY**: 큰 저대비 지층·암면으로 물린다. 큰 얼룩은 노드/고주파 수가 적어도 대비가 강하면 화면을 압도하므로 별도로 점검한다.
4. **FORE**: 큰 프레이밍 형상과 빈 공간을 사용한다. 크고 가까운 물체라고 잎맥·잔가지를 촘촘히 넣지 않는다. 배우·조준·목표 가독성을 우선한다.
5. **원경**: 낮은 대비와 큰 형태·대기감을 유지한다. 질감보다 공간 구분이 목적이다.

같은 물체라도 배경 BODY, 플레이 가능한 지붕/발판, 상호작용 문을 별도 역할로 나눌 수 있다. 공통 자산에는 역할·기준 표시 크기·중요 특징·허용 오차를 붙인다.

## 36장 시험의 초깃값 (아직 전 장 확정 성능 예산이 아님)

정상 플레이 화면에서 캐릭터 높이를 H로 둔다. 실제 UI의 CSS 픽셀 기준이며 DPR을 섞지 않는다.

- 플레이 재질의 읽히는 주요 특징: 대략0.04–0.10H. 접촉선/얼굴/구멍 같은 중요 특징은 이보다 작아도 별도 보호한다.
- 배경·장식의 의미 없는 내부 조각:0.12H 미만은 병합·삭제 후보. 외곽 형태·문/창의 의미를 훼손하지 않는다.
- 심부 BODY 주된 면:0.35H 이상 큰 덩어리, 좁은 무늬 반복 억제.
- 위 수치는 원본의 픽셀이나 월드 단위 임계값이 아니다. 일반·최소·최대 줌에서 다시 판단하며 자동 삭제 조건으로 쓰지 않는다.

화면 진단은 고정 카메라/배율/해상도에서 해당 역할 ROI의 경계 빈도, 인접 명도 차이, 명도 범위를 함께 비교한다. ROI에 배우·다른 레이어가 겹치면 영향을 명시한다. 경계 지표 하나가 낮다고 합격시키지 않는다. 검사기의 requested camera가 아니라 **실제 렌더 직후 카메라**를 기록한다.

## 재저작과 최적화의 순서

- 과밀한 시안은 먼저 의미별로 재저작한다.36장의 기와·잔해를 큰 면으로 정리한 새 집 시안이 예다. 기존 raw와의 색/형태 차이는 의도적인 미술 변경이며 무손실 최적화로 포장하지 않는다.
- 새 시안을 실제 Inkscape로 벡터화한 뒤, 그 raw를 불변 기준으로 기존 오차 제한 최적화를 적용한다. 색 수를 줄여 지붕과 목재가 합쳐지면 수를 늘리거나 팔레트를 다시 설계한다. 색 개수 자체가 밀도 목표는 아니다.
- 기존 벡터의 팔레트 병합은 의미 있는 선택으로 기록한다. 같은 색 인접 도형의 실제 Boolean Union으로 보이지 않는 중복을 줄일 수 있으나 그리기 순서/알파/구멍을 비교한다.
- 플레이 지면의 장식은 실제 접촉선/통로를 침범하지 않는다. 그림만 요철을 만들어 보이지 않는 벽/발판을 만들지 않는다. 실제 지형 윤곽을 바꾸면 물리와 그림을 같이 바꾸고 해당 이동·점프·사선을 재검증한다.
- 코드로 임의 폴리곤을 늘리는 방식은 밀도 향상이 아니다. 구조 안내선과 실제 물리 clip은 코드로 만들 수 있지만 최종 재질 미술은 시안→Inkscape 자산을 사용한다.

## 적용 순서와 승인

1.36장: 배경 집/벽/잔해 저밀도화 + 문짝 구조 선명화 + 발밑 접촉 띠 강화 + 심부 지반 대비 억제.
2.35장: 실제 엄폐와 발판/지면 구조, 대나무 장식/근경의 상대 밀도 확인.
3.32장: 공통 건물과 상부 통로에서 같은 기준 재현.
4. 기준이 일관되게 읽힌 뒤31–40 전체에 적용한다. 단순히 한 필터를 모든 자산에 일괄 적용하지 않는다.

원본/수정본을 같은 구도에서 전체·접촉부·상호작용 상태·세로 화면으로 직접 검수한다. 보호해야 할 작은 특징, 배우보다 시선을 빼앗는 배경, 지나치게 평평해진 재질, 떠 보이는 발판/기단을 확인한다. Native 검사와 실제 브라우저/휴대폰 검증, 원격 저장/배포는 각각 구분한다. 스크립트가 미술 합격을 생성하지 않는다.

## 32·35장 실제 화면에서 확인한 보완 규칙

- 색 수와 경계 빈도가 줄어도 넓은 고대비 암면이 화면 아래 절반을 차지하면 불합격이다.31·32의 팔레트 병합 후보와35의 초기 후보가 이 사례다. 깊은 부분의 대비를 낮추되, 지면 가까운 재질까지 지워 커다란 빈 면으로 만드는 것도 피한다.
- 심부 감쇠는 실제 접근 가능한 경계로부터의 거리로 설계한다. 바닥의 상단과 동굴 천장의 하단은 서로 다르다. 천장 자산에 바닥용 위쪽 띠를 그대로 적용하지 않는다.
- 작은 발판은 명암 점을 늘리는 대신 윗면, 두께, 옆면, 판재의 연결을 구분한다. 반복 모듈은 가로로 길게 늘리지 않고 자른 뒤 실제 경사에 맞춘다. 묻혀야 하는 끝은 지반 뒤에 그린다.
- 돌계단은 디딤면과 수직 높이가 우선이다. 서로 다른 단수·높이의 계단에 완성 그림 하나를 통째로 늘리지 않는다. 원본에서 실제로 잘라낸 디딤돌·옆면 모듈을 사용하고 작은 떠 있는 돌 조각은 의도적으로 정리한다.
- 엄폐용 돌담은 배경보다 구조가 뚜렷해야 하지만, 작은 푸른 돌·이끼 점까지 촘촘히 남길 이유는 없다. 깨진 상단, 큰 돌의 맞물림, 전체 높이를 보호하고 내부 잡음을 낮춘다.
- 화면 캡처를 공유한 중간 후보는 최종 승인으로 간주하지 않는다. 미해결 항목을 함께 기록하고, 후속 수정 후 같은 카메라에서 다시 검수한다.

### 스테이지별 완료 증거

각 스테이지는 아래를 별도로 기록한다. 하나의 통합 `pass` 값으로 대체하지 않는다.

1. 원본/새 미술 마스터/최적화본의 구분, 역할별 보호 특징과 의도적 삭제·변경.
2. 최적화본의 실제 확장 노드·경로 길이·파일 크기와 raw 대비 화면 오차. 실패한 임계값도 보존.
3. 동일 실제 카메라의 보통 배율·확대·세로 화면. 접촉·엄폐·상호작용부와 심부 배경을 각각 직접 관찰한 판정.
4. 물리 지형 및 상호작용 계약 비교, 실제 입력 진행, 저장·불러오기 결과. 미술 검수와 기능 검수는 별개.
5. 원격 커밋 확인, 배포 확인, 실제 브라우저 검증. 로컬 Native 렌더만 수행했다면 그대로 명시.
