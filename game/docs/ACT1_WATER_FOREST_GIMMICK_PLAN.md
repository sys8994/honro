# 1막 물·원경·장소 기믹 재설계안 — 2026-09-30

이 문서는 1막의 물·원경·장소 기믹 **전체 설계안**이다. 현재 3–6장 맵과 1·2장 목업 기반 맵의 차이를 다시 분석했다. 2026-09-30 후속 작업에서 사용자 요청에 따라 **3·4장을 먼저 구현**했고, 아래의 5·6장 및 1·2장 확대 적용은 남은 계획이다. 세 목표는 (1) 읽히는 물의 흐름, (2) 배경 구조와 게임 경로가 결합한 장소, (3) 1막 전체를 관통하는 높고 빽빽한 한국 산지의 밤숲이다.

## 1. 현재 진단

- 1·2장에서는 큰 소나무의 줄기·가지와 실제 밟거나 부술 수 있는 가지 발판이 한 구조로 보인다. 가지가 없어져도 지상 경로가 남는다. 3–6장에는 기존 일방향 발판과 5장의 파괴 가능한 `cliff-cleat`가 있지만, 대부분 배경 오브젝트와 게임 경로의 인과관계가 약하다. 3장의 나루 지주와 6장의 교각은 설치 이유는 설명하지만, 플레이 결정은 별로 바꾸지 않는다.
- `shared/runtime/art-dark.js`의 `water-pool`은 정적 그라데이션 면·직선 수면·반복 짧은 선이다. `shared/runtime/map-art-polish.js`의 폭포 역시 고정 폴리곤과 선이다. 그래서 물의 방향, 장애물에 부딪히는 흔적, 낙수 충격이 보이지 않는다.
- `shared/runtime/renderer.js`는 보통 배율에서 지형·수면·장식물을 전체 맵의 정적 캐시에 그린다. 지금 함수에 `this.time`만 섞으면 대부분 화면에서 움직이지 않는다. 원경도 별도 카메라 버킷 캐시에 묶인다. 동적인 물·안개는 캐시 밖에서 그리는 렌더 순서를 설계해야 한다.
- `art-dark.js`의 원경은 다섯 겹의 꺾인 산 능선과 규칙적 나무 반복이다. 3–6장 전체 지도에서는 하늘과 능선이 화면을 대부분 차지하고, 소나무는 낮고 희미해 1막의 숲보다는 탁 트인 산길로 읽힌다. 5장 개요의 폭포는 상류와 낙수 지점을 연결하는 물줄기라기보다 절벽의 얇은 수직 띠로 읽힌다.
- 5장의 `waterfallFoot` 앵커는 x≈3280인데 최근 시각 폭포는 x≈2960에 그려진다. 미술·앵커·수면·이벤트가 같은 낙수 지점을 가리키는지 재검증해야 한다.

## 3. 물: 고정 지형 위에 작은 움직임을 얹는다

**정적 기층.** 수면의 실제 영역, 깊이, 양 둑, 젖은 돌, 바닥의 그림자는 캐시에 둔다. 물의 전도·통과 판정과 저장 데이터는 기존 맵 컴파일 결과를 그대로 사용한다. 파란 반투명 면을 주인공으로 쓰지 않고, 야간의 검푸른 수체와 밝기 낮은 물가 가장자리를 기본으로 한다. 밝은 청백색은 달이 닿는 좁은 줄기, 소용돌이 끝, 낙수 포말에만 배분한다.

**동적 수면.** 각 물 영역의 바깥 윤곽을 캐시한 마스크로 만들고, 마스크 내부에서만 2–3개의 짧고 불연속적인 흐름선과 드문 반사 조각을 움직인다. 물가 양끝의 위상과 높이는 고정하고 중앙은 작은 진폭으로만 흔든다. 속도와 방향은 장면별로 다르게 정한다. 고요한 못은 넓고 느린 흔들림, 좁은 여울은 빠르고 끊긴 선, 바위 뒤는 제자리 회류를 배치한다. 모든 물을 동일한 정현파로 채우지 않는다. 장애물 앞뒤에 갈라짐·거품·재합류가 있어야 흐름이 읽힌다.

**낙수.** 5장 폭포는 상류의 얕은 물길과 절벽 턱, 2–3겹의 폭이 다른 낙하 막, 중간의 끊긴 백색 속선, 바위 충돌 지점의 포말·낮은 안개, 이어지는 하류 웅덩이로 묶는다. 낙하 막의 외곽은 크게 흔들지 않고 내부 획과 드문 물방울만 아래로 이동시킨다. 낙수 충격은 웅덩이의 동심원보다 좌우로 짧게 깨지는 낮은 포말이 어울린다. 낙수 시작점·종점·관련 앵커는 일치시킨다.

**상호작용.** 캐릭터 착수, 화살/물체 낙하, 전격이 실제 물 표면과 만날 때만 1–2초짜리 국소 파문을 낸다. 전격 시각 피드백은 기존 `conductive` 판정이 참인 영역에만 보인다. 상호작용이 없을 때는 루프 물결만 있고 다량의 입자는 만들지 않는다. 시각 애니메이션이 수면 높이, 충돌, 전기 판정, 턴 진행을 바꾸지 않는다.

**렌더 순서/예산.** `캐시 원경 → 캐시 지형·물의 기층 → 보이는 물의 후면 패스 → 유닛 → 필요한 소량의 전면 포말 → UI`로 설계한다. 큰 물 폴리곤 전체를 매 프레임 갱신하지 않는다. 카메라와 교차하는 물만 그리고, 곡선·마스크는 `sceneVersion`별로 준비한다. 낮은 성능에서는 띠/파문 수와 갱신 빈도를 단계적으로 낮추고, 숨겨진 탭에서는 멈추며, 줄인 모션 설정에서는 고정 위상으로 보여준다. 구체적인 15/30/60fps 선택은 먼저 기준 성능을 재고 정한다. 추가 물 패스의 잠정 목표는 화면별 p95 1ms(데스크톱), 2ms(저사양 모바일) 이내이며, 장면 전체의 기존 목표 fps와 캐시 재빌드 0회를 우선한다.

## 4. 장소와 게임 기믹의 연결

각 기믹은 `보이는 원인(나무·말뚝·바위·교각) → 지지되는 충돌체 → 플레이 선택 → 부서짐/우회 후 결과` 네 칸으로 작성한다. 배경에 그려진 지지물과 실제 발판의 좌표·기울기가 맞아야 한다. 경로를 여는 구조물은 주요 임무 대상과 겹치지 않게 두고, 파괴 후에도 필수 진행이 가능해야 한다. `경로의 수`보다 한 장소에서 **두 가지 이상의 의미 있는 플레이 선택**이 읽히는지가 기준이다.

| 장 | 장소의 원인과 화면 요소 | 실제 게임 요소 및 선택 | 사전 검증할 위험 |
|---|---|---|---|
| 3장 · 나루 | 강둑→물에 박힌 나루 말뚝→물에 젖은 접안판→창고 하역대. 아래에는 여울·젖은 돌, 위에는 짐을 묶는 줄. | 기존 `dock-*`와 `cargo-step-*`를 같은 말뚝·가로보에 결합한다. 선택적으로 부술 수 있는 낡은 연결판 하나로 상부 접근/하부 물가 전투를 나눈다. 물에 선 적에 대한 기존 전격 규칙을 장소가 암시한다. | 부순 뒤에도 장부·출구에 이르는 지상 경로, 상여/아군 통과, 나루 발판 아래의 충돌과 전격 깊이. |
| 4장 · 관문 밖 | 관문 석축→불탄 민가의 남은 기둥→수레가 막힌 좁은 방어선→언덕 위 망루. 각 발판은 집의 들보나 망루 받침에서 나온다. | 수레/무너진 담장 한 곳을 방어 엄폐와 우회 대상으로 만들고, 기존 `watch` 발판을 정찰/사격 위치로 읽히게 한다. 관문 앞 보호 구역과 적 진입선이 명확해야 한다. | 호위·방어 NPC를 가두지 않기, 적 소환/진입 동선, 원거리 시선 차단이 기존 규칙으로 구현 가능한지. |
| 5장 · 폭포 절벽 | 산길→암반 균열의 선반→상류 수로→폭포 턱/물막→충돌 분지. 평평한 `climb-*`는 암반에서 실제로 돌출한 면으로 변환한다. | 기존 파괴 가능한 `cliff-cleat`를 **선택 가능한** 지름길/사격각으로 만들고, 건조한 바깥 암벽 길과 폭포 가까운 젖은 선반 길을 구분한다. 물막은 투명한 장식처럼 보이다가 갑자기 고체로 막지 않게 충돌과 외형을 일치시킨다. | 각 선반 사이 실제 점프 거리, `waterfallFoot`와 낙수 위치, 소단/이벤트 목표의 접근, 물막의 투사체/시야 규칙. |
| 6장 · 끊어진 목교 | 양쪽 지반→교량 상판 잔해→하중을 받는 교각과 결속 줄→아래 여울/돌바닥. 파손 지점은 상판·줄·잔해가 함께 설명한다. | 상부는 빠르지만 노출된 길, 하부는 느리지만 엄폐가 있는 길. 낡은 잔해 발판 1–2개만 파괴/우회 선택으로 만들고, 교각 옆돌을 하부 발판으로 결합한다. 수면 흐름은 교각 주위에서 분기한다. | 필수 구출 대상의 안정적 위치, 발판 파괴 후 양방향 복귀, 적/아군 AI의 하부 경로, 카메라에서 상·하부가 모두 읽히는지. |

1·2장에도 새 물 표현을 적용해 미술 언어를 통일한다. 이후 구간은 기존 임무·발판을 기준으로 다음 장소 설계가 자연스럽다. 3–6장 세로 단면을 검증한 뒤 상세 좌표를 확정한다.

| 장 | 후속 기믹 설계 방향 |
|---|---|
| 7장 · 거목 마을 | 기존 `tier-*` 지그재그와 `side-perch-*`를 한 거목의 줄기·뿌리·집 발코니에 잇는다. 주민 구조 지점은 실제로 접근 가능한 나무 구멍/뿌리 터에 두고, 측면 가지는 구조 순서를 바꾸는 사격 자리로 만든다. |
| 8장 · 빈 상여 길 | 긴 행렬길과 `eave-step-*`를 실제 처마 회랑으로 연결한다. 기존 파괴 가능한 `bier-screen`·`bier-knot-*`를 묶음/가림막의 시각적 근거와 함께 쓰고, 상여 이동 경로는 파괴 여부와 무관하게 남긴다. |
| 9장 · 바람 없는 마당 | 우물과 두 받이진 사이의 마당 축, 양쪽 회랑, `center-lookout`의 사격각을 한 공간으로 묶는다. 원경 숲은 마당 벽 뒤로 밀고, 중앙 우물 주변에 전투 선택을 집중한다. |
| 10장 · 상단 사당 | 의식대·계단·양쪽 회랑의 세 높이를 건축적으로 연결한다. 위치 점령이 보스 사격각을 바꾸되, 의식/받이진 목표와 출구에 필수 경로가 남아야 한다. |

장식이 상호작용을 암시하면 실제로 상호작용 가능해야 하고, 순수 배경은 명도·깊이로 구분한다. 후반부에는 기믹 수만 늘리는 대신 기존 임무의 판단을 바꾸는 구조를 장마다 추가한다.

## 5. 1막의 원거리 배경: 산맥에서 밤숲으로

1막 1–10장의 기본 지형 어휘를 **멀리 낮게 깔린 산이 아니라, 키 큰 소나무·참나무가 시야를 막는 골짜기 숲**으로 바꾼다. `sky / far canopy / middle trunks / near framing / fog`를 별도 거리층으로 설계한다.

1. 하늘은 먹색에 가까운 남청·먹녹 그라데이션. 달은 매 장 화면 구석에 찍는 원이 아니라 구름/수관 틈에서 일부만 보이게 하고, 달빛은 구름 아래의 옅은 냉색 경계와 줄기 한쪽의 미약한 림라이트로 나타낸다.
2. 가장 먼 수관은 서로 겹치는 어두운 덩어리로 만들되 일정 간격의 나무 아이콘 반복을 없앤다. 수관 높이와 골의 빈틈은 고정 시드로 변주한다. 장면마다 2–3개의 큰 수직 실루엣을 두어 인물과 나무의 크기 차가 느껴져야 한다.
3. 중간층은 길고 불규칙한 줄기, 위로 올라갈수록 좁아지는 가지, 낮게 처진 수관과 일부 고사목. 1·2장의 큰 나무, 3장 둑 소나무, 5장 절벽 소나무 등 전경 구조와 원경의 수종·규모가 이어지게 한다.
4. 가까운 프레이밍은 화면 가장자리의 짙은 나무/바위와 얇은 안개다. 유닛·탄도·임무 표식을 가릴 만큼 밝거나 불투명하게 하지 않는다. 원경의 명도 단계는 플레이 지형보다 낮게 유지한다.
5. 장별 차이는 같은 숲의 상태 변화로 만든다. 3장은 수변 안개와 벌어진 둑, 4장은 그을린 수관과 재, 5장은 절벽의 안개 틈과 젖은 소나무, 6장은 협곡을 덮는 나무의 검은 천장이다. 관문·사당의 실루엣은 숲 속 실제 빈터에만 나타난다.

원경을 전부 매 프레임 다시 그리지 않는다. 정적 수관/줄기 경로를 시드와 카메라 버킷으로 캐시하고, 구름·안개의 낮은 속도 이동만 작은 동적 패스로 분리한다. 현재 단일 배경 캐시와 `.055` 보정 때문에 거리별 시차가 정확히 유지되는지 확인해야 한다. 층별 시차가 화면에서 유의미하다면 원경 캐시를 거리별로 분리하거나 버킷 이동량을 보정한다. 산 능선은 국소 지평선 뒤에 조금만 남기고, 화면의 주된 실루엣은 나무가 맡는다.

## 6. 제작 순서와 판정 기준

1. **기준 장면 측정:** 1–6장 전체/실제 플레이 배율, 5장 폭포와 3·6장 물가의 확대 화면, Game/Stage View/Playtest, 렌더 시간·캐시 횟수·메모리를 같은 조건에서 기록한다. 물의 출처/유출, 발판 지지, 필수 경로를 지도 위에 표시한다.
2. **장별 세로 단면 시제품:** 사용자 우선순위에 맞춰 3·4장의 물가·방어선·밤숲부터 구현했다. 다음 5장은 상류–폭포–분지·암반 선반·밤숲의 한 카메라 폭을 먼저 만들고, 0초·0.5초·1초 화면과 짧은 재생 영상으로 흐름과 게임 배율 가독성을 확인한 뒤 넓힌다.
3. **남은 장소별 설계:** 각 장에 한 장짜리 도면을 만든다. 배경 구조물과 충돌체 ID, 전투/이동 선택, 파괴 전후 경로, 물의 유입/유출, 카메라 컷을 같은 도면에 적는다. 1·2장의 물과 1막 전체 원경은 장별 검토 뒤 이어 적용한다.
4. **관련 검증:** 맵 컴파일/마이그레이션·저장 복원·전격/물 판정·발판 파괴 후 목표 도달을 해당 장의 검사로 확인한다. 동일 시간 위상에서 두 HTML의 Game·Stage View·Playtest를 비교하고, 서로 다른 시간의 물 화면이 실제로 달라지는지 확인한다. 실제 전투 배율과 전체 지도 배율에서 시각 검수를 반복한다. 렌더러·스키마·물리를 바꾼 라운드는 `tests/migration.mjs`와 `tests/integration.py`를 통과시키고, 성능은 다른 브라우저 부하 없이 순차 측정한다. 광범위한 배포 전 검증을 제외한 작업 라운드에서는 관련 검사만 실행한다.

**수용 기준:** 폭포에서 물의 출처와 종점이 설명되고, 3·5·6장의 물 흐름이 방향과 장애물 반응으로 구분된다. 1막 원경은 산 능선보다 수직 숲이 먼저 읽힌다. 3–6장 각 장에서 배경 구조와 결합된 게임 선택이 최소 하나는 **실제 플레이 중** 확인된다. 발판 파괴/우회 후 필수 목표를 완료할 수 있고, 전도·저장·기존 캐시 성능을 해치지 않는다. 정지 화면과 실제 재생 화면 모두 한국형 다크 판타지의 무게감과 읽기 쉬운 전투 화면을 유지한다.

## 7. 3·4장 우선 적용 기록

- 3장: 나루의 기존 물 영역 `ferry-water`를 전도 가능한 얕은 물로 등록했다. 정적 수체 위에 작게 흔들리는 표면, 오른쪽으로 흐르는 불연속 물띠, 지주 주위의 회류, 착수 파문을 캐시 밖에서 그린다. 잔교 아래에 지주와 결속 줄이 받치는 파괴 가능한 `ferry-side-gangway`를 더했다. 높은 잔교와 물가의 중간 경로다.
- 4장: 불탄 민가를 더 분명한 구조물 층에 놓고, 남은 기둥·가로보 위에 파괴 가능한 `burned-gallery`를 더했다. 방어선 위쪽의 선택적 사격 자리이며 지상 도로와 보호 목표는 그대로 남는다.
- 두 장: 반복 산 능선 원경을 키 큰 소나무 줄기·겹친 수관·구름·수관 뒤 달빛이 있는 밤숲으로 바꿨다. 불탄 민가 쪽은 수관 색과 부러진 가지를 더 검게 처리했다. 현재 배경 캐시가 한 장이므로 숲 거리층의 시차 속도는 공통 값이다. 서로 다른 거리별 시차는 이 캐시 구조를 다시 나눌 때 추가한다.
- 두 장의 [실제 화면 비교와 3장 물 애니메이션](../../_local/reports/stage34-water-forest/index.html)을 `_local/reports/stage34-water-forest/`에 저장한다. 해당 범위의 렌더링·게임 데이터 검사는 `node tests/stage36-place-design.mjs`와 `python -X utf8 tests/stage36-place-browser.py --stage34`다.
