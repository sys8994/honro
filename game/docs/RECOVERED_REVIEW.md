# Reconstructed review tools · 2026-10-06

The original review-job source did not survive the environment rollback. The current implementation is a separately reconstructed, deliberately bounded current-source reviewer. This is not byte-for-byte recovery of the former historical-evidence or intent-orchestration implementation. Earlier counts and CLI guarantees in INTENT_PIPELINE.md remain historical until individually restored.

Supported commands are listed by `npm run review-job -- help`: init an explicit stage scope and goal, resume fixed build/test commands, inspect status, import externally observed browser evidence, record explicit current user art approval, and write a gated local delivery manifest. It has no remote writer, deployment command, browser driver or automatic approval. `act-canonical`, linked intent runs and historical-browser adapters are explicitly rejected rather than treated as approved.

The source fingerprint covers checkout files excluding Git metadata, dependencies, local reports and generated runtime targets. Both built HTML files and external MP3 assets have a separate target digest. Every browser observation must name both exact digests, its actual observer/time, linked report and screenshot hashes, and precise coverage. Normal play must explicitly be ordinary input, completed, non-debug and unmodified. Same-profile campaign continuity and measured numeric performance need their own observations. A native render, simulated terminal state or command exit is not browser completion.

Known failures remain across source/build changes. Only a strictly later passed observation of the same check/stage on the current target resolves them. Evidence hashes are rechecked even for stale receipts. Partial proof never automatically supplies art acceptance or local delivery. The operator must verify real user/observer provenance outside the adapter: hashes authenticate bytes, not the honesty or identity of an author.

`resume` runs a fixed, explicit offline subset including rest, charge and camp regressions. It runs commands again rather than reusing the old implementation's cached-success protocol. This subset is not the full `npm run verify`. Browser CSS/focus/touch/storage, Game/Workshop/Playtest, isolated performance and genuine campaign completion remain separate.

Tests use synthetic files and packets under temporary directories only. Those fixtures are never real release evidence. Recovered regression scripts call production functions while clearly disclosing DOM/storage, clock, rendering and terminal-state doubles.
