# 인트로·막 엔딩 방향별 그림 연결 현황

현재 판정: 구현 및 3회 집중 검수·별도 최종 기능/배치 검수 완료. 신규 세로 원본 공급과 부모의 해당 그림 최종 미술 검수는 **대기 중**이다. master/Pages는 변경하지 않았다.

## 부모 전달 사항 · 2026-10-21

- 작업 브랜치: `feat/responsive-story-art`. 조사 시 `origin/master`와 작업 기준은 모두 `c5e5ec8e80ccc03c5ee7d5c8a4a4eea102b83c2f`이며 그 이후 원격 변경은 없었다.
- 부모가 직접 그림 생성·편집을 맡는다. 이 브랜치는 그림을 생성하거나 수정하지 않는다. 최종 부모 이미지 검수 전에는 master에 병합하거나 Pages에 배포하지 않는다.
- 현재 인트로 가로 원본: `shared/assets/environment/title/landscape.webp`, JPEG 대체본 `shared/assets/environment/title/landscape.jpg`.
- 현재 인트로 세로 원본: `shared/assets/environment/title/portrait.webp`, JPEG 대체본 `shared/assets/environment/title/portrait.jpg`. 이미 독립 세로 그림이 존재한다. 새 위아래 확장 그림은 이 세로 파일만 교체하고 가로 파일은 유지하는 방식을 권장한다.
- 제목은 배경 그림에 포함되지 않는다. `shared/runtime/title-markup.js`의 `<h1 class="title-brand">`가 `hanja-wordmark.png`의 `魂路`와 `wordmark.png`의 `혼로`를 별도 이미지로 올린다. 부제·시작 버튼·설정도 DOM이다. 새 그림에 제목과 메뉴 글자를 넣지 않는다.
- 인트로 선택 코드는 같은 파일의 `scene()`의 `<picture>`이다. `shared/web-build.mjs`가 실제 에셋을 해시 파일로 내보내고 방향별 preload와 초기 HTML을 만든다. `game/src/title.css`가 제목·본문·버튼 위치와 safe area를 담당한다. 생성된 HTML을 직접 고치지 않는다.
- 엔딩 가로 원본은 `shared/assets/endings/act-1.webp`, `act-2.webp`, `act-3.webp`이며 보존한다. 권장 신규 세로 경로는 `shared/assets/endings/act-1-portrait.webp`, `act-2-portrait.webp`, `act-3-portrait.webp`이다.
- 엔딩 데이터는 `shared/runtime/act-endings-content.js`의 10/20/30 항목이다. `shared/runtime/act-endings.js`의 `preload()`·`show()`가 로딩·표시하고, `game/src/act-endings.css`가 배치한다. 엔딩 본문 및 다음 막 제목도 DOM이다. 기존 모바일은 가로 그림을 cover로 확대하고 막마다 가로 초점을 옮긴다.
- 현재 `shared/runtime/main.js`는 승리 후 대화 직전에 해당 막 그림만 preload한다. 게임 시작 시 엔딩 그림을 선로딩하지 않는다. 새 구현도 시작 시 금지·현재 막/보이는 방향만 로딩 원칙을 유지한다.

## 구현·검수 상태

방향별 에셋 선택, 회전, 캐시 재사용, 화면 크기 고정, safe area와 본문 위치 구현을 완료했다. 새 엔딩 세로 파일이 없는 동안 명시적으로 가로 대체를 유지하며 없는 파일 요청이나 임의 이미지 가공을 하지 않는다. 최종 새 세로 그림의 미술 합격은 아직 대기 중이다.

320×568, 390×844, 412×915 및 가로 화면을 대상으로 실제 Chromium 스크린샷 검수 3회와 별도 종합 검수를 기록한다. 자동 결과와 스크린샷은 저장소 지침에 따라 `_local/reports/responsive-story-art/`에 두고 이 문서에 판정과 제한을 남긴다.

## 세로 파일 공급 계약

엔딩의 `portraitImage`는 위 권장 경로를 가리킨다. `node game/build.mjs`가 파일 존재를 확인하여 있으면 원본 바이트 그대로 해시 URL로 발행하고 없으면 생성 런타임에서 null로 바꾼다. 부모는 세 파일을 해당 경로에 공급한 뒤 빌드하면 된다. 기존 가로 파일 및 인트로 가로/JPEG/제목 파일은 교체하지 않는다. 새 인트로 세로 WebP는 `portrait.webp`를 교체하며 JPEG 대체본도 부모가 직접 제공한다. 브라우저가 지원하는 WebP만 선택하고 JPEG는 포맷 대체본이다. 파일을 같은 이름으로 교체해도 빌드 결과 URL의 내용 해시가 바뀌므로 예전 캐시와 충돌하지 않는다.

## 1차 집중 검수 · 구조와 기본 화면

실제 Chromium에서 320×568, 390×844, 412×915, 844×390, 1440×900을 촬영했다. 인트로와 세 막의 첫 컷 20장 및 `1/checks.json`은 `_local/reports/responsive-story-art/`에 있다. 인트로 4개 화면, 엔딩 세로 각 막과 가로 3막 캡처를 직접 열어 확인했다. 방향별 인트로 한 장만 요청, 시작 시 엔딩 요청 0건, 엔딩 해당 막 한 장만 요청, 전체 화면 이미지와 본문 범위를 통과했다. 새 엔딩 세로 미공급으로 현재 가로 확대의 구도 제한은 남아 있으며 미술 합격으로 간주하지 않는다. 인트로 하단 음악 제목과 footer가 가로에서 겹쳐 후속 단위에서 간격을 교정한다. 기존 가로/세로/JPEG 7개 파일 SHA-256이 모두 유지됨을 확인했다.

## 2차 집중 검수 · 문구·safe area·제목

인트로 footer의 아래 여백을 `max(28px, safe-area-inset-bottom + 24px)`로 늘려 고정 음악 제목과 분리했다. 세로 3종과 가로 2종에서 safe area를 실제 Chromium CDP로 적용했다(세로 위 44/아래 34px, 가로 좌우 44/아래 21px). 긴 본문과 다음 막 제목, 두 개의 재개 버튼을 포함한 35장을 촬영했다. 인트로 4개 화면, 세로 세 막의 문구와 가로 다음 막 제목을 직접 열어 글자 겹침 해소·본문 잘림 없음·안전 영역 확보를 확인했다. 기록: `2/checks.json`.

초기 화면 이미지 로딩 중 CLS는 0.01 미만으로 확인한다. 시험 코드에서 버튼 수를 인위적으로 바꾼 뒤의 이동까지 섞어 측정한 2차 첫 진단은 실패했으며, 이미지 로딩의 측정 구간을 초기 표시로 한정해 수정 후 통과했다. 이 진단 수정을 화면 결함 해결로 혼동하지 않는다.

## 3차 집중 검수 · 방향 전환·캐시·실패

같은 5개 크기에서 세 막의 세로/가로 전환 30장을 촬영했다. 신규 그림을 만들거나 가공하지 않고 기존 인트로 `portrait.webp`의 원본 바이트를 브라우저 시험 응답으로만 제공했다. 이 그림은 엔딩 에셋 경로에 저장하거나 배포하지 않았다. 세로 3종 및 가로 전환 결과를 직접 열어 중앙 정렬·본문·전환을 확인했다. 최초 현재 방향만 1건 요청하고 반대 방향으로 돌릴 때만 추가 1건, 되돌릴 때 재요청 0건을 확인했다. 인트로 native picture의 회전 및 프로필 전체 불변도 통과했다. 기록: `3/checks.json`.

별도 지연 응답 검사에서 늦은 세로 응답이 가로 화면을 덮지 않고 화면 이탈 뒤 엔딩을 복원하지 않으며 이미지 사각형과 전체 프로필을 보존했다. 세로 404 시 기존 가로, 둘 다 실패 시 어두운 전체 화면에 본문 유지, 다음 정상 그림 복구를 확인했다. 기록: `races/checks.json`. 시험용 그림이므로 신규 엔딩 미술 검수 통과를 뜻하지 않는다.

## 부모용 구도 가이드

인트로는 세로에서 제목이 위쪽 약 12~30%, 메뉴가 약 43~60%에 놓인다. 배경에는 글자·버튼을 그리지 않고 이 영역의 여백을 유지한다. 엔딩 본문은 하단 safe area 위에 약 2~4줄, 다음 막 제목은 화면 중앙이다. 세로 그림에는 가로 화면에서 잘렸던 주변 요소를 살리고 위아래 확장 여백을 제공한다. 320×568에서 412×915까지 화면비가 달라 cover 표시에서는 소량의 가장자리 차이가 남으므로 주요 피사체는 중앙 안전 영역에 둔다. 확대·새로 그리기·색조·자르기 작업은 부모가 맡으며 이 브랜치는 원본 바이트를 보존한다.

## 별도 최종 종합 검수 · 2026-10-21

최종 런타임·CSS를 대상으로 320×568, 390×844, 412×915, 844×390, 1440×900에서 인트로·세 막의 긴 본문·다음 막 제목 35장을 새로 촬영했다. 최종 인트로 4개 크기, 각 막의 세로 긴 문구, 큰 가로 다음 막 제목을 직접 열어 종합 검수했다. 그림·문구·제목 경계와 safe area, 음악 제목/footer 간격이 통과했다. 각 막×5개 화면에서 컷 2 실제 저장/새로고침/Continue, 진입 클릭 방지·터치 1컷·중복 클릭 방지·Enter/Space·reduced motion, 쉼터 복귀, 완료 막 재생 금지 및 쉼터 재진입의 성장/장비/보상/기록 중복 없음도 통과했다. 컷 진행 및 회전은 기존 프로필을 보존한다. 정상 쉼터의 기존 합류·대화 처리는 그대로 유지한다.

최종 시험 초기에는 제목 버튼용 인위적 전투 데이터를 그대로 저장한 fixture가 재개에 실패했고, 그 가짜 전투를 실제 엔딩처럼 null로 정리했다. 이어 기존 쉼터 합류까지 불변으로 기대한 잘못된 assertion을 컷 진행 보존과 쉼터 안정화 후 중복 확인으로 분리했다. 이 두 진단은 시험 fixture/기대치 교정이며 제품 저장 로직은 수정하지 않았다. 교정 후 최종 전체 항목을 새로 실행해 통과했다.

실행·증거:
- `node game/build.mjs` 통과. 생성 HTML/해시 런타임/CSS/그래픽은 커밋했다.
- `python tests/responsive-story-art-browser.py --round 1`, `--round 2`, `--round 3`, `--round final` 통과. 각 20/35/30/35개 캡처와 JSON은 `_local/reports/responsive-story-art/{1,2,3,final}/`에 있다.
- `python tests/responsive-story-art-races-browser.py` 및 `node tests/web-build-retention.mjs` 통과. 지연/실패 시험 캡처 4개는 같은 경로의 `races/`에 있다.
- 초기 인트로 방향별 한 장만 요청, 시작 시 엔딩 그림 0건, 해당 막의 보이는 방향만 요청, 회전 후 캐시 재사용, 이미지 고정 크기와 초기 CLS < 0.01, 페이지 오류 0건을 확인했다.
- 기존 인트로 WebP/JPEG 4개와 엔딩 가로 WebP 3개의 SHA-256 및 원본 저장소 파일을 보존했다. 제목 이미지·저장/보상/전투/음악·지형 소스도 변경하지 않았다.
- 종료 전 원격 master를 명시적으로 다시 fetch하여 여전히 `c5e5ec8e80ccc03c5ee7d5c8a4a4eea102b83c2f`임을 확인했다.

이 검수는 실제 Chromium의 터치/회전 에뮬레이션과 생산 UI·저장 경로를 사용한 fixture 검수이며 물리 모바일 기기·새 정상 전투 완주·새 세로 그림 미술 승인·Pages 배포 확인은 아니다. 시험용 세로 응답을 실제 공급 미술로 오인하면 안 된다.

## 남은 부모 단계

현재 차단/거부된 접근 작업은 없다. 미완료 작업은 부모가 직접 제작한 신규 세로 파일 공급 및 미술 검수이며 **대기** 상태다. 대상은 인트로 `shared/assets/environment/title/portrait.webp`(JPEG 대체본 `portrait.jpg`)와 엔딩 `shared/assets/endings/act-{1,2,3}-portrait.webp`이다. 이 파일들이 제공되면 이 브랜치 최신에서 빌드 후 위 집중 검사와 최종 검사를 실행하여 실제 새 그림의 구도·본문 대비를 다시 확인한다. 부모의 이미지 합격 전에는 master 병합/Pages 배포를 진행하지 않는다.
