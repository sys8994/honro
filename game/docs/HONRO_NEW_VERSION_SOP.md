# 혼로 새 버전 40장 제작 SOP — 작업 초안

## 우선순위와 기준선
- 사용자의 최신 지시와 승인된 스토리·세계관·취향이 우선이다. 이 문서는 40장 전면 개편의 기준이며, 개별 장/빠른 수정 요청에는 해당 범위와 변경 단계만 적용한다. 전체 개편은 기획·시안부터 구현·실제 플레이·검수·배포까지 구분해 수행한다.
- 2026-11-06 확인 당시 기존 master 기준 커밋은 3e56b3427c33f50cdafb386a9854af46368d7a78이다. 이 커밋은 기존 소스의 식별자이며 별도 스냅샷/태그를 만들었다거나 현재 공개 페이지가 같은 SHA임을 뜻하지 않는다. 기존 v3 설계 파일과 이전 결과를 훼손하지 않고 보존한다. 기존 버전과 새 버전의 코드·기준·증거·배포 상태를 구분한다.
- 코덱스는 사용·재개하지 않는다. 막히면 원인을 밝히고 허용된 다른 방식을 찾으며 독립 작업을 계속한다. 접근 제한이나 승인 정책은 우회하지 않는다. 사용자 승인 대기를 이유 없이 새로 만들지 않는다.

## 1. 40장 공통 및 개별 정량 기획
- 장별 기존 원문·현재 구현·최신 사용자 지시·스토리/승패 조건·동행/지형·전투 역할·검수 근거를 먼저 대조한다. 원본과 개정안·현재값·실측값을 한 칸에 섞지 않는다.
- 각 장에 분량(턴·시간), 난도(정상 전략별 성공률·피해·적 실효 행동), 적 총예산·필수교전·일반/정예/중간/주요보스·공격 예고/대응, 맵 가로·세로·면적·종횡비·실제 활용구역, 유효 고저차·경로·점프·하강, 기믹·승패·화면 품질과 측정 방법을 정한다. 비전투·호송 등에는 해당 유형의 지표를 적용한다. 각 수치에 사용자 원칙과 해당 장의 이야기·전투/동선상의 근거를 남긴다. 기존 값을 유지해도 이유를 명시한다.
- 전 장을 나란히 비교해 난도는 장별 강약과 국소 편차를 두고 전반적으로 우상향한다. 패턴·협공·보스·목표 압박을 보며 턴/HP만 늘려 난도를 만들지 않는다. 평균 턴은 완만히 오르되 기존 v3의 20턴 상한은 기존 설계안으로 기록하고, 사용자가 허용한 예외는 사유와 실제 측정을 남긴다.
- 맵 크기는 초반 완만한 증가 후 비교적 일찍 수렴·포화하고 대부분 적정 편차 범위에 둔다. 스토리·지형·전투상 필요한 장만 큰 예외로 둔다. 가로·세로·면적과 기존 종횡비를 함께 정량 확인하며 수직형/복합형의 필요한 고도와 실제 이동을 함께 검토한다. 미검증 숫자를 확정값이나 통과 기준으로 가장하지 않는다.
- 2026-11-10 사용자 지시: 점프·하강 횟수는 동선 진단용이며 장애물 할당량이 아니다. 수치를 맞추기 위한 엄폐물·반복 발판·강제 왕복·대기 턴을 추가하지 않는다. 이동을 막는 엄폐물은 전투/지형 역할을 확인해 불필요한 것만 제거하고, 필요한 차폐·지지면은 유지한다. 처치 수와 교전 수를 구분한다.
- 전원 생존을 임의로 요구하지 않는다. 특정 장의 명시적 필수 생존 조건만 적용한다. 측정·설계 미완료 또는 근거 없는 예외는 통과가 아니다.
- 실제 Engine RNG·성장/장착·합법적 Game UI와 입력 정책의 동등성을 확인하기 전에는 seed 라벨·모델 실행 수로 성공률을 주장하지 않는다. 자동화와 사람 플레이, 모델 probe와 실제 Game 입력을 구분한다.

## 2. 스테이지별 지형 50%
1. [10점] 원경/지형, 기획·정량 목표·기존 지형 및 스토리와 연결 확인.
2. [10점] 플레이 동선·전투 스켈레톤과 원경·지형을 구분한 시안을 기획/레퍼런스와 대조하고, 이 단계부터 기존 공통 엔진에 내부 통합 preview를 연결한다. 미술/최적화가 모두 끝나기를 기다리지 않는다.
3. [10점] 공통/장별 플레이 지형을 Inkscape로 벡터화하고 필수 형상을 보존한다. 원경은 이미지 레이어이며 충돌 지형과 분리. 최적화는 최대 두 후보로 제한하고, 실패 시 기존 예산·형상 기준을 만족하는 raw를 채택한다. 두 번은 운영 상한이며 시간 만료나 예산/형상 미달의 통과를 뜻하지 않는다.
4. [10점] 지형·충돌·발판·이동·카메라를 게임에 반영하고 필수 목표/저장 호환을 확인.
5. [10점] 전체 구조·접합, 보행 배율/가독성, 카메라·모바일·상태 변화의 세 관점으로 실제 화면을 검수한다. 같은 snapshot 세트를 재사용하며 중복 촬영·별도 검수자·별도 순환 절차를 강제하지 않는다. 수정 영향이 있는 화면만 다시 확인한다.

## 3. 스테이지별 게임플레이 50%
1. [10점] 장별 적·정예·중간/주요보스·기믹·동선·퀘스트·전술을 새 정량 기준과 이야기 맥락에 맞춰 설계.
2. [10점] 적·행동·전투·기믹·대사와 상태 전이를 구현하고 변경된 핵심 기능 확인.
3. [10점] 바뀐 구간을 먼저 브라우저 실제 입력으로 짧게 검수한다. 이동·사선·상호작용 등 바뀐 조건이 통과하면 최종 빌드에서 정상 성장·정상 입력으로 신규 완주 한 번을 실행해 승리·정산·저장 복원을 확인한다. 전체 개편과 사용자가 완주를 요청한 수정에 적용한다. 같은 위치·조건에서 다시 막히면 전체 실행을 중단하고 그 구간만 격리해 원인과 수정 결과를 확인한다. 시나리오 준비 상태·자동화 입력·사람 플레이는 구분한다.
4. [10점] 신규 완주에서 사전에 정한 라운드·피해·적 행동·전투/수직 이동 등 해당 장의 지표를 기록한다. 전략에 따라 결과가 달라지는지 확인할 필요가 있으면 핵심 구간만 비교한다. 승률은 충분한 표본이 있을 때만 보고한다. 실제 화면과 흐름에서 반복이나 정체를 확인하고, 게임 결함과 조작 문제를 구분한다.
5. [10점] 최종 소스에서 앞선 세 관점의 근거와 실제 기능을 함께 종합 판정하고 필요한 빌드·master 통합·기존 Pages 배포·공개 동작을 확인한다. 유효한 증거는 재사용하며, 변경 영향이 있는 항목만 다시 검증한다.

각 단계의 점수는 필요한 확인이 된 경우에만 부여하고, 필수 검수의 실패/미측정은 미완료로 남긴다. 비차단 후속 개선과 필수 조건 누락을 구분한다. 한 장은 지형/게임플레이 각 50%이며 40장 평균을 전체 진행률로 산출한다. 한 장 100%=전체 2.5%이고 원격 배포·공개 확인 전 100%로 표시하지 않는다. 빠른 부분 수정이나 공유 SOP 정리를 전체 장 완료 점수로 가산하지 않는다.

## 4. 작업 루프와 보고
- 공통 기준과 해당 장 설계 카드를 대조하고, 독립 파일은 충돌 없이 병렬 처리한다. 40장 표 전체의 완성을 개별 수정 시작의 선행 조건으로 만들지 않는다. 작은 통합 preview에서 정상 플레이에 보이는 결함과 진행 불능을 먼저 고치고 일관된 변경 단위를 보존·커밋·push한다.
- P2 미세 장식·서로 다른 rasterizer의 1px 안티앨리어싱 차이·전체 hash만 달라진 무관한 장 검사를 출시 차단으로 쓰지 않는다. 실제 Game의 접합·식별·기능 문제는 관련 범위에서 수정한다. 원문·저장·기하·보행면 보호와 코어 validator 한도는 유지하고, 실측 없이 증거 hash만 바꾸거나 미달을 통과로 표시하지 않는다.
- 사용자 2026-11-09 지시에 따라 30분 정기 보고는 하지 않는다. 중요한 결과·스크린샷·실제 차단·배포 결과를 필요할 때 보고하며, 완료/진행/미검증과 근거를 구분한다.
- 누적 실패는 감추지 않고 조작/게임 결함을 분리한다. 완료 여부·정량값·예외·시안·실제 게임·공개판을 혼동하거나 미검증 수치를 사실처럼 말하지 않는다.
- 세부 제작은 game/docs/STAGE_PRODUCTION_SOP.md와 관련 지형·벡터·플레이·교전·취향 지침을 변경 범위에 적용한다. 같은 근거를 문서별로 중복 생산하지 않는다. 사용자 최신 지시가 우선하며 v3 원형과 새 수치·예외·실측은 구분해 보존한다.
