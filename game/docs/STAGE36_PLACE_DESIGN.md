# 3–6장 장소 설계 · 2026-09-30

1·2장 목업 지형을 기준으로 3–6장을 다시 살폈다. 이번 작업의 기준은 장식의 양보다 **실제로 세울 수 있는 장소인가**였다. 건물의 바닥, 하역 터, 교량의 받침, 물의 상류와 하류를 먼저 연결하고, 그 위에 암석·소나무·갈대·재와 지면 재질을 배치했다. 한국 산지의 나루, 불탄 관문 밖 마을, 폭포 절벽, 무너진 목교라는 장소의 흐름을 유지한다.

| 장 | 장소 구성 | 주요 수정 |
|---|---|---|
| 3 · 나루의 남은 장부 | 습한 나루 → 하역 터 → 언덕 위 창고 | 세 나루 발판 아래 목재 지주, 창고·제단의 평탄한 석축, 물가 갈대와 둑의 자갈·소나무. 창고 하역 구역을 평탄하게 다듬음. |
| 4 · 문 밖에 남은 사람들 | 관문 → 불탄 저지대 민가 → 감시 지점 | 비탈에 놓였던 불탄 민가를 골짜기 바닥으로 이동, 관문 기초와 망루 버팀대, 재·돌·그을린 나무를 장소별로 배치. |
| 5 · 폭포 틈의 한 발 | 산길 → 암반 선반 → 절벽 물길 → 웅덩이 | 반복되는 직사각 발판을 불규칙 암반 선반으로 수정, 절벽 면을 연결, 상부 물길부터 연속 폭포와 얕은 하류 웅덩이를 구성. |
| 6 · 끊어진 나무다리 | 옛 교량 상판 → 교각 → 하부 계곡길 | 상판 아래 세 교각과 줄 흔적, 바닥의 잔해·돌·얕은 물길을 배치해 끊어진 다리의 높이와 물길을 설명. |

활성 원본은 `shared/data/campaign.json`이다. `migration/legacy/`는 비교 자료다. `workshop/recipes/stage36-place-design.js`의 189개 Workshop 명령을 1·2장 레시피 뒤에 적용하면 활성 원본을 재현한다. 적용/확인은 각각 `node tools/map-forge/apply-stage36.mjs`, `node tools/map-forge/apply-stage36.mjs --check`이다. 새로운 장식은 `builtin:placeDetail` 한 종류의 벡터 렌더러에서 지주·석축·절벽·물길·교각 등으로 그린다. 기존 맵 장식의 노드 상한은 `test:map-art`에서 계속 검사한다.

지면 상단점은 3장 218, 4장 178, 5장 156, 6장 222개다. 이동에 쓰는 지면은 연속이고, 건물의 기초 면은 평탄하다. 5·6장의 물은 단순 색면이 아니라 얕은 통과 가능 수면과 전기 전도가 연결된 구역이다. 기존 유닛·목표·앵커의 지면 높이를 새 지형에 맞춰 옮겼으며, 진행 중 저장 상태를 다시 열어도 강제로 초기화하지 않는다.

시각 검수는 [3장](../../_local/reports/map-place/stage-3-overview.png), [4장](../../_local/reports/map-place/stage-4-overview.png), [5장](../../_local/reports/map-place/stage-5-overview.png), [6장](../../_local/reports/map-place/stage-6-overview.png) 전체 화면과 같은 폴더의 주요 지점 확대본으로 수행했다. Game과 Stage View는 네 장 모두 픽셀 차이 0, Workshop Playtest도 네 장 모두 실제 맵을 로드했다. `npm run test:stage36`은 레시피 재현, 구조물 접지, 폭포·교각·수면 연결, 초기 충돌, 저장 복원, 지면 연속성을 검사한다.

[전후 비교 페이지](../../_local/reports/map-place/index.html)를 자동 생성한다. 3–6장 대상 Game·Workshop 24개 성능 측정은 모두 통과했으며 최소 56.49 fps, 최대 평균 렌더 1.752 ms, 최대 로드 126.1 ms, 캐시 재빌드 0회였다. `npm run test:map-art`도 기존 장식의 2배 노드 상한과 브라우저 오류 0건을 통과했다. 전체 `npm run verify`는 맵·마이그레이션·통합 브라우저 검사까지 통과했지만, 뒤의 `tests/skill-effects.mjs`에서 맵과 무관한 A99 캠페인 재사용 대기시간 단언이 실패해 종료됐다. 별도로 실행한 `npm run test:performance`는 통과했다.

남는 한계: 5장의 암반 선반은 전투·도약 경로를 위해 수평 착지면을 유지하므로 자연 절벽보다 계단성이 남는다. 6장의 교량 또한 파손된 세 상판의 기존 플레이 경로를 유지한다. 전 구간의 수동 완주는 별도 플레이테스트가 필요하다.

## 3·4장 물·밤숲·선택 경로 추가

3장의 `ferry-water`는 수면·둑에 고정된 얕은 물이고, 캐시 밖의 작은 표면 굴곡·이동하는 흐름선·지주 뒤 회류·착수 파문이 움직인다. 기존에는 시각 수면이지만 `b.waters`에 등록되지 않았던 전도 불일치를 고쳐 `conductive:true`로 연결했다. 잔교 아래 `ferry-side-gangway`는 부술 수 있는 일방향 통로이며, 아래 물가와 기존 높은 잔교 사이의 사격/이동 선택을 만든다.

4장의 `burned-gallery`는 불탄 민가의 남은 기둥에서 나온 일방향 사격 자리다. 부수더라도 지상 방어선과 목표 경로가 남는다. 두 장의 원경은 동일 공통 Scene에서 능선 위주의 하늘을 높은 야간 소나무 숲·구름·가려진 달로 교체했다. [3·4장 실제 화면과 나루 물 애니메이션](../../_local/reports/stage34-water-forest/index.html)에서 게임 배율을 확인한다. 5·6장 원경과 폭포는 이번 범위에 포함하지 않았다.

검증은 관련 범위로 좁혔다. 레시피 `--check`, `tests/stage36-place-design.mjs`, `tests/migration.mjs`(10장), `tests/integration.py`(47개), `tests/stage36-place-browser.py --stage34`가 통과했다. 3·4장 Game/Stage View 픽셀 차이는 각각 1·0이고 Playtest도 두 장을 로드했다. 3장 수면 전용 캔버스는 1.2초 간격으로 15,293픽셀이 달랐고 착수 파문 1건을 확인했다. 두 장의 고정 카메라 24회 렌더 중 월드·원경 캐시 재빌드는 0회였다. 브라우저 부하에 따라 측정되는 렌더 p95는 대략 1–3ms였다. 사용자가 요청한 간소화에 따라 전체 `npm run verify`는 실행하지 않았다.
