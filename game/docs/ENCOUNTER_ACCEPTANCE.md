# 혼로 플레이 경험 검수 SOP

## 목적과 우선순위

혼로의 검수 목적은 실행 가능한 프로그램을 넘어서, 상황을 이해하고 판단하며 행동의 결과를 배울 수 있는 전투·탐험 경험을 만드는 것이다. 기본 관찰 단위는 **상황 인지 → 선택과 예측 → 이동·조준·기예·상호작용 → 읽을 수 있는 결과 → 성취·발견·긴장 해소 또는 다음 시도의 개선**이다. 이는 혼로용 설계 가설이며 인간의 재미를 자동 판정하는 과학적 공식이 아니다.

지형·동선·적 편성·행동·기믹·목표·진행의 제작과 변경에 적용한다. 제작 순서는 [스테이지 제작 SOP](STAGE_PRODUCTION_SOP.md), 배치는 [적 배치 기준](ENCOUNTER_PLACEMENT.md), 발행은 [원격 반영과 배포](RELEASE_OPERATION_GUARD.md)를 따른다. 플레이 경험 판정과 완료 표현은 이 문서를 단일 기준으로 삼는다.

정량 목표 범위는 필수다. 다만 총점·평균 점수·몬스터 수·승률·피해량·정예 비율·검수 횟수만으로 재미를 승인하지 않는다. 근거 없이 모든 장에 같은 할당량을 강제하거나 수치 달성으로 실제 결함을 덮지 않는다. 기술 통과는 설계 확인이나 인간 경험 확인을 대신하지 않는다.

## 1. 책임과 작업 범위

담당 조정자는 구현자의 성공 보고나 자동 검사만 받아 완료를 선언하지 않는다. 최종 후보의 실제 게임 화면을 직접 조작하고 결과를 확인한 뒤 범위와 한계를 판정한다. 구현자의 설계 의도는 검증할 가설이다. 군집에 ‘압박’, 길에 ‘우회’라는 이름만 붙여 역할을 인정하지 않는다.

- **장 전체 제작·개편:** 정상 진입부터 핵심 교전·기믹·목표 달성·종료 또는 다음 장 연결까지 실제 화면으로 플레이한다. 실패·중단도 기록하고 원인을 해결한다. 성공 경로 하나만으로 전술·난도·반복성까지 승인하지 않는다.
- **막 전체 개편:** 수정한 각 장을 확인하고 장 사이 자원·성장·목표 전달·반복성을 연결해서 확인한다. 대표 장 스모크를 막 전체 검수로 확대하지 않는다. 무관한 전 캠페인 순회를 추가하지 않는다.
- **국소 버그·밸런스 수정:** 수정 경로와 직접 영향받는 대안·상태, 이후 정상 진행을 확인한다. 완료 표현도 해당 수정에 한정한다.
- **미술·렌더만 변경:** 실제 화면의 조준·충돌면·적·상호작용 가독성과 가림을 확인한다. 보행면·사선·위협 인식에 영향이 있으면 관련 플레이까지 확인한다. 기존 게임플레이 전체를 재검증했다고 하지 않는다.
- **문서만 변경:** 문구·링크·상호 모순을 확인한다. 게임 빌드·플레이를 수행한 것처럼 기록하지 않는다.

최소 검증은 무관한 검사를 줄이는 원칙이지, 변경된 장의 경험 검증을 기능 스모크로 축소하는 근거가 아니다.

## 2. 시작 전 설계 가설

기존 장별 설계 카드에 다음을 간단히 기록한다.

1. 플레이어가 해결할 문제와 화면에서 알 수 있어야 할 목표·위협·규칙.
2. 실제 고민할 선택과 각 선택의 이득·위험.
3. 지형·동료·기믹이 그 판단을 바꾸는 방식.
4. 앞뒤 장과 달라지는 판단과 의도적으로 재사용하는 학습.
5. 설계를 무력화할 가능성이 큰 반복 전략과 이를 시도할 반증 계획.
6. 보존할 서사·승패 조건·동행·저장 계약.

모든 장에 다중 경로·모든 동료 활용·새 기믹을 강제하지 않는다. 짧은 전투, 휴식, 익숙한 기술을 능숙하게 쓰는 구간도 흐름에 기여하면 허용한다. 적 숫자는 장별 목표 범위를 설계하고 실제 경험에 맞춰 조정한다. 숫자만 채우거나 플레이 시간을 빈 이동·대기·체력 부풀리기로 늘리는 것은 목표 달성이 아니다.

## 2.1 정량 설계 카드와 캠페인 곡선

각 장은 제작 전에 아래 목표 범위를 기록해야 한다. **현재 구현값 / 제안 목표 범위 / 실제 측정값 / 판정과 조정 이유**를 별도 열로 둔다. 같은 값의 복사나 ‘추후’만으로 설계 완료를 선언하지 않는다. **스토리·기믹·전체 40장 곡선을 먼저 함께 검토 → 장별 정량 목표 범위를 사전 설계 → 실제 제작 → 다양한 정책의 실측 통계로 필수 검증** 순서다. LLM이 사전 목표를 구상할 수 있으며 실측 전에도 v1 설계 목표를 명시·고정한다. 이때 ‘설계 목표 v1·미보정’과 ‘실측 미완료’를 별도 상태로 적는다. 측정이 끝나야만 목표를 정할 수 있다는 뜻이 아니다. 구체적인 40장 수치는 별도 작성 중인 단일 기준표를 참조할 예정이며, 이 SOP에 중복 복사하지 않는다. 기준표가 연결되기 전 이 문서 자체가 40장 목표값을 확정한 것은 아니다.

| 필수 항목 | 정의·측정 조건 |
|---|---|
| 플레이 시간 | 정상 성공 1회 실제 경과 분. 전투·이동·대사/성장 선택을 구분하고 로딩·자리 비움·도구 지연을 별도 기록. 재도전 포함 누적 시간도 구분. AI 도구 호출 시간을 인간 플레이 시간으로 사용하지 않는다. |

| 성장과 난도 조건 | 정상 진입 동료 수·경지·장비·기예·자원, 예상 보상·레벨업 회복·소모. 난이도 계수와 실제 행동 상한을 함께 대조. |

막/캠페인 단위로 위 수치의 흐름을 함께 제시한다. **초반에서 후반으로 전체적인 도전·플레이 분량·편성 깊이는 완만하게 우상향**하되 장별 편차, 휴식·탐색, 강적 고점과 다음 장의 회복을 허용한다. 모든 지표를 매 장 동시에 증가시키지 않으며 파티 분할·합류·새 기예·서사 전환에 따른 예외는 이유를 기록한다. 후반이 초반보다 급격히 빈약해지거나 과도하게 길어지는 단절은 실제 데이터로 설명하고 수정한다.

강적·중간보스는 막 전체 배치표에서 등장 간격과 예고·정점·해소를 기획한다. 모든 장에 한 마리씩 기계적으로 넣거나 끝 장에만 몰지 않는다. 정확한 등장 간격과 수치는 막의 길이·플레이 시간·서사와 함께 정하고 측정 뒤 보정한다.

목표 범위를 벗어나면 원인을 조사하고 장 또는 목표 범위를 근거와 함께 수정한다. 목표를 실제값으로 자동 덮어써 통과시키지 않는다. 반대로 범위 안이어도 무의미한 반복·목표 혼란·무기능 적이 남으면 설계 확인은 통과하지 못한다. 정상 플레이·여러 정책의 차이를 제시하며 소수 실행의 평균을 인간 모집단 기준처럼 표현하지 않는다.

## 2.2 사전 설계 목표를 실제 플레이 분포로 검증하는 필수 정량 gate

정량 목표는 스토리·기믹·공간 유형과 전체 40장 곡선의 관계를 근거로 먼저 설계한다. 장 하나만 보고 숫자를 정하거나 한 성공 실행을 목표로 복사하지 않는다. 기존 사용자 승인 1막의 지형과 다른 공간 전개의 대표 장은 비교·보정에 활용하되 사전 목표 작성의 선행 측정 의무로 삼지 않는다. 기존 1막 참조 승인을 현재 모든 장의 난도·재미 승인으로 확대하지 않는다. 보정용 표본과 최종 후보 평가 표본을 분리한다.

1. **목표·측정 계획 선등록:** 전체 40장 곡선과 서사 근거를 검토한 장별 v1 목표 범위·허용 예외·실패 조건·버전을 제작 전에 고정한다. 목표의 미보정 상태와 실측 미완료 상태를 분리한다. 이어 장 유형(수평/수직/복합), 정상 진입 성장·동료·난이도, 초보/일반/숙련 정책과 반복 우세 전략, 난수 조건, 종료/실패/timeout 정의, 기록할 지표와 표본 확보·불확실성 판단 방법을 실행 전에 기록한다. 해법을 아는 정책은 표시한다.
2. **제작 후 실제 플레이:** 사전 목표를 기준으로 제작한 후보를 다양한 정책·합법적 경로·난수 조건으로 플레이한다. 필요한 대표 장 비교도 같은 조건 구분으로 기록한다. 성공 실행뿐 아니라 패배·진행 불가·timeout·중단을 보존한다. UI 직접 관찰과 엔진 자동 표본을 구분하고 실제 화면에서 핵심 관측을 대조한다. 엔진 진단만으로 입력·가독성·인간 체감을 검증했다고 하지 않는다.
3. **정책별 분포 보고:** 성공 수/전체 유효 시도 수, 실패·timeout·중단 수, 성공률과 Wilson 신뢰구간(신뢰수준 명시), 표본수, 라운드·행동·시간·점프·도달 영역 등의 평균·중앙값·분포/범위를 제시한다. 성공한 실행의 클리어 라운드는 성공 조건부 통계임을 명시하며 실패 시간을 성공 시간처럼 합산하지 않는다. timeout은 삭제하거나 임의 클리어 턴으로 치환하지 않는다.
4. **독립성과 원인 분리:** 같은 결정론적 초기 상태·정책·입력의 재실행은 재현성 확인이지 새 독립 표본이 아니다. 동일 seed에 여러 정책을 적용한 짝비교는 그 구조를 표시한다. seed 효과와 정책의 지식·조준·탐색 오류를 분리하고 유리한 seed만 고르지 않는다. Wilson 구간은 독립 이항 표본 가정을 만족하는 성공률 집계에만 적용하며 의존 표본에 가짜 정밀도를 부여하지 않는다. 표본이 부족하거나 불확실성이 크면 더 측정하거나 미완료로 남긴다.
5. **사전 목표와 대조:** 실측 분포를 사전에 고정한 v1 목표·실패 조건과 대조한다. 유형별 대표 장의 분포는 해석·보정 근거로 활용한다. 적용 난이도·정책·표본·소스·목표 버전을 함께 기록한다. 과거 봇의 길 찾기 오류나 빈 이동으로 부풀려진 시간은 좋은 분량의 기준으로 삼지 않는다.
6. **수정·독립 재평가:** 기준 미달은 구현 수정이 우선이다. 수정 후보는 고정된 목표로 새 표본에서 독립 재평가한다. 수평형에 수직형 점프 최소치를 요구하지 않되 유형 변경으로 실패를 숨기지 않는다. 우세 전략, 실제 판단, 서사 적합성, 화면 검수도 함께 통과해야 한다.
7. **실패 처리:** 필수 측정 없음, 임계값 미설정, 표본/조건 불명, 현재 버전 증거 없음, 적용 기준 미달은 gate 불합격(미완료)이다. 목표 숫자를 관측값으로 자동 수정하거나 기준을 낮춰 통과시키지 않는다. 설계 가정 자체가 잘못됐으면 후보 수정과 분리해 사유·실측 근거·전체 40장 곡선과 인접 장 영향·서사를 재검토한다. 목표 변경을 새 버전으로 명시·고정하고 별도 표본에서 독립 재평가한다. 관측값에 맞춘 은밀한 목표 변경은 금지한다. 이전 실패 기록은 보존한다.

이 gate는 장 개편의 내부 완료·최종 품질 승인에 필수다. 작업 중 커밋·원격 보존과 별도 검증 후보 공개는 완료 승인과 구분하며 사용자의 허용 범위에서 진행한다. 필수 gate가 미완료인 후보를 완성품으로 배포·보고하지 않는다. 코드로 자동 강제되는 부분과 사람이 확인하는 부분, 아직 구현되지 않은 부분을 구분한다. 현재 이 문서는 사전 목표 설계·실측 필수 판정 정책을 정의하며 1–40장 기준표의 작성·보정이나 실행 gate 구현을 완료했다고 주장하지 않는다.

## 2.3 적 종류·패턴과 세계관의 연결

등장 종족·직업·강적마다 **왜 이 장소에 있는가 / 무엇을 지키거나 추구하는가 / 형·기·혼 및 현재 서사와 어떻게 맞는가 / 플레이어에게 어떤 다른 대응을 요구하는가**를 기록한다. 기존 설정과 충돌하면 종류를 늘리기 전에 원인을 해결한다.

같은 기본 추격·평사 패턴에 이름과 그림만 바꾼 다양성은 구분한다. 지형 제압, 예고 돌진, 엄폐 사격, 아군 지원·보호, 이동 방해, 위험 구역 형성 등은 실제 능력·예고·대응이 구현되고 화면에서 관찰될 때만 새 패턴으로 센다. 이 예시가 새 기능 구현의 승인이나 모든 역할의 의무 배치를 뜻하지는 않는다. 강적은 내구·피해뿐 아니라 배치·행동·패턴의 차이로 기억될 이유를 가져야 하며 부당한 정보 은폐로 강함을 만들지 않는다.

## 2.4 미술 정량 목표와 최종 시각 검수

미술은 [벡터 제작 SOP](VECTOR_AUTHORING_SOP.md)의 **시안 → 실제 Inkscape 벡터화·편집 → raw → optimized → 게임 화면**을 따른다. 게임플레이 목표와 함께 미술의 사전 정량 목표도 설계하고 단계별 결과를 대조한다. 구체 수치는 별도 40장 단일 기준표 및 그 미술 기준 참조로 연결할 예정이며 본문에 별도 숫자 사본을 만들지 않는다.

| 지표 | 측정·판정 원칙 |
|---|---|
| 재질별 윤곽 복잡도 | 바위·흙·목재·건축 등 재질과 역할별로 외곽의 형태 변화·곡률·굴곡을 측정한다. 서로 다른 재질에 같은 요철을 강제하지 않는다. |
| 긴 직선 비율 | 윤곽 길이 중 정해진 화면상 길이 이상의 직선 비중과 위치를 기록한다. 건축의 의도된 직선과 자연 지형의 과도한 평탄화를 구분한다. |
| 내부/배경 edge 밀도 | 플레이 지형 윤곽·내부 재질·배경·전경을 분리해 화면 면적당 edge 밀도와 대비를 대조한다. 내부 장식만 화려하고 실제 윤곽은 단순한 불균형을 찾는다. |
| 노드·path 밀도 | raw/optimized의 노드·path·polygon 수와 가시 면적·윤곽 길이당 밀도를 기록한다. compound path 수만 줄어든 것을 경량화로 판정하지 않는다. |
| 실루엣·보호 영역 오차 | 시안→raw의 재현 차이와 raw→optimized의 최적화 오차를 분리한다. 실루엣·접지선·발판 끝·눈코입 등 보호 마스크별 오차를 확인하며 전체 평균이 작은 중요 부분 손실을 숨기지 못하게 한다. |
| 용량·렌더 비용 | 편집 원본/배포 자산 크기, 실제 로딩 크기, 최종 화면의 렌더 비용을 구분한다. 기기·해상도·배율·장면·프레임 조건을 함께 기록한다. |

화면상 복잡도·edge·오차는 **같은 screen-scale로 정규화**한다. viewport·줌·device pixel ratio·출력 해상도와 가시 영역을 명시하고 같은 조건의 렌더끼리 비교한다. 단순 확대·축소로 밀도 수치를 맞추지 않는다. 전체 맵 구조 비교와 실제 플레이 거리의 가독성 비교를 분리한다. 노드 등 원본 기하 수치도 실제 표시 크기와 함께 해석한다.

정량 통과 뒤에도 담당 조정자가 시안/raw/optimized 및 최종 인게임 이미지를 직접 열어 시각 검수해야 한다. 작은 중요 형태·자연스러운 윤곽·재질·레이어 우선순위·보행/조준 가독성의 손실은 수치 평균으로 상쇄하지 않는다. 최종 시각 미확인이나 중요 결함은 미술 gate 미완료이며, 임계값을 낮추거나 보호 마스크를 지워 통과시키지 않는다. 이 문서는 측정 정책이며 측정기·마스크·임계값 또는 최종 미술이 이미 구현·통과됐다는 뜻은 아니다.

## 3. 플레이 조건과 증거의 정체성

기록에는 장 번호·map revision·소스 SHA(또는 정확한 미커밋 변경 범위), 로컬/공개판 여부와 URL·확인 가능한 배포 식별, 브라우저·화면 크기·입력 방식, 난이도·동료·성장·장착·주요 자원을 남긴다. 정상 연속 진입/준비 세이브/디버그/엔진 진단, 사람/AI 조작, 해법 사전 지식도 구분한다.

- 정상 난도는 정상 진행에서 얻을 수 있는 성장·장비·자원과 실제 UI를 기준으로 한다.
- 준비 세이브는 생성 방법과 정상 상태와의 차이를 기록한다. 정상 연속 캠페인으로 부르지 않는다.
- 디버그 고성장·무적·자원 보충·좌표 이동·목표 강제 변경은 재현·원인 진단에만 사용한다. 정상 난도·완주 증거로 쓰지 않는다.
- 디버그 여부가 불명확하면 정상 판정을 보류하고 조건부터 확인한다.
- 공개 UI에 없는 엔진 명령이나 대역 DOM의 성공은 엔진 진단이다. 실제 화면 플레이가 아니다.

## 4. 실제 화면 플레이 기록

최초 검수는 정답 좌표·입력 스크립트·해법 코드·내부 목표 조건을 먼저 읽지 않고 화면의 정보로 시작한다. 원인 진단이나 이전 플레이로 이미 알고 있다면 초견으로 주장하지 않는다. 같은 AI가 지식을 숨겼다고 가정해 다시 플레이해도 실제 초보 데이터가 되지 않는다.

2026-10-30 기준 담당 조정자는 31장의 실제 조건을 원인 진단 과정에서 이미 알고 있다. 그 이후 조정자의 31장 플레이는 사전 지식이 있는 재검수로 기록하며 초견 목표 이해의 증거로 사용하지 않는다. 이 제한은 당시 검수 기록의 조건이며 이후 실제 초견 참가자의 기록까지 제한하지 않는다.

핵심 판단·막힘마다 아래를 기록한다. 모든 클릭의 장황한 나열은 필요 없다.

| 시점·장소 | 화면에서 이해한 상황 | 고려한 선택·예측 | 실제 입력 | 실제 결과 | 배운 점·문제 | 화면 증거 |
|---|---|---|---|---|---|---|

- 실패 원인, 반복 구간, 기믹 전후, 목표 완료와 종료 연결을 남긴다.
- 정지 스크린샷만으로 시간 흐름·입력을 증명하지 않는다. 필요한 구간은 연속 캡처 또는 영상·입력 기록으로 보완한다.
- 캡처를 직접 열어 본다. 파일 존재·해시 일치만으로 시각 검수를 대신하지 않는다.
- 관찰 사실과 해석을 구분한다. ‘적이 두 턴 움직이지 않았다’와 ‘위협이 없었다’는 다른 주장이다.
- 보지 못한 장면, 실패, 도구 차단, 남지 않은 증거를 통과로 기록하지 않는다.

원본 캡처·영상은 기존 `_local/reports/` 또는 `_local/game-reports/`에 둔다. 현재 판정 요약에는 실제 증거 위치와 접근 가능 여부를 남긴다. 원본이 없으면 재확인 불가능한 한계를 표시하며 새 증거를 만든 것처럼 꾸미지 않는다.

## 5. 초보·일반·숙련 관점

AI의 세 정책은 세 명의 인간 테스트를 대신하지 않는다. 각 정책은 인간 반응에 대한 가설을 검토하는 수단이다.

- **초보 관점:** 화면 안내와 배운 기본 행동으로 접근한다. 숨은 지름길·정답 탄도·내부 트리거를 미리 사용하지 않는다. 목표·충돌면·실패 이유를 이해할 수 있는지 본다. 의도적으로 멍청한 행동이나 임의 능력 봉쇄로 난도를 만들지 않는다.
- **일반 관점:** 이동·각도·힘 조절·기예를 이해하되 해당 장의 정답은 모르는 상태로 합리적으로 선택한다. 실수 뒤 수정·회복 가능성을 본다.
- **숙련 관점:** 실제 UI에서 가능한 지형·사선·상태·동료 조합을 활용한다. 저위험 반복 전략이 다른 선택을 무의미하게 만드는지 찾는다.

각 관점의 사전 지식과 실제 선택 차이를 기록한다. 사전 지식 때문에 수행할 수 없는 조건은 미확인으로 남긴다. 난도는 이 관찰과 실제 사람의 반응으로 조정하며, 임의 성공률을 맞추려고 체력·숫자를 기계적으로 바꾸지 않는다.

## 6. 반복 우세 전략 반증

제작자가 의도한 좋은 경로뿐 아니라 설계를 무력화할 전략을 실제로 시도한다. 예시는 한 안전 지점에서 같은 원거리 공격 반복, 가까운 적부터 순서대로 공격, 기믹 무시·기본 공격 반복, 적을 무시한 목표 직행, 한 동료·기예로 여러 장을 같은 방식으로 해결하기다.

모든 예시를 모든 장에 억지 적용하지 않는다. 해당 가설을 가장 잘 반박할 전략과 이유를 고른다. 일부러 나쁜 조준이나 불필요한 이동으로 반복 전략을 약하게 만들지 않는다. AI 최적해를 인간 평균 행동으로 취급하지 않는다.

대안의 존재만으로 다양성을 인정하지 않는다. 위험·시간·자원·보상·조작 만족에서 실제 이유가 있는지 본다. 반복 전략의 성공 자체는 반려 사유가 아니다. **대부분의 판단을 지워 버리고, 대안은 손해만 늘리며, 장 사이에서도 같은 작업을 반복하게 만드는 경우** 수정 대상으로 판정한다.

## 7. 플레이 경험 판정 질문

- **판단과 지형:** 위치·높이·엄폐·사선이 선택을 바꾸는가? 그림 속 길을 실제 동선으로 오인하게 하지 않는가?
- **조준과 학습:** 각도·힘의 결과를 읽고 다음 시도를 개선할 수 있는가? 모바일 입력 오차나 충돌 불일치를 전략 실패로 처벌하지 않는가?
- **위협과 난도:** 적이 피해뿐 아니라 이동·기예·우선순위·목표 보호에 영향을 주는가? 단서와 대응 기회, 실패 후 개선 가능성이 있는가? 제자리 대기·표적 없는 발사·도달하지 못한 추격을 실효 행동으로 세지 않는다. 모든 파동에 피해를 강제하지 않는다.
- **기믹과 동료:** 실제 행동을 바꾸는가? 제거해도 같다면 장식과 기능을 구분한다. 횟수를 채우기 위한 교대를 강제하지 않는다.
- **반복과 호흡:** 앞뒤 장의 판단이 다른가? 빈 이동·대기·체력만 깎는 작업이 흐름을 지배하지 않는가? 휴식 구간을 무조건 적으로 채우지 않는다.
- **목표와 보상:** 해야 할 일과 남은 일이 읽히는가? ‘목표 완료’와 실제 종료 조건이 일치하는가? 별도 탈출·승선이 필요하면 그것을 분명히 전달하는가?

이는 합산 점수표가 아니다. 중요한 실패를 다른 항목의 장점으로 상쇄하지 않는다. 저장·스키마·진행 경계 변경은 관련 옛 저장과 신규 진입을 선별 확인하며 보존할 기존 성장·진행을 지킨다. 증원 조건 변경은 예고·입장·첫 행동, 영향을 받는 중복 방지·취소·재개를 확인한다. 승인되지 않은 목표·서사·파티 분할을 추가하지 않는다.

## 8. 세 종류의 검증과 완료 표현

| 상태 | 필요한 근거 | 의미하지 않는 것 |
|---|---|---|
| 기술 확인 | 관련 빌드·검사·실행·진행·충돌·저장 결과 | 재미·미술 합격 |
| 설계 확인 | 실제 화면 플레이·반복 전략 반증의 판단·기믹·난도·반복성 | 인간이 재미있었다는 검증 |
| 인간 경험 확인 | 실제 사람의 플레이·자발적 피드백과 관찰 조건 | 모든 사람에게 재미있음 |

각 상태는 **통과한 범위 / 문제 있음 / 미확인 / 변경으로 재확인 필요**로 표시한다. 한 칸의 통과를 전체 완료로 확대하지 않는다. 인간 검증이 없으면 ‘인간 재미 미검증’이라고 쓴다. AI가 감정을 경험했다고 주장하지 않는다.

장 개편 내부 완료는 적용 가능한 정량 필수 gate와 관련 기술·설계 확인이 끝난 범위에서만 선언하며 인간 검증 상태를 함께 밝힌다. 기술 통과 후보를 완성된 장으로 제출하지 않는다. 알려진 수정 범위의 무기능 군집·진행 불가는 해결 전까지 미완료다. 무관한 장의 미확인 때문에 작은 수정까지 차단하지 않는다.

## 9. 수정·재검수·발행

1. 관찰된 문제를 화면·행동·결과로 특정한다.
2. 가장 작은 관련 원인을 수정한다. 적 증가나 전체 재제작을 자동 처방으로 삼지 않는다.
3. 같은 실패 상황과 영향받는 대안·이후 진행을 다시 플레이한다.
4. 플레이 관련 소스가 바뀌면 영향받는 판정은 재확인 필요로 전환한다. 무관한 증거는 무조건 폐기하지 않는다. 생산 계약 도구를 사용하는 경우 그 도구의 기존 fingerprint 만료 규칙도 준수한다.
5. 원격 반영·배포 상태를 확인한다. 로컬 결과를 공개판 결과로 부르지 않는다.
6. 공개판에서 관련 실제 동작과 후보 일치를 확인한다. 공개판의 새 문제가 있으면 해결 전까지 해당 검수는 완료가 아니다.

작은 문서·미술 수정 발행을 위해 전 캠페인 인간 검증을 새로 요구하지 않는다. 검증용 공개 후보를 제품 완성 판정으로 바꾸지 않는다. 보고는 다음을 구분한다.

> 대상·버전 / 실제 플레이 조건 / 확인한 판단 장면 / 발견·수정·재확인 / 기술 상태 / 설계 상태 / 인간 검증 상태 / 공개 배포 상태 / 남은 문제

## 10. 기존 자료의 사용과 근거

자동 도구·관측 러너·fixture·생산 계약은 기술 진단과 증거 정리에 재사용한다. 도구 통과는 실제 화면이나 인간 경험을 대신하지 않는다. 과거 보고서는 당시 소스·조건·범위의 기록이다. 현재 증거로 재사용하려면 관련 동작 보존과 한계를 확인한다. 과거 횟수나 다른 장의 성공으로 현재 장의 미확인을 메우지 않는다. 본문의 정량 필수 gate를 적용한다. 관련 없는 전 장 재검사는 추가하지 않는다. 이 문서 변경은 gate 정책 수립이며 실행 코드가 구현·검증됐다는 뜻은 아니다.

기준의 연구 배경은 다음과 같다. 구체적인 혼로 적용은 아직 검증할 가설이며 아래 연구가 이 게임의 재미를 인증한 것은 아니다.

- [Ryan·Rigby·Przybylski 2006](https://selfdeterminationtheory.org/SDT/documents/2006_RyanRigbyPrzybylski_MandE.pdf): 네 연구에서 유능감·자율성 경험과 즐거움·재플레이 의향의 관련성을 관찰했다. 조작 숙달만으로 만족스러운 경험을 보장하지 않는다. 대학생·단기 세션과 자기보고 등의 한계가 있다.
- [Petralito 등 2017](https://www.mmi-basel.ch/extras/2017_Petralito.pdf): Dark Souls III 이용자 95명의 회고에서 실패도 학습·성취를 통해 긍정 경험에 연결됐다. 자기선택된 이용자 연구이므로 혼로를 고난도로 만들 근거는 아니다.
- [Maddy Thorson, Celeste & Forgiveness](https://www.maddymakesgames.com/articles/celeste_and_forgiveness/index.html): 입력·위치 허용 폭으로 의도를 관대하게 수용한 제작자 사례다. 실험적 인과 검증이나 혼로의 자동 조준 도입 지시는 아니다.
- [SDT 게임 연구 비판 검토](https://arxiv.org/html/2405.12639v1): 이론을 인용하는 것과 설계 인과를 실제 검증하는 것은 다르다. 따라서 본 SOP도 실제 관찰·사람의 반응으로 수정한다.

## 부록: 기존 관측 사례와 선택형 도구

### 관련 결함을 고칠 때 참고할 기존 사례

- `stage8-first-seal`: 서쪽 산개 3체가 R8에 나타나 R12에 처음 행동했지만 총 7행동이 제자리였고 피해 교환·플레이어 대상 행동이 없었다.
- `stage8-low-health`: 보스가 중앙으로 이동한 뒤 동쪽 산개 2체가 옛 뒤쪽 입구에 나타나 약 2,000 거리에서 전투를 마쳤다.

이 사례는 과거 관측이며 현재 수정본의 실패 판정이 아니다. 해당 결함을 고칠 때만 같은 파동의 현재 경로·사선·실효 행동을 비교한다.

## 선택형 관측 도구

기존 `npm run encounter:review -- help`, `tests/encounter-evidence-gate.mjs`와 [조건부 파동 도구 계약](ENCOUNTER_CONDITIONAL_DISPOSITIONS.md)은 상세 관측 자료를 정리하거나 도구 자체를 수정할 때 재사용할 수 있다. 이 기존 도구의 manifest·해시 묶음·전 장 inventory·별도 검수자는 모든 국소 수정의 필수 절차가 아니다. 단, 본문 2.2의 장 개편 정량 필수 gate를 면제하지 않는다. 도구를 선택하면 그 도구의 입력 계약을 지키며 합성 fixture 성공을 실제 맵 합격으로 표시하지 않는다.

`npm run test:encounter-evidence`는 관측 도구 자체의 회귀 검사다. 배치·디자인·문서 수정마다 실행하지 않는다. 기존 테스트와 도구는 보존한다. [복원된 review-job](RECOVERED_REVIEW.md)도 선택형 도구이며 별도 전체 검수나 발행 승인 의무를 만들지 않는다.
