# 교전 설계와 완료 판정 SOP

## 적용 범위와 기존 지침

지형·동선·적 배치·정예·증원·활성화·행동 선택을 바꾸는 작업은 시작 전에 이 문서와 [캠페인 적 배치 기준](ENCOUNTER_PLACEMENT.md)을 읽는다. 배경/장식만 바꿔도 교전의 가독성·차폐 인지에 영향을 주면 관련 화면 검수를 한다.

**기존 지침이 없었던 문제가 아니다.** `AGENTS.md`와 `ENCOUNTER_PLACEMENT.md`에는 이미 등간격 금지, 역할 군집, 여백, 사선, 실제 전투 확인, 숫자나 봇 승리만으로 완료 금지가 있었다. 11장 기록도 44체/9군집과 단일 표적 명중이 실제 결집을 보증하지 않았음을 설명한다. 이 문서는 그 원칙을 작업 시작, 증거 수집, 독립 검수, 완료 차단에 연결한다. 편성 역사·장별 수치의 원본은 기존 문서를 유지하며 여기로 복사하지 않는다.

## 1. 바꿀 전투 경험을 먼저 정의한다

혼로는 **발사만큼 이동, 좋은 위치 선점, 다양한 동행과 기예 활용이 중요한 포격 RPG**다. 변경 전 실제 맵을 보고 다음을 장별로 적는다.

- 어느 지형 요충지를 누가 왜 지키는가. 근접 전위·고저차 사수·지원·정예가 서로 어떻게 지키거나 견제하는가.
- 실제 걸을 수 있는 서로 다른 높이/층, 차폐와 사선, 정면·측면·우회·퇴로가 어떤 선택을 만드는가. 그림 속 발판이나 이름만 다른 층은 실제 다층 지형의 증거가 아니다.
- 밀집 교전 구간은 어디인가. 군집 사이의 여백은 접근 선택·재정비·위협 예고·퇴로 중 어떤 목적을 갖는가. 먼 곳에 고립되어 아무 영향도 못 주는 군집을 의도된 여백으로 설명하지 않는다.
- 초기 병력과 정예의 관계, 유한 증원의 총량/시점/입구, 동시 생존 상한, 실제 행동 상한을 따로 적는다. 정예 수와 HP 배수 증가만으로 역할 관계를 대신하지 않는다.
- 기존 봉인·NPC 구조/호송·의식·고지 점유 등의 사건에 적이 어떻게 반응하는가. 처음 놓인 적만 늘리고 이후 사건 반응은 비워 두지 않는다. 사건에 맞는 예고된 유한 파동을 설계하며 승인되지 않은 목표·서사·규칙을 추가하지 않는다.

길 전체에 저밀도 적을 등간격으로 늘어놓거나 작은 난수로 흐트러뜨리는 방법은 불합격이다. 모든 장에 같은 군집 반경·정예 비율·첫 행동 라운드·피해량을 강제하지 않는다. 필요한 수치는 지형·진입 경지·파티·목표·사거리·진행 시간에 따른 장별 저작 결정과 근거로 남긴다.

## 2. 실제 역할과 사건 반응을 확인한다

대표 교전은 초기 군집별로 확인하고, 증원은 작성된 사건과 방어 목표의 **각 실제 파동**을 끝까지 추적한다. 여러 파동을 하나의 총원으로 합쳐 숨기지 않는다.

1. 실제 지지면과 사선에서 전위·사수·지원·정예의 역할을 본다. 범위 공격, 단일 표적, 다른 동행/기예, 다른 높이·경로를 고를 이유가 관측되어야 한다.
2. 예고 → 플레이어의 실제 대응 행동 기회 → 안전한 행동 경계의 입장 → 첫 실효 행동 또는 플레이어의 선제 대응을 기록한다. 예고가 UI에 표시된 것만으로 대응 기회를 인정하지 않는다.
3. 입구 점유 때는 같은 방향의 저작된 대체 입구 또는 대기다. 플레이어 위 생성, 일부만 생성, 중복 생성, 예산 소실을 허용하지 않는다. 입구가 비면 재개하고, 죽음/승리/취소 및 Continue에서 상태를 일관되게 복원한다.
4. 이동한 보스/NPC/방어 대상의 **현재 전장**과 연결된 입구인지 확인한다. 대상의 옛 위치 뒤쪽에 남아 전투가 끝날 때까지 닿지 않는 생성은 역할 수행이 아니다.
5. `action cap`, 활성 거리·층/지지면 조건, 행동 큐의 경쟁을 함께 본다. 다른 층의 사선 없는 적이나 제자리 행동이 지역 전위/지원의 순번을 계속 빼앗는지, 적은 살아 있지만 행동 기회가 없는지 관측한다.
6. 첫 행동과 첫 실효 행동을 구별한다. 제자리 대기·표적 없는 발사·도달하지 못한 추격 횟수는 효과 증거가 아니다.

효과는 피해뿐 아니라 제압, 회피 유도, 경로/위치 변경, 기예·동행 선택, 목표 방어 압력으로 관측할 수 있다. 모든 파동에 피해를 강제하거나 일부러 맞아 검사를 통과시키지 않는다. 예고를 읽고 우회해 피해 없이 통과했다면 그 선택과 실제 위협/대안 사선의 증거가 필요하다. **피해도 전술 선택 변화도 없는 것으로 확인된 파동/군집은 알려진 차단 결함**이다. 완주, 적 총원, 스크린샷의 적 표시, 실행된 테스트 수로 덮고 끝내지 않는다.

### 보존해야 할 구체적인 불합격 사례

다음은 8장 기존 검수에서 보고된 회귀 재현 대상이다. 새 수정본도 같은 결함이라는 뜻이 아니며 현재 소스에서 재검증해야 한다.

- `stage8-first-seal`: 서쪽 산개 3체가 R8에 나타나 R12에 처음 행동했다. 총 7행동이 제자리였고 피해 교환 0, 플레이어 대상 행동 0이었다. 등장·행동 횟수만 세면 통과하지만 실효 교전은 성립하지 않는다.
- `stage8-low-health`: 보스가 중앙으로 이동한 뒤에도 동쪽 산개 2체가 옛 뒤쪽 입구에 나타나 약 2,000 거리에서 전투가 끝났다. 생성 성공만으로 추격/포위 역할을 입증하지 못한다.

수정 후에는 같은 파동 ID의 trigger·예고·entry·첫 실효 행동·플레이어 반응과 실제 경로/사선을 함께 비교한다. 정확한 수치·거리의 원본 trace를 보고서에 연결하고, 전해진 요약만 있으면 원본 미확인이라고 남긴다.

## 3. 최종 증거 묶음

장별로 아래 항목의 결과와 실제 파일 링크를 남긴다. 전후·trace·정상 플레이는 소스/빌드 digest와 실제 관측 방법을 명시한다. 다른 소스에서 얻은 성공을 현재 성공으로 재사용하지 않는다.

- 같은 카메라 위치·줌·viewport의 수정 전후 실제 배치 이미지. 전체 화면만이 아니라 요충지와 대표 교전도 비교한다.
- 모든 초기 군집과 미소속 적의 ID/구성원, 목적·역할 관계·지지면·정예/지원 사선, 선택 경로와 여백의 이유.
- 실제 행동/위치/표적 trace와 플레이어 반응. 군집마다 어떤 전술 선택이 달라졌는지 관측한 근거.
- spawn 이벤트·방어 목표·런타임 전용 파동 목록과 각 파동의 trigger/예고/entry/첫 효과. 목표 하나가 여러 차례 생성하면 phase를 분리한다.
- 정상 경지·합법적인 배분·실제 보유 자원·현재 UI 입력의 전투. HP·위치·목표·적을 주입한 격리 실험, 무한 이동, 숨은 소모품 명령, 준비 세이브의 개별 장 관측을 정상 연속 캠페인으로 표시하지 않는다.
- 예고 뒤 행동 기회·점유 대기/대체 입구·죽음 취소·Continue·반복 재개, 옛 저장의 지형/배치/HP/목표/성장 보존, 신규 진입과 옛 전투의 경계.
- 원본 생성기/활성 JSON/Game/Stage View/Playtest의 일치, 최신 양 HTML 빌드와 관련 회귀. Native Canvas, Node 진단, 실제 브라우저, 성능, Pages 검수는 별개로 적는다.
- 실제 이미지를 본 시각 검토와 실제 교전을 본 전술 검토. 수치·해시·자동 테스트는 미관·재미·밀도·사선의 적절성을 자동 증명할 수 없다.

증거 파일은 `_local/reports/`에 두되, 현재 계약은 이 문서와 장별 정식 문서에 남긴다. `_local/`은 Git에 포함되지 않으므로 인수인계/최종 보고 시 검수자가 실제로 열 수 있는 별도 보존 자료의 위치도 제공한다. 사용자에게 내부 작업 경로나 존재하지 않는 링크만 전달하지 않는다.

## 4. 실행 순서와 완료 차단

1. 변경 전 소스와 화면을 보존한다. `npm run encounter:review -- init --stages 8,11 --out _local/reports/encounter-review.json`으로 미검증 manifest를 만든다. 실제 작업 장 목록을 사용한다.
2. 편성·지형·원본 생성기와 관련 런타임을 함께 수정한다. 일관된 변경 단위마다 저장한다. 총괄/게시 담당이 있는 병렬 작업은 소유 파일·커밋을 조율한다.
3. 관련 기존 회귀와 `npm run test:encounter-evidence`를 실행한다. 후자는 **검수 도구 자체의 합성 fixture 회귀**이며 실제 맵 합격이 아니다. 최신 소스/빌드가 확정된 뒤 관측을 다시 수집한다.
4. manifest의 실제 파일/해시, 장별 군집·파동 ID와 관측, 항목별 상태를 채운다. `npm run encounter:review -- check _local/reports/encounter-review.json`을 실행한다. 파일/해시/ID 누락·stale·`pending`/`blocked`/`ineffective`·열린 결함은 완료를 막는다.
5. **구현자와 다른 검수자**가 같은 화면과 원본 trace를 직접 열고, 원본 생성기/런타임과 파동 목록을 대조한다. 구현자가 쓴 결론을 그대로 승인하지 않는다. 정상 자원 조건, 제자리/멀리 있는 적, action cap 경쟁, 역할 사선, 피해 이외 전술 영향을 별도로 판단한다. 검토 보고서와 검수 대상 증거 묶음 digest를 남긴다. 독립 검수자의 신원과 실제 열람은 도구가 대신 증명하지 않는다.
6. 최종 보고에는 위 항목별 증거 링크·결과·미검증 범위·발견 결함·재검증을 적는다. **필수 항목 누락이나 알려진 무기능 파동이 남으면 완료라고 하지 않는다.** 기술 검사 통과와 증거 형식 충족은 품질 승인과 다르다. 기존 `npm run verify` 및 master/Pages 직접 검수 의무를 이 도구로 대체하지 않는다.

현재 `review-job`은 [복원 범위](RECOVERED_REVIEW.md)에 명시된 별도 1–20장 current-source 도구다. 이 교전 gate는 1–30장의 증거 목록을 추가 확인하며 기존 review-job의 브라우저/사용자 미술 승인/배포 권한을 확대하거나 자동 입력하지 않는다.

## 5. Manifest와 관측 파일 계약

CLI `help`와 `init` 출력이 필드 형식의 기준이다. `init`은 관측을 만들지 않으며 모든 판정을 `pending`으로 둔다. 현재 campaign의 encounter group, 미소속 적, spawn 이벤트, 방어 목표를 읽어 누락되기 쉬운 ID를 초기화한다. 동적 런타임 전용 파동은 자동 완전 열거를 보장하지 않으므로 `runtime-wave-inventory` 검토에서 `runtimeWaves`를 추가하고 근거 소스 파일을 연결한다.

각 군집/파동의 `observation`은 해시 검증된 JSON 파일의 JSON Pointer다. JSON 관측은 `schema: honro-encounter-observation/v1`, 현재 `sourceDigest`/`targetDigest`, `stageId`, 관측자/시각/방법, 원본 `rawEvidencePaths`와 `clusters`/`waves`를 갖는다. 군집 관측은 같은 ID/구성원·목적·역할·지지면, 실제 행동과 플레이어 반응, 효과를 갖는다. 파동 관측은 같은 ID 아래 `phases`를 나누고 각 phase에 trigger/예고/entry, 행동/플레이어 반응/첫 효과를 남긴다. `actions`는 `actorId`, `round`, `kind`, `x`, `y`, `targetId`를 기록한다. `playerResponses`는 `actorId`, `round`, `kind`, `detail`을 기록한다. 효과는 `type`, `detail`, 실제 배열을 가리키는 `actionIndexes`/`responseIndexes`로 연결한다. 피해 0이라도 관측된 회피·경로·기예 선택이면 가능하다. 빈 배열이나 효과 없는 관측은 통과하지 않는다.

`same-camera`의 비교 JSON은 `schema: honro-encounter-comparison/v1`, `stageId`, 현재 digest, 기준선 `baselineRevision`, `views`를 갖는다. 각 view는 `id`, `beforePath`, `afterPath`, `beforeCamera`/`afterCamera` (`x`, `y`, `zoom`, `width`, `height`)를 담는다. 실제 이미지 파일과 동일 카메라를 검사한다. 이미지 내용의 적절성은 직접 검토한다.

`normal-resource-play`의 JSON은 `schema: honro-encounter-normal-play/v1`, 장/현재 digest, `method` (`browser-input` 또는 `native-input`), `debug:false`, `modifications:[]`, `normalResources:true`, `completed:true`, `profile`, 원본 `rawEvidencePaths`를 갖는다. `profile`에는 `entryLevel`, `skillAllocation`, `startingResources`를 적는다. 실제 UI 입력과 자원 조건은 독립 검수한다. Native 정상 입력 기록이 브라우저 증거가 되는 것은 아니다.

모든 증거는 checkout 상대 경로와 SHA256으로 연결하며 symlink·체크아웃 밖 경로·변조를 거부한다. `review`는 별도 검수자의 명시적 `conclusion` (`no-blocking-findings`, 그 외는 차단), 검토 시각, manifest 내용/증거 해시를 묶은 `reviewDigest`, 실제 보고서 경로와 `unresolvedFindings`를 갖는다. `digest` 명령은 검토할 현재 묶음 digest만 출력하며 승인하지 않는다. `check`의 성공 출력은 **`evidence-records-complete` / `quality: not-automatically-assessed`**다. 수집기·작성자가 거짓 관측을 만들지 않았는지, runtime 파동을 빠뜨리지 않았는지, 게임이 좋아졌는지는 독립 검토와 최종 보고의 책임이다.
