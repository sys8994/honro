# Act 4 published source recovery

`cc33f68a` published compiled assets from source snapshot `cd84db106f04224d5b9a145890bf11c5d8eb0ebc` before source synchronization. The latter object is not available from the remote. A separately preserved source snapshot, `74628ce460059fc7ab4458a798f53a1ca20ba052`, provides the exact matching runtime sources and the literal Act 4 world parts; its part manifest reconstructs 32,073,198 bytes with SHA-256 `801df923ce89d8747f337f0b71e2ae38c604a8efbd6250d56e885b931af9f1b5`.

After restoring those sources and the guarded parts materializer from `badbd5af`, a clean `npm run build` reproduced the published game and Workshop entry hashes, all 69 common and nine game-only runtime hashes, and the campaign manifest hash. All 40 chapter JSON objects were identical, including stage geometry, actors, water, events and placements. Identical content-addressed campaign manifest and asset references establish the published asset graph; these comparisons do not establish new art or gameplay approval.

`shared/data/act4/world.parts/` is canonical. Run `npm run act4:source:materialize` to reconstruct the ignored `world.json`; the command refuses to overwrite a differing working copy. Run `npm run act4:source:pack` only for intentional edits, then `npm run test:act4-source`. The release guard uses the same materialized world. The 31 legacy SHA now identifies the **already published** stage and referenced assets, rather than the obsolete pre-publication JSON; it does not waive evidence requirements for a changed stage.

This recovery does not include new terrain candidates, additional Act 4 features, or full mission acceptance. The existing published runtime source recovery was subsequently reviewed and fast-forwarded to master; that approval does not extend to later candidates.
