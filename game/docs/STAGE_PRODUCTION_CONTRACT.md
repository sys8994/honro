# 시각 제작 계약 v1 — 직접 제작 중

이 계약은 2026-10-28 사용자가 요구한 **스테이지보다 제작 틀을 먼저 만들기**에 대한 구현이다. 담당 조정자가 기존 구현을 읽고 직접 작성한다. 기존 Workshop, `HonroMaps`, `HonroTerrainDomain`, `HonroScene`, Engine을 사용한다. 별도의 모양만 비슷한 렌더러로 검수하지 않는다.

## 기존 구현에서 가져오는 것

- 3장: 실제 잔교/물가/화물 적재대/지붕의 지지면과 다른 높이의 접근. `tools/map-forge/stage3-positioning.mjs`가 적 위치의 역할을 기록한다.
- 30장: `stage30-ferry-layout.json`의 지지면, `stage30-ferry.mjs`의 이동 경로 및 군집별 목적, `stage30-ferry-art.mjs`의 큰 지질면과 구조물 접지. 단, 기존 그림에 문제가 있으면 그대로 복제하지 않는다.
- 단일 지형 영역: `shared/map/terrain-domain.js`와 `TERRAIN_DOMAIN.md`. 공중에 떠 있는 단면과 끝없이 내려가는 내측 절단면을 가림막/카메라로 숨기지 않는다.
- 명령과 편집: 기존 `HonroCommands`의 복제본·검증·Undo/Redo, 기존 Workshop의 실제 공통 렌더러와 Playtest.

## 고정 기준의 소유권

`shared/map/production-contract.js`의 고정 `rules`가 실행 가능한 기준의 소유자다. 개별 맵은 허용 오차·규칙 비활성화 플래그를 제공하지 않는다. 실패를 해결하기 위해 규칙을 낮추는 변경은 지형 수정과 분리해서 설명해야 한다. 검수 횟수, 적 수, 빌드 성공은 품질을 뜻하지 않는다.

1. 기존 장의 실제 구현 참조와 보존 목표·사건·동행이 있어야 한다.
2. 하나의 확장 지형과 공통 충돌 투영을 사용한다. 내부 끝단을 지하 바닥까지 수직으로 잘라 놓지 않는다.
3. 경로는 실제 지지면을 참조한다. 그림 속 길을 플레이 동선으로 주장하지 않는다.
4. 모든 적에 지지면/공중 공간, 역할, 교전 목적, 대상 구역이 있어야 한다.
5. 등간격과 동일한 두 마리 조합 반복으로 채우지 않는다. 몸이 겹치거나 시작·상호작용을 잠그지 않는다.
6. 공통 에셋과 미술 체계를 재사용한다. 새로운 에셋의 이유는 별도로 기록한다.
7. 전체·일반·확대·최소 줌·모바일·좌우 끝을 같은 렌더러로 본다.
8. 경로·사격 차이·적의 실효 행동·목표 진행은 실제 엔진 관측이 필요하다.
9. 전체 구조, 디테일/가독성, 카메라/상태의 세 집중 검수와 최종 종합 검수를 구분한다. 소스가 바뀌면 기록을 만료시킨다.
10. 자동 판정은 미관·재미·사용자 승인을 제공하지 않는다.

각 집중 검수의 세부 질문도 코드의 고정 `reviewCriteria`에 둔다. 전체 경로의 전술적 차이, 기존 장과의 비교, 큰 명암면과 접지, 정상·최소줌·모바일·기믹 변화, 모든 군집의 실효 역할을 항목별로 `미확인/불합격/직접 확인한 범위 통과` 중 하나로 기록한다. 일부 항목이 미확인인데 전체 통과로 저장할 수 없으며, 단일 관찰 문장이나 같은 화면 반복으로 네 검수를 대체할 수 없다.

## 편집 흐름

Workshop의 `제작 계약`을 열고 현재 장에 계약을 시작한다. 전투 질문과 기존 참조 장을 선택한다. 캔버스의 실제 적/지형을 선택하여 역할·지지면·대상 구역과 경로 지점을 연결한다. 노란 선은 실제 컴파일된 충돌, 초록/보라 선은 주경로/대안, 주황 영역은 적의 목적 구역이다. 카메라 좌표와 실제 캔버스 크기를 기록하며 실제 렌더와 오버레이를 캡처한다.

좌표만 넘겨 적을 만드는 새 생산 API 대신 `HonroWorkshopAPI.production.placeEnemy`는 교전 목적·역할·지지면을 먼저 요구하고 공통 지형에서 발 좌표를 계산한다. 역할 기록과 실제 `encounters/unitIds/encounterGroup`도 대조한다. 문서에만 군집명을 붙여 놓으면 실패한다. 초기 수·정예·유한 증원·동시 행동 예산과 근거는 따로 작성한다.

`bankFromProfile`은 맵 좌우까지 이어지는 유효 단면만 받아 기존 단일 지형 저작기로 확장한다. 기존 지형을 암묵적으로 덮어쓰지 않는다. `placeScenery`는 기존 참조 에셋 또는 사유가 기록된 에셋, 허용된 크기, 실제 지지면이 있어야 배치한다. 기존 자유 편집은 초안용이며 계약 실패를 없애 주지 않는다.

`Export`는 계약이 시작된 맵 및 관리 대상 31장을 `.draft.honro-map.json`으로만 저장한다. 제작용 버튼과 `exportProject/exportHonroSpec`는 고정 검사 및 현재 소스에 묶인 검수/엔진 관측이 없으면 실패한다. `exportDraft`는 초안 보존 전용이다. 31장은 계약 필드만 삭제해도 제작용 검사를 피할 수 없다.

사격선은 선택한 실제 유닛·기예·각도·충전과 공통 `Engine.predict`로 표시한다. 원형 범위나 새 물리식을 그려 맞는 것처럼 보이지 않는다. 지형/충돌/역할 안내는 끄고 실제 미술만 캡처할 수 있다.

## CLI와 현재 확인 범위

```sh
node tests/production-contract.mjs
node tools/stage31/contract.mjs audit
node tools/stage31/inspect.mjs baseline
node tools/stage31/probes.mjs draft.json stage-31 inputs.json probe-results.json
node tools/stage31/contract.mjs export draft.json stage-31 approved.json
```

현재 배포 31장 원본을 바꾸지 않고 검사하면 x=6280의 지하 수직 절단, 설계 카드/지지면 역할/경로/필수 화면/엔진 관측 누락으로 **실패**한다. 네 개의 `pass` 문자열만 넣어도 이 기계 결함은 통과하지 못한다. 배우 위치를 바꾸면 앞선 검수 fingerprint가 만료된다. 정상 지형 단위 fixture는 기계 검사만 통과하고 검수·플레이 증거 없이 제작용 내보내기는 차단된다.

CLI 내보내기는 실제 증거 파일의 바이트와 SHA256도 비교한다. 기록을 작성했다는 것은 사람이 실제로 봤다는 사실의 암호학적 증명이 아니다. 따라서 임의 JSON을 작성하여 확인한 척하는 것은 금지되며, 실제로 본 문제·수정·재확인과 범위를 보고해야 한다. 이것은 작업 절차의 강제 경로이지 파일 시스템의 모든 소스 수정을 봉쇄하는 보안 샌드박스가 아니다.

`probes.mjs`는 선택·이동·점프·발사·방어·시간 진행만 받아 실제 Engine을 실행한다. HP/기력 리필, 배우 위치 대입, 적 삭제, 강제 명중/승리 필드는 받지 않는다. 경로의 순서 있는 체크포인트, 실탄 충돌/피해, 적의 실제 피해 또는 목적 구역으로의 접근을 관측한다. 31장 목표는 별도의 생산 App 어댑터에서 실제 승선 상태까지 확인하며 단순 전멸을 승선 완료로 취급하지 않는다. 이 어댑터의 DOM·음향은 대역이므로 브라우저 플레이 증거로 부르지 않는다. 엔진만 사용하는 러너는 목표 확인 요청을 `not-supported`로 반환한다.

현재 단위 검증은 실제 이동 입력이 통과하고 가만히 기다리기만 한 경로는 실패함, HP 주입 필드가 거부됨, 31장 시작/대기만으로 승선 목표가 성공하지 않음을 포함한다. 아직 새31장을 완주한 기록은 아니다.

`npm run build` 앞의 `check-release.mjs`는 실제 발행될31장 지형/참조에셋이 바뀌면 검증된 제작 패키지와 같은지 확인한다. 기존 배포본의 알려진 잘못된31장은 **역사적 미검수 기준선**으로만 등록하여 무관한 아이템/지도 수정의 빌드를 막지 않는다. 이 해시를 새 지형에 맞춰 갱신해서 검사를 피하는 것은 금지한다. 코드/맵이 바뀌면 엔진/미술 근거를 갱신해야 한다.

현재 미완료: 실제 브라우저에서 새 편집/검수 기록/내보내기 흐름 확인, 새31장 제작과 그 장의 실제 경로·교전·승선 검수. 편집 UI의 실제 브라우저 검수가 아직 완료되지 않았다. 이를 실행 검수 통과로 표시하지 않는다. 이 항목이 끝나기 전 **제작 틀 완료** 또는 **31장 재제작 완료**로 보고하지 않는다. 현재31장 지형·전투 데이터는 변경하지 않았다.
