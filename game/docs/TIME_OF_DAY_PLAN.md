# 시간의 흐름 그래픽 기획 v0.1 (2026-11-03, 사용자 검토 대기)

목표: 장마다 이야기 속 **날짜와 시각**을 정하고, 그 시각에 맞는 색감·달·별·구름으로 시간의 흐름을 보여 준다. 장 안에서는 턴이 지날수록 시각이 흘러 색감과 달의 위치가 바뀐다. 시간 설정은 지형·전투 데이터와 완전히 분리해, 지형을 고쳐도 시간 설정은 그대로 두고, 시간을 고쳐도 지형은 그대로 둘 수 있게 한다. 부수 효과로 이야기의 시간 순서를 장별로 못 박아 서사의 논리를 단단하게 한다.

관련 취향(취향서): 한국형 다크 판타지, 동화·유아틱 금지, 막별로 다른 색감(1막 짙은 녹색 저녁, 2막 동굴 흑회색, 3막 뿌연 황토 낮, 4막 쓸쓸한 푸른 바다안개), 벡터는 면으로 구분하고 그라데이션은 원경 분위기와 이펙트에만.

## 1. 기술 방식: 벡터를 다시 칠하지 않고 "시간 색 보정"을 덧입힌다

현재 화면은 원경 이미지 → 날씨 입자 → 지형·배경물 → **분위기 색 덧칠(`environmentTone`)** → 캐릭터·표식·UI 순으로 그린다. 덧칠 자리가 이미 캐릭터보다 앞에 있어서 배경과 지형만 물들고 전투 가독성은 지켜진다.

| 방식 | 판단 |
|---|---|
| 벡터 색을 시각마다 다시 칠하기 | 쓰지 않음. 지형 그림을 매번 다시 래스터화해야 해 무겁고, 막별 고유 색(면 구분)을 망가뜨린다. |
| 화면 전체 CSS 필터 | 쓰지 않음. 캐릭터·UI까지 함께 물들고 색상 회전으로 색이 탁해진다. |
| **덧칠 자리에서 합성 보정(권장)** | 프레임마다 전체 화면 채우기 2~4번이라 가볍다. 막별 고유 색은 그대로 두고 시각만 얹는다. |

보정은 네 겹이다. 모두 캔버스 합성 모드로 처리한다.
1. **채도**(`saturation` 합성): 밤일수록 색을 뺀다.
2. **어둡기·색조**(`multiply`): 밤은 푸른 회색으로 어둡게, 낮은 거의 투명하게.
3. **지평선 빛**(`screen`, 원경 높이의 띠): 해질녘은 붉은 금빛, 새벽은 푸르거나(기본) 붉게(장별 지정). 원경 분위기 효과라 그라데이션을 허용한다.
4. **캐릭터 약보정(선택)**: 밤에 캐릭터가 오려 붙인 듯 보이면, 같은 보정을 20~30%만 캐릭터에 따로 건다. 시안으로 판단한다.

하늘 요소는 원경 이미지 위, 지형 아래에 그린다.
- **달**: 흐린 원판과 넓고 옅은 달무리. 시각에 따라 호를 그리며 이동한다. 날짜별 위상(차고 기욺)을 둔다. 밝고 선명한 동그라미는 쓰지 않는다.
- **별**: 깊은 밤에만 아주 옅게 반짝인다. 원경 이미지에 하늘이 보이는 장에서만 쓴다.
- **구름**: 실시간으로 흐른다. 방향과 속도는 전투의 바람(wind)을 따르고, 턴과는 무관하다. 어두운 하늘에 흐릿하게 번진 낮은 채도의 덩어리 2~3겹으로 그린다. 윤곽선·둥근 뭉게구름·흰 구름은 금지한다. 구름 색과 밝기도 시간 보정을 받는다.

턴과 시각의 연결: `시각 = 시작 시각 + (현재 라운드 − 1) × 턴당 분`. 상한 시각을 넘으면 거기서 멈춘다(라운드가 길어져도 해가 뜨지 않는 등). 새 라운드가 시작될 때 2~3초에 걸쳐 부드럽게 바뀌고, 순간 전환은 하지 않는다. 시각은 라운드에서 계산하므로 저장 데이터를 추가하지 않는다. 옛 저장·이어하기와도 호환된다.

## 2. 데이터 체계 (지형·전투와 독립)

### 2-1. 시각 보정표 `shared/data/time-grades.json` — "몇 시면 어떤 색인가"

장과 무관하다. 24시간 위의 키프레임을 두고 사이는 보간한다. 이름 붙은 **프로필**로 막·장소별 차이를 준다.

```json
{
  "version": 1,
  "profiles": {
    "default": {
      "keys": [
        {"t": "00:00", "saturation": 0.40, "multiply": ["#2f3b57", 0.66], "horizon": null, "stars": 0.5},
        {"t": "05:00", "saturation": 0.45, "multiply": ["#3c4762", 0.58], "horizon": ["#7d8fb0", 0.18]},
        {"t": "06:30", "saturation": 0.75, "multiply": ["#8a93a3", 0.25], "horizon": ["#a9b8c9", 0.20]},
        {"t": "12:00", "saturation": 0.95, "multiply": ["#ffffff", 0.00], "horizon": null},
        {"t": "17:30", "saturation": 0.85, "multiply": ["#b08a72", 0.20], "horizon": ["#c4744e", 0.30]},
        {"t": "19:30", "saturation": 0.55, "multiply": ["#4a4d63", 0.50], "horizon": ["#7a4f5a", 0.15]},
        {"t": "22:00", "saturation": 0.42, "multiply": ["#323e5a", 0.64], "horizon": null, "stars": 0.4}
      ]
    },
    "ember-dawn": {"extends": "default", "override": [{"t": "05:30", "horizon": ["#c0604a", 0.32]}]},
    "sea-fog": {"extends": "default", "override": [{"t": "12:00", "saturation": 0.6, "multiply": ["#8fa3b2", 0.28]}]},
    "cave": {"fixed": {"saturation": 0.5, "multiply": ["#3a3d44", 0.45]}}
  }
}
```
숫자는 출발점 가안이다. 시안을 보고 사용자와 함께 맞춘다.

### 2-2. 시간표 `shared/data/timeline.json` — "이 장은 며칠 몇 시인가"

```json
{
  "version": 1,
  "stages": {
    "10": {"day": 2, "start": "23:00", "minutesPerTurn": 30, "hold": "05:45",
           "profile": "ember-dawn", "moon": {"phase": 0.72}, "clouds": {"density": 0.45}}
  }
}
```
- `day`: 막 첫날을 1로 하는 일차. `start`: 시작 시각. `minutesPerTurn`: 턴당 흐르는 분. `hold`: 이 시각 이후로는 멈춤.
- `profile`: 시각 보정표의 프로필 이름. `moon.phase`: 0 그믐, 0.5 보름. `clouds.density`: 구름 양.
- 원경 이미지에 하늘이 없는 장(동굴 등)은 `sky:false`로 두어 달·별·구름을 끈다.

### 2-3. 막별 고유 색과의 관계

최종 화면은 **장소의 색(막별 고유 팔레트)** 위에 **시간의 색(이 문서)**, 그 위에 **날씨(안개·비)** 순으로 얹는다. 지금의 1막 `act1Mood`(장 번호에 따라 점점 어두워지는 색)는 사실상 "시간이 흐른다"는 대용품이었으므로 1막에서는 이 체계로 대체한다.

### 2-4. 검사 도구

`node tools/timeline-check.mjs`가 막 안에서 일차·시각이 거꾸로 흐르지 않는지, 상한 라운드(20)까지의 시각 범위를 표로 보여 준다. 이야기 시간표 문서도 이 표로 자동 생성한다. 시각 보정 미리보기 페이지(Workshop)에서 시간 슬라이더로 장면을 확인한다.

사용자 최신 지시(10/28)는 "낮이긴 하지만 우울하고 블루한, 짙은 바다안개 혹은 대나무숲 안개". 31장 새벽 하구에서 시작해(30장의 "날이 밝으면"), 대부분 `sea-fog` 낮. 37~39장 곶의 구조는 조수와 함께 해질녘, 40장 귀환은 저녁으로 두어 막의 끝을 어둡게 닫는 안을 제안한다.

## 4. 단계

1. **시간표 확정**: 사용자 결정(8장 한 단어, 1막 3일 안), 2·4막 초안 검토.
2. **보정 체계**: 데이터 두 파일, 보간, 라운드 전환 애니메이션, `environmentTone` 대체. 1막에 먼저 적용. 장마다 시작·중간·끝 시각 화면을 PC와 휴대폰으로 보여 드리고 숫자를 함께 맞춘다.
3. **달과 별**: 위상과 호 이동. 원경에 하늘이 보이는 장만.
4. **구름**: 바람을 따라 실시간으로 흐르는 흐릿한 구름. 1막 10장으로 먼저 시안을 만든다.
5. **2·4막 적용**, 3막은 재작업 뒤에 적용.
6. **쉼터·여정첩 화면**도 그 장이 끝난 시각의 색으로.

런타임 렌더러를 바꾸므로 단계 2·3·4는 각각 31장 재검증 후 배포한다. 시간 데이터만 고치는 단계는 문서·데이터 변경으로 가볍게 처리한다.

## 5. 위험과 확인

- **원경 이미지와의 충돌:** 원경은 장면별 래스터 이미지라 고유 조명이 칠해져 있다. 밝은 낮 그림을 보정만으로 깊은 밤으로 만들면 탁해질 수 있다. 1막 10장처럼 밤에서 새벽까지 크게 바뀌는 장은 밤용과 새벽용 원경 두 장을 교차 페이드하는 안을 예비로 둔다.
- **가독성:** 깊은 밤에도 밟는 윗면과 적이 보여야 한다(지형 세 기준 중 "경계는 분명하게"). 가장 어두운 시각에도 윤곽 대비가 남는지 확인한다.
- **성능:** 프레임당 전체 화면 채우기 2~4번과 구름 몇 장이라 부담이 작다. 구름은 미리 흐리게 만든 이미지를 재사용한다.
- **취향:** 구름과 달이 "동화 같은" 느낌이 되지 않게 한다. 시안마다 취향 기록부에 AI 예측을 먼저 적고 사용자 판단을 받는다.
