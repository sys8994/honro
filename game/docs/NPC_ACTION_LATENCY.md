# NPC 행동 준비 지연

2026-09-30, HBUG-044 재발 조사. 프레임 처리 비용과 캐릭터가 움직이지 않고 판단을 기다리는 시간을 별도로 측정한다.

## 재현과 원인

이전 검사는 평지에서 이동을 마친 적·동맹의 즉시 사격을 주로 확인했다. 실제 캠페인의 경사·절벽·막힌 사선에서는 다음 비용이 남아 있었다.

- 이동 후보마다 최대 240회의 공통 물리를 실행하며, 후보 하나 내부에서는 프레임을 양보하지 않았다. 직접 경로와 우회 경로를 모두 비교하고 이동 위치별 탄도도 탐색했다.
- 다각형 지면의 멀리 떨어진 변까지 매번 법선을 계산하고, 발밑의 표면 검색은 전체 지형을 훑었다. CPU 프로파일에서 `segmentTerrain`, `terrainContains`의 비용을 확인했다.
- 4ms 계획 예산이 프레임 시작 시각부터의 마감 시간이었다. 판단 전의 물리·현장 처리도 예산을 소비했다.
- 유효한 첫 기술을 찾은 뒤에도 다른 기술을 검사했고, 막힌 사선에서는 기술·대체 표적·재이동마다 조준 격자를 반복했다. 5장 적 하나는 이동/방어 결정까지 2,357회, 10장 적 하나는 2,600회 예측했다.
- 동맹은 공통 조준 뒤에 35개 후보를 다시 검사했다. 피해가 없는 이동/방어에도 0.65초의 피해 확인 시간을 붙였다.

## 현재 처리

- 4ms는 generator 실행에 실제 소비한 CPU 시간만 차감한다. 같은 프레임의 적·동맹 판단은 잔여 예산을 공유한다. 이동 중에는 새 판단 iterator를 만들지 않는다.
- 경로의 공통 물리 검사는 8단계마다 양보한다. 우선순위가 높은 도달 가능한 후보 3개 또는 충분히 개선되는 경로가 나오면 이동을 결정한다. 유망한 높은 지점의 2단계 우회 검사는 유지한다. 실행은 실제 걷기/점프이며 순간이동이나 지형 무시는 없다.
- 표면 검색은 기존 지형 공간 인덱스를 공유한다. 이음새·매몰 표면 검사에 필요한 주변까지 포함한다. 높이 범위를 벗어난 표면과 궤적에서 떨어진 다각형 변은 비싼 계산 전에 제외한다. 점/경계 거리 비교에는 제곱 거리를 사용한다.
- 위치 평가에는 역산 후보와 세 가지 호만 사용한다. 실제 발사는 역산 후보 → 낮은/높은 호의 유한 격자 → 주변 미세 조정으로 검증한다. 군집에는 범위 기술을 우선하며 유효한 기술을 찾으면 나머지 기술 탐색을 끝낸다. 동맹의 중복 격자는 제거한다.
- 일반 적 투사체는 실제 예측의 6초 수명과 균일한 중력·바람·항력으로 가능한 발사각 전체의 도달 범위를 먼저 확인한다. 시간 표본 사이의 최대 이동량과 대상 몸/폭발 반경을 여유로 더하므로 확실히 누구에게도 닿지 않는 경우만 제외한다. 지역별 물리·기류·장판 또는 플레이어의 특수 기술에는 이 제외를 적용하지 않는다. 8장 원거리 상두꾼이 불가능한 포격을 계속 계산하던 재현을 막는다.
- 피해 없는 NPC 행동 뒤 확인은 0.18초다. 플레이어와 실제 명중 피해는 기존 0.65초를 유지한다. 배속 적용 전의 전투 시간 기준이다.

지형/아군 피해 검증, 동맹 발사력 0.82 상한, 난이도별 오차, 적 보스의 지정 기술 순서는 유지한다. NPC는 충분한 경로·사격을 먼저 선택하므로 이전의 전수 비교와 이동 위치·발사각·선택 기술이 달라질 수 있다. 모든 특수 지형에서 최적의 사격을 보장하는 탐색은 아니다. 플레이어의 조준 미리보기와 물리 규칙은 변경하지 않는다.

계획 예산·iterator·공간 인덱스는 런타임에만 존재한다. 저장 스키마를 늘리지 않으며 진행·XP·SP를 초기화하지 않는다. 도중 저장을 불러오면 현재 전장에서 다시 판단한다.

## 검증

- `tests/npc-latency.mjs`: 10개 캠페인의 표면 816조건과 다각형 접촉 4,080조건을 전체 지형 조회/수정 전 좁은 충돌 검사와 비교한다. 인덱스 경계 이음새·지형 변경, 실제 계산 시간만 차감하는 공유 예산, 피해 유무별 확인 시간, 벽 뒤 동맹의 발사 보류·대기열 진행을 검사한다.
- 도달 범위 제외는 저중력/중량 기술, 바람 3조건·발사각 5조건의 실제 비행 종점 30개를 잘못 거르지 않는지 확인한다. 지역별 물리와 특수 기술은 원래 예측으로 돌아간다.
- `tests/npc-latency-browser.py`: Game/Workshop에서 1·3·5·7·8·10장 적 각 3명과 2장 동맹 3명의 판단을 원래 지형/배치와 실제 App 프레임으로 실행한다. 총 42사례의 이동 시작, 최종 공격/방어, 중간 정지 프레임, 예측 횟수, 실제 CPU/경과 시간을 분리한다. 실제 방어 버튼으로 동맹 턴에 진입하는 2사례도 검사한다. 자동 대사를 제거한 독립 브라우저 상태를 쓰며 캠페인 전체 수동 완주로 취급하지 않는다.
- 기존 `finale-update`, `attack-tempo-finale`, `tactics-audit`로 분할/동기 결정·중간 저장·변경 표적 재탐색·비행·아군 피해·대체 표적을 확인한다. 분할 검사 예산은 개선 후에도 실제로 중단되는 작은 값으로 조정했다.
- 전후 측정은 `_local/reports/npc-action-latency/`의 `before-browser.json`, `after-browser.json`, `unit.json`, `comparison.json`에 둔다. 21사례씩의 예측 합계는 각 HTML에서 11,030→1,583회, 행동 사이 최장 정지는 Game 61→12프레임/Workshop 98→12프레임, 첫 행동 중앙값은 7→3/6→3프레임이었다. 실제 방어 입력 뒤 동맹 행동 인계는 약 117ms였다. 최종 NPC 논리 검사와 두 HTML의 44개 행동 검사는 통과했다.
- 전체 검증은 완료로 집계하지 않는다. 첫 실행의 8장 원거리 조준 대기 실패는 도달 범위 제외로 수정하고 해당 집중 검사를 통과했다. 이후 전체 재실행은 사용자가 필요한 검사만 요구하여 중단했다. `failed-latency-verify.log`와 `failed-latency-verification.json`은 수정 전 실패, `full-verify.log`는 중단된 재실행의 부분 기록이다. `verification.json`도 성공 보고서가 아니다.
- 프레임 수는 디스플레이/브라우저 주기에 영향을 받으므로 일정한 밀리초 응답을 보장하지 않는다. 시작 직후 캐시 생성과 로딩을 포함한 측정도 그대로 기록한다.
