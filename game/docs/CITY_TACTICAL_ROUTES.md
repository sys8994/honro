# 21·24·28장 전술 경로

## 범위와 원본

`tools/map-forge/city-tactical-routes.mjs`의 `applyCityTacticalRoutes`가 세 장만 저작한다. `shared/build.mjs`는 기존 장소·서사 저작과 열린 건축물 정책 뒤에 이를 적용한다. Game, Stage View, Workshop Playtest는 같은 최종 프로젝트와 엔진/렌더러를 사용한다. 캠페인 JSON에도 같은 저작 결과를 저장한다. 기존 9·13장 별도 저작과 서로 다른 장/에셋 ID를 소유하며, 라이브 저장을 이 함수에 다시 통과시키지 않는다.

맵의 크기를 늘리거나 적 수·HP·행동 상한·유한 파동·목표·이야기·분할 팀·자원 규칙을 바꾸지 않았다. 새 낮은 기단이 차지하는 기존 지상 적은 같은 ID/x/능력으로 윗면에 접지한다. 기존 건축물/원경은 유지한다. 비충돌 후면 기둥은 배경 무윤곽 정책을, 실제 지지/차폐 면은 공통 지형 윤곽을 따른다.

## 장소별 선택

- 21 성문 아래: 기존 서쪽 성곽에 짧은 기본 접근을 붙이고 동쪽에는 참이 있는 석회랑과 시장으로 내려오는 귀환을 둔다. 성문 안 낮은 돌기단과 시장 옆 높은 회랑은 지상 직사와 후위 곡사 엄호를 나눈다. 주민 구조와 2턴 방어, 성 안 출구는 원래 순서다.
- 24 휘겸의 문장: 대청 양쪽의 접근에서 후원 상부 면으로 이어진다. 아래 옹벽 발과 위 돌출부 사이에는 낮은 접근/귀환 공간이 남는다. 사당 동쪽은 90폭 평참에서 지붕까지 기본 상승 136으로 연결한다. 첫 후보의 X형 교차와 정확한 이륙점에 의존하던 높이 222의 점프를 제거했다.
- 28 지운 이름과 남은 명령: 기존 두 제어팀과 중앙 집결을 그대로 두고 청원마당 지붕 접근, 동쪽 기록 경사와 연결된 교차엄호, 낮은 실제 차폐를 추가한다. 새 강제 분할이나 사건은 없다. 서쪽 820/동쪽 660 제어 거리 예산과 12적턴 화재 제한을 유지한다.

낮은 기단은 별도 겹침 polygon으로 덧그리지 않고 `a3-foundation`의 연속된 윗면으로 합친다. 이로써 지면 아래에 다른 형상의 얼룩이 생기는 문제를 없애고 같은 원본 지형이 충돌과 미술을 소유한다.

### 24장 봉인문

독립 기본입력 검수에서 기존 높이 200의 닫힌 사당문을 목표 0개 상태에서 기본 점프로 넘는 결함을 재현했다. 새 진입의 문 높이는 350이며 x/바닥/HP/담허의 봉인 열림 조건은 그대로다. 이 수정은 저장된 전투의 문을 강제로 늘리지 않는다. 기존 문 200과 새 문 350이 각각 App 내보내기/가져오기/이어하기에서 유지되는 회귀가 있다.

28장의 원래 수문 지붕을 통한 제어 전 이동은 다른 계약이다. 단순 이동 가능성만으로 기존 벽을 높이지 않으며, 양 제어·화재 패널티·전원 집결·출구 목표가 실제로 우회되는지를 따로 확인한다.

## 검증과 한계

- `tests/city-tactical-contracts.mjs`: 단계별 저작 범위·재현성, 기존 에셋/배우 ID·수치·개수·x, 목표/파동/자원, 단일 지형 영역, 실제 컴파일 초기 신체 공간을 확인한다. 24문 높이 변경은 명시적인 예외로 검사한다.
- `tests/city-tactical-save.mjs`: 세 장×새/옛 지형 6개 App export/import/Continue 조건에서 지형·월드 지형·배우 좌표/HP/MP·목표/상태를 보존한다. 준비된 저장 fixture이며 정상 연속 완주 증거가 아니다.
- 기본 경로 검수는 실제 spawn에서 Engine 이동·기본 점프·기본 내려가기·대기와 유한 이동 예산을 사용한다. 별도 독립 보고서의 최종 SHA/조건을 기준으로 한다. 좌표 목록·도식·제자리 표적 배치는 접근 성공 증거가 아니다.
- `tools/environment/capture-act3-production.mjs --tactical-focus`는 동일 카메라의 desktop/mobile Native Canvas 화면을 남긴다. Native 미술은 브라우저 조작/성능 검증과 구분한다.
- 전체 `npm run verify`는 변경 전 25ae85c에서도 실패하는 encounter-density 역사 fingerprint 경계에서 중단된다. 해당 assertion과 원본 fixture는 약화하거나 덮어쓰지 않았다. 집중 검사 통과를 전체 verify 통과로 표현하지 않는다.

정상 자원 플레이·실탄/반사·관통·닫힌 상태/열린 상태·허용 공차·최신 브라우저와 Pages의 완료 범위는 통합 검수 기록에서 명시한다. 당시 후보의 성공을 수정 후 최종판의 성공으로 조용히 재사용하지 않는다.
