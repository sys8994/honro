## 저장과 동일 조건

`tools/testing/capture-battle-runtime-saves.mjs`가 기존 `tests/stage11-ravine-fullplay.mjs`의 정상 입력 정책을 재사용해 1·7·15·16라운드에서 기록했다. 장 이동·HP·기력·적·목표를 중간에 조작하지 않았다. 정상 캠프 API로 준비한 경지10 네 동행 fixture이며 사용자의 실제 저장은 아니다. Native 엔진/실제 mission 메서드로 만든 저장을 생산 App의 실제 저장 로드→Continue→mount에 넣었다. Native 실행은 브라우저 입력이나 사람의 플레이 속도와 구분한다.

초기 엔진 RNG는 `19388`, 브라우저 Math.random 초기 seed는 `899411`이다. 각 전후 쌍은 같은 gzip 원본 저장과 그 안의 동일 RNG 상태를 사용한다. 저장별 원본 SHA256은 `evidence/saves/manifest.json`과 각 raw 결과에 있다. Native 15라운드 체크포인트에는 35,069 step(120Hz 논리 시간 약292.24초), 입력 호출5,894회가 기록돼 있다. 조사 중 프로세스를 멈춘 시간은 플레이 시간으로 계산하지 않았다.

## 캐시·엔티티·장기 왕복 결과

실제 발사는 전후 모두 투사체 최대3개, FX 최대11개, spark 파티클 최대9개를 관측했다. 발사 직후 spark가 생기고 수명 뒤0으로 돌아왔으며 같은 시나리오의 RNG가 전후 일치했다. 전체 units와 생존 적 수는 저장 표와 일치한다. 이 시험만으로 모든 기예나 모든 장면의 누수 부재를 증명하지 않는다.

일반24표본에서 world raster 보유량 최대19,170,432B, 전경/원경 화면 캐시 각각 최대3,425,280B였다. 실제 AuthoredFar 캐시는 `dawn`1개/6,293,408B, 상한3개, 오류0이었다. old SVG 준비와 실제 원경 준비를 혼동하지 않는다.

[최종 16라운드 안정성](evidence/measurements/final-stability.json)은 동일 원본 실행 바이트 두 컨텍스트에서 각각1,800 rAF/180배율 구간/반복 팬을 수행했다. 시계열61개, tile 최대10개, 종료8개/8,520,192B, 화면 두 장 각각3,425,280B였다. tile 총할당1,500회와 screen 총생성571회는 **누적 작업량**이며 보유 개수/메모리 증가량이 아니다. 이 churn은 남아 있다. JS heap 범위는 한 실행17,658,853~31,002,009B, 다른 실행17,574,030~30,938,670B로 GC에 따라 오르내렸다. GPU/컴포지터 메모리는 측정하지 않았으며 이를 누수 부재의 증명으로 읽지 않는다.

최종 안정성의 7개 RGBA뷰와 [최종 세로15라운드](evidence/measurements/final-mobile-pixels.json)의7개 뷰는 전부 완전 일치했다. 렌더 전후 battle, Continue, 실제 저장→reload→Continue, 성장/장착/완료/아이템 보존과 캐시 cap/resize/해제/alpha/composite 검사가 통과했고 pageerror0이었다. 후보의 [별도28뷰 검사](evidence/measurements/verified-pixels.json)도 남겼다.

## 인계

미해결은 원 사용자의 급격한 렉 트리거다. 다음 조사에는 실제 해당15라운드 저장과 기기/브라우저·줌·카메라·발사 기예를 연결한 짧은 재현이 필요하다. 맵 크기/누수/M05 중 하나라고 미리 정하지 않는다. 원래 문제 해결은 미완료이며 이 보고서는 해결됐다는 배포 근거가 아니다. 환경/권한 차단은 없고 원격 브랜치 보존까지 수행했다.

최종 순 변경은 검수 도구와 이 문서/증거뿐이다. 이전 실험 커밋을 개별 cherry-pick하지 말고 최종 브랜치 순 diff를 통합한다. `shared/runtime/renderer.js`, stage 데이터, 이미지, act-endings/rest-journey/menu-ui의 최종 차이는 없다. master/Pages는 부모 담당자가 처리한다.
