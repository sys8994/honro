# 후속: 같은 문서의 연속 전투와 표시 참조 경계

## 연속 전투 표본

기준 실행은 원 보고서와 같은 f8cc1a82 실행 바이트이며 체크아웃 d0d8e4d5에서 시작했다. 도구는 6b7fa346의 정상 정책 어댑터다. 음악/효과음 off, 1280×800/DPR1, headless Chromium 154.0.8037.57이다. Android/Safari/사용자 실기 표본이 아니다.

**같은 Chromium 문서에서 1→16라운드에 도달했다.** 약691.9초, 실제 App.frame19,652회, mount1회, Engine 교체0회, Scene 교체0회, 중간 reload/Continue/context 재생성0회다. 실제 simulation/AI planning budget4ms/자동 카메라/동적 FX/HUD/저장 경로를 유지했다. HP·기력·경지·적·좌표를 중간에 수정하거나 e.tick을 도구가 직접 호출하지 않았다. 기존 정상 정책의 e.move 요청을 App 조이스틱 값으로 전달하고 다음 실제 rAF까지 유지했으며, 발사/선택/대기는 기존 정상 Engine 입력 API를 썼다. 대화는 실제 skip 버튼을 눌렀다. 전투 속도는 원 fixture의 플레이어1/적2다.

Native 경로와 rAF/AI 예산·입력 발행 간격이 달라 라운드별 상태/승리 타이밍이 Native 기록과 일치한다고 주장하지 않는다. 시작 저장은 동일하고 이후는 실제 생산 루프로 자연 진행했다. 교착/수십 턴 반복 없이 16라운드에서 정책을 종료했다.

### 마지막 fresh 비교의 한계

원래 연속 문서의 종료 후 paused 비교는 수행됐으나, 이어서 새 문서 mount wrapper가 Playwright 평가 결과로 자동 실행되는 어댑터 오류로 중단돼 그 paused 비교 값은 파일에 저장되지 않았다. 실제 게임의 연속 표본/최종 저장은 오류 전에 보존됐고 게임 pageerror0이었다. 이 오류를 게임 결함으로 계산하지 않는다. 후속 도구는 wrapper를 명시적 화살표 함수로 감싸고 live 비교를 먼저 저장하도록 고쳤다. 긴 표본은 다시 돌리지 않았다.

대신 저장된 동일 최종 전투를 짧은 새 문서에 로드해 round/rng/phase/units/projectiles/terrain/honroState/items의 의미적 일치를 확인했다. [짧은 fresh control](evidence/continuous/fresh-control.json). 이것은 저장된 live 마지막 AIM83프레임과 나중의 fresh 표본을 비교한 **비동시·근사 대조**다. 카메라/선택 기예는 기록으로 재구성했고 시각 clock은 새 문서에서 시작한다. 이 제약을 숨기고 정밀 paired 비교로 부르지 않는다.

live 마지막 AIM frame 4.1 / 14.9 / 42.9, fresh warm150프레임 4.6 / 16.1 / 43.5. fresh가 살아 있던 문서보다 뚜렷하게 가볍지 않았고, 이 근사 대조로 지속 누적을 입증하지 못했다.

## 별도 조건부 참조 정리 버그

`combat-feedback.js`는 pause/대화 때 hurt>0인 유닛을 `Scene.settledHits`에 `{unit,hurt,hp}`로 보관한다. 원래 정리는 현재 b.units 순회에만 있어, hurt가 남은 소환귀를 실제 Engine.expireSummon/newRound/pruneExpiredSummons가 배열에서 제거하면 그 객체 참조가 Map에 남았다.

실제 Engine 생성→실제 hurt→표시 settle(pause)→resume→newRound 만료/prune 경계 fixture12회에서 고아 참조가0→12로 늘었다. 일반 물리 시간 전체를 재생한 시험은 아니며 명시적 라운드 경계 fixture다. 이 조건이 모든 정상 전투에서 일어난다고 주장하지 않는다. 이번 연속 표본에서 settledHits의 큰 누적도 관측하지 않았다.

수정 `b8487309`: 현재 b.units에 객체 자체가 없는 항목만 지우는 표시 참조 정리1줄과 주석2줄이다. live 유닛의 pause/resume/새 피격/hurt 종료/객체 복원 동작은 기존대로다. 피해·능력치·적·미술·FX 규칙은 바꾸지 않았다. 메모리 참조 소유권 버그이며 사용자 렉 원인이나 체감 최적화라고 부르지 않는다.

## 후속 계측 도구 주의점

새 아키텍처 검토에서 `turnNotice=null`만 직접 지정하고 배너 DOM을 정상 종료시키지 않으면 시작 배너가 남을 수 있음을 실제 화면에서 확인했다. 이전 고정 저장/화면 비교 도구도 notice 직접 clearing을 사용하므로 그 rAF 결과를 일반 플레이의 대표 FPS로 확대 해석하지 않는다. 폐기한 raster 후보의 미입증/롤백 결론은 유지한다. 이 문서의 연속 전투 도구는 `turnNotice`를 직접 지우지 않고 실제 App.frame/Story lifecycle 및 대화 버튼을 사용했으며, 해당 연속 표본과 고정 화면 계측을 구분한다. 후속 아키텍처 최종 계측은 생산 루프의 배너 종료를 기다린다.
