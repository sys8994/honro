# 11장 정상 입력 전체 진행 검수

## 결론과 정확한 범위

2026-10-09, 경지10의 정식 수련 프로필과 새 11장 원래 스폰에서 시작한 진행이 **7목표 완료와 실제 `phase: won`**에 도달했다. 최초 적45(주민에게 붙은 혼 포함), 유한 증원19, 최종 적64 전원 제압, 방어 진행4/4·잔향6, 주민566/950HP, 동행3명 생존, 아이템 소비0이다.

다만 실패 없는 단일 실행이나 네 명 생존 완주는 아니다. 입력 정책을 교정하며 일반 저장/Continue를 사용했고, 31턴에 소단이 쓰러진 분기에서 보관한27턴 저장으로 한 번 돌아갔다. 이어간 분기에서도 소단은74턴 적 행동 중 쓰러졌다. 최종 구출은 붙은 혼을 처치한 뒤 궁수가 E를 사용하는 기존 대체 경로였다. **살아 있는 혼 약화 후 소단 분리까지 포함한 전체 완주는 미입증**이다.

생산 코드를 검수에 맞춰 바꾸지 않았다. 진행 중 선택·이동·기본점프·장착 기예 발사·대기·E만 사용했고 HP/기력/이동력/XP/좌표/적/목표 값을 보정하지 않았다. 캠프 준비는 실수련/능력치 API와 실제21포인트 한도다. 정상1–10장 기준20,571XP가 실제 경지10이며, 옛 설정의 입장경지12라는 표기로 레벨을 올리지 않았다. M10 회복말뚝과 A05 등 정상 회복 효과는 허용했다.

## 실제 진행과 정책 실패

- 10턴: 소단이 서쪽 매듭 E. 경고 후13턴 서쪽 추격3명이 들어왔다. 17턴까지 초기 서측과 되돌아온 무리를 제압했다.
- 40턴: 무사가 동쪽 매듭 E. 48턴 방어4회 완료. 처음 경고는 review에서, 첫 잔향은 다음 배우의 행동 시작 경계에서 나타났다. 총6으로 끝났고 입구 증원도 유한했다.
- 57턴: 붙은 혼을267/796HP(33.5%)로 약화했다. 주변 적이 구출을 막았다.
- 71턴: 구출 marker360 안의 위협2. 72–74턴에는 위협0으로 실제 분리 창이 열렸다. 그러나 소단은 marker에서 약550 떨어진 후퇴 목적지에 남았다. 궁수/진목은 약994, 무사는 약3730 떨어져 있었다. 소단은48→8HP가 된 뒤74턴 적 행동에 쓰러졌다. 이 실패는 구출 불가능성의 증거가 아니다.
- 171턴: 혼 처치 후 궁수의 실제 E로 구출. 주민566HP. 분리 가능 창을 놓치고 원거리 목적지를 오래 유지한 입력 정책 때문에 크게 지연됐다.
- 208–210턴: 무사가 동고지의 짧은 사격 선반에 기본점프로 올라 측면을 잡은 뒤 고지 잔적을 줄였다. 지상에서의 대기와 선반 점령 후 결과가 달랐다.
- 218턴: 궁수의 실제 가지 이동 후 A01, 각156.5090752°/세기0.6845421로 마지막 박쥐371→143HP. 224턴 두 번째 A01, 각151.7438763°/세기0.6330065로 제압. 특정 고급기예나 적 위치 변경은 없었다.
- 225턴: 잔적0·clear-road 자동완료. 228턴 진목의 북쪽 흔적 E와 production App의 실제 승리 판정. 최종본 Continue도 같은 결말이다.

겹친 oneWay 면의 끝을 지나지 않고 아래 목적지와 가깝다는 이유로 되돌아가는 정책, 넉백 이후 완료된 경로를 재계산하지 않는 정책, 약화한 혼을 소단 사망 뒤에도 공격 대상에서 제외하는 정책을 교정했다. 물리/목표 판정을 완화하지 않았다. 첫 수동 기본점프는 의도한 가지가 아닌 고목에 착지했고, 이후 전투 변위와 정상 보행으로 가지 사선을 얻었다. 따라서 그 시도를 독립적인 ‘한 번의 깨끗한 점프로 진입’ 증거로 쓰지 않는다.

## 턴 수와 대기 해석

전체 기록은228턴이다. 중복 Continue 시작 기록을 합치고, 한 턴 안에서는 공격 > 치유 > E > 이동 > 대기 순으로 분류했다.

| 라운드 분류 | 수 |
|---|---:|
| 플레이어 발사가 있었던 라운드 |114|
| 발사 없이 이동한 라운드 |16|
| 발사/이동 없이 치유 또는 E한 라운드 |1|
| 대기만 한 라운드 |97|

배우별 행동 턴은 공격250, 이동88, 회복말뚝8, E4, 대기407이다. 같은 라운드에 이동과 사격이 함께 있을 수 있고, 발사 횟수가 실제 유효 피해 횟수와 같지는 않다.

**75연속 무발사 대기는 오래 남은 검수 목적지와 정책 정지 때문에 발생했다. 228턴이나97대기를 맵의 필수 소요시간/난도/인간 플레이 평균으로 해석하면 안 된다.** 정상 입력으로 완료할 수 있다는 존재 증명이며, 최적 경로·재미·평균 난도 승인은 아니다. 이전4b061b의129턴 정지/378턴 예산 종료와도 정책이 달라 직접적인 난도 비교가 불가능하다. 시간/프레임 값은 마지막 Node 실행 구간과 일부 초기 불완전 카운터를 포함해 성능 지표로 쓰지 않는다.

실제 전체 진행 checkpoint를 바꾸지 않고 독립 Native 프로세스로 서측15턴, 중앙41턴, 동측210턴과 최종 흔적을 렌더했다. 지상·가지·줄기의 분산, 중앙의 전위/상단 지원/방어원, 동고지의 선반 측면을 볼 수 있다. Native Canvas이며 DOM/HUD·실제 브라우저 입력·모바일 성능 증거는 아니다. Chromium socket EPERM 제한을 재시도하거나 우회하지 않았다.

## 보존물과 재검토

검수 도구는 `tests/stage11-ravine-fullplay{,-summary,-capture}.mjs`다. 실제 입력 계획은 이동 목적지·배우 선택·치유/조준/기본점프 지시만 담고 battle 값을 담지 않는다. 목표 좌표는 이동 명령의 목적지이며 배우 위치 주입이 아니다. production Continue와 mount의 DOM 이전 핵심을 그대로 실행하고 전원 x/y/HP/focus/moveLeft/dead, phase/round가 저장 전후 같은지 assert한다.

오프라인 복구본의 evidence에는 다음 두 폴더를 보존한다.
- `fullplay-composed`: 초기값/초기 출처 재구성,31턴 사망 분기,27·37·43·87·190·217턴 원본 저장,226턴 종료 전 저장, 전체 result/summary, 정책 변경 이력, 각 실행 로그, Native PNG.
- `fullplay-final-runtime`: 최종본 Continue 초기값·종료 checkpoint/result/summary/runtime·script SHA·로그·최종 Native PNG.

result의 actions는 고수준 실제 행동과 발사 각도/세기를 기록하며 프레임별 모든 키 입력의 완전한 재생 파일은 아니다. 실시간으로 바꾼 계획과 정상 저장 재시도가 있으므로 script 한 번의 실행이 동일한228턴 경로를 자동 재현한다고 주장하지 않는다.
