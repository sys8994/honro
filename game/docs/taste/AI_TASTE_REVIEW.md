# AI 취향 검수 절차 v1.0 (2026-11-03)

재미·미감·분위기는 숫자가 아니라 느낌이고 사용자 고유의 취향이다. AI는 그것을 **판정하지 않는다.** AI는 [혼로 취향서](HONRO_TASTE_BIBLE.md)와 [취향 기록부](TASTE_LEDGER.md)에 비추어 어긋남을 찾고, 사용자가 볼 곳을 좁혀 질문한다. 최종 판단은 사용자다.

배경: AI 평가는 점수를 중간으로 몰고(중심 경향), 미감 판단은 모델끼리도 거의 일치하지 않는다는 연구가 있다. 개인 취향은 그 사람의 판단 예시와 교정 사례로 맞출 때만 쓸 만하다(LLM-Rubric, LLM-as-a-judge 보정 실무). 그래서 점수 대신 비교·위반·질문을 쓴다.

## 1. 쓰지 않는 것

- "재미있다/아름답다/합격" 같은 단정이나 10점 척도 점수.
- 취향서에 없는 일반론(“보통 게임은…”)으로 사용자 취향을 대체하는 것.
- 숫자 지표(라운드·피해·실효 행동 등)만으로 재미를 승인하는 것. 숫자는 고장 탐지용이다.
- 원본을 보지 못한 이미지·음원에 대한 승인 범위 추정.

## 2. 검수 순서

1. **대상 확인.** 실제 화면(필요한 화면비·줌·상태), 실제 대사 원문과 조건, 실제 소리(측정값·파형), 실제 플레이 기록을 모은다. 보지 않은 것은 판단하지 않는다.
2. **북극성 대조.** 취향서 §1의 여섯 느낌 중 이 대상이 맡아야 할 것을 고르고, 그 느낌을 깨는 요소를 찾는다.
3. **반목표 대조.** 취향서 §7과 영역별 금지 항목을 하나씩 확인한다. 위반은 근거 화면·원문과 함께 적는다.
4. **기록부 대조.** 비슷한 과거 승인·반려 사례를 찾는다. "10-20 단색 지형 반려와 같은 특징"처럼 사례로 말한다.
5. **비교 판단.** 가능하면 두 안(현재 대 이전, A안 대 B안)을 놓고 "어느 쪽이 취향서의 어느 조항에 더 가까운가와 근거"를 쓴다. 절대 점수는 쓰지 않는다.
6. **질문 목록.** 확신할 수 없는 것은 결론 대신 사용자에게 줄 구체적 질문으로 남긴다. 예: "4막 31장 연실의 '감탄은 배 대고 해요'가 쓸쓸·공허한 4막 공기에 비해 가벼운가?"
7. **예측 기록.** 사용자에게 보여 주기 전에 예상 판단을 기록부의 예측 표에 적는다. 사용자 판단 뒤 일치 여부를 채운다.

## 3. 보고 형식

```
대상: (장/화면/대사 id/소리 이름, 증거 종류)
맡아야 할 느낌: (취향서 조항)
어긋남 의심: (근거 화면·원문) — 관련 조항/기록부 사례
비교: (A vs B, 더 가까운 쪽과 근거)
사용자에게 묻고 싶은 것: (예/아니오로 답할 수 있게)
AI 예측: (승인/반려, 확신 낮음/보통/높음)
```

## 4. 신뢰 범위

- 영역(미술·대사·소리·음악·플레이 흐름·UI)별로 예측 적중률을 본다. 최근 10건 중 8건 이상 맞힌 영역만 AI가 "어긋남 없음"을 1차로 걸러도 된다. 그 밖의 영역은 AI가 질문만 하고 사용자가 직접 본다.
- 사용자가 AI 판단을 고친 사례는 기록부에 우선 추가한다. 틀린 사례가 가장 좋은 예시다.
- 취향서와 실제 사용자 판단이 다르면 사용자 판단이 맞다. 취향서를 고치고 §9(바뀐 입장)에 남긴다.

## 5. 갱신

- 사용자가 새 취향을 말하면 기록부에 원문과 함께 추가하고, 반복되는 판단은 취향서 해당 영역에 한 줄로 올린다.
- 취향서를 바꾸는 커밋은 문서만 바꾼 작업이다. 게임 빌드·브라우저 검사는 하지 않는다.
