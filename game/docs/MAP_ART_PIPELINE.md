# 벡터 지형·이미지 원경 미술 제작 기준

현행 1–30장은 기존 벡터 지형과 장면별 이미지 원경을 사용한다. 장 개편의 순서·최소 3회 집중 미술 검수·별도 최종 종합·장별 내부 검수·화면 보고 기준은 [STAGE_PRODUCTION_SOP.md](STAGE_PRODUCTION_SOP.md)를 따른다. 아래 과거 장식 검사 수치는 해당 도구의 범위이며 개편 완료 gate가 아니다.

## 제작과 보존

장별 이야기·참가 동행·실제 이동/사격 선택을 먼저 확인한다. 충돌과 미술을 함께 저작하되 원경을 밟을 수 있는 지형으로 오인하게 만들지 않는다. 근경의 뒤쪽 지표 폭·보행면·앞 경사면은 연결된 장소로 구성하며 충돌면만으로 전체 그림을 잘라내지 않는다. 필요한 앞 가림은 별도 그리기 순서로 처리한다.

기존 공통 벡터 에셋과 렌더러를 사용한다. 큰 실루엣→수평 선반·수직 절리·비스듬한 암반 등 중간 형태→명암·접지 순서로 만든다. 같은 돌의 격자 복제, 임의 삼각형, 미세 균열/노이즈, 거대한 단색 면, 장식 콜라주로 완성도를 대신하지 않는다. 소나무는 비대칭 수관과 지지하는 몸통/가지를, 건축은 지붕·기둥·벽·기단과 통행 공간을 함께 읽히게 한다.

승인된 이미지 원경의 장별 매핑과 공통 로딩/캐시를 유지한다. 동굴·실내·묘역 등 실제 장소에 맞는 깊은 공간을 사용하고 skyVisible을 존중한다. 사진 같은 미세 질감은 벡터 근경의 목표가 아니다. 일반/확대/최대축소/모바일에서 원경 끝·공백·반복 경계·지형 오인과 캐릭터/조준선 대비를 직접 확인한다. 근경 변경을 이유로 기존 원경을 임의 교체하지 않는다.

Game·Stage View·Playtest는 shared/build.mjs의 공통 번들을 사용한다. 생성 HTML은 직접 수정하지 않는다. 성능 관련 변경은 기존 캐시·메모리·실행 검사를 필요한 범위에서 확인한다. 캡처와 검수 기록은 소스 SHA와 함께 보존하고 사용자 전달 화면은 Library에 저장해 확인된 ID를 보고한다. 수치 통과는 미술 승인이나 사용자 승인을 대신하지 않는다.

## 과거 장식 전용 검사 범위

### 제작 소스와 점 수 예산

`shared/runtime/map-art-polish.js`가 기존 `Scene.background`/`Scene.landmark`에 장식 그림만 추가하거나 교체한다. `shared/build.mjs`에서 Game·Stage View·Playtest에 같은 순서로 번들한다. Stage 1–2의 밝은 화강암 3종은 `tools/map-forge/polish.py`로 활성 프로젝트 라이브러리의 **visual**만 수정한다. 물리 `collision` 배열은 변경하지 않는다. 10장 `ritualDais`만 `back`에서 `prop`으로 옮겨 땅에 가려지던 제단을 보이게 한다.

변경 전 커밋 `b81d8cc`의 실제 Canvas 경로 점 수는 `tests/fixtures/map-art-baseline.json`에 고정한다. `tests/map-art-browser.py`가 Stage 1–10의 52개 장식/배경 표본에서 `moveTo`·`lineTo`·곡선 끝점·사각형/타원 대응 점을 계수해 **각 표본이 원본의 2배 이하**인지 검사한다. 현재 최고 배율은 장식 1.28배(화강암 25→32점), 배경 1.79배(5·6장 112→200점)이다. 점 수는 Canvas 경로 명령의 비교 지표이며, 픽셀·투명도·레이어 합성과 시각 품질을 대신하지 않는다.

### 제한된 장식 변경 검사

미술 변경은 필요한 HTML을 빌드한 뒤 수정한 배경/장식의 실제 이미지와 레퍼런스를 비교한다. 작은 게임 크기의 대비·접지·캐릭터 가독성을 보고, 움직임을 바꾼 경우에만 해당 모션을 확인한다. `npm.cmd run test:map-art`는 전장 1~10과 세 실행 화면을 검사하는 선택형 전체 도구다. 관련 문제가 있을 때 재사용하며 매 수정마다 전 장 캡처·세 호스트 픽셀 비교를 요구하지 않는다. 과거 전후 자료는 `_local/reports/map-art/`에 있다.

배경은 기존 단일 정적 레이어 캐시를 사용하고 별도 매 프레임 효과를 만들지 않는다. 성능 관련 로직 변경이나 실제 문제가 있을 때만 해당 기존 성능 검사를 선택한다. 전체 verify는 필수가 아니다. 새로 만든 디자인의 심미적 판단은 자동 통과와 분리하여 위 이미지로 검토한다.
