# 맵 장식·배경 제작 기준

## 범위와 시각 목표

활성 `shared/data/campaign.json`의 Stage 1–10 장식과 `shared/runtime/art-dark.js`의 배경 레이어를 대상으로 한다. 지형 충돌, 발판, 표면 재질, 상호작용, 저장 상태는 미술 작업의 기준에서 제외한다. 작은 전장 화면에서 읽히는 실루엣과 어두운 재료감에 점을 쓴다.

- 산은 둥근 반복 곡선 대신 단층·암면이 보이는 비대칭 능선으로 그린다. 원경은 저채도 청록·먹색, 근경은 더 어둡게 겹쳐 전투 지형과 구분한다.
- 건물은 긴 용마루, 낮고 깊은 처마, 기와선, 목재 기둥, 창호 분할, 낮은 돌 기단을 사용한다. 성문·창고·불탄 민가·산신당·누각·의식 제단을 같은 전각으로 돌려 그리지 않는다.
- 마을/상여 길목에는 풍화된 장승과 솟대를 작은 크기로 둔다. 웃는 표정이나 과장된 색·기와 곡선은 피한다. 실제 조형의 참고는 [국가유산포털의 한국 지붕 설명](https://heritage.go.kr/heri/html/HtmlPage.do?pageNo=3_1_7_0&pg=%2Fpalaces%2FpalacesRoof.jsp), [한국민족문화대백과의 장승](https://encykorea.aks.ac.kr/Article/E0048619) 및 [솟대](https://encykorea.aks.ac.kr/Article/E0030608)이다. 게임 그림은 시대 고증의 재현이 아니라 그 형태를 낮은 해상도에 맞춘 추상화다.
- 소나무는 짧은 삼각형 반복 대신 긴 가지와 한쪽으로 기운 수관으로 만든다. 거대 소나무의 기존 발판 가지는 높이와 방향을 보존한다.

## 제작 소스와 점 수 예산

`shared/runtime/map-art-polish.js`가 기존 `Scene.background`/`Scene.landmark`에 장식 그림만 추가하거나 교체한다. `shared/build.mjs`에서 Game·Stage View·Playtest에 같은 순서로 번들한다. Stage 1–2의 밝은 화강암 3종은 `tools/map-forge/polish.py`로 활성 프로젝트 라이브러리의 **visual**만 수정한다. 물리 `collision` 배열은 변경하지 않는다. 10장 `ritualDais`만 `back`에서 `prop`으로 옮겨 땅에 가려지던 제단을 보이게 한다.

변경 전 커밋 `b81d8cc`의 실제 Canvas 경로 점 수는 `tests/fixtures/map-art-baseline.json`에 고정한다. `tests/map-art-browser.py`가 Stage 1–10의 52개 장식/배경 표본에서 `moveTo`·`lineTo`·곡선 끝점·사각형/타원 대응 점을 계수해 **각 표본이 원본의 2배 이하**인지 검사한다. 현재 최고 배율은 장식 1.28배(화강암 25→32점), 배경 1.79배(5·6장 112→200점)이다. 점 수는 Canvas 경로 명령의 비교 지표이며, 픽셀·투명도·레이어 합성과 시각 품질을 대신하지 않는다.

## 눈으로 보는 검사

미술 변경은 필요한 HTML을 빌드한 뒤 수정한 배경/장식의 실제 이미지와 레퍼런스를 비교한다. 작은 게임 크기의 대비·접지·캐릭터 가독성을 보고, 움직임을 바꾼 경우에만 해당 모션을 확인한다. `npm.cmd run test:map-art`는 전장 1~10과 세 실행 화면을 검사하는 선택형 전체 도구다. 관련 문제가 있을 때 재사용하며 매 수정마다 전 장 캡처·세 호스트 픽셀 비교를 요구하지 않는다. 과거 전후 자료는 `_local/reports/map-art/`에 있다.

배경은 기존 단일 정적 레이어 캐시를 사용하고 별도 매 프레임 효과를 만들지 않는다. 성능 관련 로직 변경이나 실제 문제가 있을 때만 해당 기존 성능 검사를 선택한다. 전체 verify는 필수가 아니다. 새로 만든 디자인의 심미적 판단은 자동 통과와 분리하여 위 이미지로 검토한다.

## 현재 벡터 미술 교정의 출시 차단 조건

이 절은 현재 공통 벡터 미술 교정에 적용한다. 위 Stage 1–10 장식 작업의 과거 범위·점 수 예산으로 이번 지형·건축·쉼터의 미술 합격을 대신하지 않는다. 다음 항목은 실제 렌더 픽셀로 판정하며, 하나라도 실패하면 출시를 막고 수정한 항목을 다시 검토한다.

1. 깊은 지형 전체를 단색·gradient·몇 개의 거대한 도형으로 대체하지 않는다. 큰 지형 몸체 → 중간 규모의 구성 → 국소 재질 디테일의 위계가 정상 시야와 넓은 시야 모두에서 읽혀야 한다.
2. 장소에 맞는 암반·뿌리·흙·물길·침식 형태와 전경 가림이 의미 있게 결합되어야 한다. 반복 노이즈·타일 무늬로 빈 면이나 디테일을 대신하지 않는다.
3. 윗면은 좁게 조금 보이고 지형 몸체는 화면 앞쪽으로 깊이를 가져야 한다. 이동 경로가 읽히면서도 모든 미술이 수평 플레이 경계선에 몰려 있지 않아야 한다.
4. 건축의 지붕·기둥·벽·기단 구조, 원근, 인물 대비 크기가 성립하고 지형 접지·전후 가림이 맞아야 한다.
5. 이전 개별 벡터와 비교해 형태·디테일이 소실되지 않아야 하며, 승인 이미지에 견줄 충분한 입체감과 장소성이 있어야 한다. 옛 벡터와 `1935a106` 시제품은 비교 원본일 뿐 승인 품질 기준이 아니다.
6. 빌드 성공·런타임 오류 없음·성능 결과와 미술 합격은 독립 판정이다. 수치나 연결 성공으로 위 시각 결함을 통과 처리하지 않는다. 거부된 `b02fb44d`도 미술 승인본으로 사용하지 않는다.

대표 실제 픽셀 검토는 **3장 정상/넓은 시야, 18장 정상/넓은 시야, 1장 숲, 21장 도시와 해당 장의 관련 쉼터**다. 공통 변경의 영향을 받는 나머지 장은 렌더된 전체 구도에서 장소별 고유성·빈 면·반복 여부만 확인한다. 전투 완주·무관한 기예 검사·전체 verify·추가 성능 게이트를 만들지 않는다.

### 최소 5회 집중 검수와 최종 전체 심미 검수

사용자 지정에 따라 현재 후보를 실제 렌더·촬영하고 **원본 스크린샷의 픽셀을 열어 보는 집중 검수**를 최소 5회 수행한다. 단순 파일 생성·자동 검사·보고서 읽기는 한 회로 세지 않는다.

1. 전체 구도, 좁게 보이는 상면과 앞쪽 지형 깊이, 경로의 읽힘.
2. 지형의 큰 몸체·중간 구성·작은 재질 디테일 위계, 빈 면과 반복.
3. 접지·전후 가림·인물 대비 규모, 건축 구조.
4. 재질·색·명암·광원·원근의 일관성.
5. 정상 시야·줌아웃·모바일에서의 가독성, 장소 고유성과 이전 통과 항목의 회귀.

각 회는 소스 **내용 hash**(검수 기록을 포함한 Git SHA의 자기참조 대신 실제 미술 소스·에셋 범위의 내용), 장·카메라·뷰포트, 원본 스크린샷 경로와 hash, 직접 본 pass/fail 근거, 발견한 결함과 수정·재촬영 결과, 이전 pass 항목의 회귀 확인을 남긴다. 기준본·교정 전 현재본·교정본은 같은 카메라로 비교한다. 실패는 수정 후 재촬영·픽셀 재열람으로 닫으며, 5회를 넘겨야 하면 계속한다.

소스가 바뀌면 영향을 받은 검수와 이전 pass의 회귀를 다시 확인한다. 특히 공통 renderer 변경 뒤 이전 관련 pass를 자동 유지하지 않는다. 서로 다른 후보의 pass를 합산하지 않으며 최종 후보의 같은 소스 내용 hash에서 집중 5개 항목의 통과 증거를 확보한다. 그 뒤 **동일 최종 소스**의 전체 결과를 별도로 열어 전체 심미 검수를 하고 위 출시 차단 조건을 다시 판정한다.

### 증거와 배포 차단

미술 변경 범위 manifest에 소스·에셋과 내용 hash, 영향받는 장/쉼터·화면, 검수 원본과 기록을 연결한다. 실제 배포 준비 명령은 이 manifest와 검수 증거를 필수 gate로 검사해야 한다. 5회 이상 실검수 기록, 실제 존재하는 원본 사진과 hash 일치, 동일 최종 소스의 집중 검수 및 별도 전체 심미 검수, 미해결 fail 없음 중 하나라도 빠지면 배포 준비를 실패시킨다. 허위 pass·placeholder·같은 기록/사진의 복제로 횟수를 채우는 행위를 금지한다. gate 통과는 픽셀 심미 판정을 대신하지 않는다.

후보가 위 기준과 검수를 모두 통과한 뒤에만 비교 이미지와 항목별 구체적 판정을 담당 조정자에게 한 번 전달하며, 미완성 미리보기는 사용자에게 제시하지 않는다. 담당 조정자의 최종 픽셀 확인과 명시적 통합 전까지 master 반영·Pages 공개를 진행하지 않는다.
