# 캠페인 적 배치 기준

## 출처와 해석 경계

현재 요구사항은 등간격을 피하고, 의미 있고 논리적인 배치, 개체수·밀도 증가, 정예 추가를 앞으로의 공통 제작 기준으로 유지하는 것이다.

8→30명, 정예10→20%, 동시10명은 기본 엔진에 남은 함수/난이도 설정이며 캠페인에 그대로 적용하는 확정 수치로 취급하지 않는다. 아래에서는 구현 역사와 이번 막의 저작값을 구분한다.

1막의 실제 구현 역사인 `COMBAT_STORY_RULES.md`에는 일반 적 HP60%, 초기 적·유한 증원2배, 작은 무리, 보스/필수 인물 복제 제외와 XP·행동 상한 보존이 적혀 있다. 2막 `ACT2_REVISION_DESIGN.md`는 초기18–28, 명시 정예4–5체당1체, 정예HP×1.55/공격×1.15, 행동 상한3–4를 기록한다. 이는 과거 구현 사실이며 이후 막마다 그대로 복사하는 고정 공식이 아니다.

## 앞으로 적용할 기준

1. 먼저 장소와 전투 역할을 쓴다. 문지기, 기록/의식 수호, 고지 사격, 호송 차단, 증원 진입처럼 무엇을 왜 지키는지 설명한 뒤 정확한 공간을 배정한다.
2. 가로 거리 비율이나 일정 간격 배열로 적을 채우지 않는다. 등간격에 무작위 오차만 주거나 모든 적을 복제하는 것은 공간 설계가 아니다. 같은 지역의 군집과 비어 있는 연결 공간을 함께 저작한다.
3. 근접 전위·사격 후위·높은 사격점·정예를 실제 지지면, 차폐, 교전 거리와 함께 조합한다. 단일 대상과 범위 공격, 정면/측면/다른 층 접근이 의미 있는 선택인지 실제 탄도로 확인한다. 군집명만 붙이고 실제 위치와 활성화 그룹을 그대로 두지 않는다.
4. 장별 총인원, 밀집 구간, 정예 수, 증원 수와 위치, 행동 상한을 따로 감사한다. 전체 개체수 증가가 한 턴에 모두 공격한다는 뜻은 아니다. `maxAlive`, 실제 생존 수, 동시 행동 수, 난이도 배수를 혼동하지 않는다.
5. 정예는 중요한 호위·차단·고지 역할에 명시한다. 순번에 따른 숨은 승격과 명시 승격을 중복 적용하지 않는다. HP/공격/XP는 같은 기준값에서 난이도를 한 번만 적용한다.
6. 구조 대상의 몸, 필수 상호작용 면, 시작 파티 공간, 제한시간 초반 접근, 호송 보행면, 최종 집결 공간은 군집 밀도와 별도로 확인한다. 적이 목적지를 가리는 이유가 없는 곳까지 채우지 않는다.
7. 유한 증원은 실제 진입로를 사용한다. 구조 대상이나 파티 바로 위에 재등장시키지 않는다. 현재 방어/증원 조건을 바꾸는 것은 배치 감사와 별도 변경이며, 승인되지 않은 승리조건·UI 문구를 함께 수정하지 않는다.
8. 원본 생성기, 캠페인 JSON, 실제 Game/Stage View/Playtest를 함께 맞춘다. 좌표·종류·정예·난이도·접지·충돌과 실제 전투를 대조한다. 문서의 적 수나 봇 승리만으로 공간/난이도 검수가 끝났다고 하지 않는다.
9. 현재 1막의 형·기 중심 들림과 3막의 육신 악귀 설정을 보존한다. 기존 진행 전투는 적·체력·좌표·목표를 보존하고 새 진입/재시도에만 새 편성을 적용한다.
10. 파티분할·새 지형·새 동선 승인 시 해당 장의 무리와 사선을 다시 저작한다. 네 명 기준의 적 수를 두 명 파티에 자동 적용하지 않는다.

## 검사와 후속 범위

`npm run test:act3:encounters`는 실제 컴파일된10장×5난이도의 좌표/종류/정예/배수/그룹/신체 접지/겹침/빈 공간/저장 재적용을 확인한다. 검사 결과에는 실제 좌표·역할·난이도별 수치를 함께 남긴다. 이 검사는 사람의 난이도 판단이나 브라우저 정상 완주를 대신하지 않는다.

새 수로·외곽·무덤, 2+2팀 분할과 재합류는 별도 승인 전 기획이다. 지형 또는 파티가 바뀌는 장의 편성은 다시 검수해야 한다. 여기서는 승리조건, 퀘스트/클리어 문구, 대사, NPC의 장면 등장 시점은 변경하지 않는다.

## 수정 편성의 정상 입력 검사

검증 범위 정정: 아래 과거 개별 장 입력봇은 현재 HONRO 화면에 없는 엔진 소모품 명령을 호출할 수 있었다. 이 기록은 엔진 행동 진단이며 사용자가 현재 UI로 수행할 수 있는 완주나 연속 난도 합격의 근거로 쓰지 않는다. 소모품 필드는 기존 저장 호환을 위해 유지되지만 새24→27 검수는 실제 화면의 이동·기술·방어만 사용하고 숨은 소모품 명령을 금지한다.

21–30장을 준비된 개별 진입 세이브에서 실제 App/엔진 입력봇으로 모두 승리했다. 체력·좌표·목표를 직접 수정하지 않고 이동·점프·기예·아이템·E상호작용·대기와 대화 넘김을 사용했다. 라운드/행동 수는 순서대로7/29, 16/67, 13/57, 21/88, 10/46, 19/77, 13/58, 19/81, 13/54, 24/116이다. 30장에서 가장 긴 방어 교전과 큰 체력 소모를 관측했다.

이는 장별 한 번의 Native 입력봇 관측이며, 이전 장에서 이어지는 브라우저 연속 캠페인·다섯 난이도 완주·사람의 재미/난이도 승인을 뜻하지 않는다. 기존 승리조건을 유지했으므로 먼 선택 무리를 남긴 채 목표를 마칠 수 있다. 각 군집의 별도 실탄 검사는 지지된 가까운 공격면에서50회 명중했으며 정상 이동/모든 개체의 접근 가능성을 대신하지 않는다.

최종 소스 검수에서 원본 생성기 재실행, 실제10장×5난이도, 90개 맵 안전 조건, 30장 내보내기/재가져오기, 양HTML 빌드, TypeScript검사, 단독 Workshop Playtest 원문 복원, 1막 migration, 게임 Node 회귀를 모두 통과했다. Game과 Stage View의 모든 배우(주민 포함) 초기 좌표·정예·수치가 정확히 일치한다. 기존1·2막·에셋·3막의 적 외 지형/목표/NPC/문구 데이터는 그대로다.

전체 브라우저 통합·성능과 배포판 직접 검수는 이 소스 검사에 포함되지 않는다. 이후 승인되는 두 명 파티와 새 지하/묘역 지형은 별도 편성으로 검증해야 한다.
