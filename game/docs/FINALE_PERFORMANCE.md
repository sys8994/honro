# 행동 종료 사건과 1막 피날레

2026-09-29 후속 요청의 설계·검증 기준. 현재 수치는 [COMBAT_STORY_RULES.md](COMBAT_STORY_RULES.md)에 모은다.

## 사건을 보여주는 시점

조건을 발견하면 `pendingEvents`와 `eventActors`에 사건·캐릭터·라운드를 저장한다. 플레이어/적의 `finishAction`이 연격과 비행, 피해 확인을 끝냈을 때 공통 `actorEnd`가 사건을 실행한다. 동맹과 소환귀도 각자의 완료 순번 변화에서 같은 경계에 들어간다. 대사 큐의 `afterAction`, `waitActor`, `waitRound`는 저장 가능하며, 캐릭터 선택 변경은 완료로 취급하지 않는다. 이미 열린 대화 페이지는 바꾸지 않는다. 승리 조건 판정은 계속 즉시 수행하고, 그때 남은 발견은 결말 앞에서 회수한다.

아직 행동 중인 캐릭터의 장면이 먼저 들어왔더라도, 다른 캐릭터가 완료한 장면은 자기 경계에서 읽을 수 있다. 같은 이야기 ID가 없더라도 서로 다른 캐릭터의 대기를 한 대화로 합치지 않는다. 소단 협력 뒤의 이전 대치 설명과 주민 셋을 구한 뒤의 구조 방법 설명은 낡은 안내가 되므로 제거한다.

## 소단의 판단과 행동

- 3장: 설오가 처음 만난 휘겸에게 신분과 주민들의 행방을 묻는다. 휘겸이 호송 중 남은 이유를 말한다.
- 4~6장: 붉은 실과 방울에 대한 관찰을 쌓는다. 고리를 끊은 선택의 영향은 처음부터 단정하지 않고 이후 목격으로 확인한다.
- 7장: 어떤 주민을 먼저 구해도 설오가 소단이 누구인지 묻고 소개를 듣는다. 주민의 이름과 사정도 당사자의 말로 듣는다.
- 9장: 소단과 처음 대면한다. 손을 놓았다가 사람이 들린 경험과 일행이 앞서 끊은 고리 때문에 도움을 경계한다. 진을 놓는 것은 허락하지만 줄을 넘겨주는 합의는 하지 않는다.
- 10장 전반: 소단이 주박으로 접근을 막는다. 일행은 사람을 죽이는 대신 주박을 걷어 받이진을 잇는다.
- 전환: 양옆 진이 실제 혼을 받는 모습을 확인한다. 끊지 않은 외문 쪽에서 새 들림이 들어오는 것을 함께 본다. 소단이 방어 주박을 거두고 중앙 혼매듭을 맡기로 선택한다.
- 후반: 소단은 이동·공격 없이 의식을 유지한다. 일행은 최소 6회의 온전한 적 턴 동안 보호한다. 중간의 짧은 대화와 의식 뒤 손을 펴는 행동으로 협력의 결과를 보여 준다.

후반에는 적 행동 인원도 한 라운드 4명에서 6명으로 늘린다. 협력이 매우 일찍 이루어지면 6회 방어 이후에도 스테이지 완료 하한인 12라운드까지 증원을 유지한다. 일반 사건의 잔여 증원도 생존 상한 28명을 공유한다.

지문은 짧은 괄호 텍스트로 작성하고 말줄임표는 실제 망설임에 한정한다. 설오는 아직 모르는 내용을 물으며, 담허도 관찰 전에는 추측과 확신을 구별한다. 질문/응답이 끊기지 않는 후속 묶음은 `storyFollowups`로 명시한다. 도입은 안내 포함 최대 8개, 후속 묶음은 최대 5개다.

## 성능 조사와 변경

기존 피격 표현은 캐릭터 몸을 그리는 동안 `CanvasRenderingContext2D.filter`에 밝기·세피아·채도·색상 회전을 설정했다. 복잡한 벡터의 각 fill/stroke가 필터 경로를 통과해, 동시에 피격되는 적이 많을수록 합성 비용이 급증했다. 정지 상태의 기존 성능 검사만으로는 이 상황을 잡지 못했다.

새 표현은 재사용하는 작은 투명 캔버스에 몸을 한 번 그리고 `source-atop`으로 적색/백색을 합성한 뒤 전장에 그린다. 벡터 에셋의 도형 수·실루엣·애니메이션은 줄이지 않았다. 화면 밖 유닛은 세로 범위까지 제외한다. 궤적은 변경되지 않은 전장/각도/충전량의 일반 예측과 충돌 이후 예측을 각각 캐시한다.

칠성추혼은 가운데 자탄의 경로가 끝나면 화면용 예측을 종료한다. 그전까지 다른 자탄의 충돌/사망은 함께 계산하므로 유도의 실제 경로를 유지한다. 대표 자탄이 아닌 다른 화살의 접촉을 연장선의 출발로 잘못 사용하지 않는다. 변경 각도 36개 검사에서 예측 p95가 약 16.7ms에서 8.3ms로 줄었다.

전체 프레임을 측정하니 렌더링 개선 후에도 적의 이동/사격 후보 탐색이 한 번에 140~155ms를 점유했다. 각 이동 후보·탄도 후보 사이에서 중단할 수 있는 generator로 기존 탐색 순서와 평가식을 유지하고, 실제 프레임의 계획 계산에 4ms 예산을 부여했다. 월드가 바뀌면 입력 키를 비교해 다시 계획한다. 중간 계산은 엔진의 임시 상태이며 저장에는 넣지 않아 재개 시 현재 입력으로 다시 계산한다. 시간 예산을 사용하지 않는 기존 분석 API는 같은 generator를 끝까지 실행한다. 좁은 충돌 검사 전에 유닛 AABB를 확인해 먼 대상의 교차 계산/배열 할당도 제외했다. 28마리 실제 프레임 검사 최대 처리 시간이 Game 155.4→8.5ms, Workshop 152.5→8.7ms였다(최종 verify는 별도로 재측정).

효과음은 사용자 입력으로 AudioContext를 연 뒤 유휴 시간에 자주 쓰는 파형을 하나씩 미리 만든다. 첫 명중 시 파형 생성 비용을 줄이고, `latencyHint:'interactive'`를 사용한다. 음량이 바뀔 때만 gain 자동화를 예약한다. `startedAt`은 버퍼 합성과 source.start 이후의 실제 시각을 기록한다. 이것은 브라우저 예약 지연이며 스피커/블루투스의 물리적 출력 지연을 측정한 값은 아니다.

## 검사 구성

- `tests/finale-update.mjs`: 자기 캐릭터 경계, 선택 변경, 저장 대기, 6회 방어·부분 턴 제외·소단 사망·기존 2턴 저장, 조기 협력·증원 상한, 신규 합류 SP/직접 환불 보존, 진목 증가량·치명 수치, 구조 순서별 첫 소개. 분할/동기 AI 판단의 전투 상태 일치·중간 저장·입력 변경과 1,200개 교차 조건의 기존 판정 일치를 검사한다.
- `tests/finale-browser.py`: 두 HTML에서 실제 연속사격/방어 입력, 다른 캐릭터의 대기열 분리, 얇은 실선과 예측 캐시, 협력 대사·정지·저장 재개, 3/6→6/6 진행, 실제 피해로 인한 소단 사망, 효과음 버퍼 재사용과 시작 예약 시간.
- `tests/performance-combat.py`: 같은 28마리 배치와 화면에서 평상시·동시 피격·충전 조준을 순차 측정한다. 추가로 실제 App 프레임에서 비행·피격·적 판단·HUD·효과음을 함께 처리하고 함수별 지연을 기록한다. 결과는 `_local/reports/finale-performance/combat-before.json`, `combat-after.json`에 남긴다. 전후 공통 3장면과 변경 후 추가한 실제 프레임 장면을 구별한다.
- `game/tests/tactics-audit.mjs`: 기존 비행·후보 탐색·아군 피해·대안 표적 검사. 옛 개방 전장 fixture는 변경 전 코드에서도 수평 이동을 선택해 두 축 이동 단정이 실패했다. 높이를 명시하고 수평 통로의 장애물을 배치해 원래 의도한 두 축 우회 검사를 재현했다.
- 기존 `test:story`, 두 HTML integration, migration, 전투/성장/오디오/미술 회귀 및 순차 성능을 전체 `npm run verify`에 포함한다.

완료 조건과 여섯 번의 적 턴 카운터는 명시적 상태 fixture로 준비한다. 실제 브라우저 입력/피격 표현/저장 복귀 검증과 구별하며 전체 10장 수동 완주, 사용자 PC의 체감 난이도, 실기기 GPU/오디오 지연을 검증했다고 주장하지 않는다.
