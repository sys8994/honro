# 혼로 미술검수 계획 v2

**복잡도는 노드·폴리곤·장식 개수가 아니라, 일관된 스타일로 필요한 형태를 충분히 만들고 그 품질을 적은 비용으로 유지하는 정도다.** 기본은 **풍부하게 구성된 화면**이다. 큰 지형부터 충분히 만들고 오브젝트·근경·장식·게임 요소로 불필요한 빈 곳을 채운다. 단순한 지형을 잔장식으로만 덮어서는 안 된다.

아래는 **미측정 설계 목표**다. 수치는 보편 미학 법칙이 아니며, 승인판·실패판을 실측해 제작 전에 고정한다. 실제 카메라 1280×720 / 390×844 CSS px, 최소·일반·최대 줌에서 각각 검사한다.

**공백을 면책하지 않는다.** 꼭 필요한 조준·시야·동선만 범위를 사전 등록한다. 그 밖의 큰 공백은 지형·오브젝트·근경·장식으로 구성해 채운다. 측정 뒤 “의미 있는 여백”으로 재분류해 통과시키지 않는다. 채움률만 높이거나 잔무늬를 늘리는 대신 큰 형태의 배치와 화면 완성도를 본다.

**상면·천장을 속이지 않는다.** 화려한 하부 바위·장식 프레임을 합산하지 않는다. 평탄 보행면 제외는 범위·이유·제외 길이/면적을 공개하고 핵심 상면·천장 전체를 제외할 수 없다. 미세 톱니는 8/3/1px 다중스케일로 걸러내며 자연 윤곽의 `(L1−L3)/L3≤0.12`도 검사한다.

## 숫자에 과적합하지 않는 중간 이미지검수

1. **스켈레톤 → 단색 실루엣 시안 → Inkscape native → raw/최적화 → runtime**마다 실제 크기 스크린샷을 찍는다. 각 단계에서 빈 곳·단조로운 상면·불일치 부품을 표시해 수정한 뒤 다음 단계로 간다.
2. **숫자를 숨긴 비교:** 제작자와 다른 검수자가 기준판/후보를 익명·순서 무작위로 보고 자연스러움, 풍부한 구성, 스타일, 가독성을 판정한다. 독립 이미지검수 에이전트는 실패 위치와 이유를 제시하되, 시각 모델도 놓칠 수 있으므로 점수나 단독 판정을 최종 승인으로 쓰지 않는다.
3. **미공개 시점:** 제작 중 보지 않은 카메라 위치·중간 줌·이동 프레임을 검수자가 뽑아 검사한다. 실패하면 고친 뒤 새 시점을 다시 뽑는다. 보기 좋은 한 장만 고르는 것은 금지한다.
4. **검수 자체 시험:** 평평한 상면·과한 빈 곳·눈 소실 등의 실패판을 반드시 탈락시킨다. 노드 쪼개기, 톱니 추가, 하부 장식 몰기, 유리한 크롭/제외 마스크로 숫자만 개선한 조작판도 탈락해야 한다. 통과하면 작품이 아니라 검수법부터 수정한다.
5. 최종 runtime에서 보존·이음새·색을 재확인하고 등록 기기 대표/최악 장면 warm 60초×3회 각 p95를 검사한다. 원본 해시·보호 ID·카메라·판정과 전후 스크린샷을 남긴다.

**PASS:** 수치와 이미지검수 모두 통과. **FAIL:** 해당 단계 재작업. **BLOCKED:** 기준판·범위·실측 부재. 목표/실측/판정을 분리하고 총점 상쇄·사후 기준 완화를 금지한다. 상세 계산은 기존 `art-metrics`, 충돌 시 본 최신 목표를 우선 적용한다.

근거: [Valve](https://help.steampowered.com/en/faqs/view/0688-7692-4D5A-1935)는 게임 시점 반복 평가를 강조한다. [OpenAI](https://openai.com/index/faulty-reward-functions/)·[DeepMind](https://deepmind.google/blog/specification-gaming-the-flip-side-of-ai-ingenuity/)는 지표를 달성해도 의도를 놓치는 사례를 설명한다. 위 블라인드·미공개 시점·조작판 검사는 이를 혼로에 적용한 운영 제안이지 검증된 만능 해결법은 아니다. 거리 계산은 [OpenCV](https://docs.opencv.org/4.13.0/dd/d49/tutorial_py_contour_features.html)·[scikit-image](https://scikit-image.org/docs/stable/api/skimage.metrics.html)를 따른다.
