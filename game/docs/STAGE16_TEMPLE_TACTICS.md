# 16장 잠운사: 위치와 동행 역할의 실탄 비교

2026-10-09. `tests/stage16-temple-tactics.mjs`와 `tests/stage16-temple-tactics-helper.mjs`의 현재 canonical 전장 검사다. 적 숫자나 군집 이름을 합격 근거로 삼지 않고, 같은 실제 표적에 다른 높이·공격·접근을 적용하여 무엇이 달라지는지 비교한다.

## 재현과 증거 범위

저장소 루트에서 실행한다.

```sh
node tests/stage16-temple-tactics.mjs
```

결과는 `_local/reports/stage16-temple/tactical-shots.json`에 기록한다. 사용한 Stage16·검사·helper의 SHA-256, 실제 입장 수련 원장, 적의 초기 수치, 발사 위치/각도/충전, 예측 결과, 실제 지형 접촉·표적 적중·반사 횟수, `hurt`의 피해 사건과 독립적인 HP 차이를 남긴다. 아래 피해는 이번 소스에서 관측한 값이며 별도로 주입하는 기대 피해 상수가 아니다.

공통 조건:

- 정상 캠페인 Stage16, `normal` 난도. 초기 적35·명시 정예8·적 행동 상한4인 동일 편성으로 매 사례를 시작한다. 이 숫자 자체는 전술 품질의 합격 조건을 대신하지 않는다.
- 기본 장착·정상 수련으로 만들어진 동행을 사용한다. 각 사격 사례는 명시된 동행의 **최초 지지면 포즈와 최초 아군 차례**만 격리해서 설정한다. 전장까지 걸어 온 증거가 아니다.
- 좌표의 `y`는 발 위치다. 실제 `topAt` 지지면 높이를 읽고 접지·지형 신체 여유·다른 배우와의 겹침을 확인한다.
- 아래 `(각도, power)`는 그대로 `Engine.fire(skill, angle, power)`에 전달한다. 각도는 0°=오른쪽, 90°=위, 180°=왼쪽이며 `power`는 0–1 정규화 충전값이다.
- 발사 후 **전체 `Engine.tick(C.STEP)`**, 현재 `C.STEP=1/120`초를 실행한다. 투사체만 옮기는 별도 물리나 예측 명중으로 합격시키지 않는다. 정상 신체 물리·근접 행동·피해·기력 소모가 함께 처리된다.
- NPC와 적을 재배치·복제·축소하거나 HP·방어·공격력·피해계수·폭발 범위를 주입하지 않는다. 지형을 지우거나 고치지 않는다. 정상 피격에 따른 HP/상태/움직임 변화는 엔진 결과다.
- 이동력·기력·쿨다운을 보충하지 않는다. 각 독립 대조는 새 동일 전장에서 시작한다. O08→설오 사례만 두 행동을 한 전장에서 이어서 검증한다.

이 검사는 초기 포즈에서의 전투 효과를 입증한다. 정상 새 입장부터의 이동·적 AI 전체 턴·방어10회·승리·연속 캠페인·브라우저 입력·사람의 재미/난도 평가는 별도 검수다.

## 실제 입장 성장과 낮은 수련 비용

`campaignEntryReadiness`가 생산 코드의 1–15장 최초 완료·합류 보상 원장을 계산하면 동행마다 **37,445XP / 경지13 / 수련점27**이다. 이는 앞선15장을 플레이했다는 기록이 아니다. 현재 곡선의 임의 XP나 전투 배우의 경지를 직접 높이지 않는다.

이 원장을 복사하고 기존 수련을 `Core.untrain`/정상 단련 환불 API로 되돌린 뒤, 필요한 선행 기예를 포함해 `Core.train`으로 각각 랭크1만 배운다. 추가 기초 단련은 없다. `sanitizeLoadout`이 채운 최종 장착까지 기록·검사하며 최대4칸을 넘기지 않는다.

| 동행 | 수련점 사용/잔여 | 배운 유료 기예: 모두 랭크1 | 실제 장착 |
|---|---|---|---|
| 설오 | 0 / 27 | 없음 | A01 |
| 담허 | 5 / 22 | M06, M02, M04, M03, M11 | M01, M04, M11, M02 |
| 휘겸 | 1 / 26 | S01 | S00, S01 |
| 소단 | 6 / 21 | O02, O03, O04, O06, O07, O08 | O01, O04, O08, O02 |

각 동행의 기본기 A01/M01/S00/O01도 랭크1이다. 이 표의 배운 기예를 모두 발사하는 것은 아니다. 실제 비교에는 A01·M01·S00·O01과 M04·M11·O08만 사용한다. A01/M01/O01은 무료 대안이고, 완전 축세 S00은 실제 기력8을 쓰므로 무료라고 부르지 않는다.

## 1. 설오: 낮은 기단과 높은 옆회랑에서 같은 전위를 겨냥

표적은 대법당 동쪽 전위 `tm-hall-screen`이다. 두 사격점은 높이540이 다르고 수평 거리도 다르다.

| 조건 | 최초 지지면과 발 위치 | A01 `(각도, power)` | 실제 결과 |
|---|---|---|---|
| 낮은 기단 | `tm-great-hall-plinth`, (6500,4250) | (1.6175323084719204, 0.6719319020472235) | 전위 명중161, 지형 접촉0 |
| 높은 옆회랑 | `tm-hall-side-gallery`, (5530,3710) | (-12.34775109546585, 0.9371401544154627) | 같은 전위 명중161, 지형 접촉0 |
| 높은 곳의 조준을 낮은 곳에 적용 | (6500,4250) | (-12.34775109546585, 0.9371401544154627) | 기단 석면에 막힘, 전위 피해0 |
| 낮은 곳의 조준을 높은 곳에 적용 | (5530,3710) | (1.6175323084719204, 0.6719319020472235) | 전위는 지나치고 뒤의 `a2-enemy-13` 명중161 |

모두 기력0이다. 높은 위치가 단순 피해 보너스인 것이 아니라, 다른 탄도와 사격 거리·표적 순서를 제공한다. 같은 조준을 두 위치에 복사하면 같은 표적을 맞히지 못한다.

## 2. 휘겸: 실제 접근 후에만 닿는 기본 평참

`tm-great-hall-plinth`의 (5470,4250)에서 `S00(185,1)`은 정예 `a2-enemy-11`에 닿지 않는다. 별도의 동일 초기 전장에서 다음 입력으로만 접근한다.

```js
while (hero.x > 5350 && movementFrames < 100) {
  engine.move(-1, C.STEP);
  engine.tick(C.STEP);
  movementFrames++;
}
engine.fire('S00', 185, 1);
```

발 위치는 (5350,4250), 실제 이동력 지출120이며 남은 이동력이 있다. 같은 평참이 정예에263의 피해를 준다. 베기 중 위치를 순간 이동시키지 않고 두 공격 모두 기력8을 지불한다. 넓은 기단의 가까운 전위 역할이 실제 이동·근접 거리로 성립함을 확인한다.

## 3. 담허: 앞마당의 돌등불 두 체

- 랭크1 M04 `(12.161015118903586, 0.7447168499788914)`: `a2-enemy-0`에146, 뒤의 `a2-enemy-1`에55, 기력38.
- 무료 M01 `(12.619804813215339, 0.7481621759552732)`: 앞의 `a2-enemy-0`에84, 뒤 표적 피해0.

입구의 가까운 앞뒤 배치는 한 체를 천천히 처리하는 무료 기파와 뒤까지 함께 건드리는 범위 공격 사이의 선택을 만든다. 범위 공격을 유리하게 만들기 위해 적 간격이나 기술 범위를 바꾸지 않는다.

## 6. 담허: 서회랑 석벽으로 돌아오는 반탄파

최초 포즈는 `tm-cloister-landing`의 (4650,3830), 표적은 떠 있는 정예 혼 `a2-enemy-7`이다.

- M11 `(45,0.5)`: `tm-west-reflection-wall`에 실제 접촉한 뒤 되돌아와 표적에71. 적중 당시 `reflectCount=1`, 기력34, 시전자 자해0.
- **실패각 대조** M01 `(45,0.5)`: 같은 벽에서 멈추고 표적 피해0. 가까운 벽 폭발로 **시전자 자해54**가 발생한다. 안전한 무료 대안이나 성공 사례로 세지 않는다.
- **안전한 무료 대안** M01 `(116.19017813627273,0.5210744883254981)`: 같은 포즈에서 표적 쪽으로 다시 조준하면 벽 접촉 없이27, 기력0, 자해0.

벽은 장식이 아니라 실제 반사면이다. 반탄파의 돌아오는 탄도와 직접 쏘는 무료 탄도가 모두 가능하지만, 기술만 바꾸고 같은 각도를 유지하는 선택에는 분명한 실패 비용이 있다.

## 8. 소단: 현형부가 동행의 형 공격을 실제로 바꿈

같은 새 전장에 두 초기 포즈만 둔다. 소단은 `act2-floor` (9800,4777.777777777777), 설오는 같은 바닥 (9900,4772.222222222223)이다. 표적 `tm-archive-rear`의 저작 위치·몸·기초 방어는 보존한다.

1. 대조 전장에서 설오를 정상 선택한다. 표적은 설오에게 보이지 않고 유도 대상으로 잡히지 않는다. A01 `(41,0.35)`를 실제 발사하면 우연히 충돌할 수 있지만 형 저항 때문에 피해는16이다.
2. 별도의 동일 초기 전장에서 소단이 랭크1 O08 `(34.585005526351424,0.6468921326895859)`를 실제 발사한다. 현형부 자체 피해107·기력59를 독립 기록한다.
3. 전체 `Engine.tick`으로 `flight → review → aim`을 마친 뒤 `Engine.select('p-archer')`로 설오에게 넘긴다. 차례 종료나 현형 상태를 직접 주입하지 않는다.
4. 표적이 보이고 유도 대상이 된다. 원래 Act2 현형 규칙으로 `manifested=true`, `revealSpiritToParty=true`, 형 피해 보정0.92, 만료 `현재 round+2`가 생긴다. 표적의 몸/기초 방어와 설오의 경지/공격력/랭크는 그대로다.
5. **동일 포즈·각도·충전**의 무료 A01 `(41,0.35)`를 발사하면 실제 피해154가 된다. 현형부의107을 화살 피해에 합산하지 않는다.
6. 지원을 쓰지 않는 무료 대안도 따로 확인한다. 같은 소단 포즈에서 O01 `(29,0.35)`는 혼에게90의 피해를 주고 기력0을 쓴다.

소단은 혼을 혼자 공격할 수도 있고, 기력을 써서 설오가 그 혼을 보고 형 공격을 효과적으로 가할 수 있게 할 수도 있다. 현형 아이콘·예측선만 보인다는 검사에 그치지 않고, 실제 다음 동행의 동일 공격에서 결과가 달라짐을 확인한다.
