# 지형 생성 SOP · 2026-11-02

## 제작 범위
- 사람·몬스터·NPC를 시안/지형 SVG에 넣지 않는다. 크기 표본도 별도 검수 오버레이로만 표시한다.
- 원경·하늘·먼 산·먼 건물·안개는 별도 이미지/효과 레이어다. 지형 시안은 투명 배경의 플레이 지형과 근거리 고정 구조만 만든다.
- 이동 상여·배·문 상태·파괴 가능한 가지/주박목·수면/폭포·표식/발광은 정적 지형에 굽지 않는다. 해당 객체의 독립 자산·상태 계약을 유지한다.
- 기존 지형의 동선·갈림길·다층 구성·통로·접지·카메라 범위를 미술 때문에 바꾸지 않는다.

## 크기·비율 고정 (2026-11-02 보완)
- 캐릭터를 축소하거나 카메라 줌을 바꿔 작은 시안을 보상하지 않는다. 캠페인 collider h92/r22 및 기존 rig 표시 크기를 유지한다.
- 전체 맵 시안은 원본 world 종횡비로 만든다. 1장5400×2200(2.4545:1), 2장4300×3300(1.3030:1). 전체 맵을 일괄1536×1024에 재구성하지 않는다.
- 스켈레톤의 world→image 배율과 여백을 기록한다. 여백이 있는 참조를 이미지 전체에 맞춰 늘려 붙이지 않는다. 실제 접촉선은 원본 지형에서 가져온다.
- 전체 축소도와 **기존 기본 줌의 PC/모바일 부분 화면**을 함께 검수한다. 1440폭/.94 줌은1531.9world 폭, 390폭/.82 줌은475.6world 폭이다. 이는 초기 프레이밍 계산값이며 실제 HUD/리사이즈/스토리 카메라도 별도로 확인한다.
- 나무·관목·바위 크기도 고정된 캐릭터 world 크기와 비교한다. 장식이 거대해 맵이 작은 모형처럼 보이면 장식과 구성을 수정하며 인물을 줄이지 않는다. 시안에 인물을 넣지 않는 원칙은 유지한다.
- `tools/act1-vector-production/scale-guide.py`는 원본 비율 가이드/배율 계약을 출력한다. 출력만으로 시안의 접지 정합이 검증되는 것은 아니다. 정합 미검증이면 벡터 통합 단계로 승격하지 않는다.

## 필수 순서
1. **현재 원본 고정:** `shared/build.mjs`가 실제 합성한 프로젝트와 `HonroMaps.compile`의 충돌/지지면을 추출한다. 미적용 후보 스크립트나 raw JSON만을 현재 원본으로 오인하지 않는다. 장별 geometry digest와 사용 버전을 기록한다.
2. **제작 단위 구분:** 지형 본체/접촉면, 고정 근경, 상태가 바뀌는 객체를 구분한다. 공통 부품과 장 고유 구조를 분리하며 색별 path를 의미별 자산이라고 부르지 않는다.
3. **시안:** 구조용 스켈레톤과 미술용 채택 레퍼런스를 분리해 입력한다. 옆보기의 명확한 보행 경계와 풍부한 큰 굴곡/오버행을 유지한다. 내부는 큰 색면과 재질별2–4개 주요 명암으로 정리한다. 잔잎·미세 균열·작은 붓자국·노이즈로 밀도를 채우지 않는다.
4. **시안 검수:** 실제 투명도, 사람/원경 부재, 구조 개연성, 원본과 접촉선/필수 틈 정합을 확인한다. 가이드 ON/OFF, 정상 줌/모바일 크기에서 밟는 면이 읽혀야 한다. 시점 자체의 완벽함보다 가독성과 채택된 느낌을 우선한다.
5. **실제 벡터화:** Inkscape 추적·편집으로 생성하고 source/immutable raw/final을 구분한다. 최종 SVG의 image 요소·외부 bitmap 의존은0이어야 한다. 흐린 다중 색 띠, 색 영역 사이 투명 틈, 작은 노이즈 섬을 실제 렌더로 확인한다.
6. **오차 제한 최적화:** raw를 보존한 채 매번 raw에서 후보를 만든다. 불필요한 노드·중복 경로·미세 조각과 수치 정밀도를 줄인다. 중요한 보행 윤곽·플랫폼 끝·구멍·좁은 통로·접합부는 보호한다. 원본→raw와 raw→final 오차를 따로 기록한다. 평균 색 오차 하나로 합격시키지 않는다.
7. **한도 내 수렴:** 현행 경로60000자/자산512노드 등의 importer 한도를 올리지 않는다. 실패하면 허용 오차 내 단순화/원래 의미별 자산 분리/구멍 보존 분할 후 재검사한다. Skia 교집합의 범위 검사가 실패하면 가드를 끄지 말고 명시적인 오차 예산을 가진 GEOS 대안을 검증한다.
8. **최종 검사:**1×/2× 및 실제 사용 줌에서 비교한다. 기존 기본 오차 예산(전체 윤곽1.5px, 보호부0.5px, RGB MAE2/보호부1)을 시작 전에 고정하고, 후보가 실패했다고 느슨하게 바꾸지 않는다. 내부 색 경계·구멍·타일 이음새·부분 투명도도 검사한다. 현재 검사가 측정하지 못한 항목은 미측정으로 남긴다.
9. **장별 전달:** 시안과 최종 SVG 실제 렌더를 작업 중 첨부한다. 파일 크기/경로/노드/오차/미완료 항목을 기록한다. 벡터 제작 통과와 게임플레이·배포 통과는 별개다.

## 금지
- 원경까지 통째로 추적한 재현 실험을 게임용 근경 자산으로 완료 처리.
- 임베드 PNG를 SVG라고 전달, 선언만 PASS, 원본/실측 없이 기준 하향.
- 경계 가독성 개선을 핑계로 평지화하거나 재미있는 기존 동선을 삭제.
- 불합격 후보를 다음 제작/배포 단계로 넘기거나 승인 대기 중 독립 작업까지 멈춤.

세부 실행과 시행착오는 `VECTOR_AUTHORING_SOP.md`, 최적화 도구는 `tools/vector-production/`을 따른다. 이번1막은1–10장 전부 이 순서로 제작하며 기존 게임 데이터는 별도 통합 검수 전까지 보존한다.

## 벡터 재현 실험에서 확인한 주의점 (2026-11-02)
- 사용자가 “일단 벡터화”를 요청한 경우 미정합 시안도 독립 재현 실험으로 추적할 수 있다. 단독 SVG 제공은 게임 지형 정합/통합 단계의 통과가 아니며 원래 게이트는 미검증으로 남긴다.
- 투명 래스터의 반투명 경계를 그대로 색 추적하면 밝은 테두리가 생길 수 있다. 원본을 보존하고 추적 입력의 alpha 처리와 임계값을 기록하며 결과 투명도를 확인한다.
- Inkscape Simplify는 작은 임계값에서도 경로/노드가 늘 수 있다. 실제 크기와 노드를 측정하고 커진 후보를 최적화 성과로 부르지 않는다.
- 색 팔레트 근사 일치 픽셀의 최근접 거리는 실제 경계 이동량과 다르다. AA 때문에 한 픽셀의 분류만 바뀌어도 수십px 오차로 나올 수 있다. 엄격한 오차 기준을 낮추지 말고 기하 변위·작은 구성요소/구멍 보존·픽셀 오차를 분리 검증한다. 보조 실루엣 검사만 통과한 결과를 전체 품질 통과로 대체하지 않는다.
- GEOS 분할로 엔진 경로 한도에 들더라도 전체 파일이 커질 수 있다. 한도 충족과 용량/노드 최적화 성과를 별도로 보고한다.
