기본 저작 절차는 [벡터 제작 SOP](VECTOR_AUTHORING_SOP.md), 장 통합은 [스테이지 제작 SOP](STAGE_PRODUCTION_SOP.md)를 함께 적용한다.

## 맵 끝 환경 연결 기준

2026-11-02 사용자 확인: 2장 좌우 확장 지질 처리의 느낌과 방식을 이후 제작의 기준 사례로 채택한다. 이는 해당 검수 이미지의 미술 방향 승인이지 브라우저·저장·게임플레이·배포 검사 면제는 아니다.

- **맵 끝도 같은 장소의 연속이다.** 플레이 지형만 섬처럼 놓거나, 좌우·하단을 큰 단색 벽으로 메우지 않는다. 본 지형의 암석 층·큰 명암면·색 계열이 비플레이 영역까지 자연스럽게 이어져야 한다.
- 현재 world domain과 실제 카메라 허용 범위를 먼저 읽고 시안의 확장 범위를 정한다. Play Bounds 밖을 숨기려고 카메라를 제한하거나 캐릭터를 줄이지 않는다. 별도 충돌 dummy/skirt를 만들지 않는다.
- 외곽도 **스켈레톤 가이드 → 이미지 시안 → Inkscape 추적 → 보호 오차 안의 최적화**로 제작한다. 반복 암석 타일이나 임의 코드 폴리곤으로 대체하지 않는다. 원경 이미지는 계속 별도다.
- 외곽은 플레이 영역보다 차분하게 그리되, 색 하나로 비워 두지 않는다. 거대한 단색 면, 과밀한 잡티, 같은 바위의 격자 반복을 모두 피한다.
- 플레이 영역 경계가 미술의 직사각형 절단선이 되면 안 된다. 같은 연속 지질을 뒤 절벽·지반 기초에 사용하고, 본체의 불투명 밑색이 확장 그림을 다시 가리지 않는지 확인한다. 밝은 암석 면도 캔버스 하단에서 일자로 끊기지 않도록 자연스러운 형태로 끝낸다.
- 비플레이 절벽 안에 실제 길처럼 보이는 보행선·테두리를 남기지 않는다. 실제 발판과 보행면의 가독성은 유지한다. 렌더 표시 교정과 물리 지형 변경을 구분한다.
- **필수 화면:** 기본 배율, 최소 줌 전체보기, 허용되는 좌우 최대 pan, 모바일. 형식 변환·용량 검사만으로 연결 미술을 합격 처리하지 않는다. 진짜 연결부를 크게 보고 색면 단절·틈·떠 있는 외곽·가짜 통로를 확인한다.

기준 사례: [2장 연속 지질 기준 사례](https://github.com/sys8994/honro/tree/dbbb4995510201974539a98e4cc0fc54a190e5f7/art/act1-near-vector-candidates/stage02-continuous-v2). 맵 4300×3300은 유지하고 시안의 시각 범위만 x=-4000~8300, y=0~4500으로 넓혔다. 이 수치를 다른 장에 복사하지 말고 각 장의 원본 지형·카메라에서 다시 계산한다.


## 정밀도 최적화 검수의 주의점
2장 확장 지질의 .1 단위 반올림은 엔진 형식을 통과했지만 1× alpha 윤곽 오차가 2.236px로 1.5px 상한을 넘었다. .01 정밀도로 복원해 1×/2× 최대 1px를 확인했다. 엔진 형식이나 확대 화면만으로 통과시키지 않는다. 새 브라우저 저장 성공도 과거 전투 기록이 누적된 저장 용량까지 보증하지 않는다.

## 재질 크기와 실제 화면 검수
전체 월드용 시안에서 바위 크기를 줄였더라도 실제 보행 카메라에서는 거대한 얼룩으로 보일 수 있다. 3장 실험에서 수치 오차·30% 경량화 통과 후에도 이 문제로 후보를 반려했다. 단독 전체보기 외에 실제 배우 높이를 유지한 보행 구간을 먼저 확인한다. 반복 타원 돌무늬로 면적을 채우지 않으며, 연결된 지질 명암과 필요 시 정확한 스켈레톤에 맞춘 국소 재질 레이어를 사용한다.

## 국소 재질과 외곽 접합 검수
5장 지반 실험에서 전역 시안의 큰 암면과 이끼 띠가 실제 배우보다 지나치게 커 보였다. 국소 시안을 합성해 재질 크기를 맞추더라도 사각형 패치 경계가 새로 생길 수 있다. 따라서 합성본을 다시 이미지 시안으로 연결 교정하고 Inkscape 추적·오차 제한 최적화·실제 보행 및 좌우 pan 화면을 재검수한다. 재질 개선을 이유로 충돌·배우·카메라를 바꾸지 않는다. 동굴 천장과 지반을 별도 BODY로 제작할 때는 기존 빈 통로와 지지부를 보호한다.

Inkscape 누적 이진 추적에서 밝은 색의 모든 연결 성분이 명시한 잡티 제거 임계값 이하이면, 제거 후 흰 배경 사각형만 반환되는 경우가 있었다. 이를 밝은 지형으로 착각하여 채택하지 않는다. 원본 마스크의 성분 크기와 임계값을 확인하여 빈 색 레이어임을 입증한 뒤 제외하고, 보호 색/중요 디테일에는 적용하지 않는다. 병렬 추적 프로필도 전체 출력 경로별로 분리한다.

실제 브라우저 최소 줌에서는 서로 겹친 두 지형의 내부 경계가 잘린 덩어리처럼 드러날 수 있다. 5장 절벽처럼 지반에 묻힌 부분은 기존 원본 polygon의 차집합 표시 마스크로 가려 연속 지반을 보존한다. 충돌이나 배치를 바꾸지 않으며, 실제 빈 통로·보행면을 가리는 임의 덧칠로 해결하지 않는다.

## 보호 영역 픽셀 비교의 8비트 반올림
7장 신목의 옹이에서는 보호 영역67픽셀이 RGB 최대1/255만 달라졌고 alpha는 같았으나, 팔레트 소속 판정의 거리3→4 경계 때문에1px 윤곽 이동으로 오인됐다. 기본 검사는 그대로 두고, 명시적으로 `protectedRgbQuantizationTolerance255: 1`을 켠 경우에만 alpha가 완전히 같고 RGB 각 채널 차이가1이하인 픽셀의 팔레트 소속을 원본 기준으로 맞춘다. 원시 오차·보정 후 오차·허용 픽셀 수를 모두 남긴다. 실루엣, RGB 평균, 변경 비율,0.5px 보호 오차 상한은 바꾸지 않는다. 고대비1px 이동·점/가는선 제거·2단계 색 차이·alpha 변경의 실패 회귀검사를 유지한다. 전체 대비가1/255 이하인 실제 변화까지 구별할 수는 없으므로, 이 한계와 확대 육안검수를 함께 기록한다.

복합 경로는 기존 vector-v1의 dParts를 사용해 하나의 fill 연산으로 보존할 수 있다. 이전 실험 브랜치에만 있던 preserveCompounds 입력 어댑터를 현재 도구에도 포함한다. 조각당60,000자·복합240,000자·32조각·자산4,000,000자와512노드 등 기존 런타임 한도는 높이지 않는다. 윤곽/구멍을 독립 도형으로 무작정 나누지 않고 원본 경로 문자열의 순서와 상대 좌표를 그대로 이어 붙이며, 정확한 fill·hole·상대 원점 픽셀 회귀검사를 통과시킨다.

## 2026-11-02 검수·최적화 시행착오
- 세로형 스테이지의 기존 진입 줌은 가로형과 다를 수 있다. 예: 7장3600×5000은 데스크톱0.82. 다른 장의0.94를 복사한 테스트를 맞추려고 실제 카메라나 배우 크기를 변경하지 않는다. 미니맵 검수는 보더가 아닌 실제 클릭 가능한 내부를 사용한다.
- 상여집 뒤 암벽처럼 비충돌 근경의 거대한 단색 면도 별도 시안→추적 대상으로 분리한다. 8장은 기존 뒷벽 커버리지3경로와 석축·지지 표시를 보존하고, 벽 내부 재질만 교체한다. 건물·기믹·충돌은 분리한다.
- 8장 뒷벽 미세 단순화가 실루엣 오차에 실패하여 원본 첫 실루엣 경로를 보존했다. 마른 소나무 옹이 보호구역은 원본 세그먼트 정밀도를 유지해 통과시켰다. 임계값은 올리지 않았다. 뒷벽 단일 자산 감소율29.6%, 전체6자산33.7%로 구분하며 모든 개별 자산이30% 이상이라고 쓰지 않는다.
- 전투용 테스트 helper의 profile은 저장 포맷의 game/schema/equipment를 보장하지 않는다. 정상 진입 fixture는 현재 fresh 저장 포맷에 정당한 보상·훈련 데이터만 얹고, 실제 타이틀→여정 경로로 확인한다. 저장 복구 모달을 우회하거나 현재 전투를 주입하지 않는다.

- 9장 바닥v2는 픽셀 오차 검사를 통과했어도 정상 카메라에서92단위 배우에 비해 바위 면이 지나치게 커 보여 채택하지 않았다. 원본 맵·배우·카메라는 그대로 두고 시안의 접지 주변 재질 규모만 작게 재생성한v3를 검수한다. 넓은 더미 영역까지 한 이미지에 담으면 이미지상 작은 면도 게임에서는 커질 수 있으므로 최종 렌더러의 배우 대비 비율을 반드시 함께 확인한다.
- 추적 입력 가이드는 SVG viewBox 선언만 믿지 말고 실제 모든 path의 외곽 범위를 포함해야 한다. 9장 뒷받침 암반은x3440까지 존재하여 초기x3200 crop을 생성 전에 확장했다. 접지·틈새를 임의로 재설계한 것으로 간주하지 않는다.

## 10장 재발: 최적화 전 재질 크기 검수와 병렬 제작

10장 바닥 v2는 정량 오차·경량화 검사에 통과했지만 둥근 얼룩 같은 돌 배치로 반려됐다. v3는 각진 암면으로 바뀌었으나 13000 월드 폭의 더미 포함 시안을 통째로 매핑해, 실제 높이92인 배우 옆에서는 암면과 이끼 띠가 지나치게 크게 보였다. 앞선3·5장 교훈을 문서에만 두고 시안 단계에서 실행하지 않은 재발이다. v3는 최종 미술 승인본으로 기록하지 않는다.

- 이미지 생성 직후 저비용 native 합성으로 시작점·대표 보행 구간·중앙 지형을 실제 카메라 배율과 배우 크기로 먼저 확인한다. 시안만 보고 곧바로 추적·정밀 최적화 전체를 반복하지 않는다.
- 원본 맵 크기·캐릭터 크기·카메라를 유지하며, 플레이 영역과 더미 확장의 재질 해상도를 나눠 계획한다. 더미의 거대한 폭 때문에 플레이 영역의 암면까지 확대하지 않는다. 필요하면 국소 지질 시안과 연속 확장 시안을 분리하고 연결 경계를 검수한다.
- 큰 암면 자체를 일률 금지하거나 돌 개수를 할당하지 않는다. 화면의 공간감·보행 경계·재질 크기를 승인 레퍼런스와 함께 판단하고 실제 화면을 증거로 남긴다.
- 병렬 제작은 독립 자산/스테이지별 소유 파일을 분리한다. 공통 런타임과 master 통합·배포는 한 담당자가 직렬 관리한다. 한 자산의 반려가 완료된 다른 자산을 덮어쓰거나 재생성하게 만들지 않는다.
- 사용자에게는 시안·native 합성·실제 브라우저·공개 배포 화면을 구분해 중간 결과를 전달한다. 부품 병렬 제작을 여러 스테이지 병렬 완료라고 보고하지 않는다.
