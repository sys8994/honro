# 혼로 지형 벡터 제작

사용자가 2026-10-31 승인한 4막 2·5·7장 파일럿의 방법이다. **LLM이 좌표를 직접 대량 작성하는 방식으로 자연 지형을 대체하지 않는다.** 시안의 자연스러운 큰 형태를 만들고, 추적하기 좋은 그림으로 정리한 뒤 벡터화한다.

## 제작 순서

1. **기획과 원본 확인.** 이야기·지리·지형 스켈레톤과 실제 참조 이미지를 읽고 본다. 유지할 이동 경로, 높이, 연결부, 동굴 개구부, 기믹 공간을 기록한다. 스타일 시안은 정확한 충돌 스켈레톤이 아니다. 실제 스테이지 제작에는 승인된 배치 도면·랜드마크를 입력으로 사용하고 대조한다. 자료가 없으면 스타일 연구로 범위를 명시하고 기획 일치 통과를 주장하지 않는다.
2. **레이어 분리.** 원경은 이미지로 유지하고 플레이 지형·근경·조수 상태는 분리한다. 재사용 제작은 지형·건축·식생·소품을 의미별 자산으로 계획하고 추적한다. 전체 장면을 색별 복합 경로로 추적한 결과를 의미별 모듈화 완료라고 부르지 않는다.
3. **벡터형 래스터 제작.** 이미지 편집 도구에 실제 기준 이미지를 넣고 `references/vector-ready-prompt.txt`를 스테이지에 맞게 수정한다. 큰 형태·윤곽·연결을 보존하고 작은 타일/그물/풀잎/잡티, 그라데이션을 줄인다. 풍부한 지형을 단순한 평면 슬랩으로 바꾸지 않는다. 10–12색은 프롬프트의 방향이지 실제 색 수 보장이 아니다. 생성 결과를 보고 부족하면 이 단계로 돌아간다.
4. **Inkscape 추적.** `references/pipeline.md`를 읽고 스크립트를 실행한다. 투명 영역의 숨은 RGB를 정리하고 alpha는 별도 추적한다. 흰 레이어를 무조건 지우면 벽·계단·하이라이트도 사라진다. 원본과 raw SVG는 불변 보관한다. 작은 의미 요소(문양·표식·눈코입·장치 연결)는 추적 전에 보호 ROI로 지정한다. 전역 팔레트에서 합쳐지면 `references/pipeline.md`의 별도 보호 레이어 절차를 적용한다.
5. **오차 제한 최적화.** 같은 raw에서 후보를 만든다. 실측 오차를 통과한 후보 중 가벼운 것을 고른다. 숫자를 맞추려고 허용 오차를 계속 키우지 않는다. 엔진 한도를 못 맞추면 래스터 디테일·색 수·의미별 분할을 재설계한다. 파라미터, 해시, 용량, path/subpath/segment 수, 원본→추적 손실과 raw→최종 손실을 각각 기록한다.
6. **이미지 검수.** 시안/벡터형 래스터/raw/최종을 전체 보기, 실제 게임 표시 배율, 최소 200% 중요 부위로 비교한다. 계단·보행면·처마·목재 지지대·다리 연결·창/구멍·수위별 통로·색 역할을 확인한다. 수치만으로 합격 처리하지 않는다. 새 손실과 원래 시안의 문제를 구분한다.
7. **납품.** 원본 시안, 벡터형 래스터, raw/최종 SVG, 비교 이미지, 프롬프트, 실행/검수 기록을 함께 준다. 미리보기/ZIP은 가볍게 만들되 alpha와 원본은 보존한다. 충돌·플레이·성능을 검증하지 않았다면 미검증으로 표시한다.

## 엔진 연결 시 필수 분기

시안/추적 제작까지만 맡으면 위 절차로 제한한다. 충돌·배우·이벤트까지 연결할 때는 먼저 [게임 통합과 실측 검수](references/game-integration.md)를 읽는다. 실제 canonical 스테이지와 승인 스켈레톤을 기준으로 미술·물리·이벤트를 정합하며, 이동 fixture를 전투·목격·미션·브라우저 합격으로 확대하지 않는다. 후보와 테스트 입력 SHA가 다르면 재검증 범위를 명시한다. 현재 진행 스냅샷은 저장소 `_local/reports/act4-integration-progress.json`이며 스킬의 영구 판정값이 아니다.

## 게임 화면 환경 연결 — 최종 미술 필수 gate

투명 시안의 지형 덩어리만 놓은 화면은 최종 게임 미술이 아니다. 기획 단계부터 아래 지반·절벽 기초·해저와 좌우 비플레이 환경, 해당 동굴의 천장·측벽 연결을 별도 레이어로 설계한다. 승인 main 원본은 보존하고 연장 자산도 이미지 시안 → 실제 Inkscape → 오차 제한 최적화로 만든다. 실제 허용 최소 zoom/pan 및 모바일·가로 viewport에서 떠 있는 외곽·물 사각형·단절이 없는지 공통 렌더러로 검수한다. 환경 연장과 BODY/물/FORE 합성 순서를 함께 검수한다. FULL BODY와 중복된 하단 FORE만 제거하고 실제 배우 가림용 근경은 보존한다. 카메라 제한만으로 숨기거나 단색 슬랩·동일 절벽 반복으로 메우지 않는다. 상세 판정은 [환경 연결 gate](references/game-integration.md#환경-연결-gate--2026-10-31-사용자-추가-지침)를 따른다.

## 미술 판단

- 자연스러운 큰 윤곽, 공간 다양성, 읽히는 보행면이 장식·노드 수보다 우선이다.
- 막별 스타일을 확인한다. 4막의 푸른 해안 팔레트를 다른 막에 강제하지 않는다.
- 공중 통로는 암반·기둥·벽·로프 등 납득되는 지지를 가진다. 지지를 고치되 좋았던 수직·분기 구성은 보존한다.
- 수직 이동 횟수는 참고다. 할당량을 채우려 억지 발판을 만들지 않는다.
- 의미 없는 공백은 구성으로 해결하되 잡동사니로 메우지 않는다. 내부 무늬만 복잡하고 외곽이 직선 덩어리면 재작업한다.
- 배경/장식보다 플레이 지형의 실루엣·연결이 읽혀야 한다. 노드 밀도를 기계적으로 같게 맞추지 않는다.

설정·한계: `references/pipeline.md`. 승인 파일럿: `references/accepted-pilot.md`. 스킬은 제작 방법이며 저장소 수정·배포 권한을 새로 부여하지 않는다.

환경 횡전개·흰 테두리·renderer 차이·추출 자산 비대화가 발생하면 [환경 확장 교정](references/environment-rollout-corrections.md)을 읽는다. 보호 플레이 ROI는 보존하되 비플레이 접합 색면의 픽셀 불변을 강제하지 않는다. 최종 화면 판정은 실제 브라우저 기준이다.

확대 선명도 검수와 캐시·원본 미술의 원인 분리는 [선명도 검수](references/sharpness-acceptance.md)를 따른다.
