# Workbench 실증: 5막 2장 서측 부분을 그려 공유 절리를 저장하고 다시 열기

이 디렉터리는 격리된 실험이며, 이전 CI/운영/생산 브랜치와 무관하다. 고정된 기존 가시 외곽/원본 절벽/성책/near/충돌을 가이드로 보존한다. 그 외곽을 에디터로 만들었다고 계산하지 않는다. 4점으로 정하는 두 개의 맞닿은 면과 공유 분기점 1개만 native 캔버스에서 새로 저작한다. 외부 이미지를 가져오지 않으며 작업 파일은 경로가 아니라 좌표와 재질만 포함한다.

## 브라우저 작업 경로
1. 격리된 Workshop에서 5막2장을 열고 '공유 절리' 도구, '암층 재질' 선택.
2. 서측 암벽의 면 끝을 시계방향으로 위→오른쪽→아래→왼쪽 지정. 다섯 번째는 두 면 사이에서 동일한 경계를 이루는 공유점. 스크린 포인터 다섯 클릭만 사용한다.
3. '공유 절리 저장'. 노란 점을 눌러 드래그하면 두 면의 경로가 한 번의 미리보기에서 갱신된다. '공유 절리 저장'을 누르면 한 Undo로 둘 다 되돌아온다.
4. '절리 초안 내보내기'로 작업 파일 다운로드. 새 브라우저의 그대로인 기저 프로젝트에서 '절리 초안 열기' 후 파일 선택. 두 면이 정확히 복원되고 공유점을 다시 드래그할 수 있어야 한다.

## 재현과 한계
- 상태 시험: scoped preview/apply/undo/redo와 360바이트 내보내기/새 Workshop 인스턴스에서 exact 재입력 및 재편집을 통과. SHA-256으로 전체 비대상 프로젝트·원래 BODY를 각각 확인한다. 제품 내 전역 처리와 무관한 scoped commit이고, 관련 없는 기존 검증 오류가 있어도 이를 증폭시키지 않는지 본다.
- 브라우저: `prepare.mjs`는 복사된 폐기용 fixture의 정확한 번들 해시를 검사 후 그 복사본 하나만 수정한다. 그 복사본을 별도 서버에서 띄운 뒤 `python smoke.py OUTPUT_URL_DIR http://HOST/HONRO_WORKSHOP.html` 실행. 실제 브라우저 테스트, 캡처는 아직 이 단계에서 실행하지 않았다. smoke가 브라우저에서 쓰는 API는 카메라/스테이지 선택과 읽기 확인뿐.
- 이 제어 구간을 제품미술로 승인하지 않는다. 자동으로 사각형을 칠하는 기존 시험을 더 확장한 것으로 말하지 않는다. 2면 허용에 초점을 맞춘 현재 버전은 볼록 4점 영역만 지원하고, 겹침/AA 잔틈, 전장 전체 조형/문턱 재질 및 양방향 게임 QA에는 확장하지 않았다. 같은 경계는 유한한 점 하나라 실제 곡선 핸들 가이드는 독립 작업으로 남아 있다.

## 브랜치 증거 계획 (실행하지 않음)
기존 단일 면 증거 브랜치와 분리한 qa/stage42-editor-section 전용 job. workflow-plan.yml은 해당 branch 이름과 경로 외에는 발동하지 않는다. 테스트 폴더에는 prepare, source-check, patch, joint, curve, guard, smoke의 파일만 필요하다. 빌드 직후 raw owner/clip와 guard SHA를 모두 검사한다. 브라우저에서도 stage-42 원본 body/clip pin을 확인하고 재열기 전후 원본 벡터 및 비대상 전 프로젝트 SHA를 대조한다. 새 브라우저에서는 원본 텍스처의 점유 가이드/구멍을 바꿀 수 없다. 최초/재열기 화면의 카메라는 같은 위치다. 드래프트는 일시 파일이며 artifact로 보내지 않는다.
게임 네이티브 1뷰에는 두 편집 면이 실제 보이며 절벽·원근 구조는 unchanged였다. 하지만 단순한 면이 마름모처럼 튀어 보이므로 미술은 반려하고, 브라우저 작업 또한 실제 저작/공유 경계/재열기의 기술 실증으로만 표시한다.
